# 分层森林图详细规则（编写者手册）

> 读者：架构图的**编写者**（人 / agent）。**阅读者**读 `CLAUDE.md` §项目架构 的简略内容即可。
>
> 校验命令：`python3 scripts/format_architecture_blocks.py --check` 与 `python3 scripts/check_architecture_paths.py`。

## 1. 心智模型

**图是一张分层 DAG：节点可以被多条边共享引用。**

### 1.1 两类节点

| 类别 | 定义 | 图上形态 |
| --- | --- | --- |
| **抽象节点** | 只是一种概念或架构层 | 层名行 |
| **实体节点** | 可以定位到文件或文件夹，或者具体的一个数据 | 目录项行 / 值行 |

### 1.2 两类边

| 类别 | 连接 | 图上形态 |
| --- | --- | --- |
| **组成目录树的边** | 抽象节点 → 其所辖的实体节点 | 缩进 + 盒线（`├──` / `└──`） |
| **数据流边** | 实体节点 → 实体节点 | `↓` |

**目前不存在第三种边。**

### 1.3 书写模型

节点按 **充要定义一行 / 精确实现一行 / 契约一行或多行** 书写。

### 1.4 画图前提

```text
可以画出架构图 ⟺ 层间数据线性化流动 ∧ 层与实际目录对应 ∧ 契约可判定真假 ∧ 列出的文件与文件夹可被明确定义
```

### 1.5 不合并

即便两条边传递的是同样的数据，也**不合并**；按 DAG 的绘制方式类比绘制数据流边。

> 这条规则的**确切范围待定**（§7.1-1）。

### 1.6 来源可追

任一列的来源，要么是紧邻其上的层，要么被 `§` 列锚点声明（§5.4）。

## 2. 节点三元组

### 2.1 `≝` 充要定义

充要定义用符号 `≝` 表达，用自然语言书写。

- 定义必须**抽象**且**精确**（能判断某物是否属于该层）。
- **使用（引用）前必须先定义**：`§<层>` 只能指向文中**此前**已用 `≝` 定义过的层；定义出现在引用之后 = 违规。
- 推论：**声明区在前、管道区在后**（同一个 ```text 块内也遵守）。原位声明（层名 + 紧邻的 `≝`）不受此约束。

### 2.2 `= ⊂ ⊃` 精确实现

精确化实现用集合语言并以集合关系符 `= ⊂ ⊃` 连接充要定义集：

| 符号 | 含义 |
| --- | --- |
| `=` | 定义和实现一致 |
| `⊂` | 定义不包含实现 |
| `⊃` | 实现落后于定义 |

- 若符号顺接层级定义，那么运算符右侧为**基目录**（相对仓库根的目录路径）。
- 多个基目录以 ` + ` 连接（但不建议使用这条规则，优先考虑重构）。
- **顶层各个架构层**默认**代码文件目录即精确实现的集合，故顶层不写 `=`**，但写定义行和契约行。
- **`=` 的判据**：目录项条目集 = 该目录的实现集，才写 `=`。
- **省略约定**：`*.test.ts`、`AGENTS.md`、资源目录（如 `frontend/src/assets/`）不入图，且必须显式声明——否则 `=` 的真值不可判定。

### 2.3 `s.t.` 契约

契约用 `s.t.` 引出**命题逻辑**，并用逻辑联结词（`∨ ∧ ¬ ⇒ ⟺`）构造由自然语言表达的各个简单命题，履行契约对应命题为真，违反契约对应命题为假。

- **图内只放可判定命题**：判不出真假的约定（设计意图、使用惯例、待办）不要写成 `s.t.`——改为 `←` 注解，或移到图外的散文小节（`CLAUDE.md` §项目架构 文末「附：设计意图与约定」即此类归口）。
- `∨ ∧ ¬` 与数学上的用法一致。
- `⇒` 理解为：只要不是“前件真，后件假”就为真。
- `⟺` 理解为：只要不是“两侧真值不同”就为真（即 `A ⇒ B ∧ B ⇒ A`）。

### 2.4 成员枚举 `= { … }`

- 用于列出该条目的公开面（如 `graph_store.ts` 的公开入口集合）。
- 要求：穷尽该条目的公开面；目录名不要混进函数名列表（会让人误以为两者同类）。

## 3. 数据流块

### 3.1 层与值交替

数据流由**层**（黑盒行）与**值**（数据行）交替构成，行间以 `↓` 连接。

- 层是**抽象节点**；值是**实体节点**（具体的一个数据）。

### 3.2 `↓` 是数据流边

- `↓` 独占一行，写 `↓ [函数]`：上面是输入或层，下面是输出或层，右边是转换动作，可留空。
- 层为黑盒：`≝` / `=` / `s.t.` 只声明接口；层上方的 `↓` 是其入口，下方的 `↓` 是其出口。

### 3.3 多步转换

同一列**允许**连续多行 `↓`（一次转换占一条边，多步就多行），但**各行之间必须上下对齐**。

### 3.4 多列 = 并行管道

多条 `↓` 按行、列排布：**列 = 一条管道**，同行并列 = 并行管道；读序行自上而下、行内自左而右。

### 3.5 默认解析（上下留空时）

`↓` 的上下两端**没有显式写出层名**时，按一下规则默认解析：

1. **块级默认**：一条管道块的**上方层行** = 该块所有列的默认**来源**；**下方层行** = 默认**去向**。
2. **层行判据**（indent 4 上，层行与值行同形，必须给判据）：以 `§` 开头的行 ∨ 下一行为 `≝`（缩进 8）的行；值行 = indent 4 且两者都不是。
3. **列级覆盖**：来源用该列上方的**列锚**覆盖（§5.4）；去向用列内行末的 `§` 值覆盖（§5.5）。
4. **不跨块搜索**：默认解析只在**同一个 ```text 块内**上下搜索；跨块 / 跨子架构一律显式写 `§`。
5. **值跨层必须点名**：默认解析只保证**位置**一致，不保证**因果**——某值来自更远的层时，必须显式点名（`←` 注解或 `§`），否则会被归给最近的层。

## 4. 层级即缩进

缩进 = 层级，每级 4 空格：根 `0` / 层与流 `4` / 层属性 `8` / 目录项与续行 `12`

- 层间流（`↓` / 值 / `§` 引用）与层名同级，**不缩进进层内**。
- 目录项行：缩进 12，以 `├──` 起头、**末项用 `└──`**；它是所在抽象节点所辖的**实体节点**，与抽象节点之间由**组成目录树的边**相连。
- 目录项续行对齐到该文件的 `≝`；语义续行以 `│` 引导，纯对齐可省 `│`。

**不进一步嵌套**：

- 层级只用这四级（`0` / `4` / `8` / `12`），**层内不再声明层、块内不再套块**。
- 要到更细的结构（子架构）时，**另开一个 ```text 块**（或另一份 md）单独画；跨块引用一律显式 `§<层>: <实体节点>`。
- 理由两条：嵌套同时毁掉可读性与可维护性；且一旦用到缩进 16，`format_architecture_blocks.py --write` 会把它当续行抹平（见 §7.3）。

## 5. 其他符号

### 5.1 `§` 引用：语法

```text
§<层>: <实体节点>
```

- `<层>`：已定义的**抽象节点**，须与图内层名逐字一致。
- `<实体节点>`：**可省略**；指向该层下的实体节点（文件 / 文件夹 / 具体数据）。
- 同一层的多个实体节点并列：`§<层>: <实体节点1> + <实体节点2> + ...`（以 ` + ` 连接）。
- 缺省约定：**能指到具体节点就指**（粒度到「可定位」），指不出才省略；同一层的多个引用点各写各的。

### 5.2 声明与引用

层只需在顶层的**声明区**声明一次（`≝` / `=` / `s.t.`），其余位置一律用 `§` 引用，不重复声明。

- **声明区条目的判据**：缩进 4 的层行，且**紧邻两处都不是 `↓`**（层名的上一行、其属性块之后的下一行都不是 `↓`）——即它不参与任何管道。

1. **声明区的位置不代表层序**：层序只由管道（`↓`）与依赖契约表达；声明区只按可读性排布。
2. **一个层有三种合法形态**：只声明不引用（保留给"入图但当前无流"的设施）、独立声明并别处引用、同时声明并同时引用。
3. **纯声明层建议带 `←` 注解**说明它为何入图（如 `← 外部设施，当前无流`），否则读者分不清"有意入图"与"漏画了"。

### 5.3 用法一：整行引用

架构图中同一层重复出现（数据流回经该层）时写 `§<层>`（可带 `<实体节点>`），不再重复 `≝` / `=` / 注解。

反馈（逆层序）把目标层重锚到下方，保持输入在上、输出在下。

### 5.4 用法二：列级来源锚点

当某列的来源**不是紧邻其上的层**时，在该列 `↓` 的正上方写锚点行，例如：

```text
                         §工具交互逻辑层: cognition/deconstruct.ts
    ↓                    ↓
    registry + batch     operation params
    ↓ `apply_batches`    ↓ `compose`
```

- 作用域：**仅该列**。
- 对齐：锚点列位 = 该列 `↓` 的列位。
- 未加锚点的列沿用上方层（默认下行）。
- 锚定行其余列留空；锚点不替代该列的 `↓`（见 §7.1-3）。

### 5.5 用法三：列内去向端点

当某列的数据流**流入某个已声明的层**时，把该层的 `§` 引用写在该列的**行内**（值行位置），作为该列的终点。例如 `CLAUDE.md` 中「提交时写出」那一列：

```text
    ↓                       ↓ write `lastValidationResult`    ↓ 提交时 `saveGraph` / `deleteGraph` 写出
    new `graphView`         `lastValidationResult`            §浏览器本地存储（localStorage）【外部存储】
```

- **列上方 = 该列的来源；列内行末 = 该列的去向**——两个位置表达两个方向。
- 去向端点的层**不需要在附近重复声明**，也不需要在其下再写层属性行。
- 与用法二相同：作用域仅该列；列级空缺合法。

### 5.6 `←` 注解

行末右侧 `←` 表注解。

## 6. 排版

- `↓` 多列块里**仅使用英文字符**，不要使用汉字，除非汉字处于行末，且之后没有 `↓` 需要对齐。
- `↓` 多列块里的**代码用 `` ` `` 包裹**，以区分自然语言英语。
- 同一列各行上下对齐（§3.3）；多列块各列的起点由该块内各段的最大宽度决定。

### 6.1 脚本盲区（必须人眼保证）

- `s.t.` 命题的真值。
- `§` 的 `<层>` 拼写、`<实体节点>` 是否存在。
- 锚点的列位正确性（放错也不会报错）。
- 条目是否**穷尽**了该目录的实现：脚本只查"列出的存在"，不查"未列的缺失"。
- 多列块字符集（"仅使用英文字符"）无校验。
- 目录项续行的对齐列由脚本按**整块**计算——正文"对齐到该文件的 `≝`"是简写（块内所有条目与续行共用一列）。
- 是否违背层间单向依赖契约。
