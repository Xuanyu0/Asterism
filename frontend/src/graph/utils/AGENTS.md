# graph/utils/ — 层内共享辅助

## 本目录的定义

存放**层内共享的辅助逻辑**：被 `graph/` 层（及向上调用它的工具层 / UI 层）**多处**复用的、无状态的计算与判定。

默认形态是**纯函数**；本目录唯一允许的副作用是**跨模块共用的开发者通道报告**（见文末例外表）。

## 规则：不耦合消费方特有逻辑

**本目录只提供「计算与判定」；「数据从哪来」与「失败了怎么办」一律由调用方决定。**

具体地，本目录的函数：

- **不得内置数据读取策略** —— 不读持久化、不读注册表、不决定枚举什么；数据一律以参数传入。
- **不得内置异常 / 失败处理策略** —— 不对「读取失败 / 数据缺失 / 部分损坏」做**取舍**（返回默认值、静默跳过、整体失败…）。失败语义属于**消费者的不变式**，写在消费者那里。
- **不得只服务单一消费者** —— 只有一个消费者时，逻辑应留在该消费者内，而不是伪装成通用工具。

判定模板：

```text
这份逻辑是「算法 / 判定」还是「某个消费者的取舍」？
    ├─ 算法 / 判定（入参自包含、无 I/O）  → 可放本目录
    └─ 消费者的取舍（读什么、读不到怎么办）→ 留在消费者处
```

### 为什么有这条规则（真实案例）

`collectGraphTreeIds` 曾在本目录，它把**导出场景的失败取舍**（「任一图读不到 → 整体失败，不静默跳过」）写成了自己的契约 —— 而那段论证的依据指向的却是 `persistence/coordination/export_graphs.ts` 的不变式。**通用工具替消费者背了策略。**

收敛后：只保留纯算法 `collectDescendantIds`（数据以参数传入），两个数据源适配各自回到消费者（导出用例的 `collectTreeIds`、`diverge` 调用侧）。

反例：把「任一图读不到就整体失败」写进通用遍历。

> 文件命名、注释、import 分组等通用规范见项目级 `AGENTS.md`，本文件不重复。
