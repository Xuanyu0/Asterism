# 节点

## 知识节点

### 两种类型

* **虚节点**：表示学生未掌握/想掌握的知识
* **实节点**：表示学生已经掌握的知识

### 虚节点

* **属性**：标签
* **不可被归纳或者解构**
  * 但可在子图中创建

##### 虚节点上的边

* **只能用无向虚边与实节点连接**（多条或单条）
* **只能用无向虚边与最多一个虚节点连接**

##### 虚节点的更新

* 虚节点可以通过学生的掌握或直接删除进行更新
  * 对虚节点更新得到的具体内容完全由用户单轮学习得到的见解并最后自己组装决定

* 掌握后，更新时**用户必须依次处理原来虚节点连接的每条无向虚边**
  * 每条无向虚边原来连接虚节点的一端，在处理该边时**也必须同时确定该端连接的节点**
  * **每条无向虚边的处理都由人类决定**
  * 无向虚边可以不变，可以删除，也可以替换为其他边

### 实节点

* **属性**：标签，认知抽象等级，摘要，笔记跳转链接，度数
* **可被归纳或者解构**

## 引用节点

* 沟通节点
* 启发节点
（具体内容见下）

## 节点属性
* **标签**：概括表示这是什么知识，直接显示在节点上。
  * **限制**：**不超过20个中文字符**
* **可被掌握**：用户可通过点击虚节点浮空窗的掌握属性进入单轮学习，结束后更新虚节点
* **认知抽象等级**：认知抽象等级就是内部最大的子图层数。
  * **例如**：初始时节点是**零级抽象**，一级抽象代表一级子图，如三级级抽象节点表示可以最多可以展开三次，得到三级不同的子图
  * **限制**：**用户无法主动修改抽象等级，仅由知识图谱系统决定**
* **摘要**：**严格不能超过80字**，由用户自主编写，凝练地表示知识点的具体内容，**支持轻量 $ Markdown $ 与 $ \KaTeX $**
* **笔记链接**：笔记文件地址，用户点击直达对应笔记（由系统管理）
* **度数**：表示连的边的数量
  * **含义**：度数越大，表示该知识点越不容易遗忘
  * **视觉效果**：**度数越大，节点大小越大**
* **定义沟通节点**
  * 区别与实节点和虚节点，只是子图中才具有的概念。
  * 在父图中与对应子图的抽象节点相邻（与其相邻的节点以下称为相邻节点）
    * 如果相邻节点还是抽象节点，则对递归查找相邻节点，直到不是抽象节点为止
    * 显示标签时，显示最终的子图路径以及对应最底层的节点标签。
  * 用来联系子图和父图
  * 分别在**子/父图中都出现**
  * 用户的修改在**子/父图中同步更新**
  * 在子图中与沟通边连接，并**半透明化**
  * 点击沟通节点回到上一层父图
* **定义沟通边**
  * 这种边可以一端**半悬空**（用沟通节点半透明实现）
  * 半悬空的一端逐渐淡化，直到与沟通节点一样半透明

## 节点交互设计

* 鼠标触碰时**放大**，表示可交互，否则恢复
* 鼠标**点击节点**才会弹出抽象等级以及笔记等详细信息
* 展开子图在鼠标点击后再在**浮空窗内点击**才会跳转到新的子图

## 子图视觉效果设计

* 用户点击子图展开时，**父节点逐渐放大直到消失，子图从中心扩散开**。（点击“沟通节点”反之）

# 边

### 目标
* 能够清晰地看到知识链条，有效阻止链条断裂
* 帮助学生发现知识间的联系

## 定义

* **有向边**：表示前置依赖或启发关系。
  * **有向实边**：前置必要知识 --（被依赖）--> 后继知识
  * **有向虚边**：某个知识 -.(启发).-> 后继知识

> **有向虚边**：启发边，鼓励学生在高维度看待低维度知识，由此更好的掌握低维度知识

* **无向边**：表示一般或不明确的关系，学生可自行对边注释。
  * **无向实边**：知识A --（相关于）-- 知识B
  * **无向虚边**：知识A -.（似乎联系于）.- 知识B

> **无向虚边**：鼓励学生发现这种边上的具体联系，为学生接下来的探索指引方向，提高学生兴趣

## 边的属性

* 任何边都有标签的属性
* **标签**：由用户自定义（可以留空）
  * **限制**：**不超过10个中文字符**，不做其他限制

## 添加边

* 添加一个实节点时可以用有向实边**指向另一个节点**
* 添加一个实节点也可以用有向实边**被其他节点指向**
* **只有当两个节点同时已经存在时**才能连接**无向边**
* **只有当两个节点同时已经存在时**才能连接**有向虚边**
* 添加一个虚节点时**可以独立添加，也可以用无向虚边与实节点连接**。

## 禁止的情况

* **任何边形成的自环**
* **任何两种边构成的重边**
* **在只通过有向实边的情况下成环**（有向虚边不受限制）

## 允许的情况

* 允许**孤岛**
* 允许**单个节点被多个节点用有向实边指向**

# 节点数量控制

## 数量限制

对于**任意**子/父图：
1. 尽量保持在 **50个节点以内**
2. **超过100个节点提醒用户进行抽象**
3. 当前层的知识图谱**超过150个节点拒绝添加**新的节点

## 控制策略

* **抽象**：
  * **设计意图**：让人类主动去抽象提炼相知识，形成一个抽象节点，并且这个节点独立表示一个子图。
  * **功能**：让知识图谱更轻量，AI 分析更快。
  * **抽象的实现**：
    1. 可以把一个实节点转换为抽象节点，并在内部新建空子图（此时抽象节点的**抽象等级为一**）
    2. 可以选取一系列节点抽象成一个新的抽象节点，选取的节点自动成为抽象节点子图的一部分（此时抽象节点的**抽象等级取所有被抽象的节点中抽象等级最高的加一**）
* **依赖折叠/展开**：
  * **折叠**：人类可以对于一个 $\text{DAG}$ 上的所有前置依赖节点折叠到该 $\text{DAG}$ 的末尾节点。仅视觉效果，折叠操作不删除图的任何成分
    * **限制**：**必须是纯 $\text{DAG}$，其中的节点不能连有无向边**
    * **功能**：辅助学习的 AI 可以通过分析后继节点的掌握判断那个被折叠的知识节点其实已经被人类掌握了
  * **展开**：**折叠**的逆操作
  
* **常识化**：在该图中删除节点操作的一种手段（当然用户也可以选择直接删除）
  * **设计意图**：表示人类已经能够极其轻松得到该节点蕴含的知识，不需要再储存在知识图谱上
  * **具体过程**：把该节点以及连接的边在原图中删除，并转移到独立的“常识层”
    * **常识层**：**仅存在节点，没有任何边**
  * **设计原因**：“完全掌握”这个知识是删除这个节点的充分条件
  * **常识化条件**：**人类能够轻松通过 AI 基于目前知识图谱出的“常识化考验”题集**

# 知识图谱与单轮 AI 辅助学习间的接口

## 进入单轮学习的方式

* 创建新节点（单个或多个）
* 进行掌握虚节点操作
* 进行掌握无向虚边操作

## 单轮学习的产出

### 定义

产出流：**知识节点** $\rightarrow$ **知识块** $\rightarrow$ **知识图谱**
产出形式：
* 单次对话 $\rightarrow$ 知识节点
* 单轮学习 $\rightarrow$ 知识块
* 多轮学习 $\rightarrow$ 知识图谱

### 过程

* 单轮学习中途：
  * **单次对话 AI 最多能够自动产出一个知识节点**（可以不产出）
    * **必须由用户决定是否保留**（可以在对话结束后统一处理）
  * 用户可以在中途自己手动添加/删除节点
  * **只有用户才能建节点间的边**
* 单轮学习结束后：
  * 首先由用户决定此轮学习中的知识节点如何保留并组装
  * 最后由用户决定**此轮学习中的知识块怎么组装到原知识图谱中**

# 三种种交互模式

* 三种模式可在知识图谱的前端页面中随时切换，但同一时间只能使用其中一种
* 三种交互模式的默认模式：相机模式且可点击节点或边弹出浮空窗交互
  * 相机模式：只能平移，缩放镜头
  * 点击交互：左键单击任意节点或边，在其周围弹出浮空框
    * 浮空窗中的修改：可在浮空框中修改标签，摘要

## 一. Cognition

* 定义：认知演化
* 图标设计：放大镜

### 包含的操作：

（格式说明：操作 +（图标设计））

* 探索（四角星）
  * 功能：开始新一轮学习，结束后为知识图谱添加知识块
* 发掘（铲子）
  * 作用对象：虚节点、无向虚边
  * 功能：开启新一轮学习，结束后更新被发掘对象
* 解构（分裂立方体）
  * 作用对象：实节点
  * 功能：不开始新一轮学习，将节点的抽象等级加一，并建立新的子图
* 归纳（聚合节点）
  * 作用对象：多个节点
  * 功能：不开始新一轮学习，创建新的抽象节点，将所选节点转移至抽象节点内部子图。
  * 具体过程：抽象节点自动继承子图边界节点的边（确保继承后合法）。与抽象节点相连的节点，在子图中自动成为沟通节点
* 内化（“1+1”图案）
  * 别名：常识化
  * 作用对象：任意实节点（包括抽象节点）
  * 功能：弹出确认对话框，若确认，则将所选节点及其边删除，并将节点转移至常识层
* 发散（无向虚边）
  * 作用对象：任意实节点
  * 设计意图：在不同子图间（在同一个图也可以）揭示各自节点间的关联
  * 衍生节点定义：**启发节点**
    * 定义：是已存在的节点在其他图内的“引用节点”
    * 特性：属性，样式和原节点完全一致，修改启发节点，会同时作用于原节点。
    * 功能：类似沟通节点，点击后，可以跳转到对应子图
    * 分类：与沟通节点属于同一类，与虚/实节点不属于同一类
  * 具体过程（分三种情况）：
    * 第一种情况：
      * 用户首先点击图上空白处，之后自动弹出搜索浮空窗
      * 用户通过搜索找到对应节点确认后，在空白处创建对应启发节点
      * 之后用户再点击该图内另一个节点进行连线
      * 然后系统就自动建立了从一个启发节点到图上节点的一条有向虚边
    * 第二种情况：
      * 用户首先点击图上节点，之后光标延伸出一条有向虚边
      * 再点击图上空白处，自动弹出搜索浮空窗
      * 搜素到对应节点后，自动创建对应应用节点，并建立连接
    * 第三种情况：
      * 用户直接点击图上节点，后再点击另一个节点
      * 系统直接建立无向虚边，不创建任何启发节点
  * 说明：
    * 进行第一种情况后，必须镜像完成（自动跳转到对应图，完成后返回）第二种情况
    * 进行第二种情况后，同意必须镜像完成第一种情况

* 定义：修改/显示
* 图标设计：扳手

### 包含的操作：

* 添加（加号）
  * 点击后添加图标右侧展开为

## 三. Arangement

* 定义：布局/知识组织
* 影响GraphData的postion属性
* 图标设计：星系
* 统一操作流程：选择操作对象 -> 确认选择完毕 -> 预览布局 -> 用户确认后写入Data

### 认知距离

* 边的距离表示的“软属性”（不是GraphData的内容，是通过边长推断出来的信息）
* 定义：视觉上代表用户在知识认知间的“关联强弱”
  * 越远，表示用户越不需要放在一起看（除非是有向虚边，启发边较为特殊）
  * 越近，表示用户越倾向于把那些知识放在一起看

### 包含的操作

* Adjust：
  * Adjust Distence（双向箭头）
    * 操作对象：任何节点
    * 定义：不改变边方向地改变两节点间边长
    * 操作：
      * 用户先选择一个“动节点”，再选择一个“不动节点”后
      * 光标在画布上拖拽
      * 系统根据光标在屏幕上的移动距离，实时修改边长
      * 确认后，写入GraphData
  * Adjust Angle （旋转角）
    * 操作对象：任何节点
    * 定义：不改变边长度地改变边与水平线的夹角
    * 操作：
      * 用户先选择一个“动节点”，再选择一个“不动节点”后
      * 光标在画布上拖拽
      * 系统根据光标在屏幕上的“移动角度”，实时修改夹角
      * 确认后，写入GraphData
* Layout：
  * Orbit 环绕布局（地月系统）
    * 操作对象：实节点（中心节点）与该节点用实边（有向或无向，禁止任何虚边）相连的实节点
    * 功能：让一些节点绕一个中心节点分布
    * 操作：
      * 用户先选择一个“中心节点”
      * 再选择一些“环绕节点”
      * 选择完毕，系统计算出布局
    * 规则：
      * 只有用户明确选择的环绕节点才会参与 Orbit。
      * 未被选择的节点若没其他规则施加，则保持原位，即便它与中心节点有边。
      * 支持有向和无向实边，但禁止虚边。
      * 如果环绕节点本身是其他 Orbit 的中心节点，只要本次操作没有选择它，它的位置保持不变。
  * Path 路径布局（三点一线）
    * 操作对象：实节点（轴心节点）与该节点用有向实边相连的实节点
    * 功能：让认知路径更加规整
    * 操作：
      * 用户先选择一个“轴心节点”
      * 再选择一些“路径节点”
      * 选择完毕后，再通过鼠标在画布上的拖拽，确定旋转角
      * 之后，系统实时计算出多个路径节点形成一条线的预览布局，但不改变边结构。
  * Cloud Layout（电子云）
    * 定义：
      * 表达知识间的认知联想（Association）。
      * 用户认为这些知识应该放在一起看，但不表达中心、顺序或层级关系。
    * 认知语义：
      * 表达：Association（联想）、Similarity（相似）、Co-occurrence（共现）
    * 操作对象：任意节点，任意边。
    * 功能：
      * 将一组知识组织为认知云团。
    * 操作流程：
      * 选择若干节点，提供任意两个节点间的最大与最小距离（可以有默认值）
      * 确认选择完毕
      * 预览布局
      * 用户确认后写入 Data
    * 规则：
      * 不产生中心节点。
      * 不改变边。
      * 被选节点形成聚集。
      * 未被选节点保持原位。
    * 几何特征：
      * 参考电子云。
      * 无固定中心。
      * 无固定方向。
      * 无规则排列。
      * 允许多种合法布局结果。
      * 系统仅保证：
        * 节点聚集
        * 节点不重叠
        * 保持云团特征
* Knowledge Group：
  * （详细的内容，见下“嵌套布局操作”）
* Move：
  * 单点移动：
    * 操作对象：单个节点
    * 功能：单独移动一个节点在图谱中的绝对位置，不改变其所属的知识群
  * 知识群移动：
    * 操作对象：知识群
    * 功能：单独移动一个知识群及其下级知识群在图谱中的绝对位置

### 嵌套布局操作（非MVP阶段实现）

用户可能对已布局对象继续进行布局操作，如：
* Path + Path
* Orbit + Orbit
* Orbit + Path
* Path + Orbit

由此引入 Knowledge Group 的概念，来界定布局操作的对象范围

#### Knowledge Group

* 定义：
  * 用户定义的一类具有共同特征或者相互关联的视觉组织单元
* 属性：标签
* 作用：
  * 不直接改变位置属性
  * 不改变知识结构
  * 不改变边
  * 只是表达知识的在空间中组织关系
  * 严格区分“抽象”，Knowledge Group 不表达知识间的从属关系
  * 是节点的一种属性
* 规则：
  * 同一个节点不能同时属于多个知识群
* 派生概念：SubGroup
  * 定义：从属于更高级的Knowledge Group
  * 作用：
    * 对更高级的Knowledge Group的整体操作，会同时以递归的方式影响从属于其Subgroup
    * 而对Subgroup的操作，不会改变更高级的Knowledge Group。
  * 规则：
    * 两个知识群之间存在从属关系的前提是：存在至少一条边，其两个端点分别属于这两个群（即直接边连接）。不通过中间节点间接连通。
    * 当删除直接连接 A 与 B 的最后一条边时，触发解除确认的系统提示。
    * 从属关系的传递具有方向性
      * 对于被操作的知识群来说：“我的附庸的附庸是我的附庸”

#### 操作

* 创建知识群
  * 操作对象：任意节点
* 链接知识群
  * 操作对象：两个知识群
  * 操作过程：
    * 先选择一个知识群A，再选择一个知识群B
    * 两次选择结束后，A自动成为B的Subgroup
  * 规则：
    * 两个知识群必须是连通的
* 解除知识群链接
  * 操作对象：两个知识群
  * 操作过程：
    * 先选择一个知识群A，再选择一个知识群B
    * 两次选择结束后，A与B解除原来的从属链接
  * 规则：
    * 两个知识群原来必须是链接的
* 删除知识群：
  * 操作对象：任意一个知识群
  * 操作过程：
    * 选择一个知识群
    * 然后系统弹出提示
    * 确认后删除这个知识群
  * 规则：
    * 一次操作只删除指定的一个知识群，以及其对应的所有从属关系
    * 不连带删除其他知识群
* 成员操作：
  * 移出知识群
    * 操作对象：单个属于某个知识群的节点
  * 加入知识群
    * 操作对象：一个节点和一个知识群

# 图 AI （Graph AI）（此部分，MVP需实现）

* 图相关 AI 采用独立模块化设计。
* 所有 AI 能力统一在后端实现。
* 每个 Agent 可替换底层大模型。
* AI 默认不直接写入正式 GraphData，只生成解释、分析或候选 GraphData。
* 所有会影响 GraphData 的结果，都必须经过 Checker 与用户确认。

## 系统完备性界定：

* **信息流完备（Information Flow Completeness）**：
  * 定义：
    * 对于任意合法的信息状态 I，
      系统都存在对应的信息流路径，
      能够在不同信息表示之间完成转换。
  * 包括：
    * 人类自然语言
    * 结构化自然语言
    * GraphData
    * Candidate GraphData
    * Graph Patch Plan
    * 分析结果
  * 要求：
    * 信息能够进入系统
    * 信息能够离开系统
    * 信息能够被检查
    * 信息能够被分析
    * 信息能够被映射为其他合法表示
* **局部可演化完备（Local Evolution Comleteness）**：
  * 定义：
    * 对于任意合法 GraphData 状态 S，
      以及任意系统允许的认知操作 T，
      系统都存在对应的 Graph Patch Plan，
      使得：
      S → Graph Patch Plan → S'
      成立。
  * 要求：
    * 不需要重建整个图谱
    * 不需要覆盖整个 GraphData
    * 不需要重新导入全部信息源
    * 仅通过局部变更即可完成状态迁移

## Agent Design Principle

* Compiler、Translator、Checker 属于信息源 Agent。
  * 规则：
    * 不允许扩展信息源
    * 允许重组信息
    * 允许压缩信息
    * 允许结构化信息
    * 允许显化输入中已有但未明确表达的结构
  * 目标：在不扩展信息源的前提下最大化降低认知熵
* Analyser 属于探索 Agent
  * 规则：
    * 允许扩展信息源
    * 允许提出假设
    * 允许提出候选关联
  * 目标：在保持可解释性的前提下探索新的认知空间
* 任何 AI 都不得直接修改 GraphData
* 所有 GraphData 的修改必须经过：
  * Schema Check
  * Tool Approval
  * Human Confirmation

## 两个链路

* 图与外部：
  * 从内向外：`GraphData (JSONB)` → `Compiler(humanize)` → `Checker(faithfulness)`（不满足条件时，打回至 `Compiler(humanize)`） → `Translator(render)` （→ `Analyser` → **给 Analyser 的提示词**）（可选部分） → 人类可以轻松理解的语言（/回答）
  * 从外向内：原始自然语言语料 → `Translator(parse)` → `Checker(faithfulness)`（不满足条件时，打回至 `Translator(parse)`） → `Compiler(formalize)` → `Checker(schema)` （不满足条件时，打回至 `Compiler(formalize)` 并交由人工裁决（或者人工手动修正））→ `Graph Patch Plan` → 顺序调用图生成工具 → 人类批准单独工具调用（直到所有操作都被审查） → Candidate GraphData 与 可视化预览 → 人类确认 → `GraphData (JSONB)`（以merge的形式写入，而不是覆盖）
* 图与单轮学习作为 $Interface$ 的 Agents：
  * Analyser
  * Context Router（非纯图AI，另见单轮学习设计文档（此文档，施工中））

## Agents

### Compiler

* 任务：将机器可读的结构化数据（GraphData）与结构化的自然语言按需进行转换
* 角色：
  * humanize：结构化数据 $\rightarrow$ 结构化的自然语言
  * formalize：结构化的自然语言 $\rightarrow$ 结构化数据
* 要求：完整，不遗漏，不编造任何信息

### Translater 

* 任务：将结构化自然语言与人类可阅读的自然语言按需进行转换
* 角色：
  * render：结构化自然语言 $\rightarrow$ 人类可阅读的自然语言
  * parse：人类可阅读的自然语言 $\rightarrow$ 结构化自然语言
* 要求：完整，不遗漏，不编造任何信息

### Checker

* 任务：对转换结果进行校验，并决定是否打回。
* 角色：
  * faithfulness：检查信息是否遗漏、编造或失真。
  * schema：检查结果是否满足 GraphData Schema。

### Analyser

* 任务：负责根据Translater的文本，以及输入的对应提示词进行分析并输出分析结果
* 规则：
  * 必须有提示词才执行分析。
  * 可以提出新的推断、建议和候选知识。


## 用户可直接调用的能力

* 分析图谱
  * → Analyser

* 导出图谱为通用语料
  * → Compiler(humanize)
  * → Translator(render)

* 外部语料导入并创建图谱
  * → Translator(parse)
  * → Compiler(formalize)

## MVP阶段说明

* 优先实现内外信息流连通
* 再实现Analyser智能体功能
* MVP阶段结束后才考虑单轮学习功能以及相关智能体

  * 逐级返回主图

  * 当前主知识图谱内全局搜索

  * 进入常识层（当前知识图谱）
  * 创建新的主知识图谱

  * 折叠按钮：导航卡片用来折叠会dock状态
