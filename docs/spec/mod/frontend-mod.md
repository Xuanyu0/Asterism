# 前端 UI Spec 模板

> 前端每个页面 / 组件区域一份。描述用户看到什么、做什么、发生什么。
> 不描述引擎内部编排——那是引擎 spec 的职责。

---

```markdown
## [页面 / 区域名]

### 一、布局

ASCII 布局图，标注各区域位置和职责。

```
┌──────────────────────────────────────────┐
│  [按钮区]                                │
│                                          │
│              （主内容区）                  │
│                                          │
│                                [浮空窗]  │
└──────────────────────────────────────────┘
```

列出每个按钮/控件的激活后行为表。

| 控件 | 激活后光标 | 行为 |
|------|:--------:|------|
| xxx  | crosshair | xxx |

### 二、交互流程

每个用户操作的完整步骤链，用伪代码风格描述。

```
[1] 用户点击 [xxx]
     → 状态变化

[2] 用户执行 xxx
     → 函数调用

[3] 结果反馈
     → 成功：xxx
     → 失败：xxx
```

### 三、错误反馈

| 场景 | 反馈形式 |
|------|---------|
| xxx | toast / 内联文字 / 高亮闪烁 |

读取端：哪个组件、watch 哪个字段。

### 四、调用关系

```
用户操作（DOM 事件）
    │
    ├─ 按钮 @click
    │   └─ controller.xxx()
    │       └─ uiStore 写入状态
    │       └─ 视觉变化（光标/高亮）
    │
    ├─ 画布交互
    │   └─ 语义事件 → controller.handleXxx()
    │       └─ graph_operations.xxx()
    │           └─ engine compose → applyBatch
    │           或 graphStore.applyOperation()
    │
    └─ 其他入口
        └─ ...
```

### 五、交互模式

| 模式 | 进入 | 退出 | 行为差异 |
|------|------|------|---------|
| 默认 | 启动 | — | xxx |
| xxx | 按钮 | 右键/再次点击 | xxx |

### 六、视觉状态

| 元素 | 状态 | 样式 |
|------|------|------|
| 按钮 | 默认 / hover / 激活 | 白底灰边 / 浅蓝底 / 蓝底蓝边 |
| 光标 | 各工具 | default / crosshair / cell / pointer |
| 高亮 | 各场景 | 蓝框（选中）/ 红框（删除待定） |

### 七、不变项

- 架构约束（不因本次变更而修改的规则）
- 数据流方向
- 引擎侧是否改动
```
