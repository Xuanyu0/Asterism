# GraphEngine 操作 Spec 模板

> 引擎侧每个 compose 操作一份。描述函数的输入契约、内部编排、输出结构。
> 不描述 UI 交互——那是前端 spec 的职责。

---

```markdown
## [操作名]

### 输入
- 参数表（类型 + 来源）

### 调用场景
- 调用方（前端、AI、引擎）
- 频率
- 与其他操作是如何 串行 / 并行 组合在一起的

### 前置条件
- 哪些情况应该被 validate 拦截（error）
- 哪些情况允许但需要提示（warning）

### 返回值
- 草稿数量
- 草稿拓展字段
- issues 的典型 error / warning 清单

### 后置影响（图结构变化）
1. 父图：哪些节点增删、哪些边增删
2. 子图（如涉及）：同上
3. 常识层（如涉及）：同上

### applyBatch 得到的原子操作序列
分图列出所有 GraphOperation，标明执行顺序。
跨图时标注哪些操作属于同一事务。

### 事务语义
- 原子操作 batch 的边界（跨图时标注）
- dryRun 行为
- 幂等性（同一输入重复调用是否有差异）
- 可逆性（createReversal 是否能构造逆操作）

### 位置安排策略
- 新增节点的位置如何确定（引用哪个 placement 原语）
- 已有节点位置是否移动
```
