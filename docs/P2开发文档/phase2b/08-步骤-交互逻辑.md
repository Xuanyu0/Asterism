## Step 6：交互逻辑迭代

### 6.1 上下文 Key 系统

> 见 `docs/设计/06-交互逻辑.md` §上下文 Key

将分散在 `ui_store`、`mediator`、`operation_controller` 中的状态判断逻辑统一接入上下文 Key 系统。

**实现内容**：

| 组件 | 职责 |
|------|------|
| 上下文键定义 | 5 个布尔键：`focusOnMainToolbar`、`focusOnModeToolbar`、`inPreview`、`toolActivated`、`notificationPanelVisible` |
| 统一查询入口 | 将 `ui_store`、`mediator` 中的状态合并到一个只读查询对象，外部代码通过一次查询获取所有上下文键 |
| 条件表达式引擎 | 解析 `&&` / `\|\|` / `!` 组合的字符串表达式，对上下文键快照求值 |
| 声明式键绑定表 | 将快捷键路由统一为 { key, command, when, priority } 配置表，替代 `Graph.vue` 和组件模板中分散的 if-else |
| Escape 链 | 按优先级：通知面板 → 预览 → 激活工具，第一条满足的生效 |

**改动范围**：`ui_store` 新增上下文键的响应式状态；新建 `context/` 目录存放核心实现；`Graph.vue` 中的事件路由改为查键绑定表。

### 6.2 Q 键提取匹配

> 见 `docs/设计/06-交互逻辑.md` §Q键提取匹配操作

**实现内容**：

- 监听全局 Q 键按下事件（仅在画布焦点时）
- 获取当前光标下的节点/边类型
- 查类型与工具的映射表，若命中则自动激活对应工具
- 若该类型的工具已在工具栏中，数字键/滚轮定位到对应槽位
- 预留双击节点匹配工具的鼠标替代路径

**映射规则**（示例）：

| 光标下元素 | 匹配工具 |
|-----------|---------|
| 原子节点（实） | 添加实节点 |
| 虚节点 | 添加虚节点 |
| 有向实边 | 添加有向实边 |
| 无向实边 | 添加无向实边 |
| 有向虚边 | 添加有向虚边 |
| 无向虚边 | 添加无向虚边 |

**改动范围**：`mediator` 新增 Q 键处理器；`registry.ts` 新增类型→工具映射表。

### 6.3 意图聚焦

> 见 `docs/设计/06-交互逻辑.md` §意图聚焦

| 操作 | 行为 |
|------|------|
| Ctrl+\` 按下 | 切换 `focusOnMainToolbar` ↔ `focusOnModeToolbar` |
| 指针图标 | 图标移动位置，视觉上显示当前聚焦在哪组工具栏 |
| 数字键/滚轮 | 按 `focusOnMainToolbar` 或 `focusOnModeToolbar` 路由到对应工具栏 |

**改动范围**：新增 `ui_store` 中的工具栏聚焦状态；指针图标位置响应式绑定；数字键/滚轮事件按聚焦状态转发。

### 6.4 错误反馈

> 原 Step 6 内容，作为本步骤子任务并入。

**错误显示位置**：

| 场景 | 显示位置 | 理由 |
|------|---------|------|
| 浮空窗操作（编辑节点属性） | 浮空窗内 | 就近原则，用户眼在浮空窗上 |
| 画布操作（Cognition / Arrangement） | 画布底部半透明通知区 | 不阻挡视野，操作后视线自然下移 |

**读取端**：
- `uiStore.lastOperationValidation` 中读取 `ValidationResult.issues`
- 操作失败时显示错误信息
- 用户关闭浮空窗或点击确认后清除错误状态

**用户可见反馈表**：

| 场景 | 反馈 |
|------|------|
| 操作成功 | 无额外提示（操作结果已反映在图谱中） |
| 操作失败 | 显示错误信息 + 保留 UI 状态不变（用户可修改后重试） |

### 待决设计问题

| # | 问题 | 建议方向 |
|---|------|---------|
| Q1 | 上下文键的 when 条件表达式需要支持多复杂？ | 初始只需支持 `&&` / `\|\|` / `!` 和括号组合，不做函数式扩展 |
| Q2 | Q 键提取匹配时，若匹配到多个工具（如"实节点"同时匹配"添加实节点"和"删除"），取哪个？ | 优先取"创建类"工具，而非"销毁类"。具体按映射表的优先级顺序 |
