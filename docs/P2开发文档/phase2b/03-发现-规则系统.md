# Phase 2b — 发现：规则系统

## Step 1.3 期间的发现

### 改进：errorIssues 过滤逻辑跨组件重复

位置：`frontend/src/components/graph/NodeWindow.vue:126` + `frontend/src/components/KnowledgeGraph.vue:154`

现象：两个组件各有独立的 computed 做 `filter(severity === 'error')` 逻辑，跨组件 2 处重复。

> 建议：当前不拆。理由：分属不同组件且逻辑极简（1 行 filter），按 CLAUDE.md 第十九条（≥2 个调用方才拆）刚好在边界上。若未来第三个组件也需要同样过滤，再提取为 composable。

状态：确认不改

### 改进：validation 归属从 ui_store 迁回 graph_store

位置：`frontend/src/graph/graph_store.ts` + `frontend/src/ui/ui_store.ts`

现象：Step 1.3 初版错误地将 validation 结果统一到 ui_store.lastOperationValidation。validation 是图操作的产物，应跟随操作执行者（graph_store），不属于 UI 意图层。后续已纠正：graph_store 持有 lastValidationResult，ui_store 通过 clearValidationResult action 在清除时机调用 graph_store。

状态：已确认（本步骤已修复）

### 改进：通知区 × 按钮可能覆盖长文本

位置：`frontend/src/components/KnowledgeGraph.vue` 通知区 `.canvas-error-close`

现象：× 按钮用 `position: absolute` 定位在通知区右上角，但通知区 padding 未给右侧按钮预留空间。错误消息接近 max-width 时 × 按钮可能覆盖文字。

> 建议：给通知区右侧 padding 加大，或给消息文本加 padding-right。

状态：已确认，不修改也没有影响

### 改进：v-bind:key 混合语义 key 和 index fallback

位置：`frontend/src/components/graph/NodeWindow.vue` + `frontend/src/components/KnowledgeGraph.vue`

现象：`v-bind:key="issue.code + '-' + index"` 混合了语义 key 和 index。issue 列表短且稳定，实际无影响，但重排时会错配。

> 建议：当前不处理。issue 列表是操作产出的一次性快照，不会动态重排。

状态：待确认
