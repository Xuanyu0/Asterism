## Step 2.0：数据层补丁 ✅

**目标**：修复 `initRegistry` 全量加载问题 + 补齐 graphPath 回溯、createRootGraph、启动哨兵、lastActiveRootId 持久化。

难度：🟢 不确定度 / 🟢 算法复杂度 / 🟡 工作量（~180 行 / 3 文件）

### 实际产出

| 文件 | 新增/修改 |
|------|----------|
| `frontend/src/graph/graph_persistence.ts` | `listRootGraphIds()`；`saveLastActiveRootId` / `loadLastActiveRootId`（独立 key `last-active-root-id`） |
| `frontend/src/graph/graph_store.ts` | `initRegistry` 预加载当前根图完整子树（`isInRootTree`）；`loadGraphToView` 补全 `graphPath` 回溯链 + 环检测 + 祖先链断裂 warning + 写入 `lastActiveRootId` + 失败时写入 `lastValidationResult`；`createRootGraph(title)`；删除 `lookupOrLoad`，`getGraphById` / `makeLookup` 直接 `lookupGraph` |
| `frontend/src/views/Graph.vue` | 启动哨兵：确定 rootId → 尝试加载 → 失败降级创建，三段分离 |

### 关键架构决策

- **注册表语义 = 当前工作根图树**：`initRegistry` 通过 `lastActiveRootId` 定位根图，预加载其全部子孙图；其他根图不进入
- **`lastActiveRootId` 持久化**：独立 localStorage key，`loadGraphToView` 确认 `kind === 'root'` 后写入；链断裂不写
- **`loadGraphToView` 错误接入 NotificationPanel**：失败时写 `lastValidationResult`（code: `LOAD_FAILED`），已有 UI 自动展示；祖先链断裂写 warning（code: `ANCESTOR_CHAIN_BROKEN`）
- **惰性加载已移除**：预加载覆盖后 `lookupOrLoad` 冗余，已删除
