# 07.5 前端 delete 工具分发 — 提示词

## 当前状态

`frontend/src/feature-tools/toolbar/delete.ts`（165 行）的删除工具对所有节点统一走普通 `delete_node` 原子操作：

- 两步确认流程（首次点击标记待定、再次点击确认）已实现
- `executeDeleteNode`：`operations.commitToCurrentGraph([{ type: 'delete_node', nodeId }], { source: id })`
- notification 文案固定为 `再次点击将删除："${targetLabel}"`

**问题**：抽象节点（`childGraphId !== undefined`）被删除时只删节点本身，其子图树成为孤儿死图。07.3 已产出 `deleteAbstractNode` compose（递归清空子图 + 注销），前端 delete 工具尚未接线。

**提交入口约束（重要）**：`useGraphOperation.commitToCurrentGraph` 只支持**单图**——它把 inGraph 批的 graph 固定为当前 `graphView`（useGraphOperation.ts L134-141）。而 `deleteAbstractNode` 输出的批次是**跨图**的（深层子图清空批 + 图级注销批 + 父图清空批）。**工具层不得直接调 store**（依赖方向：业务 → 用例层 → store）——需要用例层提供多图批次转发方法（本子步骤新增 `commitBatches`）。

## 目标

UI 保持**单一 delete 工具**，代码层按节点类型分发删除语义：

- 非抽象节点（含引用节点）→ 普通 `delete_node`（现状逻辑，零改动）
- 抽象节点 → `deleteAbstractNode` compose → 用例层 `commitBatches` → `store.commitBatchToGraphs` 提交
- 抽象节点删除的确认文案提示"将删除该节点及其子图"（用户可感知的交互单元）

## 架构变更

```
旧：delete 工具 → 一律 delete_node → 抽象节点子图变孤儿死图

新：delete 工具 → 按 deriveNodeForm 分发
       ├─ 非抽象 → delete_node（现状）→ commitToCurrentGraph（单图，不变）
       └─ 抽象   → deleteAbstractNode({ nodeId, registry })
                    → { batches, issues }（跨图批次）
                    → issues 无 error → commitBatches(batches)【用例层新增】
                                        → store.commitBatchToGraphs（多图入口）
```

## 具体子任务

### 5.1 用例层新增 commitBatches（多图批次转发）

`frontend/src/graph/use-case/useGraphOperation.ts`：

- `GraphOperationAPI` 新增方法 `commitBatches`：

```ts
/**
 * 对多个目标图提交预组装批次并返回校验结果。
 *
 * @remarks
 * 与 commitToCurrentGraph 的区分：本方法接收已按图分组的 OperationBatch[]
 * （跨图场景，如 deleteAbstractNode compose 输出）；commitToCurrentGraph 接收
 * 扁平原子操作（单图场景）。提交经 store.commitBatchToGraphs——内部已同步
 * 校验结果到 store.lastValidationResult，本方法仅透传返回。
 *
 * @param batches - 预组装的批次序列（图内批携带 graph 对象）
 * @param options - [可选] source：操作来源的工具标识
 * @returns 校验结果（valid + issues 汇总）。
 */
commitBatches(
    batches: OperationBatch[],
    options?: { source?: string },
): ValidationResult
```

- 实现：`createGraphOperation` 内 `commitBatches(batches, options)` → `return useGraphStore().commitBatchToGraphs(batches, options)`（薄透传；commitBatchToGraphs 签名接受 OperationBatch[] + { source? }，直接传参）
- **不动现有方法**：`commitToCurrentGraph` / `reportComposeValidation` / `makeLookup` / `clearValidationResult` / `undo` / `redo` 零改动
- 文件头 JSDoc 提及"多图批次转发"（如需要）

### 5.2 delete.ts 分发改造

`frontend/src/feature-tools/toolbar/delete.ts`：

- `executeDeleteNode(nodeId)` 内分发：
  1. 从 `graphStore.graphView` 查找目标节点（守卫：节点不存在 → 防御性返回，现状行为）
  2. 用 `deriveNodeForm(node)`（engine 导出）判断：`'abstract'` → 抽象路径；`'atomic'` → 现状路径
  3. **抽象路径**：调 `deleteAbstractNode({ nodeId, registry: graphStore.graphRegistry })`（engine 导出，07.3 已实现）→ 返回 `{ batches, issues }`
     - issues 含 error（防御，正常不可达：TARGET_NOT_FOUND / NOT_ABSTRACT）→ 不提交（可选：console.warn 开发者通道）
     - 无 error → `operations.commitBatches(batches, { source: id })`（用例层，非直接调 store）
  4. **非抽象路径**：保持现状 `operations.commitToCurrentGraph([{ type: 'delete_node', nodeId }], { source: id })` 零改动
- notification 文案**按 pending 节点动态化**：pending 节点为抽象节点时，文案改为 `再次点击将删除："${targetLabel}"（及其子图）`；非抽象/边保持现状 `再次点击将删除："${targetLabel}"`
  - 判断方式与分发一致（`deriveNodeForm`），在 computed notification 内计算
- import 更新：`deleteAbstractNode`、`deriveNodeForm` 从 `@my-project/graph-engine` 导入（确认导出链路完整）
- 文件头 JSDoc 更新：规则部分补充"抽象节点 → 递归删除子图树"分发说明
