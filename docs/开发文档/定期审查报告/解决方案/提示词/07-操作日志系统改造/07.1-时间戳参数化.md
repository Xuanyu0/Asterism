# 07.1 时间戳参数化 — 提示词（方案 B 最终版）

## 当前状态

GraphEngine 执行层存在 **14 处非确定性时间戳**（`new Date().toISOString()`）：`src/core/execute_operation.ts` 9 处（execute 函数内部自行生成当前时刻，强制覆盖写入对象级与图级 updatedAt）、`src/compose/cognitive/` 4 文件 5 处（构造操作时填充时间戳，被 execute 覆盖，属死代码）、`tests/test_case_factory.ts` 1 处。

**当前工作树实现为方案 A（含 `preserveTimestamps` 执行模式标记）**，需按本契约收敛为方案 B。方案 B 与方案 A 的差异：

- **删除 `preserveTimestamps`**（含 ExecuteContext / BatchOptions / ApplyBatchesOptions / commitBatchToGraphs options 四层字段与透传）
- execute 对象级规则简化为 **`操作携带值 ?? executedAt`**（无模式分支）
- **新增构造约定**：前端 `default_tool.ts` 构造 `update_node` / `update_edge` 时**清除 updatedAt**（正向构造不携带时间戳，时间由 applyBatches 统一注入）

**用户已裁决（方案 B 设计依据）**：
1. 时间戳方案 B（事件时间严格恢复）：undo 恢复历史状态。
2. 时间参数命名 `executedAt`，语义 = 本批次执行的时刻。
3. **正逆三路径共用同一时间戳**：一次提交 = 一条日志条目 = 一个 `entry.timestamp`（批级唯一时间）。正向提交时以当前时刻写入 `entry.timestamp`；undo / redo 均从该 entry 读取同一值传入——executedAt 永不 undefined，无"撤销时刻"。
4. 图级 updatedAt 语义 = 该图最近参与的批操作时间（批级时间戳）；undo 是该批的一部分，图级保持该批时间。

## 目标

execute 层非确定性时间戳消失，时间戳由 Runtime 统一传入；undo / redo 均恢复历史状态；无执行模式标记。

## 架构变更

```
旧（方案 A）：
executeOperation(graph, op, { executedAt, preserveTimestamps? })
  ├─ preserveTimestamps=true：对象级尊重操作携带值（undo 逆元恢复历史）
  └─ preserveTimestamps=false/缺省：对象级 = executedAt（覆盖）

新（方案 B）：
executeOperation(graph, op, { executedAt })
对象级 createdAt/updatedAt = 操作携带值 ?? executedAt   ← 无分支
图级 updatedAt            = executedAt（恒）
  ├─ 正向：构造不携带 → executedAt（applyBatches 统一注入）
  ├─ undo：逆元快照携带 T0 → 尊重 → 恢复历史
  └─ redo：正向不携带 → executedAt = entry.timestamp = T1
```
