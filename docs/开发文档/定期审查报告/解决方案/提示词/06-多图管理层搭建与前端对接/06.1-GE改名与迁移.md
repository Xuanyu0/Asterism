# 06.1-GE 改名与迁移 — 提示词

## 当前状态

`packages/graph-engine/src/` 下两个文件需要改名与迁移（纯改名，无行为变化）：

- `core/execute.ts`：导出 `executeOperation`（单操作路由，switch-case 分派）。**不从包入口导出**（包入口 index.ts 明确 execute 内部函数不导出），包内引用方：`compose/pipeline.ts`、`core/replay.ts`，测试：`tests/core/execute.test.ts`、`tests/core/reversal.test.ts`
- `compose/pipeline.ts`：导出 `applyBatch` + 类型 `BatchOptions` / `PerOpResult` / `BatchResult`。导出链：`src/index.ts`（`export { applyBatch } from './compose/pipeline'`）← `compose/index.ts`（`export { applyBatch } from './pipeline'`），测试：`tests/pipeline.test.ts`、`tests/compose/pipeline.test.ts`

前端不直接引引擎内部路径（全部经包入口 `@my-project/graph-engine`），因此前端零改动。

## 目标

- `core/execute.ts` → `core/execute_operation.ts`（文件名与导出函数 `executeOperation` 一致）
- `compose/pipeline.ts` → `core/apply_batch.ts`（迁入 core/ 并改名，与导出函数 `applyBatch` 一致）
- 包对外 API 不变（`@my-project/graph-engine` 导出的 `applyBatch` 名称、签名、类型不变），全部行为不变

## 具体子任务

### 1.1. execute.ts → execute_operation.ts

- 文件重命名为 `core/execute_operation.ts`，导出函数 `executeOperation` 名称与签名不变
- 更新包内所有对该文件的 import 路径（引用方：`compose/pipeline.ts`、`core/replay.ts` 及测试）

### 1.2. compose/pipeline.ts → core/apply_batch.ts

- 文件迁移至 `core/apply_batch.ts` 并改名，导出函数 `applyBatch` 与类型 `BatchOptions` / `PerOpResult` / `BatchResult` 名称不变
- 更新包入口 `src/index.ts`：`applyBatch` 及三个类型的导出路径改指向 `./core/apply_batch`
- 更新 `compose/index.ts`：**移除 `applyBatch` 及其类型的 re-export**（applyBatch 属 core 层，不属于 compose 层；compose 层只保留 cognitive / arrangement / compose 类型导出）
- 更新测试 import 路径（`tests/pipeline.test.ts`、`tests/compose/pipeline.test.ts` 等）

## 变更边界

**禁止修改**：

- 任何函数逻辑、签名、行为（`executeOperation` / `applyBatch` / `createReversal` 等全部保持原样）
- `packages/graph-engine/src/compose/cognitive/` 与 `compose/arrangement/` 全部
- `packages/graph-engine/src/types/` 全部
- `frontend/` 全部（前端走包入口，零改动）

**禁止行为**：

- 不得改变包入口导出的名称与签名（`applyBatch` 对外可见性不变）
- 不得引入新依赖
