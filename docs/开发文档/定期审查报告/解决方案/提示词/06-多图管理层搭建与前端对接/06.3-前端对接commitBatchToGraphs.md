# 06.3-前端对接 commitBatchToGraphs — 提示词（修正补充）

## 当前状态

GE 端 `applyBatches` 已就绪（06.2 完成）。fix-3 已做前端**最小适配**（compose 返回改造的接线），现状：

- **compose 认知操作已返回 `{ batches: OperationBatch[]（判别联合）, issues }`**（deconstruct / induce / internalize / diverge）
- **前端经 `frontend/src/graph/utils/batch_converter.ts` 的 `batchesToItems` 临时转换**：`OperationBatch[]` → 旧 `OperationBatchItem[]`（`{ graph, operations }`）——因为 `commitBatchToGraphs` 仍是旧四阶段
- `graph_store.ts` `commitBatchToGraphs` 仍为四阶段：逐项 `applyBatch`（含逆元回调收集 + latestGraphs）→ 更新 state → 图级扫描兑现（graph_signals）→ 持久化 + 日志组装；fix-3 已加"图级操作不进入 applyBatch"过滤
- `graph_signals.ts`（116 行）：正向兑现（applyAddGraph / applyDeleteGraph）+ 逆向恢复（revertAddGraph / revertDeleteGraph）
- `graphRegistry` 为普通字段（shallowReactive 内搭浅响应便车，raw 原地修改 `Map.set`）
- 调用方（`operation_controller.ts` induce/internalize/diverge、`feature-tools/cognition/deconstruct.ts`）已消费 `result.batches`（经 `batchesToItems` 转换）

## 目标

- `commitBatchToGraphs` 改为接收 **`OperationBatch[]`（判别联合）**，**直接委托 `applyBatches`**——移除 `batchesToItems` 临时转换层与旧四阶段（latestGraphs / 逆元回调收集 / 图级扫描兑现）
- `graphRegistry` 响应式化：普通字段 → shallowReactive 顶层属性，承接 `applyBatches` 返回的新注册表做**引用替换**（`store.graphRegistry = result.registry`）
- `graph_signals.ts` 正向兑现迁出（applyBatches 已接管），保留逆向（undo 用）
- **行为等价**：日志结构不变（暂用 result.graphSignals 组装），undo/redo（applyEntry 三段式）暂不改（07 改造）

## 架构变更

```
旧：compose → { batches } → batchesToItems → OperationBatchItem[] → commitBatchToGraphs 四阶段
新：compose → { batches } → commitBatchToGraphs → applyBatches（直接消费 OperationBatch[]）
     → 引用替换 registry + 持久化 + 日志组装（result.reversalOperations + result.graphSignals）
```

## 具体子任务

### 3.1. 注册表响应式化

- `graphRegistry` 从普通字段提升为 shallowReactive 顶层属性（引用替换触发响应式）
- `store.graphRegistry = result.registry` 承接 applyBatches 返回的新注册表（复用未变化图引用，不深拷贝）
- 确认引擎 structuredClone 兼容性：注册表作为响应式顶层属性后，内部 Map 与 GraphData 保持 raw（shallowReactive 不深代理），引擎克隆路径不受影响

### 3.2. commitBatchToGraphs 委托

- `commitBatchToGraphs` 入参改为 `OperationBatch[]`（判别联合），主体替换为委托 `applyBatches`：
  - 输入：`store.graphRegistry` + `OperationBatch[]`（直接透传，不再经 batchesToItems）
  - 校验失败：写入 `lastValidationResult` 返回（行为与现状一致）
  - 成功：引用替换 registry → 更新 `graphView`（若当前视图图在批内，指向新注册表中对应图，逻辑同现状）→ 持久化批内涉及的图（从 `OperationBatch[]` 推导：inGraph 批的 `graph.id` + graphLevel 批 add_graph 的图，从新注册表取最新数据 `saveGraph`）→ 日志组装（operation + result.reversalOperations + result.graphSignals，格式同现状）
- 删除第一阶段（latestGraphs / onBeforeEachOperation 逆元收集）与第三阶段（图级扫描兑现）代码

### 3.3. 调用方适配（移除临时转换）

- `operation_controller.ts`（induce / internalize / diverge）与 `feature-tools/cognition/deconstruct.ts`：改直接传 `result.batches`（不再经 `batchesToItems`）
- **删除 `batch_converter.ts`**（临时转换层完成使命）

### 3.4. graph_signals.ts 瘦身

- 正向兑现（applyAddGraph / applyDeleteGraph）已由 applyBatches 接管——删除
- 逆向恢复（revertAddGraph / revertDeleteGraph）供 undo 使用（applyEntry 三段式暂保留）——保留
- 文件瘦身或保留逆向函数

## 变更边界

- `undo` / `redo` / `applyEntry`（三段式）行为——07 改造
- `loadGraphToView` 行为语义（仅允许 graphView 更新方式随注册表响应式化微调）
- `packages/graph-engine/` 全部（applyBatches 已就绪，本步只消费）
- `graphView` 字段本身（graphViewId 化在 06.4）
