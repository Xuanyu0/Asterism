# 06.5-A1 预存缺陷修复（正向 compose 批拆批）— 提示词

## 当前状态

- **A-1 预存缺陷**（发现文档 06 记录，用户已裁决立即修复）：`induce` / `diverge`（Case B）的正向 compose 批在 `applyBatch` 的 validate-all-first 下实际不可执行——批内 `add_edge` 端点依赖批内 `add_node`（沟通节点 / 启发节点 / 抽象节点），Phase 1 基于输入图校验 → `EDGE_SOURCE/TARGET_NOT_FOUND` → 整批丢弃。
- **实证确认**（真实 compose 输出 → applyBatches）：
  - induce：子图填充批 7 个 add_edge 全失败；父图批 add_edge 失败（依赖批内 add_node 抽象节点）
  - diverge Case B：当前图批 add_edge 失败（依赖批内 add_node 启发节点）；对端图批 add_edge 失败（依赖批内 add_node 镜像启发节点）
  - deconstruct / internalize / diverge Case A：正常通过（无批内依赖）
- **连锁问题**（拆批后暴露，已确认）：
  - NODE_COLLISION：父图批 add_node（抽象节点）位置 = 被选节点形心，induce 内部碰撞检测排除 selectedSet（被选节点即将删除），但 applyBatch 的 NODE_COLLISION 校验不排除 → 拆批时需 delete_node 独立成批先执行
  - NODE_LABEL_TOO_LONG：抽象节点 label = 被选节点 label 用 " / " 连接（如 "被选A / 被选B / 被选C" = 15 字符）> `nodeLabelMaxLength: 8`。**用户决策：抽象节点最终由用户后续自行命名，induce 构造的临时 label 保证 ≤ 8 字符即可（截断）**

## 目标

- 拆批：`induce` / `diverge`（Case B）的 compose 输出按"节点批 → 边批"拆分，使正向批在 validate-all-first 下可完整执行
- 抽象节点 label 构造保证 ≤ 8 字符（截断）
- 新增集成测试：真实 compose 输出 → applyBatches 完整执行（防止 A-1 复发）

## 拆批方案（已实证验证可行）

### induce（3 批 → 6 批）

```
批0: graphLevel add_graph（空子图）          ← 不变
批1: inGraph 子图 [add_node × N]             ← 子图节点（被选节点 + 沟通节点）
批2: inGraph 子图 [add_edge × M]             ← 子图边（依赖批1 的节点）
批3: inGraph 父图 [delete_node × N]          ← 先删被选节点（让形心位置空出，解决 NODE_COLLISION）
批4: inGraph 父图 [add_node(抽象节点)]        ← 依赖批3（被选节点已删，不碰撞）
批5: inGraph 父图 [add_edge × M]             ← 依赖批4（抽象节点 + 邻居）
```

### diverge Case B（2 批 → 4 批）

```
批0: inGraph 当前图 [add_node(启发节点)]
批1: inGraph 当前图 [add_edge(知识节点 → 启发节点)]   ← 依赖批0
批2: inGraph 对端图 [add_node(镜像启发节点)]
批3: inGraph 对端图 [add_edge(镜像启发 ↔ 知识节点)]   ← 依赖批2
```

### 抽象节点 label 截断

- `induce.ts` 抽象节点 label 拼接后若 > 8 字符，截断到 ≤ 8 字符（`slice(0, 8)` 即可，用户后续会重命名）

## 具体子任务

### 5.1. induce.ts 拆批 + label 截断

- 子图填充批（childOps）拆为两个 inGraph 批：add_node 批 + add_edge 批
- 父图批（parentOps）拆为三个 inGraph 批：delete_node 批 + add_node 批 + add_edge 批（顺序不可变：delete → add_node → add_edge）
- 抽象节点 label：拼接后截断到 ≤ 8 字符
- 保持语义预检、碰撞检测、位置计算逻辑不变

### 5.2. diverge.ts 拆批（Case B）

- Case B 当前图批（currentOps）拆为两个 inGraph 批：add_node 批 + add_edge 批
- Case B 对端图批（peerOps）拆为两个 inGraph 批：add_node 批 + add_edge 批
- Case A（同图直连）不变（单 add_edge 批，无依赖）
- 保持语义预检、镜像逻辑不变

### 5.3. 测试更新

- `induce.test.ts`：批数断言 3 → 6；批 kind 断言适配（批1/批2 为 inGraph 子图，批3/批4/批5 为 inGraph 父图）
- `diverge.test.ts`：Case B 批数断言 2 → 4
- **新增集成测试**（induce + diverge Case B）：真实 compose 输出 → `applyBatches` 完整执行，断言 `validation.valid === true`，并断言结果图结构正确（子图含节点与边、父图含抽象节点与边、对端图含镜像启发节点与边）
