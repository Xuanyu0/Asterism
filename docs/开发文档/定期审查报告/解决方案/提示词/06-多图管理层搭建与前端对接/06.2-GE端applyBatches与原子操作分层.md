# 06.2-GE 端 applyBatches 与原子操作分层 — 提示词（修正补充）

## 当前状态

**已有初版实现（fix-2 完成，GE 测试 167 全绿 + 前端 191 全绿），本提示词为修正补充**，按新约定修正以下问题：

1. **`apply_batches.ts` 是"分类数组 + 分块处理"形态，未实现路由函数与路由逆元构造函数**（见 2.2）
2. **批次语义未统一**：`OperationBatch` 无判别联合（图内/图级混在 `{ graph, operations }` 中）；compose 返回形态不一致——deconstruct 单数组、induce 按图分组对象、图级操作混入图内组（见 2.2、2.6）
3. **add_graph 无"只构造空图"约束**：validate 未强制 nodes/edges 为空；`compose/cognitive/deconstruct.ts` 的 add_graph 携带最终图（含沟通节点），induce 携带空图——两种模式并存（见 2.4、2.6）
4. **`apply_batch.ts` ops 参数仍是 `GraphOperation[]`**，含"图级操作跳过"死代码（见 2.5）

已就绪的部分（保留）：`AtomicOperationInGraph` / `AtomicGraphOperation` 类型分层、`GraphOperation` 别名联合、GE 端 `GraphRegistry`（types/graph_data.ts）、`executeOperation` / `createReversal` 收窄、包入口导出、初版单测。

## 目标

- `applyBatches` 重构为**批次判别联合 + 路由函数 + 路由逆元构造函数**形态：`OperationBatch = { kind: 'inGraph', graph, operations } | { kind: 'graphLevel', operations }`，循环按 `kind` if-else 直接分派，**分类预处理消失**
- **compose 返回改造（批次语义统一）**：deconstruct / induce 返回 `{ batches: OperationBatch[]（判别联合）, issues }`，图级操作独立成 `graphLevel` 批；internalize / diverge 形态统一
- **add_graph 只构造空图（函数逻辑确保）**：`graph` 仅含 `id` / `kind` / `parentGraphId` / `ownerNodeId` / 时间戳等元数据字段，`nodes` / `edges` 必须为空；由 `validateOperation` 校验强制（非口头约定）
- `applyBatch` ops 参数收窄为 `AtomicOperationInGraph[]`，删除图级跳过死代码

## 架构变更

```
旧（fix-2）：apply_batches = 分类数组（inGraphOps/addGraphOps/deleteGraphOps）→ 分块处理
             OperationBatch = { graph, operations }（图内/图级混入）
             compose 返回不一致（deconstruct 单数组 / induce 按图分组对象，图级混入）
             add_graph 两种模式并存（deconstruct 最终图 / induce 空图）
             applyBatch.ops: GraphOperation[]（含图级跳过死代码）
新：apply_batches = 批次判别联合（OperationBatch = inGraph | graphLevel）+ 循环按 kind if-else 分派
                  + 路由函数 switch（add_graph 兑现 / delete_graph 兑现 / 图内委托 applyBatch）
                  + 路由逆元构造函数 switch（add↔delete 互逆 / 图内 createReversal）
     compose 返回 { batches: OperationBatch[]（判别联合）, issues }（图级操作独立成 graphLevel 批）
     add_graph 只构造空图（validate 强制 nodes/edges 为空），内容统一走图内操作
     applyBatch.ops: AtomicOperationInGraph[]（图内批只收图内，删除跳过逻辑）
```

## 具体子任务

### 2.2. applyBatches 路由化重构（核心）

重构 `core/apply_batches.ts`，从"分类数组 + 分块处理"改为：

- **批次判别联合**：`OperationBatch = { kind: 'inGraph', graph: GraphData, operations: AtomicOperationInGraph[] } | { kind: 'graphLevel', operations: AtomicGraphOperation[] }`（类型定义放 GE types）
- **循环按 `kind` if-else 直接分派**（分类预处理消失）：`kind === 'inGraph'` → 委托 `applyBatch`（单图批事务）；`kind === 'graphLevel'` → 兑现图级操作（add_graph 注册 / delete_graph 注销）
- **路由函数（类 `executeOperation` 的 switch 分派，纯函数）**：图级批内正操作按类型分派——`add_graph` 兑现注册、`delete_graph` 兑现注销；签名 `(registry, op) → registry`（与 `executeOperation(graph, op) → graph` 对称：输入注册表 + 操作 → 输出新注册表，**不修改入参**，未变化图复用引用）；`add_graph` **直接注册操作自带空图**（顺序由操作构造方保证：add_graph 批在对应子图填充批之前，注册空图后由后续图内批填充覆盖，`executeGraphOperation` 不查批内结果图）；`graphSignals` 累积由 `applyBatches` 调用方从操作类型推导（`add_graph` → added.push / `delete_graph` → deleted.push）
- **路由逆元构造函数（类 `createReversal` 的 switch 分派）**：逆元按类型构造——`add_graph` → `delete_graph`、`delete_graph` → `add_graph` + 操作前整图快照（执行前从注册表捕获）、图内 → `createReversal`（执行前捕获操作前状态）
- **批次操作对象存在性校验（保险）**：图内批的 `batch.graph.id` 必须存在（注册表或本批 add_graph 已注册）——applyBatches 图内批执行前检查 `newRegistry.has(batch.graph.id)`，不存在返回显式 error issue（`BATCH_GRAPH_NOT_FOUND`）整批丢弃，防止操作构造方对不存在的图操作被隐式创建
- 其余保持：纯函数（不修改入参注册表，返回新注册表复用未变化图引用）、事务性（任一失败整批丢弃）、返回值 `{ registry, validation, reversalOperations, graphSignals }`（graphSignals 中间态）、**融合而非拼接**（单循环，禁止"图内先、图级后"两段式）

### 2.6. compose 返回改造（批次语义统一）

统一四个 compose 认知函数的返回形态为 `{ batches: OperationBatch[]（判别联合）, issues }`：

- `deconstruct.ts`：返回 `batches = [{ kind: 'inGraph', graph: 父图, operations: [update_node] }, { kind: 'graphLevel', operations: [add_graph(空图)] }]`——沟通节点从 add_graph 移出，改为 add_graph 空图 + add_node 填充（配合 2.4）
- `induce.ts`：返回 `batches = [{ kind: 'inGraph', graph: 子图(空), operations: [add_node...] }, { kind: 'inGraph', graph: 父图, operations: [...] }, { kind: 'graphLevel', operations: [add_graph(空图)] }]`——add_graph 独立成 graphLevel 批；**compose 保证顺序**：add_graph 批在对应子图填充批之前
- `internalize.ts` / `diverge.ts`：返回形态统一为 `batches` 判别联合（`graphOps` 为空，纯图内批）
- 消费方同步：包入口导出、GE 测试适配（compose 测试 + 前端在 06.3 对接，本步骤仅保证类型编译不破坏）

### 2.3. executeOperation 路由瘦身

（已实现，保留）参数类型收窄为 `AtomicOperationInGraph`，图级 default 静默分支消除；`createReversal` 同步收窄。

### 2.4. 图级操作空图对称约定（add ↔ delete 互逆，函数逻辑确保）

- **`DeleteGraphOperation` 签名统一**：`{ type: 'delete_graph', graph: GraphData }`——与 `AddGraphOperation` 统一为携带图数据（`{ type, graph }`）；`graph` 为被删空图骨架（仅元数据字段 id/kind/parentGraphId/ownerNodeId/时间戳）
- **`add_graph` 只建空图**：`graph` nodes/edges 必须为空（图内容走图内操作构建）
- **`delete_graph` 只能删除空图**：注册表中目标图（`op.graph.id`）nodes/edges 必须为空才能删除——与 add_graph 只建空图对称（真正互逆）；undo 路径天然满足（图内逆元先清空图）
- **图级校验收口 `validate_graph_operation.ts`（与 `validate_operation_in_graph.ts` 对称）**：导出**单操作校验函数 `validateGraphOperation(registry, op)`**（图级局部规则，只有空图校验）——`add_graph` 校验 op.graph 空图；`delete_graph` 校验注册表目标图空图。applyBatches 图级批 **for 循环内边校验边执行**（逐 op：validateGraphOperation → executeGraphOperation，任一失败整批丢弃）。`validate_operation_in_graph.ts`（原 validate.ts 改名，单图批校验）是单图上下文（graph, op），无注册表，图级操作不进单图 validate
- `AddGraphOperation` / `DeleteGraphOperation` 类型注释同步说明空图约定
- `compose/cognitive/deconstruct.ts`：add_graph 改构造空图（沟通节点从 childGraph 移出），新增 `add_node`（沟通节点）填充——统一"add_graph 空图 + 图内填充"约定（induce 已是该模式，无需改）

### 2.5. applyBatch ops 参数收窄

- `core/apply_batch.ts`：`ops` 参数类型 `GraphOperation[]` → `AtomicOperationInGraph[]`，删除"图级操作跳过"逻辑（图级类型上不可能传入，死代码）
- 同步适配 `BatchOptions.onBeforeEachOperation` 回调类型、`PerOpResult` 等关联类型

## 变更边界

**禁止修改**：

- 图内操作（add/delete/update/move/collapse/expand）的 execute 与逆元行为
- `compose/arrangement/` 全部
- `frontend/src/` 全部（本子步骤仅保证前端类型引用编译通过，不改行为）
- 已确定的类型分层与包入口导出（AtomicOperationInGraph / AtomicGraphOperation / GraphRegistry / applyBatches 导出）

**禁止行为**：

- 不得在 applyBatches 内保留"图内先执行、图级后兑现"的两段式拼接（验收红线）
- 不得绕过 validate 的 add_graph 空图校验（规则必须函数逻辑确保）
- 不得改变图内操作的逆元构造语义（createReversal 行为不变）
- 不得引入新依赖
