# 09.3 硬性不变量缺席配置面与开关语义收窄 — 提示词

## 当前状态

09.1 已完成物理结构重组（`core/rules/` 分层），09.2 已完成 EDGE 端点迁入 structural.ts。当前 `run_invariants.ts` 仍保持旧等价语义：传入的开关表可关闭**任意**规则（含硬性）。`BatchOptions.globalRulesTable` 语义仍是"全规则可关"，默认 `DEFAULT_GLOBAL_RULES_TABLE`。

目标语义（分类模型已定稿）：**硬性不变量不可配置、恒跑、缺席配置面；只有偏好规则可开关**。`preferences.ts` 已定义 `PreferenceTable` / `DEFAULT_PREFERENCE_TABLE`（仅含 7 个偏好 code）就位但尚未接为唯一数据源。

**已定决策 Q2**：`NODE_COUNT_HARD_LIMIT_EXCEEDED` 存在双轨——`preconditions/in_graph.ts` 的 validateAddNode 有 Phase 1 预判检查（"即将超过禁止添加"），Phase 3 `validateNodeCountHardLimit` 也有。移除 Phase 1 侧，只保留 Phase 3 侧（一次提交 = 一批事务，dry-run 后 Phase 3 拦截与 Phase 1 预判对用户结果等价）。

## 目标

`run_invariants.ts` 收窄为最终语义：硬性规则无条件执行（不查表）+ 偏好规则按偏好开关表执行（缺省开启）。`BatchOptions.globalRulesTable` 收窄为偏好开关表语义。`NODE_COUNT_HARD_LIMIT_EXCEEDED` 双轨消除（Phase 1 预判移除）。

## 架构变更

```
旧（09.1 等价态）：
run_invariants(graph, table = DEFAULT_GLOBAL_RULES_TABLE)
  └─ 遍历全部规则（硬性 + 偏好），table[code] ?? true 决定是否执行
     ← 硬性也可被 table 关闭（SELF_LOOP: false 会跳过自环检查）

新（本步收窄）：
run_invariants(graph, table = DEFAULT_PREFERENCE_TABLE)
  ├─ 硬性规则（structural.ts 列表）：无条件执行，不查 table
  └─ 偏好规则（preferences.ts 列表）：按 table[code] ?? true 执行
     ← 硬性恒跑；table 只表达偏好开关
```

## 具体子任务

### 3.1 run_invariants 收窄

- `core/rules/invariants/run_invariants.ts`：
  - 拆分遍历：先硬性（structural 规则列表，无条件执行），后偏好（preferences 规则列表，按 `table[code] ?? true`）
  - 默认表改指 `DEFAULT_PREFERENCE_TABLE`
  - 结构上硬性/偏好两份列表来源：structural.ts / preferences.ts 各导出规则列表，run_invariants 引用之（类别文件仍不实现执行循环）
  - 行为断言：传入含 `SELF_LOOP_FORBIDDEN: false` 的表 → 自环仍被检出（硬性不可关）；传入 `NODE_LABEL_TOO_LONG: false` 的表 → 标签过长不再检出（偏好可关）

### 3.2 BatchOptions.globalRulesTable 语义收窄

- `core/apply_batch.ts`：
  - `BatchOptions.globalRulesTable` 类型/默认改指 `PreferenceTable` / `DEFAULT_PREFERENCE_TABLE`（或保留泛型 `Record<string, boolean>` 但 JSDoc 明确"仅偏好规则可关，硬性恒跑"）
  - Phase 3 调用 run_invariants 传参不变（类型随之收窄）
  - 注释更新：`globalRulesTable` 语义 = 偏好开关表
- 检查 `apply_batches.ts` / 前端是否透传 `globalRulesTable`：若前端传了硬性 code 的关闭项，需按新语义修正（grep 确认 `globalRulesTable` 消费方）
- 旧 `DEFAULT_GLOBAL_RULES_TABLE` / `GlobalRulesTable` 若已无消费方则删除；`GLOBAL_RULES` 注册表拆为 structural/preferences 两份列表

### 3.3 Q2：NODE_COUNT_HARD_LIMIT 双轨消除

- `core/rules/preconditions/in_graph.ts` 的 `validateAddNode`：移除 Phase 1 的 `NODE_COUNT_HARD_LIMIT_EXCEEDED` 预判检查（`graph.nodes.length + 1 > nodeHardLimit` 分支）；该方法内不再引用硬上限阈值
- Phase 3 `validateNodeCountHardLimit` 保留（`preferences.ts`，不变量语义）；若偏好开关表关闭该规则则放行（可配置）
- 检查受影响的测试（`validate_operation_in_graph.test.ts` 中若有"add 超过硬上限被 Phase 1 拒"断言 → 改为验证"applyBatch 整体失败（Phase 3 拦截）"或经 run_invariants 检出）
- 若发现 UX 需要"点击即提示而非提交后报错"，说明该预判属 UX 引导——上报，不在本次恢复

### 3.4 测试更新

- `tests/core/checkers/global_rules_table.test.ts`：
  - "runGlobalRules 可关闭指定规则"测试改为**偏好规则**（如 `NODE_LABEL_TOO_LONG` / `NODE_COUNT_*`），断言关闭后不再检出
  - 新增断言：关闭**硬性**规则（如 `SELF_LOOP_FORBIDDEN` / `DUPLICATE_EDGE_FORBIDDEN`）不生效——仍检出
  - 默认开关表断言改指 `DEFAULT_PREFERENCE_TABLE`（若该测试引用旧 DEFAULT_GLOBAL_RULES_TABLE）
- `tests/compose/pipeline.test.ts`："globalRulesTable 可关闭指定规则"测试（关闭 `SELF_LOOP_FORBIDDEN` / `REAL_DIRECTED_CYCLE_FORBIDDEN`）→ 改为关闭**偏好**规则验证可关 + 关闭硬性规则验证仍失败（本测试现用自环边 + 硬性关闭，需重构为：a) 关闭偏好规则（如构造标签超长场景）→ valid；b) 保留硬性关闭项 → 仍 invalid）
- 若 `NODE_COUNT_HARD_LIMIT` 相关测试（Phase 1 预判）存在 → 按 3.3 更新
