# 09.1 分类归位与物理结构重组 — 提示词

## 当前状态

GraphEngine 校验相关代码结构散落、存在双轨死代码，无法凭目录定位规则归属：

- 前置条件文件散在 `core/` 根：`packages/graph-engine/src/core/validate_operation_in_graph.ts`（图内前置）、`packages/graph-engine/src/core/validate_graph_operation.ts`（图级前置）
- 不变量在 `packages/graph-engine/src/core/validators/` 子目录：`global_rules.ts`（13 条平铺 + 开关表 + 注册表）、`whole_graph_validator.ts`（全图体检）、`thresholds.ts`（阈值集中）、`rule_config.ts`（死代码，`DEFAULT_RULES_CONFIG` 全项目无人 import）
- `packages/graph-engine/src/core/layout_rules.ts` 名字撞"rules"，实为布局几何参数（`unitDistance` / `collisionGap`），被 placement/collision/cognitive 与前端 3 文件消费，index.ts 公开导出

**分类模型（已定稿）**：规则 = 类型轴（前置条件 / 不变量）× 级别轴（severity）。不变量按可配置性二分：**硬性图不变量**（结构类 + 语义类，违反后数据/引擎不可正确解释操作，不可配置、恒跑、error）与**图不变量偏好**（体验类，数据仍合法仅体验差异，可配置、默认全开、warning/info）。

**本任务为纯机械搬移**：只做文件归位 + 规则按类别拆分 + 阈值内联 + 死代码清除 + layout 改名，**不改任何校验行为**（规则函数逻辑、code、severity、开关表查询语义全部保持等价）。测试应保持全绿。

## 目标

引擎校验代码落地为 `core/rules/` 分层，完成即步骤文档 09 的"新结构"目录形态。所有规则函数从 `core/validators/global_rules.ts` 单文件平铺，拆为按类别分文件的声明形态。

## 具体子任务

### 1.1 迁移前置文件至 rules/preconditions/

- `core/validate_operation_in_graph.ts` → `core/rules/preconditions/in_graph.ts`：函数 `validateOperationInGraph` 与全部私有辅助原样迁移（逻辑零改动）
- `core/validate_graph_operation.ts` → `core/rules/preconditions/graph_level.ts`：函数 `validateGraphOperation` 与 title 校验辅助原样迁移
- 更新所有引用方 import 路径（见下方文件表）；import 相对路径按新层级修正

### 1.2 拆 global_rules.ts 为 structural.ts + preferences.ts

按分类模型拆分 13 条规则（函数逻辑、code、severity、message 一律不变，只搬家 + 内联阈值）：

**structural.ts（硬性：结构 + 语义，6 条）**：
- 结构：`SELF_LOOP_FORBIDDEN` / `DUPLICATE_EDGE_FORBIDDEN` / `DANGLING_REFERENCE`（`validateSelfLoops` / `validateDuplicateEdges` / `validateReferenceNodeConsistency`）
- 语义：`REAL_DIRECTED_CYCLE_FORBIDDEN` / `VIRTUAL_NODE_EDGE_TYPE_INVALID` / `HEURISTIC_NODE_EDGE_TYPE_INVALID`（`validateRealDirectedCycle` / `validateVirtualNodeEdgeType` / `validateHeuristicReferences`）
- 此文件无需阈值（结构/语义规则不读 `DEFAULT_GRAPH_RULES`）

**preferences.ts（偏好：体验，7 条）**：
- `NODE_LABEL_TOO_LONG` / `NODE_SUMMARY_TOO_LONG` / `EDGE_LABEL_TOO_LONG`（`validateNodeLabels` / `validateNodeSummaries` / `validateEdgeLabels`）
- `NODE_COUNT_SOFT_LIMIT_EXCEEDED` / `NODE_COUNT_WARNING_LIMIT_EXCEEDED` / `NODE_COUNT_HARD_LIMIT_EXCEEDED`（`validateNodeCountSoftLimit` / `validateNodeCountWarningLimit` / `validateNodeCountHardLimit`）
- `VIRTUAL_NODE_TOO_MANY_VIRTUAL_NEIGHBORS`（`validateVirtualNodeNeighborCount`）—— 按分界判据归偏好（违反后数据仍可解释，仅视觉歧义）；若搬移时发现折叠等引擎操作实际依赖该约束，停止并在 task 返回中上报（不自行改判）
- **阈值内联**：本文件顶部内联 `NODE_LABEL_TOO_LONG` 等使用的常量（原 `DEFAULT_GRAPH_RULES` 中的 `nodeLabelMaxLength: 20` / `edgeLabelMaxLength: 20` / `summaryMaxLength: 80` / `nodeSoftLimit: 50` / `nodeWarningLimit: 100` / `nodeHardLimit: 150`），命名与注释保留语义；`preferences.ts` 内不再 import thresholds
- **偏好开关表类型与默认**：本文件定义 `PreferenceTable`（`Record<string, boolean>`，key = 偏好规则 code）与 `DEFAULT_PREFERENCE_TABLE`（仅含上述 7 个偏好 code，默认全 true）。本子步骤仅定义就位，不接为唯一数据源

**thresholds.ts 删除**：内联完成后删除 `validators/thresholds.ts`（`DEFAULT_LABEL_RULES` / `DEFAULT_SCALE_RULES` / `DEFAULT_GRAPH_RULES` 三个导出随文件删除；如有测试直接引用则同步改为内联值或新路径导出——见 1.5）

### 1.3 run_invariants.ts 单一入口（等价搬迁）

- 新建 `core/rules/invariants/run_invariants.ts`：迁移 `runGlobalRules` 的实现（遍历规则注册表、按表查询 `table[code] ?? true` 跳过关闭项、聚合 issues）
- 规则注册表 = structural + preferences 两文件的规则声明 concat；每文件各导出一份"规则列表"（`{ code, check }[]`），run_invariants concat 后遍历
- **本步保持等价**：传入的开关表仍可关闭任意规则（含硬性）——`DEFAULT_GLOBAL_RULES_TABLE` 语义暂保留为默认表（`run_invariants` 缺省参数仍指向它，09.3 再收窄）。`GlobalRulesTable` 类型沿用原定义（本步不删，09.3 收窄）
- 结构上保留 `runGlobalRules` 作为导出名亦可（由 run_invariants.ts 导出，别名自定），调用方（apply_batch / whole_graph_validator）改名或保持均需与新路径一致
- 类别文件**只声明规则，不实现执行循环**——执行循环仅此一份

### 1.4 whole_graph_validator.ts 归位

- `core/validators/whole_graph_validator.ts` → 并入或迁移：`validateGraph` 函数保留（全图体检能力），内部改调 `run_invariants` 单一入口（默认表），不产生第二条校验路径
- 文件落位建议 `core/rules/` 下或 `core/rules/invariants/index.ts` barrel 再导出（具体放哪由你按"单一入口 + barrel 聚合"原则定，但必须复用 run_invariants）

### 1.5 死代码清除 + layout 改名 + 全链路 import 更新

- 删除 `core/validators/rule_config.ts`（死代码）；删除旧 `core/validators/global_rules.ts`；删除 `core/validators/` 目录（若已空）
- `core/layout_rules.ts` → `core/layout_parameters.ts`；符号改名：`LayoutRules` → `LayoutParameters`、`DEFAULT_LAYOUT_RULES` → `DEFAULT_LAYOUT_PARAMETERS`（接口字段 `unitDistance` / `collisionGap` 不变）
- 更新所有引用方（src + tests + frontend）import：见文件表
- 检查 `index.ts` 导出，保持公开 API 名称与消费方一致

### 1.6 测试更新

- 迁移/更新测试引用路径：
  - `tests/core/checkers/global_rules_table.test.ts` → 新路径 import（默认开关/注册表/`runGlobalRules` 行为断言不变——本步硬性仍可关，测试保持绿）
  - `tests/core/validate_operation_in_graph.test.ts` / `tests/core/validate_graph_operation.test.ts` → 新路径 import
  - 引用 `DEFAULT_LAYOUT_RULES` / `LayoutRules` 的测试（placement / adjust 等）→ 新符号名
- 引用 `thresholds` 的测试若存在 → 改为新内联导出或等价值
- **禁止**改动任何行为断言（本步等价搬移）；如某测试因搬移暴露既有错误断言，停止并上报，不自行改断言语义

## 变更边界

**禁止修改**：

- `packages/graph-engine/src/types/` —— 类型定义零改动（本步不动 ValidationIssue / GraphData 等）
- 规则函数内部逻辑、code、severity、message —— 一律不改（等价搬移）
- `validate_graph_operation.ts` 的 title 校验业务逻辑（EMPTY_TITLE / TITLE_DUPLICATE / 空图规则）
- `preconditions/in_graph.ts` 内 UX 类检查（NODE_COLLISION / EMPTY_LABEL / NODE_COUNT 预判等）—— 原样保留，⑤ 迁出是后续步骤
- `core/apply_batch.ts` Phase 1/2/3 的**时序与语义**（只允许 import 路径变化与 runGlobalRules 改名引用）
- `BatchOptions.globalRulesTable` 的开关语义（本步不收窄，09.3 范围）
- 前端 UX 迁移 / 偏好开关表持久化 / `skipValidate` 分流（分属 09.2 / 后续步骤）

**注释要求**：本任务会迁移/改写代码注释（含 JSDoc）。动手前**必须**先阅读 `FOR-AGENTS/注释资料.md` 并按其规范编写/改写注释；文件头"功能/总体结构/外部如何使用"式注释需与新目录归属一致。
