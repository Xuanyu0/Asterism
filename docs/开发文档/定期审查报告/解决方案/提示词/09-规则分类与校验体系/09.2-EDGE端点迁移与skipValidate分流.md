# 09.2 EDGE_*_NOT_FOUND 迁入 Phase 3 与 skipValidate 分流 — 提示词

## 当前状态

前置校验（`packages/graph-engine/src/core/rules/preconditions/in_graph.ts`）中，`validateAddEdge` / `validateUpdateEdge` 通过 `validateEdgeEndpointExists` 校验边端点存在性，产出 `EDGE_SOURCE_NOT_FOUND` / `EDGE_TARGET_NOT_FOUND`（error）。这是 Phase 1 局部校验。

但"悬空边"本质是**图状态不变量**，与 Phase 3 已有的 `DANGLING_REFERENCE`（悬空引用）同构——应在 Phase 3 硬性不变量中统一校验。当前放 Phase 1 是历史实现选择，导致 undo/redo 重放误报：逆元批内 `add_edge` 依赖同批 `add_node` 重建端点，validate-all-first 基于输入图校验必然误报（前端 `graph_store.ts` 因此给 undo/redo 传 `skipValidate: true`）。

`skipValidate` 有两个消费方（理由不同，需分流）：
- **undo/redo**（`graph_store.ts` undo/redo 路径传 `skipValidate: true`）：理由 = 批内依赖误报 EDGE 端点前提。EDGE 迁 Phase 3 后理由消失
- **preview**（`frontend/src/feature-tools/preview/preview_engine.ts` 占位预览传 `skipValidate: true`）：理由 = 占位节点空 label 会被 Phase 1 `EMPTY_LABEL` 拒绝。与 EDGE 无关，`EMPTY_LABEL` 是 UX 前置（⑤ 迁出范围），**本次保留**

## 目标

`EDGE_SOURCE_NOT_FOUND` / `EDGE_TARGET_NOT_FOUND` 从 Phase 1 局部校验迁入 Phase 3 硬性不变量（`structural.ts`）。撤销 undo/redo 侧 `skipValidate: true` 传参；`skipValidate` 参数保留（preview 专用）。

## 具体子任务

### 2.1 端点存在性迁入 structural.ts

- `rules/preconditions/in_graph.ts`：
  - `validateAddEdge` / `validateUpdateEdge` 内移除 `validateEdgeEndpointExists` 调用
  - 删除 `validateEdgeEndpointExists` 私有辅助（或确认无其他调用后删除）
  - Phase 1 剩余前置收敛为：ID 重复、节点/边存在（delete/update/move/collapse 目标）、位置有效、折叠条件
- `rules/invariants/structural.ts`：
  - 新增两条硬性规则（code 不变：`EDGE_SOURCE_NOT_FOUND` / `EDGE_TARGET_NOT_FOUND`；severity 不变：error）：
    - 遍历 graph.edges，edge.source 不在 graph.nodes 中 → EDGE_SOURCE_NOT_FOUND
    - edge.target 不在 graph.nodes 中 → EDGE_TARGET_NOT_FOUND
  - 实现可参考原 `validateEdgeEndpointExists` 的 issue 构造（message 保持不变）
  - 命名建议：`validateEdgeEndpointExistence`（check 函数），注册进 structural 规则列表
  - 注意与 `DANGLING_REFERENCE` 语义边界：`DANGLING_REFERENCE` 查 reference 节点指向的源节点；新规则查普通边（nodes 内的边）的端点——两规则互补不重叠（若发现重叠/重复报告，停止并上报）

### 2.2 skipValidate 分流（undo/redo 侧撤销）

- **受控实验**：将 undo/redo 执行路径的 `skipValidate: true` 移除（改缺省 false），跑前端 undo/redo 测试与 GE reversal/replay 测试
- 预期结果：EDGE 端点误报消失后，逆元批经完整 Phase 1 + Phase 3 校验全部通过
- **若实验通过**：撤销 undo/redo 侧传参——
  - `frontend/src/graph/graph_store.ts`：undo/redo 的 applyEntry reverse/forward 调用处删除 `skipValidate: true`（保留其他 options 如 executedAt / recordLog）；同步更新相关注释（含第 369-374 行附近"skipValidate 是重放的必要机制"注释改为新语义或删除）
  - `frontend/src/graph/undo_redo.test.ts` 相关注释同步（如有）
- **若实验不通过**：定位剩余批内依赖误报项，**停止并完整上报**（不自行保留 skipValidate 或改动其他机制），由编排者决策是否保留 undo/redo 侧
- **preview 侧不动**：`preview_engine.ts` 的 `skipValidate: true` 保留（EMPTY_LABEL 理由，⑤ 迁出后整体退役）
- 引擎 `BatchOptions.skipValidate` / `ApplyBatchesOptions.skipValidate` 参数**保留**（preview 消费方仍在），仅语义注释更新为"preview 专用（占位预览绕过 UX 前置）"

### 2.3 测试更新

- GE：`tests/core/checkers/global_rules_table.test.ts` 补 EDGE 端点存在性规则断言（构造悬空边 → EDGE_SOURCE/TARGET_NOT_FOUND 检出）；确认新规则在默认开关表中开启
- GE：`tests/core/validate_operation_in_graph.test.ts`：原"自环/重边由 applyBatch 全局规则检出"类测试确认语义（若原测试断言 add_edge 的 EDGE 端点误报来自 Phase 1，需改为验证 Phase 3 检出）
- GE：pipeline 相关测试确认：add_edge 端点悬空 → 仍整体失败（现在由 Phase 3 拦），`result.graph` 不变
- 前端：undo/redo 测试在无 skipValidate 下全绿（undo/redo 完整校验路径）
- **禁止**为让测试通过而给 undo/redo 重新引入 skipValidate
