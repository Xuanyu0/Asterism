# 09.4 验证与收尾 — 提示词

## 当前状态

09.1（物理结构重组）/ 09.2（EDGE 端点迁移 + skipValidate 分流）/ 09.3（硬性缺席配置面 + Q2 双轨消除）已依次执行完成。本子步骤对引擎侧重构做整体验证与收尾确认。

## 目标

重构后 GE 全量测试通过、无行为回归；前端测试与类型检查通过；确认重构满足"新人凭目录/文件名定位规则归属"的可发现性目标。

## 具体子任务

### 4.1 引擎验证

- `pnpm --filter @my-project/graph-engine test` 全绿
- `pnpm --filter @my-project/graph-engine type-check` 无错误
- 复核关键行为等价点：
  - 硬性规则（自环/重边/悬空引用/成环/边类型/EDGE 端点）在默认配置下全部 error 拦截，行为与重构前一致
  - 偏好规则（标签长度/节点数/虚邻居数）severity 与 code 不变
  - undo/redo（无 skipValidate）与 reversal/replay 测试通过

### 4.2 前端回归

- `pnpm --filter frontend test` 全绿
- `pnpm --filter frontend type-check` 无错误
- `commitBatchToGraphs` / undo-redo 行为不变；`preview_engine` skipValidate 仍工作

### 4.3 可发现性复核（面向"新人定位"目标）

- 按以下路径走查，确认可无歧义定位：
  - "这条规则是前置还是不变量？" → `core/rules/preconditions/` vs `core/rules/invariants/`
  - "这是硬性还是偏好？" → `invariants/structural.ts` vs `invariants/preferences.ts`
  - "开关表能关什么？" → `preferences.ts` 的 `DEFAULT_PREFERENCE_TABLE`（只含偏好）
  - "Phase 3 怎么执行规则？" → `run_invariants.ts` 单一入口
- 若发现命名/注释残留（如仍提旧 `global_rules.ts` / `DEFAULT_GLOBAL_RULES_TABLE` 的注释、旧路径引用）→ 清理

### 4.4 发现收集

- 执行 09.1-09.3 期间未处理的可疑点复核确认；新观察记入发现文档（由编排者收集，本任务只需如实报告）

## 变更边界

**禁止修改**：

- 任何规则函数逻辑、code、severity、message（行为已定，本步只验证不重构）
- `types/` 下类型定义（本步骤不新增 category 等字段——待确定 Q1 决策为"暂不增加"）
- 前端 UX 迁移 / 偏好开关表持久化 / UI 配置入口（后续步骤范围）

**注释要求**：如清理注释残留，动手前**必须**先阅读 `FOR-AGENTS/注释资料.md` 并按其规范改写。

- [ ] `pnpm --filter frontend test` 全绿。

- [ ] 可发现性走查 4 项全部可通过目录/文件名无歧义回答。
- [ ] 无未确认的行为回归（硬性仍拦、偏好仍提示、undo/redo 正常、preview 正常）。
