# 05.1-graph_store 核心化与适配层下沉 — 提示词

## 当前状态

`graph_store.ts` 现为模块级单例（`useGraphStore()` + 公开 interface `GraphStoreAPI`），公开 7 个方法：

- 核心入口：`loadGraphToView` / `commitBatchToGraphs` / `undo` / `redo`
- 生命周期与 UI 方法（本次移除）：`initRegistry` / `createRootGraph` / `clearValidationResult`

调用面现状：

- `Graph.vue` onMounted 调 `initRegistry()` + 哨兵序列（偷看 `graphRegistry.keys()` 取 rootId → `loadGraphToView` → 失败降级 `createRootGraph('My Graph')`）；错误面板 `v-on:close` 调 `clearValidationResult()`
- `useFloatingWindow.close` 调 `clearValidationResult()`（外部点击关闭时）
- `NavigationPanel` 经 `useNavigationAdapter.createRootGraph(title)` 用户显式新建（当前转发 store）
- `dev/bootstrap.ts` 调 `graphStore.createRootGraph(title, { id })` 种子创建（固定 ID 幂等）

错误通知现状：`NotificationPanel`（closable）+ `canvasErrorIssues` computed（消费 `lastValidationResult`）。适配层形态先例：`useNavigationAdapter` / `useGraphOperationAdapter` 均为"模块级单例 + 懒创建 + 公开 interface"。

## 目标

graph_store 收窄为四入口（唯一切换 / 唯一图操作 / 唯一回溯），成为对接 GE 的唯一核心入口；生命周期管理下沉新建适配层，创建与校验清理分别下沉导航 / 操作适配层；错误通知改为浮空窗式"外部交互即关闭"。

## 架构变更

```
旧：
Graph.vue ──→ graph_store（initRegistry + createRootGraph + clearValidationResult + 四入口混杂）
                NavigationPanel → navigationAdapter.createRootGraph → store.createRootGraph
                bootstrap → store.createRootGraph
                错误通知：NotificationPanel closable → store.clearValidationResult

新：
Graph.vue ──→ useLifecycleAdapter（restoreLastRootTree / ensureWorkspaceRoot）→ store
                NavigationPanel → navigationAdapter.createRootGraph（add_graph 统一管道）→ store.commitBatchToGraphs
                bootstrap → navigationAdapter.createRootGraph（临时接线，带注释）
                错误通知：外部点击面板外任意处 → operationAdapter.clearValidationResult
                store = loadGraphToView / commitBatchToGraphs / undo / redo（四入口）
```

## 具体子任务

执行顺序：2.1 → 2.2 → 3.1 → 3.2 → 1.1（先建适配层接手，再收窄 store，避免断链中间态）。

### 2.1. 新建 useLifecycleAdapter：restoreLastRootTree

- 新建 `frontend/src/graph/adapters/useLifecycleAdapter.ts`，模块级单例 + 懒创建 + 公开 interface（与现有适配层形态一致）
- `restoreLastRootTree(): GraphId | null`：
  - 逻辑移自 `graph_store.initRegistry`（函数级）：`loadLastActiveRootId` → `loadGraph` 校验 `kind === 'root'` → 注册根图 → 遍历 `listSavedGraphIds` 用 `isInRootTree` 筛出全部子图注册 → **返回恢复的根图 ID**
  - 缺口修复（行为设计）：
    - `kind !== 'root'`：开发者通道报告（console.warn，可新增专用报告函数，风格沿用 `data_integrity_reporter` 的 `DATA_INTEGRITY_PREFIX` 前缀）→ 清理 `lastActiveRootId` → 返回 null
    - corrupted：沿用 `reportCorruptedGraph` 报告 → 清理 `lastActiveRootId` → 返回 null
    - missing：静默（正常状态）→ 清理 `lastActiveRootId` → 返回 null
    - 无历史（`loadLastActiveRootId()` 为空）：返回 null，不清理
- 依赖复用：`loadLastActiveRootId` / `clearLastActiveRootId`（graph_persistence）、`isInRootTree`（graph_tree）、`registerGraph` / `hasGraph`（graph_registry）

### 2.2. ensureWorkspaceRoot

- 同一适配层新增 `ensureWorkspaceRoot(): GraphId`：
  - 调 `restoreLastRootTree()`：有健康根图 → 返回其 ID
  - 无根图 → 创建兜底根图（title `'My Graph'`）→ 返回新 ID
  - 创建走 `store.commitBatchToGraphs` 统一管道（构造空根图 + `add_graph` 操作 + `recordLog: false`），**禁止**直接 `saveGraph` / `registerGraph`
- 空根图构造（nodes / edges 空数组 + `cognitiveState: { foldedDependencies: [] }` + `kind: 'root'`）在适配层内完成，`generateGraphId` 取自 `@my-project/graph-engine`

### 3.1. navigationAdapter.createRootGraph 走统一管道

- `useNavigationAdapter.createRootGraph(title, opts?: { id?: GraphId })` 停止转发 store：
  - 幂等：`opts.id` 已存在（`loadGraph(opts.id).ok`）→ 直接返回原 id
  - 构造空根图 → `store.commitBatchToGraphs([{ graph, operations: [{ type: 'add_graph', graph }] }], { recordLog: false })` → 返回 id
- `dev/bootstrap.ts` 全部 `graphStore.createRootGraph(title, { id })` 改接 `useNavigationAdapter().createRootGraph(title, { id })`，接线处注释：**临时接线——bootstrap 为 dev 种子工具，导航适配层 createRootGraph 的正式消费方仅 NavigationPanel**

### 3.2. clearValidationResult 下沉 + 外部交互关闭

- `useGraphOperationAdapter` 新增 `clearValidationResult(): void`：置 `store.lastValidationResult = null`（与 `reportComposeValidation` 同为校验状态管理，写入方式一致）
- `Graph.vue`：
  - `NotificationPanel` 移除 `closable` 属性与 `v-on:close` 绑定
  - onMounted 挂 `window` `pointerdown` 监听：点击目标不在通知面板根元素内 → `useGraphOperationAdapter().clearValidationResult()`（onUnmounted 移除；与现有快捷键监听挂载模式一致）
  - onMounted 引导序列替换为：`const rootId = useLifecycleAdapter().ensureWorkspaceRoot()` → `graphStore.loadGraphToView(rootId)`（哨兵四步序列 + 偷看 registry 整体删除）
- `useFloatingWindow.close` 的 `useGraphStore().clearValidationResult()` 改调 `useGraphOperationAdapter().clearValidationResult()`

### 1.1. store 公开接口收窄

- `graph_store.ts` 移除 `initRegistry` / `createRootGraph` / `clearValidationResult`（interface 声明 + 对象字面量引用 + 方法定义整体删除）
- `loadGraphToView` 内部原有的 `clearValidationResult()` 调用改为内联 `store.lastValidationResult = null`
- 文件顶部注释"留在本 store 的判定标准"更新为四入口表述（唯一切换 / 唯一图操作 / 唯一回溯）
- **不得**改动 `commitBatchToGraphs` 内部（含 add/delete_graph 分支、operationLog 双存、applyEntry 三段式）与 `undo` / `redo` / `loadGraphToView` 的行为语义

### 注释同步

- `graph_persistence.ts` / `graph_tree.ts` / `operation_controller.ts` 中"initRegistry"引用注释更新为"useLifecycleAdapter.restoreLastRootTree"

## 变更边界

**禁止修改**：

- `packages/graph-engine/` 全部
- `store.commitBatchToGraphs` 内部实现（add/delete_graph 分支、operationLog 双存、applyEntry 三段式、graph_signals 兑现）
- `store.undo` / `redo` / `loadGraphToView` 的行为语义（loadGraphToView 仅允许校验清理改为内联）
- `navigationAdapter.deleteRootGraphTree` 行为（保持现状）
- `cy_element_mapper.ts` 的 position 拷贝
- `useGraphStore()` 调用签名与 store 状态字段

**禁止行为**：

- 不得直接 `saveGraph` / `registerGraph` 实现创建（创建必须走 `commitBatchToGraphs` 的 add_graph 管道）
- 不得引入新依赖
- 不得改变 `reportComposeValidation` 既有行为
- 不得删除 `delete_graph` 相关分支与测试

## 验收标准

- [ ] store 公开接口仅剩四入口 + 状态；`initRegistry` / `createRootGraph` / `clearValidationResult` 全库无调用点
- [ ] `loadGraphToView` 切图仍清空 `lastValidationResult`（内联实现，行为不变）
- [ ] `useLifecycleAdapter`：restoreLastRootTree 恢复根图树并返回根图 ID；kind 非 root / corrupted / missing 各路径按子任务行为处理（含 lastActiveRootId 清理）；ensureWorkspaceRoot 无根图时创建兜底根图并经 commitBatchToGraphs
- [ ] `navigationAdapter.createRootGraph`：创建后 registry 可查、持久化可见（测试断言）；`opts.id` 幂等保留
- [ ] `bootstrap.ts` 改接导航适配层，接线处含"临时接线"注释
- [ ] 错误通知：NotificationPanel 无 closable；点击面板外任意处清错（面板内点击不清）；浮空窗 close 清错经操作适配层
- [ ] 注释同步：graph_persistence / graph_tree / operation_controller 无 `initRegistry` 引用残留
- [ ] 测试：`pnpm --filter frontend test` 全绿；新增 useLifecycleAdapter 测试覆盖 restoreLastRootTree（含异常路径）与 ensureWorkspaceRoot
