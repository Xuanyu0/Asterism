# 08.1-08.3 注册表全量注册改造 — 提示词

## 当前状态

- `useLifecycle.ts` 的 `restoreLastRootTree` 启动时只加载 `lastActiveRootId` 的根图树（根图 + 子图），按 `isInRootTree` 过滤——注册表 = 已访问图的集合
- `graph_store.ts` 的 `loadGraphToView` 导航时 `registerGraph` 累积注册
- 跨图操作（`makeLookup`）只能查到已加载的图，未加载图操作失败（`BATCH_GRAPH_NOT_FOUND`）

## 目标

- 启动时全量加载所有持久化图进注册表（`registerAllGraphs`），注册表覆盖全部图
- `loadGraphToView` 移除 `registerGraph`（图已在注册表，仅切换视图）
- `lastActiveRootId` 语义收窄为"恢复上次视图"（初始 `graphViewId`），不再决定注册表内容

## 架构变更

```
旧：restoreLastRootTree（只加载当前根图树，isInRootTree 过滤）
  → loadGraphToView（导航时 registerGraph 累积）
  → 注册表 = 已访问图的集合

新：registerAllGraphs（全量加载全部持久化图）
  → 注册表 = 全部图
  → loadGraphToView 仅更新 graphViewId（无注册调用）
```

## 具体子任务

### 1.1. registerAllGraphs 全量加载逻辑

- `useLifecycle.ts`：`restoreLastRootTree` 改造为 `registerAllGraphs`——遍历 `listSavedGraphIds` 逐图 `loadGraph` 注册进注册表（corrupted 入开发者通道 `reportCorruptedGraph`，missing 跳过），**不再按 `isInRootTree` 过滤**（全部图都注册）
- 返回"上次视图根图 ID"：`loadLastActiveRootId` 存在且健康（kind === 'root'）时返回它；异常路径（kind 非 root / corrupted / missing）沿用现有处理（报告 + `clearLastActiveRootId` + 返回 null）；无历史返回 null
- `ensureWorkspaceRoot` 适配：调用 `registerAllGraphs` 全量加载；有上次视图根图则返回它，无则创建兜底根图（现有兜底逻辑不变）

### 1.2. 重新语义化命名

- `restoreLastRootTree` → `registerAllGraphs`（全量注册全部图）
- 同步更新：`useLifecycle.ts` 内部调用、`Graph.vue` 启动引导（如引用）、`graph_persistence.ts` / `graph_tree.ts` / `graph_store.ts` 注释中的 `restoreLastRootTree` 引用

### 2.1. loadGraphToView 移除 registerGraph

- `graph_store.ts`：`loadGraphToView` 移除 `registerGraph(store.graphRegistry, loadedResult.graph)`——全量注册后图已在注册表，仅更新 `graphViewId` 切换视图
- 保留串行五步结构（加载 → 验证 → 换显示 → 根图切换判断 → 更新运行时状态），仅去掉注册步骤

### 3.1. 测试适配

- `useLifecycle.test.ts`：`restoreLastRootTree` 用例适配为 `registerAllGraphs` 语义（全量加载 + 返回上次视图根图 ID）
- `useNavigation.test.ts` / `graph_store.test.ts`：loadGraphToView 移除注册后的行为适配（如测试依赖 loadGraphToView 注册图）
- 全量测试绿（前端 191 + GE 175）+ 前端/GE type-check 无错误

### 3.2. 术语表更新

- `docs/开发文档/开发术语表.md`：`restoreLastRootTree` 条目更新为 `registerAllGraphs`（全量注册全部图）
- 术语表时间戳由 pre-commit 钩子自动同步
