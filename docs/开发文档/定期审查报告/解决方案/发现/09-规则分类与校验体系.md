#### I-S1.1：EMPTY_LABEL 归属讨论结论（2026-09-09 用户裁决：记入发现，留 ⑤ 规划）

* 状态：⏳ 待确认
* 位置：`core/rules/preconditions/in_graph.ts` validateAddNode（EMPTY_LABEL 前置）
* 讨论要点：

1. **当前语义缺口**：EMPTY_LABEL 只拦 add_node 一个入口——`validateUpdateNode` 不查 label 空（update 可改空）、`validateGraph` 全图体检不查（runInvariants 不含它）。"图含空标签节点"当前不被任何图级校验视为非法。若产品意图是"图永不含空标签节点"（状态约束），正确落点是 **Phase 3 不变量**（拦所有入口含 update）。
2. **与 NODE_LABEL_TOO_LONG 不对称**：过长在不变量（preferences），为空在前置——同是 label 合法性问题分居两类，不连贯。按分界判据（数据可解释、引擎可操作）倾向偏好类；但空标签非"可配置口味"，更接近硬性（产品语义损坏）——**判据对"engine-operable 但 product-invalid"的规则存在边界缺口**，EMPTY_LABEL 是样例，⑤ 定分类时需扩展判据或单列。
3. **preview 依赖的双重性（关键事实）**：`preview_engine.ts` 注释明示 preview 跳 Phase 1 有两个理由——`EMPTY_LABEL`（空 label 占位）+ `NODE_COLLISION`（占位位置故意可能重叠，碰撞预览是设计功能）。**占位 label 方案只能解决前者**；NODE_COLLISION 仍在 Phase 1 时 skipValidate 撤不掉。
4. **占位 label 方案（用户提出，评估为方向正确）**：预览节点用非空占位 label（如"节点"）+ 渲染层（cy_style 预览 class）隐藏标签文本。数据层合法（能过任何校验含未来 Phase 3 不变量）+ 表现层隐藏——正确分层。采纳后 EMPTY_LABEL 无论留 Phase 1 还是升 Phase 3 均不再卡 preview（连带收益：升不变量在机制上可行）。
5. **结论**：⑤ 规划时采用——占位 label + 渲染隐藏；EMPTY_LABEL 升 Phase 3 状态不变量（堵 update 漏洞）或随 UI 层禁提交（二选一，届时候选）；NODE_COLLISION 迁 UI 层后 preview 用自身 hasCollisionAt（已在用）跑完整管线 → skipValidate 才可整体退役。
