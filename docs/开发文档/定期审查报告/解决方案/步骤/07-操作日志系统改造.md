# 07-操作日志系统改造

---

## 背景与动机（承接 06 / 06.5 / 上轮 07 讨论）

06 完成后 `applyBatches`（多图管理层）已落地，前端 `commitBatchToGraphs` 已对接；06.5（A-1 修复）证明 applyBatches 管道可真实跑通。但操作日志系统仍是旧结构：

- `graphSignals` 旁路字段（图级操作的特殊待遇）
- undo/redo 三段式手工编排（deleted 恢复 → 图内逆元 → added 注销），`direction` 语义侵入执行逻辑
- 图级逆元前端手写兑现（`revertAddGraph` / `revertDeleteGraph`，且 `revertDeleteGraph` 依赖持久化 `loadGraph` 恢复——日志不自包含、undo 与持久化状态耦合）
- `item` / `entry` 命名与粒度递进不一致
- execute 层 14 处 `new Date().toISOString()` 非确定性时间戳（重放不等价、undo 后历史时间戳丢失）

本步骤目标：**日志、执行、回溯三端统一到"单图 op → 单图批 → 多批次"粒度递进**，日志成为 applyBatches 直接可消费的序列，同时落地 `delete_abstract_node`（抽象节点完全递归删除）与时间戳参数化。

### 新旧模型总览

```
旧模型（现状）：
applyBatches → { registry, reversalOperations(图级逆元被前端过滤), graphSignals }
                        ↓
               前端日志组装：过滤 isGraphLevelReversal + 存 graphSignals
undo/redo = applyEntry 三段式（direction: forward/reverse 两套镜像代码）
图级 undo  = revertDeleteGraph(依赖 localStorage loadGraph) / revertAddGraph
时间戳    = execute 内部 new Date()（非确定，undo 后 updatedAt=撤销时刻，历史丢失）

新模型（本步骤）：
applyBatches → { registry, reversalOperations(完整逆元，图内 + 图级空图互逆) }
                        ↓
               日志 BatchLog = reversalOperations（出参即入参，直接消费）
undo = 执行 reversalOperations 序列；redo = 执行 operation 序列（同一 applyBatches 路径）
图级 undo  = 图内逆元自带快照恢复内容 + 空图 add_graph 恢复注册（无持久化依赖）
时间戳    = 正逆共用 entry.timestamp（批级唯一时间）；对象级尊重逆元快照携带值恢复历史时刻
```

## 1. GE：时间戳参数化 ⏳

### 目标

execute 层非确定性时间戳消失，时间戳由 Runtime 统一传入；undo 恢复历史时刻（方案 B——事件时间严格恢复）。

### 1.1 execute 时间戳参数化

**子目标**：
  * `execute_operation.ts` 9 处 `new Date().toISOString()` 全部移除；`executedAt` 参数经 `applyBatch` / `applyBatches` 透传到每个 execute 函数，统一写对象级与图级 `updatedAt`
  * `ApplyBatchesOptions` 增 `executedAt: string`（时间参数：**本批次执行的时刻**，execute 所有时间戳基于它生成；正向传真实当前时刻，redo 可传历史时刻）
  * `test_case_factory.ts` 与既有 GE 测试改用固定 `executedAt`，时间戳从"忽略断言"升级为精确断言

### 1.2 对象级时间戳规则（携带值 ?? executedAt）

**子目标**：
  * execute 对象级时间戳规则统一为 **`操作携带值 ?? executedAt`**：操作携带时间戳（逆元快照）即尊重——节点/边级 createdAt/updatedAt 以操作对象为准；未携带（正向操作）用 `executedAt` 兜底
  * `reversal.ts` 无需改动——逆元快照（`structuredClone`）已携带完整历史时间戳；execute 天然尊重 → undo 恢复对象级历史时刻，**无需任何执行模式标记**
  * **正向操作构造方必须保证操作对象不携带时间戳**（compose 已删死代码；前端 default_tool 构造 update_node / update_edge 时清除 updatedAt）——这是"时间由 applyBatches 统一注入"的构造约定
  * 语义边界（时间参数 `executedAt` 的来源，**正逆三路径共用同一时间戳**）：一次提交 = 一条日志条目 = 一个 `entry.timestamp`（批级唯一时间）。正向提交时以当前时刻写入 `entry.timestamp`；**undo / redo 均从该 entry 读取同一 `entry.timestamp` 传入**——正逆一次双存共用同一时间，executedAt 永不 undefined，不存在"撤销时刻"这第三种时间
  * 图级 updatedAt 语义 = 该图最近参与的一次多批次操作的时间（批级时间戳）；undo 是该批的一部分（同一事件），图级保持该批时间

### 1.3 compose 死代码时间戳清理

**子目标**：
  * `induce.ts` / `diverge.ts` / `internalize.ts` / `deconstruct.ts` 5 处内部 `new Date()` 移除，构造操作不再填充时间戳（现状填了也被 execute 覆盖，属死代码；execute 统一用 `now` 兜底）
  * compose 签名不变

难度：
- 不确定度：低（机制已定，机械替换）
- 算法实现复杂度：无
- 工作量：小

### 影响范围

```
packages/graph-engine/src/core/execute_operation.ts — 9 处去 new Date()，透传 executedAt；对象级规则 携带值 ?? executedAt
packages/graph-engine/src/core/apply_batch.ts          — 透传 executedAt
packages/graph-engine/src/core/apply_batches.ts        — ApplyBatchesOptions 增 executedAt
packages/graph-engine/src/compose/cognitive/*.ts       — 4 文件删内部 new Date() 与时间戳填充
packages/graph-engine/tests/                          — test_case_factory + 相关断言
frontend/src/graph/graph_store.ts                     — commitBatchToGraphs 透传 executedAt
frontend/src/feature-tools/default_tool.ts            — 构造 update_node / update_edge 清除 updatedAt（构造约定）
```

### 决策项

**待确定决策**：

（无 —— 时间戳语义已由用户裁决）

**已确定决策**：
- 时间戳方案选 **B（事件时间严格恢复）**：undo 恢复"操作前"状态（对象级历史时刻）；redo 恢复"操作后"状态。二者对称。
- 时间参数 `executedAt` 语义 = 本批次执行的时刻；**正逆三路径共用同一时间戳**：正向提交时写入 `entry.timestamp`，undo/redo 均从该 entry 读取同一值传入（批级唯一时间，无"撤销时刻"）。
- 机制：execute 对象级规则 = **携带值 ?? executedAt**（无执行模式标记）；正向构造方"不携带时间戳"是构造约定（compose 已删死代码、default_tool 清除 updatedAt）。
- compose 时间戳填充删除（死代码清理），时间戳唯一落点在 execute。

## 2. GE：操作日志模型统一 ⏳

### 目标

日志命名统一到"树 → 提交 → 批"粒度递进（`OperationLogTree` / `CommitLog` / `BatchLog`）；新建子图注册补写图级时间戳（U-1 修复）。`graphSignals` 的移除**推迟到子步骤 4**（前端三段式 undo 依赖它，只能与对称化同步移除）。

### 2.1 日志类型命名改造

**子目标**：
  * `types/operation_log.ts`：`OperationLog` → `OperationLogTree`、`OperationLogEntry` → `CommitLog`、`ItemOperations` → `BatchLog`（**graphSignals 字段暂留**，标注子步骤 4 移除）
  * 容器与条目结构不变（entries / cursor / parentIndex / timestamp / source），仅命名调整
  * `index.ts` 导出与全部引用方（graph_store.ts / 测试）同步改名；`store.operationLog` 公共字段名保留

### 2.2 图级时间戳补写（U-1 修复）

**子目标**：
  * `executeGraphOperation`（add_graph 注册）用 `executedAt` 补写图级 `createdAt` / `updatedAt`（图骨架未携带时兜底，与 execute 层"携带值 ?? executedAt"一致）——修复 compose 删时间戳死代码后新建子图时间戳缺失
  * 图级逆元已由 `createGraphReversal` 构造**空图 add ↔ delete 互逆**，`reversalOperations` 已是包含图级逆元的完整序列——**无需新增构造逻辑**
  * 正逆原子操作数量对称：正向每个原子操作在逆元序列都有镜像，undo/redo 走同一执行路径行为完全对称

### 2.3 GE 测试更新

**子目标**：
  * 日志类型改名同步（import 类型名）
  * 新增 U-1 断言：真实 compose → applyBatches 后，新建子图 `createdAt` / `updatedAt` = 传入 executedAt

难度：
- 不确定度：低
- 算法实现复杂度：无
- 工作量：小

## 3. GE：delete_abstract_node ⏳

### 目标

抽象节点删除 = **完全递归删除子图树**（嵌套抽象节点不留死图）；前端 delete 工具对抽象节点改走本 compose。

### 3.1 compose 函数（自底向上递归）

**子目标**：
  * 新增 `compose/cognitive/delete_abstract_node.ts`，与其他 compose 函数同构（构造完整操作序列 → applyBatches 执行）
  * **递归后序 DFS**：先递归清空并注销最深层子图，逐层向上，最后删除最外层抽象节点本身（调用栈天然表达自底向上，规避 BFS"遍历到就构造"的顺序错乱）
  * 子图内容清空只需 `delete_node` 全部节点——边由 `executeDeleteNode` 级联删除（execute_operation.ts:112），无需显式 delete_edge
  * 批次结构：同图节点同批、图级批夹在单图批之间（如三层嵌套：G2 清空批 → delete_graph G2 → G1 清空批 → delete_graph G1 → delete_node A）
  * 直接用 `GraphRegistry`（新函数新接口）；现有 50 处 `GraphLookup` 暂不统一，作为后续清理项

### 3.2 集成测试

**子目标**：
  * 新增集成测试：真实 `delete_abstract_node` compose 输出 → `applyBatches` 完整执行（多层嵌套抽象节点 + 沟通节点场景），验证死图不残留、批序正确

难度：
- 不确定度：中（递归构造与批序）
- 算法实现复杂度：中
- 工作量：中

### 影响范围

```
packages/graph-engine/src/compose/cognitive/delete_abstract_node.ts — 新增
packages/graph-engine/tests/                                        — 集成测试
frontend/src/feature-tools/toolbar/delete.ts                        — 分发改造（衔接子步骤 5）
```

### 决策项

**待确定决策**：

（无）

**已确定决策**：
- 删除语义：抽象节点 = 删整棵子树（完全递归）；非抽象节点（含引用节点）保持普通 `delete_node` 单图内语义（execute_operation.ts:108 级联引用节点删除）。
- 实现用递归后序 DFS（自底向上）；批内 `delete_node` 安全（子图内无指向同图节点的引用节点，`createReversal` 逆元构造不抛异常）。

## 4. 前端：undo/redo 对称化 ⏳

### 目标

`applyEntry` 三段式手工编排消失；undo/redo 走同一条 applyBatches 路径；`graph_signals.ts` 删除。

### 4.1 日志组装改造

**子目标**：
  * `reversalOperations` **全量入日志**（不再 `isGraphLevelReversal` 过滤）；`graphSignals` 不再提取
  * **GE 同步**：`apply_batches.ts` 的 `ApplyBatchesResult` 移除 `graphSignals` 返回字段与内部累积逻辑（对称化后逆元序列自包含，graphSignals 无消费者）
  * `isGraphLevelReversal` 函数删除

### 4.2 applyEntry 对称化

**子目标**：
  * `direction` 语义消失：undo = 组装逆元序列调 `applyBatches`；redo = 组装正向序列调 `applyBatches`，同一执行路径
  * `skipValidate` 降级为防御（正逆对称 + 逆元严格逆序 + 空图增删 → 逐批校验自然通过），不再作为核心机制
  * 图内/图级批拆分逻辑保留（applyBatches 判别联合要求）
  * graph 对象解析（registry 缺失兜底 add_graph）保留在前端转换层（见 Q1）

### 4.3 graph_signals.ts 删除

**子目标**：
  * `revertAddGraph` / `revertDeleteGraph` 消亡；`graph_signals.ts` 文件删除
  * 图级 undo 不再依赖持久化 `loadGraph`（undo 与持久化状态解耦，纯内存执行）

### 4.4 时间戳 now 传入

**子目标**：
  * `commitBatchToGraphs` 正向提交时以当前时刻生成 `executedAt`（单一时间源）并写入日志条目 `entry.timestamp`（即该批操作的唯一时间，undo/redo 回读用）
  * **undo / redo 均从该 entry 读取 `entry.timestamp` 作为 `executedAt` 传入 applyBatches**（正逆共用同一时间戳）；undo 的对象级历史恢复依赖逆元快照（衔接子步骤 1 的 execute 规则）

### 4.5 前端测试更新

**子目标**：
  * `undo_redo.test.ts` 重构：三段式断言 → 对称序列断言；图级 undo（建图/注销）不再 mock 持久化恢复
  * graphSignals 相关测试移除；delete 抽象节点可撤销（完整子树恢复）新增用例

难度：
- 不确定度：中
- 算法实现复杂度：低
- 工作量：大

### 影响范围

```
frontend/src/graph/graph_store.ts        — 日志组装 / applyEntry / undo / redo 重构
frontend/src/graph/graph_signals.ts      — 删除
frontend/src/graph/undo_redo.test.ts     — 重构
frontend/src/graph/graph_store.test.ts   — 断言更新
```

### 决策项

**待确定决策**：

> **Q1**：redo 执行时 graph 对象由谁解析？
> **建议**：前端转换层保留——日志 `graphId` → 组装批次时从 registry 解析，缺失时用批内 `add_graph` 兜底（现状逻辑），applyBatches 签名不变。
> **理由**：改动面小、引擎保持纯函数输入；方案②（applyBatches 接受 graphId）影响大且需改 compose 输出形态，收益不明显。

**已确定决策**：
- undo/redo 对称执行（同一 applyBatches 路径），`direction` 语义与三段式消失。
- `skipValidate` 降级为防御，不作为核心机制。
- `graph_signals.ts` 删除，图级 undo 不再依赖持久化。
- **undo 与 redo 均传 `executedAt` = 该 entry 的 `entry.timestamp`**（正逆共用同一批级时间戳）；undo 的对象级历史恢复由逆元快照携带值驱动（execute 规则：携带值 ?? executedAt），无需额外标记。
- `entry.timestamp` 由正向提交时生成（= 该批操作的唯一时间），日志持久化后供 undo/redo 回读。
