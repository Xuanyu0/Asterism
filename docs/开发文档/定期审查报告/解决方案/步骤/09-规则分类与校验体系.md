## 背景与动机

### 1. skipValidate 参数的可疑性（07.4 讨论浮现）

07.4（undo/redo 对称化）验收后审查 `skipValidate` 参数时发现：该参数是"重放模式"与"新操作模式"的分界开关，**只跳过 Phase 1（操作前提校验）**，Phase 3 全局不变量与图级空图校验始终生效。

- 逆元/正向重放存在**批内依赖**（`add_edge` 依赖同批 `add_node` 重建端点），validate-all-first 基于输入图校验必然误报 `EDGE_SOURCE/TARGET_NOT_FOUND`（010.1 缺陷 #1 修复的机制，D-4 实测为必要机制，非防御）。
- 正向 compose 靠**拆批**规避（induce.ts："批按节点→边拆分"），逆向无法拆批（逆元顺序固定），只能 skipValidate。

### 2. EDGE_*_NOT_FOUND 的归属问题

`validateAddEdge` 的端点存在性校验（`EDGE_SOURCE_NOT_FOUND` / `EDGE_TARGET_NOT_FOUND`）当前在 **Phase 1（局部）**，但其本质是"悬空边"= **图状态不变量**，与 Phase 3 已有的 `DANGLING_REFERENCE`（悬空引用）完全同构。

- 设计文档定义："全局规则 = GraphData 不变量"、"局部规则 = 操作前提"。
- 按此定义，边端点存在性应归**全局**（与悬空引用同类），当前放局部是历史实现选择。
- **候选方向**：将 `EDGE_SOURCE/TARGET_NOT_FOUND` 迁入 Phase 3 全局规则 → 逆元重放误报源消失 → `skipValidate` 可能退役/收窄；正向 compose 的"节点→边拆批"约束同时可放松。

### 3. 局部 / 全局规则的定义与现状差距

设计文档（`docs/设计/05-规则分类.md`）：

- 硬性规则：编程语言/计算机定义，违反即崩溃。
- 自定义规则：产品设计者/程序员定义，违反不崩溃但体验差异。
  - 全局规则：一处定义，所有地方必须遵守（GraphData 元素）。
  - 局部规则：与特定操作/功能绑定（操作前提），分内联/非内联。

代码现状：

- 局部校验（Phase 1，`validate_operation_in_graph.ts`）：操作前提（ID 重复、节点存在、位置有效、折叠条件、边端点存在）——**全必选，无开关**（仅整体 `skipValidate` 重放开关）。
- 全局校验（Phase 3，`global_rules.ts`）：13 条规则，`rule_config.ts` 平铺开关表，全部 error 级。

**观察**：全局规则内部实际混合了不同性质的规则（见下）。

## 定义的更新方向（候选，不盖棺定论）

### 方向 A：EDGE_*_NOT_FOUND 迁入 Phase 3

- 边端点存在性 = 结构不变量（与 `DANGLING_REFERENCE` 同类），迁入全局规则表。
- 预期收益：逆元重放误报源消失 → `skipValidate` 退役或收窄；正向 compose 拆批约束放松；重放经受完整校验。
- **待验证**：
  - Phase 1 剩余校验（ID 重复、节点存在、位置有效、折叠条件）在逆元重放下是否全部自然通过（受控实验：skipValidate=false 下 undo/redo 全通过）。
  - execute 层对非法输入的健壮性（`executeAddEdge` 已验证不崩溃——degree+1 仅作用于存在的节点；其余操作需逐一确认）。

### 方向 B：全局规则按性质三分（结构 / 语义 / 体验）

- 结构约束：违反 = 数据不一致/无法解释 → **必选**（不可配置）。
- 语义约束：数据能表达但违反产品概念模型 → **必选**（不可配置）。
- 体验约束：数据合法仅体验/性能差异 → **可选**（可配置，如按图存储的开关表）。
- 局部规则（Phase 1 操作前提）观察为天然必选——是否永远如此待讨论。

### 方向 C：错误级别区分

- 现状全部 error。候选：结构错误 = error（数据损坏级）；体验约束 = warning（提示级）。
- 衔接前端错误呈现（数据损坏走开发者通道 / 体验提示走 NotificationPanel）。

### 方向 D：rule_config 开关表分层

- 现状平铺开关表。候选：体验约束可开关（按图存储，跟随根图谱持久化）；结构/语义约束锁死或不出现在配置面。

## 开放问题（不盖棺定论）

1. **语义约束的归属**：能否关闭？归"结构"还是独立一类？（有向环、虚/启发节点边类型是数据可表达但产品不允许的中间带）
2. **三分边界**：是否有规则同时跨越两类？（如 `VIRTUAL_NODE_TOO_MANY_VIRTUAL_NEIGHBORS` 是视觉体验还是语义限制？）
3. **局部规则是否永远必选**：操作前提是否存在"可配置"需求？（当前观察：全部必选）
4. **skipValidate 的去留**：方向 A 验证通过后，undo/redo 是否可改为完整校验（去掉 skipValidate），保留为防御还是彻底移除？
