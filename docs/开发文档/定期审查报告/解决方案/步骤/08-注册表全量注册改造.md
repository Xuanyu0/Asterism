# 08-注册表全量注册改造

---

## 背景与动机（承接 06）

06 完成后，注册表是**惰性累积式**：`restoreLastRootTree` 启动时只加载 `lastActiveRootId` 的根图树（根图 + 子图），`loadGraphToView` 导航时 `registerGraph` 累积加入。注册表 = 已访问图的集合。

**核心矛盾**：跨图操作（`makeLookup`）只能查到已加载的图——未加载的图（无论同树还是异树）操作必然失败（`BATCH_GRAPH_NOT_FOUND` 拦截）。"前端确保操作对象在注册表"的机制依赖"操作只能作用于已加载的图"，语义受限。

**架构判断**：注册表是内存缓存，持久化是权威存储。全量注册 = 启动时把所有持久化图加载进注册表，使注册表覆盖全部图，跨图操作无需先加载。

### 架构对比

```
当前（惰性累积式）：
restoreLastRootTree（只加载当前根图树）
  → loadGraphToView（导航时 registerGraph 累积）
  → 注册表 = 已访问图的集合（makeLookup 受限，未加载图操作失败）

目标（全量式）：
restoreLastRootTree 改造（加载全部持久化图）
  → 注册表 = 全部图（makeLookup 全量可查，跨图操作无需先加载）
  → loadGraphToView 仅切换视图（图已在注册表，无需注册）
```

### 代价评估（已确认可接受）

| 维度 | 代价 | 结论 |
|---|---|---|
| 内存 | 10000 节点 ≈ 10-30MB | 可接受 |
| 启动加载 | 100 次读取 + parse ≈ 100-300ms | 可接受（一次性） |
| 每次操作 Map 重建 | 浅复制 O(图数量)，微秒级 | 可忽略 |
| localStorage 容量 | 100 张图可能超 5MB | **本步骤不管**（MVP 阶段，后续 IndexedDB 迁移处理） |

## 1. restoreLastRootTree 改造为全量加载 ✅

### 目标

启动时全量加载所有持久化图进注册表，替代"只加载当前根图树"。`lastActiveRootId` 语义收窄为"恢复上次视图"（仅用于初始 `graphViewId`），不再决定注册表内容。

### 1.1. 全量加载逻辑

**子目标**：
  * `registerAllGraphs` 只做全量注册（返回 void，纯副作用）：遍历 `listSavedGraphIds`，逐图 `loadGraph` 注册进注册表（corrupted 入开发者通道，missing 跳过）
  * 不再按 `isInRootTree` 过滤——全部图（所有根图树）都注册

### 1.2. 重新语义化命名与职责拆分

**子目标**：
  * `restoreLastRootTree` 语义已变（从"恢复上次工作根图树"→"全量加载注册表"），重新命名
  * 新命名：`registerAllGraphs`（全量注册全部图，只做注册）
  * 原"返回上次视图根图 ID"逻辑（L93-107）抽成独立函数 `restoreLastActiveRootId`（恢复上次视图根图 ID，含 kind 非 root / 不在注册表验证 + 清理）
  * `ensureWorkspaceRoot` 不再做注册（无副作用）：调用 `restoreLastActiveRootId` 恢复上次视图根图，无则写死创建兜底根图（无外部参数）
  * `Graph.vue` 负责时序性编排：`registerAllGraphs()` → `ensureWorkspaceRoot()` → `loadGraphToView(rootId)`

难度：
* 不确定度：低（逻辑改造明确，职责拆分清晰）
* 算法复杂度：无
* 工作量：小

### 影响范围

```
frontend/src/graph/use-case/useLifecycle.ts — restoreLastRootTree 改造 + 重命名
frontend/src/views/Graph.vue                — 启动引导消费方适配
前端测试（useLifecycle.test 等）            — 适配全量加载语义
```

### 决策项

**已确定决策**：
* 全量加载：启动时加载全部持久化图进注册表，不再按根图树过滤。
* `restoreLastRootTree` 重命名为 `registerAllGraphs`（只做全量注册，返回 void）。
* 原"返回上次视图根图 ID"逻辑抽成独立函数 `restoreLastActiveRootId`。
* `ensureWorkspaceRoot` 不再做注册（无副作用），写死保底逻辑（无外部参数）。
* `Graph.vue` 负责时序性编排（注册 → 恢复视图 → 加载）。
* `lastActiveRootId` 语义收窄为"恢复上次视图"（初始 `graphViewId`），不再决定注册表内容。
* localStorage 容量问题本步骤不管（MVP 阶段，后续 IndexedDB 迁移处理）。

## 2. loadGraphToView 移除 registerGraph ✅

### 目标

全量注册后，切换图时目标图已在注册表，`loadGraphToView` 不再需要 `registerGraph`——仅更新 `graphViewId` 切换视图。

### 2.1. 移除注册调用

**子目标**：
  * 移除 `loadGraphToView` 中的 `registerGraph(store.graphRegistry, loadedResult.graph)`
  * 保留"先注册后设 id"的派生 getter 不变量——全量注册后图已在注册表，`graphViewId` 赋值即可
  * 保留串行五步结构（加载 → 验证 → 换显示 → 根图切换判断 → 更新运行时状态），仅去掉注册步骤

难度：
* 不确定度：低（移除明确）
* 算法复杂度：无
* 工作量：小

### 影响范围

```
frontend/src/graph/graph_store.ts — loadGraphToView 移除 registerGraph
前端测试（graph_store.test 等）    — 适配（不再依赖 loadGraphToView 注册）
```

### 决策项

**已确定决策**：
* 移除 `loadGraphToView` 的 `registerGraph`——全量注册后图已在注册表，切换图仅更新 `graphViewId`。
