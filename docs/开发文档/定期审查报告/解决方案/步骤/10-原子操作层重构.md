## 背景与动机

### 1. delete_node 名不副实："原子"却复合

`executeDeleteNode`（execute_operation.ts）实际做四件事：

- 删除目标节点自身
- 级联删除关联边（source/target 涉及该节点的边）
- **级联删除指向它的引用节点**（`findReferenceNodesPointingTo`——知识节点被删的语义）
- degree 修正 + 折叠状态清理

其中"级联删引用节点"是**类型特定的语义**（只有知识节点被引用），写在通用原子操作里——新类型加入时要么加 `if (role === ...)` 特判（原子层膨胀），要么改设计。

### 2. 正逆不对称（本质，非实现缺陷）

```
add_node X：   局部操作——只影响 X（新对象没人引用它）
delete_node X：全局操作——必须清理所有依赖者（入度越大，清理越多）
```

数学上"删除是添加的逆"成立，但逆的复杂度由被删对象的**入度**决定——这是图结构的性质（数据库删行处理外键同理）。**不对称本身无法消除**，但"级联逻辑的放置层级"可以重构。

### 3. update_node 同样不干净

- **reference 穿透**：`executeUpdateNode` 内部已有"引用节点 label 同步到源节点"的类型特判（L282-291）
- **全量替换无字段保护**：`{ ...operation.node, updatedAt }`——`childGraphId` / `sourceGraphId` / `groupId` 等**结构字段**可被随手改坏（悬空引用/子图），当前仅靠调用方自觉

### 4. reversal.ts 是"构造器"而非"定义者"

- 现状：`createReversalForDeleteNode(graph, op)` ——输入"操作 + 操作前状态"，输出逆元序列（含级联镜像）
- 缺失：**类型级代数映射的定义**（`add_node → delete_node` 纯逆等）——逆元的"定义"与"构造"混在一起

### 5. 折叠状态 undo 不对称缺口（现有缺陷）

删除节点时 `executeDeleteNode` 清理折叠状态条目，但逆元**不恢复**——undo 后节点回来了、折叠关系丢了。已确认的现有缺口，不依赖任何未来特性。

### 6. 已发生的碰撞（最硬动机）

**`delete_abstract_node`（07.3）就是复合删除**——递归清空子图 + 注销，实现时已撞上原子层耦合（级联面、骨架构造、批内安全）。前端 delete 工具（07.5）还将继续撞（抽象/非抽象分发）。**复合删除不是假设，是正在发生的事。**

## 知识群背景（非 MVP，设计已定义）

来源：`docs/设计/02-核心功能.md`（Knowledge Group）。

- **是"节点的一种属性"**（`NodeBase.groupId` 字段已预留），非节点类型
- 空间组织关系：不改变知识结构/边/从属，区别于抽象节点
- 规则：一节点不能属于多个群；SubGroup 从属递归（"附庸的附庸"）
- **操作天然复合**：创建（N 节点打标）/ 删除（移除全部成员标记 + 解除从属）/ 移动（递归收集群树 → N 个 move_node）/ 链接
- 撞点：
  - **update_node 字段保护**：加入/移出群 = "只改 groupId"的部分更新——现状全量替换靠调用方自觉
  - 复合操作编排 + 集合级逆元快照（群移动的逆元需要移动前群成员集合）

## 中继节点背景（非 MVP，**用户明确多半会做**）

用户设想的 2×2 语义矩阵之外的新节点类型：

- **约束**：入度 ≥ 1 **且** 出度 ≥ 1（类型特定的结构不变量）
- **语义**：纯连接（汇聚/分散边关系、分支节点、流程步骤），无知识语义

撞点（比 GroupNode 更进一步的两个新维度）：

1. **合法性依赖操作组合**：`add_node` 无法独立创建合法中继节点（加出来度=0 违反定义）——必须 compose 级"节点 + 入边 + 出边"组合。打破"原子操作 = 单操作合法变换"假设
2. **delete_edge 制造非法中继节点**：删掉唯一入/出边后度约束被破坏——需要"按类型限定"的不变量规则
3. **Phase 3 规则需要类型维度**：现有 13 条全局规则全图适用；中继节点度约束是"仅对该类型"的结构必选规则
4. 删除可能涉及**重路由**（A→R→B 变 A→B 直连）——复合操作 + 复合逆元

## 现状梳理：原子操作层耦合点清单

| 位置 | 耦合内容 |
|------|---------|
| `executeDeleteNode` | 级联引用节点（knowledge 语义）+ 级联边 + degree + 折叠清理 |
| `executeUpdateNode` | reference 穿透 + 全量替换无字段保护 |
| `createReversalForDeleteNode` | 级联面镜像（复杂、类型感知） |
| `reversal.ts` | 构造逆元（操作+状态→逆序列），无类型级逆元定义 |
| Phase 3 规则 | 全图适用，无"按类型限定"能力 |

## 更新方向（候选，不盖棺定论）

### 方向 A：删除原子化

- `delete_node` 纯化 = `add_node` 的**纯逆元**（只移除节点自身）
- 级联清理移出为"图一致性收尾"（独立步骤 / Phase 3 规则 / compose 封装）
- 收益：正逆行为对称、类型解耦、`createReversalForDeleteNode` 退化（仅节点快照）
- 支点问题：**"原子操作执行后图必须合法"归 execute 层还是批/收尾层？**

### 方向 B：update_node 演进

- 字段子集更新（`{ nodeId, changes }`）替代全量替换
- 结构字段保护名单：`childGraphId` / `sourceGraphId` / `groupId` 等禁止通过通用更新修改
- 收益：知识群"只改 groupId"的部分更新天然支持；结构字段不会被误改

### 方向 C：复合操作化

- 删除工具（抽象/非抽象）统一走 compose 级复合删除
- 知识群操作、中继节点操作全部 compose 级编排
- 原子操作只服务：单对象纯操作 + 逆元重放

### 方向 D：reversal 定义与构造分离

- 类型级逆元映射表（`add_node ↔ delete_node` 纯逆定义）
- 构造器（从操作前状态捕获快照）与定义分离

### 方向 E：Phase 3 类型分派规则

- 结构必选不变量支持"按类型限定"（中继节点度约束等）
- 与 09 步骤（规则分类与校验体系）的"三分"衔接
