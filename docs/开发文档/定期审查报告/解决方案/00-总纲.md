# 总纲

## 背景

来源：`docs/开发文档/定期审查报告/GE待处理问题.md`（oracle 架构评审）。核心改造方向：

1. **派生值分离**（核心试验）：`form` / `abstractionLevel` 从存储字段改为运行时派生值，确立"持久化数据与派生值分离"的类型框架。
2. **shallowRef 改造**（顺手）：根治 Vue 代理痛点（toRaw ×2、JSON 序列化克隆 ×1），GraphData 永不进深代理。
3. **抽象等级消费**（顺手）：落地设计文档构想（`docs/设计/01-核心定义.md:118` 抽象节点正多边形，边数 = 抽象等级 + 2）。

## 架构方向

```
GE 端（纯函数，不持有状态）
├── 类型契约：graph_data.ts（移除 form/abstractionLevel，定义派生函数签名）
├── 派生实现：core/derive.ts（deriveNodeForm / deriveAbstractionLevel）
└── 消费方迁移：deconstruct / induce / internalize / diverge

前端（Runtime + 渲染层）
├── 状态持有：graph_store.ts（graphView / graphRegistry → shallowRef）
├── workaround 消除：default_tool / preview_engine
├── 消费方迁移：class_mapper（form → deriveNodeForm）
├── 抽象等级消费：class_mapper + cy_style（多边形样式）
└── 验证：全量测试 + 旧数据兼容 + 框架评估
```

## 工作流约定

- 一次工作流推进一个步骤文档涉及的内容。
- 步骤 01 已完成（GE 端派生值分离）。
- 步骤 02 已完成（graph_store 单例化改造：去死 ref → 移除 Pinia → 单例化）。子步骤 2.3（语义命名）并入步骤 05；图级信号迁移评估由步骤 06 接管。
- 步骤 03 为原步骤 02 子步骤 4 拆分（前端消费方迁移 + 抽象等级消费）。
- 步骤 04 为验证与收尾（全量测试 + 旧数据兼容 + 框架评估）。
- 步骤 05 承接 02.3：graph_store 核心化（四入口收窄）+ 生命周期适配层下沉（restoreLastRootTree / ensureWorkspaceRoot）+ 创建与校验清理下沉。
- 步骤 06 承接 02 子步骤 3：GE 端新增多图管理层（`applyBatches`，多图状态转换：图内委托 applyBatch + 图级兑现 + 逆元构造）+ 前端 graph_store 对接（注册表引用替换 + graphViewId）；行为等价中间态，返回暂时保留 graphSignals。
- 步骤 07 承接 06：操作日志系统改造（graphSignals 消失、图级逆元空图增删、undo/redo 对称、日志命名 OperationLogTree / CommitLog / BatchLog）。
- 步骤 08 承接 06：注册表全量注册改造（registerAllGraphs 全量加载 + restoreLastActiveRootId 恢复视图 + ensureWorkspaceRoot 不注册写死保底 + Graph.vue 时序编排 + loadGraphToView 移除注册）。
- 步骤 01 顺利完成后，评估是否变更 CLAUDE.md 的广义 GraphData 定义（"状态层 + 派生层"两段式）。
- 步骤 09 待规划：规则分类与校验体系重构。背景源自 07.4 的 skipValidate 审查（重放误报、EDGE_*_NOT_FOUND 归属）；候选方向（不盖棺定论）：EDGE_*_NOT_FOUND 迁入 Phase 3、全局规则结构/语义/体验三分、错误级别区分、rule_config 开关表分层。独立于 07，不阻塞 07.5 与 07 合入。
