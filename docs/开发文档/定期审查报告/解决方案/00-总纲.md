# 总纲

## 背景

来源：`docs/开发文档/定期审查报告/GE待处理问题.md`（oracle 架构评审）。核心改造方向：

1. **派生值分离**（核心试验）：`form` / `abstractionLevel` 从存储字段改为运行时派生值，确立"持久化数据与派生值分离"的类型框架。
2. **shallowRef 改造**（顺手）：根治 Vue 代理痛点（toRaw ×2、JSON 序列化克隆 ×1），GraphData 永不进深代理。
3. **抽象等级消费**（顺手）：落地设计文档构想（`docs/设计/01-核心定义.md:118` 抽象节点正多边形，边数 = 抽象等级 + 2）。

## 架构方向

```
GE 端（纯函数，不持有状态）
├── 类型契约：graph_data.ts（移除 form/abstractionLevel，定义派生函数签名）
├── 派生实现：core/derive.ts（deriveNodeForm / deriveAbstractionLevel）
└── 消费方迁移：deconstruct / induce / internalize / diverge

前端（Runtime + 渲染层）
├── 状态持有：graph_store.ts（graphView / graphRegistry → shallowRef）
├── workaround 消除：default_tool / preview_engine
├── 消费方迁移：class_mapper（form → deriveNodeForm）
├── 抽象等级消费：class_mapper + cy_style（多边形样式）
└── 验证：全量测试 + 旧数据兼容 + 框架评估
```
