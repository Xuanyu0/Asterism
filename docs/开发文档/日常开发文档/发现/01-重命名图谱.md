#### U-1：renameRootGraph 返回类型设计（RenameRootResult 判别联合）

* 状态：✅ 已确认（已改为统一 ValidationResult 通道）
* 问题：契约原文"返回提交的校验结果（与 createRootGraph 返回风格一致）"语义含糊——createRootGraph 返回 GraphId 而非校验结果。实现按"防御失败须可区分 + 成功携带校验结果"设计了判别联合 `{ ok: true, validation } | { ok: false, reason: 'not_found' | 'empty_title' | 'duplicate_title' | 'commit_rejected' }`。

* 现状：用户确认方案 A（校验下沉 GE）后，`RenameRootResult` 已移除——`renameRootGraph` 返回 `ValidationResult`；目标不存在 → 前端构造 `TARGET_NOT_FOUND` issue 写入 `lastValidationResult`；空名/重名由引擎 `EMPTY_TITLE` / `TITLE_DUPLICATE` 返回。UI 按 issue.code 映射提示（fix-6）。

#### U-2：createRootGraph 重名拒绝的失败信号

* 状态：✅ 已确认（GE add_graph 校验兜底 + UI 预检保留）
* 问题：契约要求 createRootGraph "其余行为保持现状"（返回 GraphId，无失败通道），但重名拒绝必须被 UI 感知。实现选择：重名时不创建、返回请求 ID（与既有幂等 early-return 同构），并在 NavigationPanel 创建表单加 UI 先行重名预检。
* 影响：创建表单的重名预检不在原 2.1–2.3 子任务清单内，是防止"切换到不存在图"静默失败的必需集成。
* 现状：校验下沉 GE 后 `createRootGraph` 移除前端重名 guard（GE add_graph 校验兜底，重名整批丢弃不落库）；NavigationPanel 新建表单保留 trim 对齐预检做即时反馈（fix-6）。

#### U-3：title 校验下沉 GE（方案 A 决策记录）

* 状态：✅ 已确认
* 问题：校验结果格式与风格不统一——引擎链路透传 `ValidationResult`，renameRootGraph 自造 `RenameRootResult` 第二套格式；且空名/重名校验散落前端。
* 现状（用户确认方案 A）：
  - 引擎 `validate_graph_operation` 新增 `EMPTY_TITLE`（trim 后空）与 `TITLE_DUPLICATE`（root 图间 title 唯一，trim 比较、排除自身；子图不校验），`update_graph` 与 `add_graph` 均生效（fix-5）。
  - 前端统一 `ValidationResult` 通道，用例层防御 issue（`TARGET_NOT_FOUND`）与引擎 issue 同写 `lastValidationResult`（fix-6）。
  - CLAUDE.md「早期开发策略」补充错误消息模式提示（用户许可）。
