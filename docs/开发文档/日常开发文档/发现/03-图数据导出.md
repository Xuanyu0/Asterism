### BUG

#### B-1：`revokeObjectURL` 同步 revoke —— 可能「静默没下载，却报 `ok: true`」

* 状态：✅ **已修**（编排者直接执行 —— 原因见文末「执行说明」）
* 位置：`frontend/src/graph/use-case/export_graphs.ts:100-107`（`anchor.click()` 后在 `finally` 里**同步** revoke）
* 现象：下载管线是**异步取 Blob** 的。同步 revoke 会让部分浏览器**取消下载**，且**不抛任何错误**。文献证据：Firefox bug 1282407（紧跟 `click()` 的 `revokeObjectURL` 导致下载不出现，改为 zero-timeout 即恢复）+ Safari/Firefox 多起同类报告。
* **后果链与本批次最痛的点重合**：`exportGraphTree` 返回 `{ ok: true }` → UI 无成功反馈（见 `U-2`）→ **用户以为导出成功，实际没有文件**。
* 修复：`setTimeout(() => URL.revokeObjectURL(url), 0)`（仍满足契约「下载后必须 revoke」）。
* 同处一并修（低成本、同风险面）：
  * **`<a>` 未挂载 DOM 即 `click()`** —— 现代浏览器多数可用，但成熟做法（FileSaver 等）是「挂载 → 点击 → 移除」。
  * **`exportGraphTree` 的 TSDoc 声称「不抛异常」，但下载函数无 try/catch** —— `new Blob` / `createObjectURL` / `click()` 任一抛出会穿到 `NavigationPanel.vue:225` 的 click handler（无 try/catch）→ Vue 错误处理 + **用户零反馈**。应包一层归为 `unknown`，或把 TSDoc 改为如实。
> 理由：这条不是"体验问题"，是**功能可能根本不生效且无任何信号**。
