## 发现者: @fixer（fix-2 · 前端 lane）

### BUG

#### B-1：dev 种子的子图**从未被创建**（静默失败，非本步引入）

* 状态：✅ **已修**（fix-2 同批修正）
* 位置：`frontend/src/dev/bootstrap.ts` 中 `sub-golden` / `sub-silver` 的创建
* 现象：旧写法用 `commitToCurrentGraph([{ type: 'add_graph', graph: { ...nodes, edges } }])`（**带内容**的 `add_graph`）。而 `splitOperationsIntoBatches`（`graph/utils/operation_batches.ts`）只按「图级 / 图内」拆批，**不会**把它拆成「空 `add_graph` + `add_node`」→ 引擎 `validateGraphOperation` 以 `ADD_GRAPH_NOT_EMPTY` 拒绝 → **整批丢弃**；而 bootstrap **忽略提交返回值** → 子图**从未落盘**，`node-g3.childGraphId` 一直悬空。
* 证据：fix-2 实测旧 bootstrap 只落盘 `graph-golden` / `graph-silver` 两个根图；编排者已复核 `splitOperationsIntoBatches` 的语义佐证该结论成立。
* 修正：改用**真正的用户路径**（与 `induce` 一致）：空 `add_graph` → `loadGraphToView` → 图内批填充。
* 意义：这是「**不准任何形式的静默退出**」在 dev 工具里的漏网之鱼 —— 提交返回值被丢弃 + 无任何信号。同类风险：`bootstrap.ts` 内其他 `commitToCurrentGraph` 调用**也全部忽略返回值**（未修，见 I-1）。
