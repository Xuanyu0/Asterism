# 05-禁止跨树引用 ⏳

---

## 1. 跨树引用禁止 ⏳

### 目标

让「一棵根图谱树」成为**引用闭合**的单元：

> 任意图 G 的节点，其 `sourceGraphId`（引用节点）与 `childGraphId`（抽象节点）必须指向**与 G 同属一棵根图谱树**的图。

同树内跨子图谱引用**继续允许**（这是「发散」的核心设计功能）；跨根图谱树**禁止**。

**完成后系统的状态**：

- 引擎新增**注册表级（森林级）不变量**：一次提交若引入跨树引用 → **整批丢弃** + `ValidationResult`（经 `lastValidationResult` 可见，不静默）
- `diverge` 的 peer 搜索域 = **本图谱树** → 正常路径不再产生跨树引用；错误消息如实改为「目标节点不在本图谱树内」
- dev 种子的金/银跨树引用已修正（银图挂进金图树内）
- **步骤 03 的 `U-3` 消解**：「一棵树 = 一份自洽快照」成立，**导出格式零改动**

**为什么值得单独一步**：跨树引用破坏的不只是导出（那只是症状），而是「**树 = 一个自洽的编辑历史**」这条不变式 —— `graph_store.ts:180-189` 把根图定义为操作日志与 undo/redo 的边界（「根图谱 = 日志」）。一次操作横跨两棵树，其日志与撤销都会越界。

### 1.1. 引擎：森林级不变量入口

**子目标**：

- 新增**注册表级不变量**执行入口，与单图不变量（`checkInvariants(graph)`）同构：规则列表 + 单一执行循环，作用域由 `GraphData` 换成 `GraphRegistry`。
- 首条（也是本轮唯一一条）森林级规则：**引用目标必须与源图同树**（root = 沿 `parentGraphId` 回溯的最顶祖先）。
- 运行时机：`applyBatches` 循环结束后、返回前（**后置状态不变量**，与 Phase 3 structural 同性质）；失败即整批丢弃。
- **校验作用域 = 本批涉及的图**（性能；见已确定决策）。判定需要树外数据（目标在其他树 / 目标根本不存在），故归**森林级**。
- 粒度约定：**森林级**（判定需要树外数据）vs **树级**（只依赖单棵树内部数据）。本轮**不建空的树级 bucket** —— 不为不存在的实现建抽象。

难度：

* 不确定度：低（形状已定，照单图不变量同构）
* 算法实现复杂度：低（O(批内图 × 祖先链深度)）
* 工作量：中

### 1.2. 前端：`diverge` 产生点收紧

**子目标**：

- `operation_controller.diverge` 传给引擎的 `graphIds` 从「全量 registry」改为**本图谱树成员** —— 引擎的 `findPeerGraph` 只在传入集合内找 peer，收窄后跨树引用在正常路径上不可产生。
- 引擎 `DIVERGE_PEER_NODE_NOT_FOUND` 的消息语义修正：现文案称「在所有已注册图谱中均不存在」，收窄后与事实不符，应改为「目标节点不在本图谱树内」。
- ⚠️ 事实：`diverge` **当前无 UI 入口**（`feature-tools/` 中只有类型联合成员，无 handler 接线），因此本条是**接线前的预防**，不是修线上 BUG。

难度：

* 不确定度：低
* 算法实现复杂度：低
* 工作量：低

### 1.3. dev 种子修正

**子目标**：

- `dev/bootstrap.ts` 的金牌/银牌两图跨树引用修正为**同树跨子图**（银图挂进金图树内），保留「跨子图引用」这一核心功能的种子演示。
- 涉及：金图 `node-g5 → graph-silver`、银图 `sv-node-4 → graph-golden` 两条引用节点，以及银图作为根图的既有形态（挂入后不再是独立根图）。

难度：

* 不确定度：低
* 算法实现复杂度：低
* 工作量：低

### 决策项

**已确定决策**：

- 不变式本身：允许同树内跨子图引用（核心功能），禁止跨根图谱树。
- **硬守卫落引擎**：注册表级、后置；与 `DANGLING_REFERENCE`（同图引用完整性）同族同层。
- **校验作用域 = 本批涉及的图**（性能）；已知代价：未被触碰的坏图不会被发现。
- 粒度判据：**森林级 = 判定需要树外数据**；本次归森林级。
- 后置不变量对 `recordLog: false`（undo/redo 重放）同样生效。
- **dev 种子**：把银图挂进金图树内（成为同树跨子图），不删引用。
- **森林级不变量属硬规则**：按「硬 ⟺ 被消费者依赖」的判据，它被操作日志 / 撤销边界与导出自洽依赖，因此**不被任何旁路跳过**。
  （`skipValidate` 那条旁路本身的问题已移交**步骤 07**，见下。）

**待确定决策**：

> 无。
