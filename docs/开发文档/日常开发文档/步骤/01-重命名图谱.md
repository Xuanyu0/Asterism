# 01-重命名图谱

---

## 1. GE 端 update_graph 图级操作 ✅

### 目标

新增图级操作 `update_graph`，使"更新整张图谱"成为引擎一等公民：类型定义 → 批级契约 → 校验 → 兑现 → 逆元 → 导出，全链路补齐。操作语义参照 **update_node 的全量构造模式**——完整替换图对象（`{ ...op.graph, updatedAt }`），而非字段级增量。

`update_graph` 的通用性：本步骤以"重命名"为首个消费方（前端包装 `{ ...graph, title }`），但引擎层不感知"重命名"概念，未来任何"整图更新"（元信息变更等）均复用同一操作。

### 1.1. 类型与批级契约

**子目标**：

- `types/atomic_operations.ts`：新增 `UpdateGraphOperation { type: 'update_graph'; graph: GraphData }`，并入 `AtomicGraphOperation` 联合（与 add_graph / delete_graph 统一签名 `{ type, graph }`）。
- `core/apply_batches.ts` 批级 kind 契约判定（:94-103，当前硬编码 `add_graph` / `delete_graph`）：加入 `update_graph`，否则图级批会被 `BATCH_KIND_MISMATCH` 误拦。判定逻辑建议抽为文件内辅助函数（isGraphLevelType），消除三处硬编码重复。

- 不确定度：低（模式现成，仅扩展联合与判定）
- 算法复杂度：低
- 工作量：低

### 1.2. 校验

**子目标**：

- `core/validate_graph_operation.ts`：`validateGraphOperation` 增加 `update_graph` 分支——校验目标图存在（registry 命中）。
- 图内数据合法性（nodes / edges / cognitiveState 等）**引擎不校验**，由调用方保证——重命名场景前端从注册表复制当前图构造，数据天然合法；与 update_node"仅校验目标存在、内容不变量由全局规则兜底"对称。
- **title 唯一性（根图谱间不重名）与空名校验均由前端用例层承担**，引擎不感知该业务规则（详见子步骤 2）。

- 不确定度：低
- 算法复杂度：低
- 工作量：低

### 1.3. 兑现（全量替换）

**子目标**：

- `core/apply_batches.ts` `executeGraphOperation` switch 增加 `case 'update_graph'`：
  - 语义：**完整替换**——`next.set(id, { ...op.graph, updatedAt: executedAt })`（参照 update_node 的 `{ ...op.node, updatedAt }`）。
  - `createdAt` 保留：沿用 add_graph 的"携带值 ?? executedAt"兜底模式（前端从注册表复制时天然携带，兜底防构造方漏传）。
  - `updatedAt` 无条件写 `executedAt`（仿 update_node）。
- 兑现后同步 `latestGraphs`（与 add_graph 一致，保证同批后续操作基于操作后图数据）。

- 不确定度：低
- 算法复杂度：低
- 工作量：低

### 1.4. 逆元（执行前捕获，结构调整）

**子目标**：

- 现状：`createGraphReversal(op)` 只接收 op（:263），且调用点在 `executeGraphOperation` **之后**（:180 → :189）——update_graph 逆元需要**旧图全量**（含旧 title），执行后 registry 已被替换，旧值丢失。
- 调整（与图内批"执行前捕获操作前状态"对称，onBeforeEachOperation :146-150）：
  - `createGraphReversal` 签名扩展为 `(op, registryBefore: GraphRegistry)`。
  - 图级批循环内调用点**提前**：validate 通过 → 先构造逆元（捕获执行前旧图）→ 再 `executeGraphOperation`。
  - `update_graph` 分支：`registryBefore` 命中 → 逆元 = `{ type: 'update_graph', graph: 旧图全量 }`（undo 时全量回退）。
  - `add_graph` / `delete_graph` 分支不读 registry，行为完全不变。
- **逆元的真实用途**：更名进操作日志（recordLog: true，见子步骤 2 决策），undo 时执行逆元批 → title 回退；redo 时重放正向批 → title 重放。逆元构造是更名可回溯的必需支撑。

- 不确定度：中（唯一动到现有结构的位置，需保证 add/delete 逆元行为回归不变）
- 算法复杂度：低
- 工作量：低

### 1.5. 导出与测试

**子目标**：

- `types/index.ts`：导出 `UpdateGraphOperation` 类型（公开 API）。
- `tests/core/apply_batches.test.ts` 补充用例：
  - 兑现：target 命中 → title 替换 + updatedAt 写入；target 缺失 → 校验失败整批丢弃。
  - 逆元：undo 语义——逆元含旧 title，回放执行后 title 回退。
  - 批级契约：inGraph 批混入 `update_graph` → `BATCH_KIND_MISMATCH`；graphLevel 批混入图内操作同理。
  - 回归：add_graph / delete_graph 逆元行为不变（结构调整后）。

- 不确定度：低
- 算法复杂度：低
- 工作量：中

### 决策项

**已确定决策**：

- `update_graph` 采用 **update_node 式全量构造**：完整替换图对象（`{ ...op.graph, updatedAt: executedAt }`），非字段级增量（用户确认）。
- "重命名"是**前端包装**：前端构造全量新图 `{ ...graph, title }` 提交，引擎不感知重命名语义（用户确认）。
- 引擎校验仅"目标存在"；**空名 + 重名（根图谱间 title 唯一）拦截均在前端用例层**。
- 更名 **recordLog: true**（进操作日志——更名反映用户认知活动，可 undo/redo）；**逆元构造是 undo 的必需支撑**。
- 图级操作统一不进 replay.ts；undo 经 reversalBatches 捕获。
- 逆元"执行前捕获"原则：与图内批 onBeforeEachOperation 对称，是 update_graph 逆元成立的唯一路径。

## 2. 前端导航卡片接入 ✅

### 目标

导航卡片（NavigationPanel.vue 根图谱列表）获得"重命名图谱"能力：铅笔更名按钮（删除按钮左侧、视觉风格一致）+ 行内编辑（inline edit）+ 移除"当前"文字徽标；`useNavigation` 新增 `renameRootGraph` 用例经 `commitBatchToGraphs` 提交 `update_graph` 图级批。当前根图谱不可删除的两道防线原样保持；更名对当前根图谱允许。

### 2.1. 更名按钮与"当前"徽标调整

**子目标**：

- 行结构从 `[root-item + 删除]` 变为 `[root-item + 铅笔 + 删除]`；铅笔按钮图标用 `PencilIcon`（@heroicons/vue outline 24，与 TrashIcon 同源同风格）。
- 按钮样式复用 `.root-delete-btn` 模式：行悬浮时显现（opacity 过渡）、`size-3.5`、flex 布局。
- 移除 "当前" 文字徽标渲染（:134 `current-badge`）；**保留** `.root-item.current` 蓝色高亮（仍需视觉区分当前图，仅去文字冗余）。
- 可见性差异（有意设计）：删除按钮对当前根图不渲染（保持现状）；**更名按钮对当前根图也渲染**（更名允许当前根图，仅删除受限制）。

- 不确定度：低
- 算法复杂度：低
- 工作量：低

### 2.2. 行内编辑（inline edit）

**子目标**：

- 状态：`editingId: Ref<GraphId | null>` + `editTitle: Ref<string>`。
- 交互：点击铅笔 → 当前行的标题 span 切换为 `<input>`（预填当前标题、自动聚焦）→ Enter 或失焦确认、Esc 取消。
- 确认逻辑：trim 后**空名拦截**（不提交、保持编辑态或轻量提示）；**重名拦截**（根图谱列表中已有同名其他图谱 → 拒绝）；通过 → `renameRootGraph` → 成功则退出编辑并刷新列表（`listRootGraphInfos` 按标题排序 → 更名后列表自动重排生效）；失败（校验不通过）保持编辑态。
- 互斥：进入编辑态时清空删除 armed 态；点击删除时清空编辑态（同一行同一时刻只处于一种操作状态）。

- 不确定度：低（纯模板 + 局部状态，无数据流改动）
- 算法复杂度：低
- 工作量：中

### 2.3. renameRootGraph 用例与测试

**子目标**：

- `useNavigation.ts` 新增 `renameRootGraph(id, title)`：
  - 从 `graphStore.graphRegistry` 取当前图（**防御**：目标不存在时返回失败结果，不抛异常）。
  - **重名校验**：遍历根图谱列表（`listRootGraphInfos`），存在其他同名根图谱 → 返回失败（不提交）。
  - 构造全量新图 `{ ...graph, title }`，提交 `[{ kind: 'graphLevel', operations: [{ type: 'update_graph', graph }] }]`（**recordLog 默认 true** → 进操作日志），与 `createRootGraph` 同管道。
  - `updatedAt` 由引擎补写，前端不构造时间戳。
- **`createRootGraph` 同步接线**：提取重名校验为共享辅助函数（如 `assertRootTitleUnique(title, excludeId)`），创建路径同样调用（Q1 已确认）。
- `useNavigation.test.ts` 补充用例：提交构造正确性 / 目标不存在防御 / 重名拒绝（更名 + 创建）/ 更名成功后列表按新标题重排 / 空名拦截。

- 不确定度：低
- 算法复杂度：低
- 工作量：中

### 影响范围

```
frontend/src/
  ├── graph/use-case/useNavigation.ts          — renameRootGraph（图级 update_graph 批提交）
  ├── components/navigation-card/NavigationPanel.vue — 铅笔按钮 + inline edit + 移除"当前"徽标
  └── graph/use-case/useNavigation.test.ts      — 用例补充
```

### 决策项

**已确定决策**：

- 更名交互 = **行内编辑 inline edit**（用户确认）：点击铅笔 → 标题变输入框 → Enter / 失焦确认、Esc 取消。
- 更名按钮 = `PencilIcon`，位于删除按钮左侧，样式复用删除按钮模式（hover 显现、同尺寸）。
- "当前"文字徽标移除；`.root-item.current` 蓝色高亮保留。
- 更名对当前根图谱允许；删除按钮不渲染 + `requestDeleteRoot` 拦截两道防线保持。
- **空名 + 重名拦截于前端**（trim 后拒绝空名；**根图谱间 title 唯一**——否则导航卡片无法分辨不同图谱）；不限制子图重名（面包屑路径可区分）。
- **创建与更名均校验重名**（Q1 已确认：同名禁止理由对创建场景同样成立；`createRootGraph` 与 `renameRootGraph` 复用同一校验函数，消除"创建可重名、更名不可"的不一致）。
- **更名进操作日志**（recordLog 默认 true——更名反映用户认知活动）；undo/redo 经 update_graph 逆元回退 / 正向批重放；更名后列表按标题自动重排（接受该行为）。
