# 03-图数据导出

---

## 1. 导出图数据为文件（localStorage 的对外副本）⏳

### 目标

让用户能把**存在 localStorage 里的图数据导出成文件** —— 这是数据的第一份真实外部副本，同时为未来的 IndexedDB 导入**预先定死格式**。

**完成后系统的状态**：

- 导航面板底部有三个按钮的位置：**「导出」可用**、**「导入」灰色不可用（占位，零代码）**；原「笔记库 / 常识层 / 设置」三个 disabled 占位按钮**已删除**
- 点「导出」→ 弹出**置顶弹窗**，列出全部可导出的单位（**每棵图谱树一项**）→ 用户挑一项 → **下载一个 JSON 文件**
- **一次只导出一个文件**（用户重复操作导下一棵）—— 借此规避浏览器「连续多文件下载」的拦截
- 文件含该图谱树的**全部图**（根图 + 全部子图），**含格式版本号**，**不含视图状态**
- 删除任何图、导入、IndexedDB 相关代码**一律不写**

**格式定死（供未来的 IndexedDB 导入消费）**：

```text
{ format: 1, graphs: GraphData[] }
```

- `format` 为**单调递增的整数**版本号（本步骤为 `1`）。
- 未来加入操作日志时**追加可选字段**，不改变既有字段名与类型。
- **不含视图状态**（设备本地状态不该跟着走）。

**本步骤不做**：导入的真正实现、操作日志导出、IndexedDB、File System Access API、导出全部（一次一个文件）、按单张图导出。

### 1.1. 数据层：信封与导出负载（`persistence/`）

**子目标**：

- 新增 `persistence/coordination/export_graphs.ts`：定义信封类型 + 按 id 集合组装导出负载。
- 它**只产出数据对象**（不含文件、不含 DOM）—— 这样存储层不依赖 `Blob` / `URL`，可脱离浏览器测试。
- 图数据经 `categories/graph_data` 读出（**不绕过类别层**）；可复用在途的读入口。
- 命名诚实：本文件**只做导出**，不叫 `import_export`（项目规范不容忍名不副实）。

- 不确定度：低（读链路已在步骤 02 定型）
- 算法复杂度：低
- 工作量：低

### 1.2. 域层：子树遍历

**子目标**：

- 在 `graph/utils/graph_tree.ts` 补一个**向下**的遍历：给定根图 id，收集整棵树的图 id 集合（现有的是向上回溯的 `findParentGraph`）。
- **必须留在域层** —— `parentGraphId` 链构成森林是域语义；`persistence/` 不该编码它。
- 需要**环防御**（与既有回溯的 `visited` 集合同思路）。

- 不确定度：低（域层已有同类遍历可参照）
- 算法复杂度：低
- 工作量：低

### 1.3. 用例层：编排与文件下载

**子目标**：

- 新增 `graph/use-case/export_graphs.ts`：
  - 列出可导出的单位 —— 复用**既有**的 `listRootGraphInfos()`（`useNavigation`），**不新建读 API**
  - `exportGraphTree(rootId)` —— 遍历子树 → 取 ids → 调数据层组装 → 触发下载
- **文件 I/O 留在用例层**（命令外壳的活）：`Blob` + `URL.createObjectURL` + `<a download>`。
- **下载后必须 `revokeObjectURL`**（等同于手动释放，否则泄漏）。
- 文件名按根图标题，非法文件名字符做替换。

- 不确定度：中（首次在仓库引入文件下载）
- 算法复杂度：低
- 工作量：中

### 1.4. UI：入口按钮与置顶弹窗

**子目标**：

- `components/navigation-card/NavigationPanel.vue`：
  - **删除**「笔记库 / 常识层 / 设置」三个 disabled 占位按钮
  - 新增「导出」（可用）与「导入」（`disabled` + `title` 提示「后续阶段」，**零代码**）
- **新增导出选择弹窗**（新组件）：
  - 列出图谱树（数据源 = `listRootGraphInfos()`），每项可选中 → 触发该单位的导出并关闭
  - **层级置顶**：现有最高为 `GraphNavigationCard` / `GraphModeSelector` 的 `z-index: 999`、`NotificationPanel` 的 `998` → 弹窗必须 **> 999**
  - 无通用弹窗先例可复用（`GraphFloatingWindow.vue` 是节点编辑浮空窗）→ **属新建 UI**
- 导出失败反馈走**既有存储错误通道**（步骤 02 建的那条），不新开通道。

- 不确定度：中（新建弹窗组件 + 置顶层级）
- 算法复杂度：低
- 工作量：中

### 影响范围

**旧**：图数据只能经 localStorage 存活，**无任何外部副本**；导航面板底部是三个无功能的占位按钮；仓库内**不存在**任何文件下载代码。

```text
frontend/src/persistence/
  └── coordination/export_graphs.ts   ← 新增：信封类型 + 按 id 组装导出负载

frontend/src/graph/
  ├── utils/graph_tree.ts             ← 补「向下收集子树 id」（+ 环防御）
  └── use-case/export_graphs.ts       ← 新增：子树编排 + 文件下载

frontend/src/components/navigation-card/
  ├── NavigationPanel.vue             ← 删三个占位按钮；加「导出 / 导入」两钮
  └── <导出选择弹窗>.vue              ← 新增：置顶弹窗，列图谱树、选一个导出
```

### 决策项

**已确定决策**：

- **只实现导出**；「导入」按钮**存在但 disabled、零代码**。
- **删除**「笔记库 / 常识层 / 设置」三个占位按钮。
- **单位 = 每棵图谱树**（含全部子图）；**一次只导出一个文件**。
- **加格式版本号**：`{ format: 1, graphs: GraphData[] }`。
- **不含视图状态**。
- **文件 I/O = 普通下载**（`Blob` + `<a download>`），不用 File System Access API。
- **子树遍历放域层**，不进 `persistence/`。
- **弹窗数据源复用 `listRootGraphInfos()`**，不新建读 API。
- **弹窗层级 > 999**。

**待确定决策**：

> **Q1**：导出成功后是否给一次反馈？
>
> **建议**：**给**（经既有通知通道，一行「已导出 <标题>」），失败则走存储错误通道。
>
> **理由**：下载在部分浏览器里**无任何可见反馈**（尤其是下载栏收起时），用户会怀疑按钮没生效。

> **Q2**：弹窗里若**没有任何根图**，怎么表现？
>
> **建议**：弹窗内显示一行空态文案，同时「导出」按钮可保持可用（点开看到空态）——**不做额外禁用逻辑**。
>
> **理由**：避免为极端情形增加状态判断；空态文案已经说清了。

> **Q3**：导出文件名规则？
>
> **建议**：`asterism-<根图标题>.json`；标题中 `/ \ : * ? " < > |` 等非法字符替换为 `-`。
>
> **理由**：用户能在下载目录里认出是哪棵树。

> **Q4**：弹窗是**受控组件**（父组件管理显隐）还是自带显隐状态？
>
> **建议**：**受控**（父组件 `NavigationPanel` 持有 `visible`），与 `NotificationPanel` 的既有约定一致。
>
> **理由**：项目组件规则是「数据向下流、事件向上流」；弹窗自持显隐会与父组件的面板开合逻辑打架。
