## 当前状态

- 引擎的校验分两处、两个粒度：
  - `core/apply_batch.ts`（**单图**）：Phase 1 前提校验（`rules/preconditions/in_graph.ts`）+ Phase 3 不变量（`rules/invariants/check_invariants.ts`，内含硬性 `STRUCTURAL_RULES` 与可开关 `PREFERENCE_RULES`）。
  - `core/apply_batches.ts`（**多图**）：只有批级契约校验与图级操作前提校验（`rules/preconditions/graph_level.ts` 的 `validateGraphOperation(registry, op)`）。
  - **不存在任何注册表级不变量。**
- 既有唯一一条引用完整性规则是 `rules/invariants/structural.ts` 的 `validateReferenceNodeConsistency`（code `DANGLING_REFERENCE`），**只校验同图**（条件含 `node.sourceGraphId === graph.id`）→ 跨图 / 跨树引用**完全不被检测**。
- `GraphData` 的节点可携带 `sourceGraphId`（`ReferenceNodeData`，必填）与 `childGraphId`（抽象知识节点，可选），二者都可能指向 registry 中**另一棵树**的图。
- 生产者现状：`deconstruct` / `induce` 产生的引用**必然同树**；`diverge` 的 peer 搜索域由调用方传入（前端当前传全量 registry，由 05.2 收紧）；dev 种子当前**有意跨树**（由 05.2 修正）。
- `core/apply_batches.ts` 已有「任一校验失败 → 整批丢弃」的事务语义，统一经私有辅助 `aborted(registry, validation)` 返回；返回值为 `{ registry, validation, reversalBatches }`。

## 目标

在引擎内新增**注册表级（森林级）不变量**：一次 `applyBatches` 提交若引入跨树引用，**整批丢弃**并返回可判别的校验失败（前端经 `lastValidationResult` 可见，不静默）。

不变式：

> 对 registry 中任意图 G 及其任一节点 n：由 `n.sourceGraphId` / `n.childGraphId`（若有）解析出的目标图 T，必须与 G **同属一棵根图谱树**（root = 沿 `parentGraphId` 回溯至 `parentGraphId === undefined` 的最顶祖先）。

**粒度约定（必须体现在目录命名与文件头注释）**：

- **森林级** = 命题判定需要**树外数据**（目标在其他树 / 目标不在 registry）。
- **树级** = 只依赖单棵树内部数据即可判定。
- 本步骤只实现森林级这一条。

**同树内跨子图谱引用必须继续被允许**（这是「发散」的核心设计功能，不是要禁止的对象）。

## 具体子任务

### 1.1 注册表级不变量入口

- 新增**规则列表 + 单一执行循环**，与单图不变量（`rules/invariants/`：`STRUCTURAL_RULES` 规则列表 + `check_invariants.ts` 单一执行入口）**同构**，作用域由 `GraphData` 换成 `GraphRegistry`。
- 放在 `core/rules/` 下与既有 `invariants/`、`preconditions/` **并列的新目录**，目录名中性（不得暗示只有森林级），本次内含一条森林级规则文件 + 一个执行入口文件。
- **不得**建空的「树级」文件/目录占位 —— 不为不存在的实现建抽象。
- 规则函数签名接收 registry（与单图规则的 `check(graph)` 形状对应）。
- **不提供开关**：森林级不变量**恒跑**，不受 `skipValidate` 影响（与硬性 `STRUCTURAL_RULES` 的「缺席配置面」一致），且必须在文件头注释写明这一点。
- **不新增公开导出**（前端不消费；引擎测试走 `../src/...` 相对路径 import）。

### 1.2 校验作用域 = 本批涉及的图

作用域按批的类型推导，**只检查作用域内图的引用节点**：

- `inGraph` 批 → `batch.graph.id`
- `graphLevel` 批 → 每个操作的 `op.graph.id`
- 对作用域内每个图，检查其**全部**引用节点（`sourceGraphId` 与 `childGraphId` 两条路径都要覆盖）。

**理由必须写进注释**：作用域是本步的**性能取舍**；已知代价是「未被本批触碰的坏图不会被发现」，这是刻意接受的。

### 1.3 树归属的解析口径（必须在注释中明确）

- root(G) = 沿 `parentGraphId` 回溯至最顶祖先。
- **统一口径（只有一条）**：**只有当 G 与 T 两边的 root 都能解析出来、且相等，才算通过；只要有一边解析不出，就不判定（不报错）。**
- 该口径的理由必须写进注释：无法得出可靠结论时**不得误报**（误报会阻断合法写入）；代价是「真正指向森林之外的悬空引用」本步不覆盖 —— 记为**已知限制**，交由后续步骤（结构完整性成为不变量后该情形才可判定）。

### 1.4 接入 `apply_batches.ts`

- 位置：批循环**结束后、返回前**（**后置状态不变量**，与 Phase 3 同性质）。
- 失败 → 复用既有 `aborted(registry, validation)`（整批丢弃、注册表不变、逆元清空）。
- 新 issue 必须**可判别且指明肇事对象**：包含源图 id、肇事节点 id、以及目标图 id（或「解析不出」的事实）。
- issue 的 `targetType` / `targetId` 填**源图**（口径自洽即可，需在注释说明）。

### 1.5 `diverge` 的 peer 未找到文案

- `compose/cognitive/diverge.ts` 中 `DIVERGE_PEER_NODE_NOT_FOUND` 的现文案称「节点在所有已注册图谱中均不存在」—— 在 05.2 把 peer 域收窄为**本图谱树**后，该表述与事实不符。
- 改为「目标节点不在本图谱树内」；同步修正该错误码相关注释与 TSDoc。
- **只改文案与注释，不改判定逻辑、不改错误码本身。**

### 1.6 既有测试夹具修正

- 引擎测试夹具中存在反映「跨图引用可任意跨树」这一**已被推翻**假设的数据，需按新不变式修正：**把相关图放进同一棵树**（补 `parentGraphId` / 建共同根图），而不是删掉引用。
- 已知可疑位置：`tests/test_case_factory.ts` 中多处 `sourceGraphId` 指向 `graph-parent` / `graph-other` / `graph-golden` 等外部图；`tests/compose/cognitive/diverge.test.ts` 的跨图 Case。
- **修正必须保持测试原意**（引用照旧存在、照旧跨图，只是现在同树）。
- **严禁**为通过测试而放宽规则本体、删测试、或让规则可跳过。
