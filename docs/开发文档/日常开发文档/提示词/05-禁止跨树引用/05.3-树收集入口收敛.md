## 当前状态

`frontend/src/graph/utils/graph_tree.ts` 现在有 3 个公开函数 + 1 个私有核心：

| 函数 | 内容 | 消费者 |
| --- | --- | --- |
| `isInGraphTree(graph, rootId)` | 沿 `parentGraphId` **向上**回溯，祖先从**持久化**惰性加载 | `useNavigation.deleteGraphTree`（**本次不动**） |
| `collectGraphTreeIds(rootId)` | **持久化版**向下收集：`listGraphIds` + 逐图 `loadGraph` + 「任一图读不到 → 整体失败」策略 | `graph/use-case/export_graphs.ts` |
| `collectRegistryGraphTreeIds(rootId, registry)` | **注册表版**向下收集：`registry.values()` | `ui/operation_controller.ts`（diverge peer 域） |
| `collectDescendantIds(rootId, graphs)`（私有） | 纯算法：建 `parentGraphId → 子图` 索引 + BFS；入参为结构化类型 `Iterable<{ id; parentGraphId? }>` | 上面两个 collect 共用 |

**问题的实质**：两个 `collect*` 里**没有任何一行是独立于消费者的判断** —— 它们的内容就是「数据源适配 + 失败策略」，而这两样都由消费者决定。真正通用的只有 `collectDescendantIds`。更要紧的是：`graph_tree.ts` 里那段「任一图读不到 → 整体失败」的论证，**依据是 `export_graphs.ts` 的数据层不变式** —— 通用工具替消费者承载了策略。

## 目标

- 仓库里**只保留** `collectDescendantIds` 这一个「收集树成员」的能力，且它是**纯函数**（不碰 I/O、无失败通道）。
- 两个消费者**各自负责自己的数据源与失败策略**，`collectRegistryGraphTreeIds` / `collectGraphTreeIds` 两个名字**消失**。
- 导出侧的失败语义与行为**完全不变**（`missing → unknown`、`unavailable → unavailable`、任一图损坏 → `unknown`）。

## 具体子任务

### 1.1 `collectDescendantIds` 升为公开工具

- 从 `graph_tree.ts` **导出**（两个消费者分处不同文件，必须公开）。
- 保持**行为不变**，包括现有语义：`rootId` 不在传入集合中时返回 `[rootId]`（**本轮不改**这条语义）。
- 保持入参为结构化类型，不引入 `GraphData` 依赖。
- 补 TSDoc（该函数会跨文件被调，属对外公开函数）。

### 1.2 删除两个 collect 入口

- 从 `graph_tree.ts` **删除** `collectRegistryGraphTreeIds` 与 `collectGraphTreeIds`。
- 同步改写 `graph_tree.ts` 的文件头注释 —— 现文中「树成员收集的持久化版与注册表版共用同一收集核心」已不成立。

### 1.3 导出侧就地吸收（`graph/use-case/export_graphs.ts`）

- 把原 `collectGraphTreeIds` 的**数据源枚举 + 逐图读取 + 失败短路**逻辑**搬进**导出用例，就地调 `collectDescendantIds(rootId, graphs)`。
- **论证注释必须随代码一起搬**：原「任一图读不到 → 整体失败／不静默跳过」那段论证（它引用的正是本文件头部的数据层不变式）不得留在 `graph_tree.ts`，也不得丢失。
- **可简化点（以实测为准）**：`exportGraphTree` 现已先 `loadGraph(rootId)` 兜住「根图缺失 / 损坏」，因此原「`listGraphIds()` 结果不含 rootId → missing」的检查可能是**冗余**的（读得到根图 ⟹ 它就在枚举结果里）。若确认冗余就删掉，并在返回中说明；若你判断不能删，保留并说明理由。
- 失败归因仍走既有 `toExportFailure`，`ExportResult` 的联合类型**不得改动**。

### 1.4 diverge 调用侧就地调用（`ui/operation_controller.ts`）

- 把 `collectRegistryGraphTreeIds(rootId, graphStore.graphRegistry)` 换成对 `collectDescendantIds` 的直接调用（数据源 = `graphStore.graphRegistry.values()`）。
- 更新该处 `@remarks`（现文中提到「树成员收集」的旧名），保持「peer 域 = 本图谱树、纯内存、无 I/O 失败路径」的表述。
- **不得**改动 peer 域的口径（仍传本图谱树成员），**不得**引入 `packages/graph-engine/**` 的改动。

### 1.5 测试随能力迁移

- `graph_tree.test.ts` 中针对 `collectRegistryGraphTreeIds` / `collectGraphTreeIds` 的用例按新形态重组：
  - 遍历语义（BFS 层序、环防御、`rootId` 不在集合时的返回）→ 归 `collectDescendantIds`；
  - **数据源与失败语义**（`missing` / `unavailable` / 任一图 `corrupted` → 导出失败）→ 迁到**导出用例的测试**（`graph/use-case/export_graphs.test.ts` 已存在）；
  - 「注册表版与持久化版结论一致」这种**双入口对照**用例已无对象，删除并说明。
- **不得**为了好看而削减覆盖：迁移后 `collectDescendantIds` 的遍历语义与导出侧的三种失败归因都必须**仍被断言**。
- `dev/bootstrap.test.ts` 中对 `isInGraphTree` 的用法**保持不动**。
