# 02.1 持久化层抽取与图数据迁移 — 提示词

## 当前状态

- `frontend/src/graph/graph_persistence.ts`（约 220 行）**一个文件承担三类职责**：图数据存储（`saveGraph` / `loadGraph` / `deleteGraph` / `listSavedGraphIds`）、视图状态存储（`saveLastActiveRootId` / `loadLastActiveRootId` / `clearLastActiveRootId`）、以及一个**域查询**（`listRootGraphIds` —— 它反序列化全库图来读 `kind`）。
- 全部落 localStorage，**写入失败完全静默**：`saveGraph` 是裸 `localStorage.setItem`，既不 try/catch 也不返回信号，签名是 `void`。
- `graph_store.ts` 的 `commitBatchToGraphs` **先替换内存注册表、再逐图落盘** —— 落盘抛错时内存已前进、磁盘只写了一部分（torn write），且异常穿到工具确认回调，**UI 无任何提示**。
- 该模块被 **18 个文件**引用（生产 5 处 + 测试 13 处）。
- `frontend/src/composables/useDragPosition.ts` 另有一处直写 localStorage（导航卡片位置）—— **本步骤不动**。
- `AGENTS.md` 的架构图在 Runtime 层下列着 `graph_persistence.ts`；`check_architecture_paths.py` 默认校验该图，且被 pre-commit 钩子调用 —— **删文件而不改图会打断 commit**。

## 目标

`frontend/src/persistence/` 建立并**纵向打通图数据这一类**：调用点 → `coordination/` → `categories/` → `medium/` → localStorage 全链路可用。完成后：

- 调用方读写图数据**只经 `persistence/`**，不再直接触碰 storage API。
- **写入失败不再静默**：配额溢出 / 介质不可用时返回可判别的失败结果，且 UI 有可见提示。
- **torn write 的窗口被收窄，但未被消除**：整批序列化先行完成，故**序列化失败不产生任何写入**；写入阶段遇失败立即停止并回报，调用方**不推进内存**。
  **但 localStorage 无事务** —— 已写成功的条目不会被撤销，**磁盘可能留下半写态**，且**下次启动会把它读成基线**（不一致被静默合法化）。**真原子性由 P2 的 IndexedDB 事务解决；本步骤只在注释与测试里如实固化这一边界。**
- **内存与磁盘不再分歧**：落盘失败时内存状态不得单方面前进。
- 对用户**行为完全不变**：同一份数据、同一批图谱、同样的启动恢复；唯一差别是失败时不再无声。

## 架构变更

```text
旧：
frontend/src/graph/
  ├── graph_store.ts         — 既持状态，又直接调 saveGraph / deleteGraph
  ├── graph_persistence.ts   — 图数据 + 视图状态 + 1 个域查询混在一个文件
  ├── utils/graph_tree.ts    — 直接调 loadGraph
  └── use-case/*.ts          — 直接调 loadGraph / listSavedGraphIds / lastActiveRootId

新：
frontend/src/persistence/
  ├── index.ts                    — 公开面（唯一入口）
  ├── coordination/commit.ts      — 批量提交：一次接收 upserts + deletes
  ├── categories/graph_data.ts    — 图数据：键方案 + 序列化 + 判别联合
  ├── categories/view_state.ts    — 视图状态（原样搬入）
  └── medium/local_storage.ts     — 按 key 存取字符串

frontend/src/graph/               — 调用点改为经 @/persistence
```

依赖方向单向：调用点 → `coordination/` → `categories/` → `medium/`。**`categories/` 内不得出现 storage API 标识符。**

## 接口契约

```ts
// 读：判别联合（缺字段语义必须可区分）
type ReadResult<T> =
    | { ok: true; value: T }
    | { ok: false; reason: 'missing' | 'corrupted' | 'unavailable' }

// 写：可判别失败（取代今天的 void）
type WriteResult =
    | { ok: true }
    | { ok: false; reason: 'quota-exceeded' | 'unavailable' | 'unknown' }

// 公开面（本步骤实现的最小集）
loadGraph(id: GraphId): ReadResult<GraphData>
commitGraphs(change: { upserts: GraphData[]; deletes: GraphId[] }): WriteResult
listGraphIds(): ReadResult<GraphId[]>   // 介质不可用时必须报 available 失败，不得静默返回 []
listRootGraphIds(): ReadResult<GraphId[]>  // 原样搬入语义，函数上方标注「待归位」
saveLastActiveRootId(rootId: GraphId): WriteResult
loadLastActiveRootId(): GraphId | null
clearLastActiveRootId(): WriteResult
```

**跨类别变更的联合类型**定义在层内，**不导出**出 `persistence/`。

## 具体子任务

### 1.1 骨架与结果类型

- 建 `frontend/src/persistence/` 与 `index.ts` / `coordination/` / `categories/` / `medium/`。
- 定义上述读写结果类型，以及层内不导出的跨类别变更联合类型。
- 类型名与判别字段**按最终形态一次定对**（P2 异步化时不改判别字段）。

### 1.2 两个数据类别与 localStorage 介质

- `categories/graph_data.ts`：承接图数据部分的**全部行为**（键方案 `graph:<id>`、序列化、判别联合、按 id 读 / 写 / 删 / 列出），改为**委托介质**。
- `categories/view_state.ts`：三个视图状态函数**原样搬入**，签名与行为不变（§2 再收编）。
- `medium/local_storage.ts`：按 key 存取字符串的最小实现；把介质异常（配额溢出、storage 不可用）翻译成结果类型的 `reason`。
- **介质层不得吞异常**：枚举 / 读取遭遇异常时必须向上报 `unavailable`，不得降级为空结果 —— 项目 `AGENTS.md` 明令「不准任何形式的静默退出」。
- 迁移**惰性父链补读**与**启动全量读取**到新位置。

### 1.3 批量提交入口

- `coordination/commit.ts` 提供**单一变更入口**，一次接收 upserts + deletes，取代 `graph_store.ts` 里「推导 affectedGraphIds → 逐图 save/delete」的循环。
- 先在内存中组装全部待写序列，再逐条写；**任一条写失败即回报失败**，且调用方**不得**让内存状态单方面前进。
- `useNavigation.ts` 里那处直连删除改为走本入口（`deletes` 单个元素）。

### 1.4 调用点迁移

- 迁移**生产 5 处**与**测试 13 处**的 import 路径与调用形状（`saveGraph` + `deleteGraph` 的成对调用合并为一次 `commitGraphs`）。
- **测试 13 处保持同步语义** —— 本步骤不引入 async，故「先写后读」的既有假设不变，迁移以改 import 与调用形状为主。
- **删除** `frontend/src/graph/graph_persistence.ts` 与其测试文件；测试中的判别联合用例迁至 `categories/graph_data.test.ts`。
- **`AGENTS.md` 的最小修正**（仅此三处，不得扩大）：
  - 删掉架构图中 Runtime 层下的 `graph_persistence.ts` 条目；
  - 在该图内补一条显式声明：`frontend/src/persistence/` 本图暂未收录（待补）；
  - 修掉正文里提到 `graph_persistence.ts` 的过时文件清单。

### 1.5 写失败的用户可见反馈

- 在 store 上**新开一个存储错误状态位**（**不复用** `lastValidationResult`）。
- `Graph.vue` 把它并入**现有错误面板位置**，规则：**存储错误优先于业务校验错误**。
- 呈现按最高等级（`accent="red"` 的现有面板）。
- **零视觉设计投入**：不新增面板、不改样式、不改布局、不引入层叠策略。

## 变更边界

**禁止修改**：

- 文件：`frontend/src/composables/useDragPosition.ts`（§2 才收编）、`packages/graph-engine/**`、`frontend/src/cytoscape/**`

- 模块：`frontend/src/graph/use-case/` 下除 import 路径与 1.3 那处删除调用之外的任何逻辑

**禁止引入**：

- IndexedDB、任何 `async` / `Promise` 化的公开签名
- `graph_persistence.ts` 的任何转发层、别名或「向后兼容导出」
- 数据格式版本号、任何迁移代码
- 第三个 `NotificationPanel`；任何样式 / 布局 / 动效改动

**禁止扩大** `AGENTS.md` 的改动范围：只允许 1.4 列出的三处；`AGENTS.md` 的其他内容（含 §项目架构 的各层 `s.t.` 契约行）一律不动。
