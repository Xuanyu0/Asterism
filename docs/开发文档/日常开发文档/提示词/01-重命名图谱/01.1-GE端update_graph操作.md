# 01.1. GE 端 update_graph 图级操作 — 提示词

## 当前状态

GraphEngine（`packages/graph-engine/`）现有图级操作仅 `add_graph` / `delete_graph`（`AtomicGraphOperation` 联合，签名统一 `{ type, graph }`）。图级操作有独立完整闭环：批级契约判定（apply_batches 内硬编码 add/delete）→ `validateGraphOperation` 单 op 校验 → `executeGraphOperation` switch 兑现 → `createGraphReversal` 构造逆元。当前逆元构造函数只接收 op（不接收注册表），且调用点在操作兑现**之后**。

图内操作 `update_node` 是本次语义参照：完整替换匹配对象（`{ ...op.node, updatedAt }`），校验仅"目标存在"。

## 目标

新增图级操作 `update_graph`（**update_node 式全量构造**：完整替换图对象，非字段级增量），补齐类型定义、批级契约、校验、兑现、逆元、公开导出与测试。`update_graph` 是通用"整图更新"操作，不感知具体业务语义（本步骤消费方是前端重命名，引擎层不涉及）。

## 架构变更

`旧：`

```
图级批 for 循环：validate → executeGraphOperation（registry 已替换）→ createGraphReversal(op)
逆元构造函数无法访问操作前旧图（update_graph 逆元需要旧 title）
```

`新：`

```
图级批 for 循环：validate → createGraphReversal(op, registryBefore) → executeGraphOperation
（逆元在执行前捕获操作前状态，与图内批 onBeforeEachOperation 对称）
```

## 具体子任务

### 1.1. 类型与批级契约

- `types/atomic_operations.ts`：新增 `UpdateGraphOperation`（`type: 'update_graph'`，`graph: GraphData`），并入 `AtomicGraphOperation` 联合。
- `core/apply_batches.ts` 批级 kind 契约判定：图级类型判定加入 `update_graph`（当前为内联硬编码 add/delete 的判别式）。建议将该判定抽为文件内辅助函数（如 `isGraphLevelType`），inGraph 批含图级类型 / graphLevel 批含非图级类型两种判别共用，消除重复。判定加入 `update_graph` 后：inGraph 批混入 `update_graph` → `BATCH_KIND_MISMATCH`；graphLevel 批含 `update_graph` 正常通过。

### 1.2. 校验

- `core/validate_graph_operation.ts`：`validateGraphOperation` 增加 `update_graph` 分支——目标图在注册表存在，不存在则返回 error（参照现有 add/delete 分支的 issue 构造风格）。
- **title 业务校验下沉 GE（用户确认方案 A）**：`update_graph` 与 `add_graph` 均增加两项校验（注册表全量可查）：
  - `EMPTY_TITLE`：`op.graph.title` trim 后为空 → error。
  - `TITLE_DUPLICATE`：`op.graph.kind === 'root'` 时，注册表中其他 `kind === 'root'` 图的 title（trim 后）与 op.graph.title（trim 后）相同 → error（排除自身 id）。子图（非 root）不做唯一性校验（面包屑路径可区分）。
- 校验 issue 构造沿用"错误消息构造函数"模式（文件末尾私有辅助函数，如 `buildEmptyTitleIssue` / `buildTitleDuplicateIssue`），核心逻辑保持单行调用。
- 原"空名/重名由前端用例层承担"的说明**作废**（校验归属已改 GE）。

### 1.3. 兑现（全量替换）

- `core/apply_batches.ts` `executeGraphOperation` switch 增加 `case 'update_graph'`：
  - 语义：完整替换——从注册表命中目标 id 后，`next.set(id, 新图对象)`，新图对象 = 操作携带的 graph 全量字段。
  - 时间戳沿用 **"携带值 ?? executedAt"**（`createdAt` 与 `updatedAt` 均如此）：参照 update_node 的 `resolveObjectTimestamp`（execute_operation.ts 私有函数，`carried ?? executedAt`）与 add_graph 补写模式。携带值优先——**正操作构造不携带时间戳 → 引擎写 executedAt（刷新）**；**逆元携带旧图（含旧时间戳）→ undo 恢复历史时刻**（符合 CLAUDE.md 时间戳约定）。
  - 兑现后同步 `latestGraphs`（与 add_graph 一致：后续批基于操作后图数据）。

### 1.4. 逆元（执行前捕获，结构调整）

- `core/apply_batches.ts`：
  - `createGraphReversal` 签名扩展为接收注册表参数（操作前状态）。`add_graph` / `delete_graph` 分支不读取该参数，行为不变。
  - 图级批循环内逆元构造调用点**提前**到 `executeGraphOperation` 之前（在 `validateGraphOperation` 通过之后）：先构造逆元（此时注册表仍是操作前状态）→ 再兑现。
  - 新增 `case 'update_graph'`：注册表命中 → 逆元 = `{ type: 'update_graph', graph: 操作前旧图 }`（旧图全量，含旧 title）；未命中 → 空序列。
  - 逆元收集条件（`recordLog`）保持现有语义不变。

### 1.5. 导出与测试

- `types/index.ts`：公开导出 `UpdateGraphOperation`。
- `tests/core/apply_batches.test.ts` 补充用例：
  - 兑现：目标命中 → title 替换；createdAt / updatedAt **携带值优先**（未携带 → executedAt；携带 → 保留原值）；目标缺失 → 校验失败整批丢弃、注册表不变。
  - 逆元：构造结果含旧图（旧 title + 旧 updatedAt）；回放（undo 语义）执行逆元批后 title 回退且 **updatedAt 恢复旧值**（历史时刻恢复）。
  - 批级契约：inGraph 批混入 `update_graph` → `BATCH_KIND_MISMATCH`；graphLevel 批混入图内操作 → `BATCH_KIND_MISMATCH`。
  - 回归：结构调整后 add_graph / delete_graph 的兑现与逆元行为不变（对比既有用例）。

## 变更边界

**禁止修改**：

- `core/replay.ts`：图级操作统一不进 replay（保持现状）。
- `core/reversal.ts` / `core/execute_operation.ts` / `core/validate_operation_in_graph.ts` / `core/apply_batch.ts`：图内操作链路（update_node 等）保持不动。
- 前端（`frontend/`）任何文件。
- 不修改 `validate_graph_operation.ts` 中 add/delete 既有分支行为（title 校验是**新增**分支，不动既有逻辑）。

## 验收标准

- [ ] `UpdateGraphOperation` 定义并入 `AtomicGraphOperation` 联合，且从包公开入口（`@my-project/graph-engine`）可导入该类型。
- [ ] 批级契约：graphLevel 批含 `update_graph` 正常执行；inGraph 批含 `update_graph` 返回 `BATCH_KIND_MISMATCH`。
- [ ] 校验：目标图不存在 → 校验失败、整批丢弃、注册表不变（与入参引用相同）。
- [ ] **title 校验（update_graph 与 add_graph 均生效）**：title trim 后为空 → `EMPTY_TITLE` error；`kind === 'root'` 且注册表存在其他同名 root 图（trim 后比较，排除自身 id）→ `TITLE_DUPLICATE` error；子图（非 root）不做唯一性校验。
- [ ] 兑现：命中后新图 title = 操作携带值；createdAt / updatedAt **携带值优先**（未携带 → executedAt；携带 → 保留原值）；未命中的其他图引用复用（不深拷贝）。
- [ ] 逆元：`createGraphReversal` 签名扩展；`update_graph` 逆元携带操作前旧图（含旧 title + 旧 updatedAt）；逆元在兑现前构造（回放逆元批后 title 回退且 **updatedAt 恢复旧值**）。
- [ ] 回归：add_graph / delete_graph 的兑现与逆元行为与改动前一致（既有测试通过）。
