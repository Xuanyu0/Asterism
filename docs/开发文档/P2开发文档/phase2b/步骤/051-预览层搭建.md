## 5.3 预览引擎（clone 方案）✅

不确定度：🟡 / 算法复杂度：🟡 / 工程量：🟡 (新建 ~70 行 + 测试)

### 目标

新建 `preview_engine.ts`，提供 `previewAddEdge()` —— clone 当前图 → 模拟添加边 → 返回预览图 + 碰撞节点列表。

### 核心任务

| # | 内容 |
|---|------|
| 1 | 新建 `frontend/src/feature-tools/preview/preview_engine.ts` |
| 2 | 实现 `previewAddEdge(graph, sourceId, targetId, kind, direction): { previewGraph, collisions, valid }` |

### 实现要点

```
previewAddEdge(graph, sourceId, targetId, kind, direction):
  1. clone = structuredClone(graph)
  2. result = applyBatch(clone, [addEdgeOp])   // op 用 generateEdgeId + clone.id
  3. if !result.validation.valid → return { previewGraph: clone, valid: false, sourceCollides: false, targetCollides: false }
  4. previewGraph = result.graph               // degree 已更新（source/target +1）
  5. sourceCollides = hasCollisionAt(sourceId, source.position, previewGraph.nodes, new Map(), new Set([targetId]))
  6. targetCollides = hasCollisionAt(targetId, target.position, previewGraph.nodes, new Map(), new Set([sourceId]))
  7. return { previewGraph, valid: true, sourceCollides, targetCollides }
```

**碰撞检测无需半径覆盖**：clone 方案中 `applyBatch` 已真实执行 add_edge，source/target 的 `degree` 已 +1，`hasCollisionAt` 按 `unitDistance * sqrt(1 + degree)` 自动算对新半径。

**碰撞判定对象**：只判定 source / target 两端点是否与邻居碰撞，返回两个布尔。**不枚举碰撞邻居**——用户 hover 到 target 看到 target 变红 = "这里点了会导致碰撞"，语义直白；其他节点样式不动。

**端点互斥排除**：source 检测时用 `extraExcludedIds` 排除 target，反之亦然——直连两端点之间的"碰撞"不是用户关心的视觉重叠。

### 影响范围

```
frontend/src/feature-tools/preview/
└── preview_engine.ts  ← 新建
└── preview_engine.test.ts  ← 新建
```

### 已确定决策

- **返回 `{ previewGraph, collisions, valid }`** 而非 `NodeId[]`。add_edge 工具需要完整预览图来 `syncFromGraphData`。
- **本步骤仅实现 add-edge 特化**。通用的 `simulateCollision(graph, registry, operation)` 管道描述为扩展方向，move / orbit 后续复用。

## 5.4 add-edge 工具改造（clone 方案）✅

不确定度：🟡 / 算法复杂度：🟡 / 工程量：🟡 (~100 行改动)

### 目标

改造 `add_edge.ts`：hover 时渲染预览图并检测碰撞，有碰撞则红色高亮 + 拒绝点击。

### 新交互流程

```
激活工具 (cursor-crosshair)
    │
    ├── 第一次点击节点 → sourceNodeId 记录
    │       │
    │       ├── hover 到其他节点 → previewAddEdge()
    │       │       ├── syncFromGraphData(previewGraph)      ← 整图切换到预览（清掉之前所有 class）
    │       │       ├── addNodeClass(sourceId, 'edge-source-target', 'add-edge')   ← sync 后重施 source 高亮
    │       │       ├── sourceCollides → addNodeClass(sourceId, 'preview-collision', 'add-edge')
    │       │       ├── targetCollides → addNodeClass(targetId, 'preview-collision', 'add-edge')
    │       │       └── 无碰撞 → 仅 source 高亮，无红色
    │       │
    │       ├── hover 离开 → clearAllPreviews('add-edge')
    │       │       └── syncFromGraphData(realGraph) → 若 sourceNodeId 仍选中，重施 edge-source-target
    │       │
    │       └── 点击 hover 的节点
    │               ├── 有碰撞 → 忽略（不创建边），sourceNodeId 保持
    │               └── 无碰撞 → commitBatchToGraph 创建边，重置 sourceNodeId
    │
    └── 右键 → deactivate → default
```

### 核心任务

| # | 内容 | 约束 |
|---|------|------|
| 1 | `onNodeHover(nodeId)`：source 已选且非 source 自身 → `previewAddEdge` → `syncFromGraphData(previewGraph)` → **sync 之后**按 sourceCollides / targetCollides 施加 `preview-collision` class + 重施 `edge-source-target` | `useRenderer()` 的 `syncFromGraphData` / `addNodeClass` / `clearAllPreviews` |
| 2 | `onNodeHoverOut(nodeId)`：`clearAllPreviews('add-edge')` → `syncFromGraphData(realGraph)` → 若 sourceNodeId 仍选中则重施 `edge-source-target` | |
| 3 | `onNodeClick` 第二次点击：先 `previewAddEdge` 检查碰撞 → 有碰撞忽略 → 无碰撞 `commitBatchToGraph` | 复用 hover 阶段相同的 op 构造 |
| 4 | `deactivate()`：`clearAllPreviews('add-edge')` + `syncFromGraphData(realGraph)` + 重置状态 | |
| 5 | `Graph.vue`：移除 `edge-source-target` 的 `bindHighlight` 绑定 | source 高亮所有权移交 handler，避免双 owner |

### 影响范围

```
frontend/src/feature-tools/toolbar/add_edge.ts
frontend/src/feature-tools/toolbar/add_edge.test.ts  ← 更新测试
frontend/src/views/Graph.vue                          ← 移除 edge-source-target bindHighlight
```

### 已确定决策

1. **hover 预览 = 整图 `syncFromGraphData(previewGraph)`**。clone 方案的核心：画布暂时渲染预览图，`graphStore.graphView` 仍是真实图，`watch(graphView)` 不触发（真实图未变），canvas 停留在预览。
2. **`syncFromGraphData` 清空"调用时已存在"的 class**（cy.json 用 mapper 产出整体替换 + `classOwners.clear()`）。因此 **handler 的所有 transient class 必须在 sync 之后施加**——`preview-collision` 和重施的 `edge-source-target` 都会存活到下一次 sync。规则：**handler 是其所有 transient class 的唯一 owner，每次 sync 后重施**。
3. **不需要 renderer 接口改造**。不引入 syncVersion 计数器、不新增 preserve 参数——handler 在 sync 后主动重施即可，renderer 接口零改动。
4. **source 高亮所有权移交 handler**。`Graph.vue` 移除 `edge-source-target` 的 `bindHighlight`，由 handler 通过 `addNodeClass`（owner `'add-edge'`）在 sync 后重施。`delete-target` 的 bindHighlight 保留（delete 是单次点击流程，无 hover sync，不受影响）。
5. **点击前重新跑 `previewAddEdge`**（而非缓存 hover 结果）。碰撞判定以点击时最新图为准，避免 stale。
6. **hover 期间真实图不落任何状态**。只有确认点击才走 `commitBatchToGraph`——真实 GraphData 唯一变更路径。

## 5.6 move 工具：拖动边宽实时预览 ✅

不确定度：🟡 / 算法复杂度：🟢 / 工程量：🟡 (3 源文件 + 2 测试文件)

### 目标

move 工具拾取节点拖动时，实时预览与节点直接相连边的粗细变化。边宽 = `f(两端质量, 两端距离)`，拖动改变距离 → 边宽实时响应（认知距离的视觉反馈）；弹回 / 放置后边宽恢复正确。

**方案**：与 add-edge 同构的 **clone+sync 预览通道**。不采用逐属性 renderer 操作——那是 051 已废弃的 v1 方案（出 BUG、难维护）。边宽由 sync 时 mapper 按预览图新位置自动重算，无独立边宽逻辑。

### 核心任务

| # | 内容 | 文件 |
|---|------|------|
| 1 | `preview_engine` 新增 `previewMoveNode(graph, nodeId, desiredPosition)`：JSON 克隆 → `moveNode` 模拟移动 → `applyBatch` → 返回预览图 + 碰撞布尔 | `preview_engine.ts` |
| 2 | `move_node.ts` 每帧 / 拾取吸附走预览管道：`previewMoveNode` → `syncFromGraphData(previewGraph)` → **sync 后**重施 `move-picked` + 按需 `preview-collision` | `move_node.ts` |
| 3 | `cancelPick` / `deactivate`：`clearAllPreviews('move')` + `syncFromGraphData(realGraph)`——位置 / 边宽 / class 一次全部恢复 | `move_node.ts` |
| 4 | `.move-collision` 迁移到 `.preview-collision`（`cy_style.ts` 删旧选择器） | `move_node.ts` + `cy_style.ts` |
| 5 | `useRenderer` 移除 `setNodePosition` / `resetNodePosition`（迁移后无消费者的死代码） | `useRenderer.ts` |
| 6 | 测试：`preview_engine.test.ts` 新增 previewMoveNode 用例（含 reactive Proxy 图）；`move_node.test.ts` 适配新预览管道 | 2 测试文件 |

### 实现要点

```
trackCursor 回调（picked 时）：
    lastModelPos = modelPos
    applyPreviewMove(modelPos)

applyPreviewMove(pos)：
    graphView 不存在 / 未拾取 → return
    { previewGraph, collides } = previewMoveNode(graphView, pickedNodeId, pos)
    syncFromGraphData(previewGraph)                    ← 整图切到预览（位置 + 边宽 + 尺寸一次到位）
    addNodeClass(pickedNodeId, 'move-picked', 'move')  ← sync 清空 class，必须 sync 后重施
    collides → addNodeClass(pickedNodeId, 'preview-collision', 'move')

onNodeClick 拾取吸附（lastModelPos 存在时）：applyPreviewMove(lastModelPos)

cancelPick（弹回）：
    clearAllPreviews('move')
    syncFromGraphData(graphStore.graphView)            ← 切回真实图，位置 / 边宽 / class 全部恢复
    （不再使用 resetNodePosition——sync 同时刷新 nodePositionsCache）

placeAttempt：逻辑不变（getNodePosition → moveNode → 无碰撞 commit），碰撞 class 改名 preview-collision

放置成功：removeNodeClass('move-picked') 保留；watch(graphView) → sync 全量纠正
```

### 影响范围

```
frontend/src/feature-tools/preview/preview_engine.ts       ← +previewMoveNode
frontend/src/feature-tools/preview/preview_engine.test.ts  ← +previewMoveNode 用例
frontend/src/feature-tools/toolbar/move_node.ts            ← 预览管道接线 + class 迁移
```

### 已确定决策

0. **`.move-collision` 一并迁移到 `.preview-collision`**（用户已确认）。
1. **simulateCollision 通用管道本次不实施**（用户已确认，推迟）。`previewMoveNode` 是 move 专用函数，非通用管道。
2. **预览走 clone+sync 单通道**——不采用逐属性 renderer 操作（051 v1 废弃方案：出 BUG、难维护）。
3. **边宽无需单独逻辑**——sync 时 mapper 按预览图新位置自动重算，与节点尺寸同源不失步。
4. **每帧成本接受**——JSON 克隆 + moveNode + applyBatch + 全量 mapper + cy.json；用户实测无掉帧（图规模 <100 节点）。
5. **弹回恢复 = 切回真实图 sync**——不再用 resetNodePosition（sync 同时刷新 nodePositionsCache）。
6. **`setNodePosition` / `resetNodePosition` 随本步骤移除**（用户已确认）——迁移后无消费者。
7. **放置 / 碰撞拦截逻辑不变**，仅 class 改名。
