## Step 2.5：双击节点跳转子图 ✅

难度：🟢 不确定度 / 🟢 算法复杂度 / 🟡 工作量（~60 行 / 2 文件）

### 用户能做什么（功能目标）

1. **双击抽象节点** → 进入其内部子图（`childGraphId`）
2. **双击引用节点** → 跳转到原始节点所在图谱（`sourceGraphId`），并自动定位到原节点
3. **双击子图中普通节点** → 返回上一级父图（`parentGraphId`）

**优先级**：引用节点 > 抽象节点 > 普通节点。若节点同时兼具引用和抽象属性，引用优先。

### 设计权威

引自 `docs/设计/01-核心定义.md`：

> 双击节点执行跳转（跳转子图 / 跳回父图 / 跳转到原节点所在图）。跳转优先级：引用节点 > 抽象节点（即若节点同时兼具引用和抽象属性，引用语义优先）。普通节点双击回到上一层父图。

### 已就绪的基础设施（直接使用，不需新增）

| 需求          | API                                                            | 规则                                                         |
| ------------- | -------------------------------------------------------------- | ------------------------------------------------------------ |
| 图谱切换      | `graphStore.loadGraphToView(id)`                               | 失败自动通过 `lastValidationResult` → NotificationPanel 反馈 |
| 画布定位      | `ui_store.pendingCanvasFocusId` → `renderer.revealElement(id)` | 写入 ID → Graph.vue watch 消费并自动清除                     |
| 双击事件源    | `useGraphInteraction` 当前仅注册 `tap` / `cxttap`              | 需新增 `dblclick` handler                                    |
| 节点类型判别  | `node.childGraphId` / `node.role` / `node.sourceGraphId`       | 见 `graph_data.ts` discriminated union                       |
| 当前图父图 ID | `graphView.parentGraphId`                                      | 子图中非 `undefined`，根图为 `undefined`                     |

### 事件链路

```
Cytoscape 'dblclick'
    ↓
use_graph_interaction.ts — cy.on('dblclick', ...) 新注册
    ↓ handlers.onNodeDoubleClicked(nodeId)
Graph.vue — 有活跃工具？→ 跳过（不导航）
         — 无活跃工具 → 查找节点数据 → 判别类型 → 决定目标
    ↓
清理 UI 现场（closeFloatingWindow + deactivate）
    ↓
graphStore.loadGraphToView(targetGraphId)
    ↓ (若为引用节点，附加定位)
ui_store.pendingCanvasFocusId = sourceNodeId
    → renderer.revealElement(sourceNodeId)
```

### 交互规则

1. **仅无活跃工具时双击执行导航**。有工具（如删除/折叠/添加节点）激活时，双击不触发导航——避免与工具语义冲突。单次单击和双击互不干扰：单击走工具/浮空窗，双击走导航。
2. **跳转前清理 UI 现场**：关闭浮空窗、取消激活工具（与导航卡片 `switchGraphTo` 一致）。
3. 导航失败由 `loadGraphToView` 写入 `lastValidationResult`，经 NotificationPanel 统一展示。
4. 引用节点跳转后需额外定位到原节点——在 `loadGraphToView` 完成后写入 `pendingCanvasFocusId`。

### scope guard（禁止修改）

- **不改 GraphData 本身** — 双击导航是纯读 + 导航操作，不产生增量 GraphData。
- **不改 `graph_store.ts` / `graph_persistence.ts`** — 导航 API 已完备。
- **不改 `operation_controller.ts` / `ui_store.ts`** — `pendingCanvasFocusId` 通道已就绪。
- **不改工具系统** — 双击导航在 Graph.vue 中做工具激活检查后独立执行，不进入 `tool_mediator` 路由。

### 延后不做

- "双击普通节点返回父图"的视觉暗示（如光标变化）→ 暂不做，保持箭头光标。
- 动画过渡 → 延后。

### 验收

- [x] 双击有 `childGraphId` 的抽象节点 → 画布切换为子图，导航卡片路径面包屑更新
- [x] 双击引用节点 → 跳转到 sourceGraphId 对应图谱，画布自动定位到 sourceNodeId

## Step 2.8：导航卡片组件重构 ✅

难度：🟢 不确定度 / 🟢 算法复杂度 / 🟡 工作量（~400 行 / 8 文件）

### 背景

Step 2.4 产出的 `GraphNavigationCard.vue`（1325 行）混合了 7 个职责域：

| 职责域      | 内容                                          |
| ----------- | --------------------------------------------- |
| 拖拽定位    | position + clamp + snap + localStorage 持久化 |
| 面板编排    | activePanel + 面板切换 + 视口翻转方向         |
| 面包屑路径  | pathSegments computed + 导航跳转              |
| 根图谱 CRUD | 列表 + 创建 + 删除（二次确认）                |
| 图内搜索    | 即时匹配 + 结果选择 + Ctrl+K                  |
| 自动淡化    | 3s timer + pointer enter/leave                |
| 溢出检测    | DOM 溢出检测 + CSS 遮罩                       |

远超社区惯例（300 行/文件），且拖拽/淡化逻辑与导航卡片概念耦合——`useDragPosition` 若按原写法会被 `storageKey: 'nav-card-position'` 硬编码，`useAutoFade` 的淡化条件会被 `hasOpenPanel` 绑定，未来 toolbar 无法复用。

### 目标

按社区惯例拆分为 **composable（纯逻辑，不含模板） + 子组件（模板 + 样式） + 编排器（组装）**。

所有 composable 接口**参数化行为边界**（如"淡化条件"），**不参数化当前调用方是谁**（如"面板是否打开"），确保 toolbar 等未来组件可直接复用。

### 子步骤

#### 2.8.1：提取 composable

| composable             | 来源职责域 | 对外接口                                                                 |
| ---------------------- | ---------- | ------------------------------------------------------------------------ |
| `useDragPosition`      | 拖拽       | `{ storageKey?, margin?, snap?: { threshold, margin }, onDragEnd? }`     |
| `useAutoFade`          | 淡化       | `{ delay?, opacity?, preventFade: Ref<boolean> }`                        |
| `useOverflowDetection` | 截断       | `(element: Ref<HTMLElement \| null>)` — 只负责测量，watch 由调用方自己写 |

接口设计原则：

- 不出现 `hasOpenPanel`、`isDragging`、`nav-card-position` 等导航卡片特有概念
- `preventFade` 是纯行为语义：`true` = 不淡，`false` = 可以淡。调用方自己算出这个值
