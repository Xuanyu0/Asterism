## @simplifier 清理发现

### Q1：deactivate 中 clearAllPreviews 冗余调用（已修复）

位置：`move_node.ts:153-168`

现象：`isPicked=true` 时 `deactivate()` 先调 `clearAllPreviews('move')`，随后 `cancelPick()` 内又调一次。

> 修复：删除 deactivate 中提前调用，由 cancelPick 统一处理。非 picked 状态下无 class 残留无需清理。

### Q2：originalPosition 变量死数据（已修复）

位置：`move_node.ts` 多处

现象：`originalPosition` 被赋值但从未消费——`cancelPick` 已改用 `resetNodePosition` 从缓存恢复。`originalPosition === null` 守卫等价于 `pickedNodeId === null`（两者始终同时赋值/清零）。

> 修复：删除变量声明、6 处赋值/置空操作，守卫改为 `pickedNodeId === null`。

### Q3：注释引用不存在的方法（已修复）

位置：`useRenderer.ts:349`

现象：注释写 `renderer().screenToModel()`，实际为手动 `(clientX - rect.left - pan.x) / zoom` 计算。

> 修复：更新注释描述实际坐标转换方式。

### Q4：位置类型未复用 NodePosition（已修复）

位置：`useRenderer.ts` 5 处函数签名 + `nodePositionsCache`

现象：内联 `{ x: number; y: number }`，项目已有 `NodePosition` 类型。

> 修复：导入 `type { NodePosition }` 并替换所有内联位置类型。

### 不确定项：getNodeElement 防护模式重复

6 个模块级函数共享 `if (!cyInstance) return` + `getElementById` + `if (el.length === 0)` 三层防护。>2 次调用，理论上符合抽辅助函数条件。

## @oracle 审查发现

### B1：bindHighlight 不立即执行

位置：`useRenderer.ts:510-534`

现象：`bindHighlight` 依赖 watch 惰性触发。当前初始化顺序下不影响功能（handler 注册在 mount 之后），但若未来调整顺序可能漏高亮。

> 建议：加 `{ immediate: true }` 或在 mount 完成后手动触发一次同步。当前无需处理。

### 改进 I1：classOwners.clear() 依赖隐式清除

位置：`useRenderer.ts:73-92`

现象：`syncFromGraphData` 中 `classOwners.clear()` 依赖 `cy.json()` 重创元素隐式清除 DOM class。若未来改为增量同步，DOM class 将泄漏。

> 建议：clear() 前先遍历 classOwners 移除 DOM class，使两者显式同步。

### 改进 I2：idle 状态 deactivate 漏调 clearAllPreviews

位置：`move_node.ts:153-168`

现象：`clearAllPreviews('move')` 仅在 `isPicked=true` 时通过 `cancelPick()` 间接调用。idle 状态下 deactivate 不调。当前 idle 状态确无 preview 残留，但若未来添加非 pick 触发的 preview 可能漏清除。

> 建议：将 `clearAllPreviews('move')` 提升到 deactivate 顶层，无论如何都执行（幂等操作）。

### 不确定 U1：模块级函数的调用形式偏差

位置：`useRenderer.ts:73 / 540`

现象：`useRenderer` composable 返回的 `syncFromGraphData` 与模块级导出是同名函数。Graph.vue 通过 `renderer.syncFromGraphData(...)` 调用，形式像实例方法，但语义上是模块级函数。架构语义与调用代码的表层语义略有偏差。

状态：⏳ 待确认

## Step 2 — 运行时 BUG

### B2：首次 addNodeClass 不生效（已修复）

位置：`useRenderer.ts` — `syncFromGraphData`

现象：页面刷新后第一次使用 move 工具拾取节点，`addNodeClass('move-picked')` 视觉不生效（class 已加到 Cy 元素但 opacity 不变）。第一次操作完成后（watch 触发第二次 syncFromGraphData → `cy.json()` 重载元素 → 内部样式缓存重置），此后 addClass 正常。

根因：Cytoscape `cy.json({ elements })` 内部走 `startBatch/endBatch` 批处理路径。Cy 实例刚创建（`elements: []`）时，批处理内部的样式计算器会吞掉后续 `element.addClass()` 的首次视觉变化。这是 Cytoscape 3.x 已知行为（Issue #2210、#1835）。

> 修复：`syncFromGraphData` 中 `cyInstance.json({ elements })` 替换为 `cyInstance.elements().remove()` + `cyInstance.add(cyElements)`，绕过批处理路径。同样语义（全量替换），无 DIFF 副作用。
