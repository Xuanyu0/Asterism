## 本次发现的 BUG

### B1. structuredClone 无法克隆 Vue 响应式 Proxy → DataCloneError

**状态**：已修复（2026-08-02）

**来源**：用户手动测试 hover 预览时发现（运行时异常）

**内容**：`preview_engine.ts` 使用 `structuredClone(graph)` 克隆图数据。但 `graphStore.graphView` 是 Vue 响应式 Proxy（Pinia state），`structuredClone` 无法克隆 Proxy 对象，抛出 `DataCloneError: #<Object> could not be cloned`。hover 到目标节点即触发。

**根因**：单元测试传的是普通对象（可克隆），测不出此问题；真实运行时传的是响应式 Proxy。

**修复**：改用 `JSON.parse(JSON.stringify(graph))` 克隆——与 `graph_store.ts` undo snapshot（第 440 行）的既有克隆方式保持一致。GraphData 是纯 JSON 数据，序列化克隆安全。

**回归测试**：`preview_engine.test.ts` 新增"响应式 Proxy 图"用例，用 `reactive()` 包裹图数据模拟 Pinia graphView，验证 previewAddEdge 正常工作。修复前该用例会抛 DataCloneError。

**教训**：涉及从 Pinia store 读取数据并克隆的场景，测试必须用 `reactive()` 包裹模拟响应式——普通对象测试无法覆盖 Proxy 边界。

### B2. source ↔ target 互碰被互斥排除豁免 → 碰撞误放行

**状态**：已修复（2026-08-02）

**来源**：用户手动测试 hover 预览时发现（"与旧有节点的碰撞判断有时成功有时失败"、"误判没有碰撞的节点"）

**内容**：`previewAddEdge` 的碰撞判定用 `extraExcludedIds` 排除对端节点（`hasCollisionAt(..., new Set([targetId]))`）。当 source 与 target 加边后视觉重叠（如 source 半径 84→94、target 42→59.4、距离 127.82 < 半径和 153.31），互斥排除使 `sourceCollides` / `targetCollides` 均为 false → 无红色高亮、点击执行。

**根因**：
1. **互斥排除是过度设计**——"两端点通过边直连，互碰不是视觉重叠"的假设不成立。用户关心的是"加边后节点变大是否视觉重叠"，source 压住 target 正是最直观的碰撞信号。
2. **"有时成功有时失败"的来源**：加边前半径和 126 < 距离 127.82（不碰），加边后 153.4 > 127.82（碰）——恰好落在临界值附近。视觉上（preview 图 degree 已 +1）显示碰撞，但互斥排除让系统"看不见"。

**修复**：`preview_engine.ts` 移除 `extraExcludedIds` 参数，`hasCollisionAt` 不再排除对端：
```ts
sourceCollides = hasCollisionAt(sourceId, source.position, previewGraph.nodes, new Map())
targetCollides = hasCollisionAt(targetId, target.position, previewGraph.nodes, new Map())
```
source 与 target 视觉重叠 → 双端红色 + 点击拒绝。

**回归测试**：新增"source 与 target 互碰"用例（s(0,0)/t(100,0)，加边后半径和 118.8 > 100 → 双端碰撞）。修复前该用例返回 false（误放行）。

**诊断方法**：在 `previewAddEdge` 打数据日志（视觉半径 vs 引擎半径、逐对距离 vs 半径和），用户复现后从控制台确认唯一碰撞对是 source↔target，且被互斥排除豁免。诊断日志已移除。

**教训**：碰撞豁免条件必须与用户直觉一致——"视觉重叠即碰撞"，不能用"两端点本应连边"的架构假设代替视觉判断。

**来源**：051-2（fix-4）不确定项 1

**内容**：Cytoscape 的 `mouseout` 在节点间快速移动时可能因事件重定向产生边界行为（快速跨节点时可能漏发 `mouseout` 或短暂重复 `mouseover`）。当前绑定使用 `cy.on('mouseover', 'node', ...)` 的 selector 委托形式，由 Cytoscape 内部过滤目标，行为稳定。

**建议**：现阶段无需处理。若后续预览层要求精确的 hover 边界，可考虑 `event.target === cy` 判断或引入节流。

### U5. add-edge handler 移除 highlightNode getter

**状态**：已确认（ora-2 关闭）

**具体影响**：add-edge 不再暴露任何 reactive 高亮（ToolHandler 接口为 optional，类型层面安全）。当前全仓唯一 `highlightNode` 消费者是 delete-target bindHighlight。

**建议**：若未来有其他消费者依赖 add-edge 的 `highlightNode`，需重新评估。当前移除是正确决策。
