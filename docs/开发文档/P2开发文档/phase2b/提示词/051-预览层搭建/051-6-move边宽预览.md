# 051-6 — move 工具：拖动边宽实时预览：提示词

> 拓展自：[051-预览层搭建.md](../../步骤/051-预览层搭建.md) §5.6
>
> 前置依赖：051-3（preview_engine 既有 previewAddEdge）+ 051-4（clone+sync 预览通道范式）
>
> 方案定论：**与 add-edge 同构的 clone+sync 预览通道**。严禁逐属性 renderer 操作（051 v1 废弃方案：出 BUG、难维护）。

## 当前状态

`move_node.ts` 目前每帧 `setNodePosition(pickedNodeId, modelPos)` 只移动节点视觉位置，边宽 data 不重算 → 拖动时边粗细不变化。碰撞检测每帧跑 `composeMoveNode`（moveNode）并施加 `.move-collision` class。

`preview_engine.ts` 已有 `previewAddEdge`（JSON 克隆 → applyBatch 模拟 → 返回预览图 + 碰撞布尔），是本次要镜像的范式。

**本次目标**：move 拖动走同一条 clone+sync 通道——整图切到预览图，边宽由 mapper 按新位置自动重算（无需独立边宽逻辑）。

## 核心规则（必须先理解）

1. **`syncFromGraphData` 会清空"调用时已存在"的 class**（cy.json 整体替换 + `classOwners.clear()`）。因此所有 transient class（`move-picked` / `preview-collision`）**必须在 sync 之后施加**，且每次 sync 后都要重施。
2. **`syncFromGraphData` 同时刷新 `nodePositionsCache`**——弹回恢复不可再用 `resetNodePosition`（它会恢复到最近一次 sync 的**预览**位置）。弹回 = 切回真实图 sync。
3. **`previewMoveNode` 克隆用 JSON 序列化**（非 structuredClone）——`graphStore.graphView` 是 Vue 响应式 Proxy，structuredClone 抛 DataCloneError（051 B1 教训）。

## 具体子任务

### 1. `preview_engine.ts` 新增 `previewMoveNode`

```ts
export function previewMoveNode(
    graph: GraphData,
    nodeId: NodeId,
    desiredPosition: NodePosition,
): { previewGraph: GraphData; collides: boolean } {
    const clone: GraphData = JSON.parse(JSON.stringify(graph))
    const result = moveNode({
        nodeId,
        desiredPosition,
        allNodes: clone.nodes,
        nodeRadiusOverrides: computeNodeRadiusOverrides(clone),
    })
    const preview = applyBatch(clone, result.operations)
    return { previewGraph: preview.graph, collides: hasErrors(result.issues) }
}
```

要点：
- `moveNode`（引擎 compose，导出名 `moveNode`）与 `applyBatch`、`computeNodeRadiusOverrides`（`@/graph/node_radius`）、`hasErrors`（`@/graph/issue_mapper`）均为既有 API。
- `moveNode` 的 operations 恒生成（碰撞不阻止），故 `applyBatch` 恒 valid——`previewMoveNode` 不需要 valid 字段。
- 碰撞判定语义与现 move 工具完全一致（moveNode 内部 hasCollisionAt + 半径覆盖表）。
- 补 JSDoc：说明 / 参数 / 返回值 / 调用契约（collides 为 true 时调用方应渲染 previewGraph 并施加碰撞高亮）。

### 2. `move_node.ts` 改造

**a. `useRenderer()` 解构**：移除 `setNodePosition` / `resetNodePosition`，保留 `syncFromGraphData` / `getNodePosition` / `addNodeClass` / `removeNodeClass` / `clearAllPreviews` / `trackCursor`。

**b. 新增私有辅助 `applyPreviewMove(pos)`**：

```ts
function applyPreviewMove(pos: NodePosition): void {
    if (!graphStore.graphView || pickedNodeId === null) return
    const { previewGraph, collides } = previewMoveNode(
        graphStore.graphView,
        pickedNodeId as NodeId,
        pos,
    )
    syncFromGraphData(previewGraph)
    addNodeClass(pickedNodeId, 'move-picked', 'move')
    if (collides) {
        addNodeClass(pickedNodeId, 'preview-collision', 'move')
    }
}
```

**c. trackCursor 回调**：`lastModelPos = modelPos` 照旧；`isPicked` 守卫后改为 `applyPreviewMove(modelPos)`。删除原 setNodePosition + 每帧 composeMoveNode 碰撞块（碰撞判定已移入 previewMoveNode）。

**d. `onNodeClick` 拾取分支**：`lastModelPos` 存在时改为 `applyPreviewMove(lastModelPos)`；不存在时 `addNodeClass(nodeId, 'move-picked', 'move')`。保留 `getNodePosition(nodeId)` 的 null 守卫。

**e. `cancelPick`**：

```ts
function cancelPick(): void {
    if (pickedNodeId === null) return
    // 弹回：整图切回真实图——位置 / 边宽 / class 由 sync 一次全部恢复
    clearAllPreviews('move')
    if (graphStore.graphView) {
        syncFromGraphData(graphStore.graphView)
    }
    pickedNodeId = null
    isPicked.value = false
    collisionMessage.value = null
}
```

**f. `placeAttempt`**：逻辑不变（getNodePosition → moveNode → hasErrors → commit），仅碰撞 class 改名 `move-collision` → `preview-collision`。更新相关注释。

**g. class 迁移**：全文 `move-collision` → `preview-collision`；更新文件头规则注释中涉及 class 的表述（如有）。

**h. `deactivate`**：结构不变（stopCursorTracking → 若 picked 调 cancelPick → 重置状态）。注释中涉及 `resetNodePosition` 的表述同步更新。
