# 3.-1 清理 graph_operations.ts 中间层

> 步骤文档：[05-步骤-共依赖.md](../../../P2开发文档/phase2b/05-步骤-共依赖.md#3-1-清理-graph_operationsts-中间层-)

## 设计文档依据

- `CLAUDE.md` § 架构分层：GraphEngine 是纯函数引擎，Runtime 层（graph_store）负责持有状态和编排引擎操作。UI 适配层（operation_controller）负责事件路由，组件层负责渲染。
- `05-步骤-共依赖.md` § 3.-1：删除 `graph_operations.ts`，将浮空窗编辑迁入 `GraphNodeWindow.vue`，认知操作迁入 `operation_controller.ts`，消除无消费者的中间透传层。
- `05-步骤-共依赖.md` § 3.0（展望）：未来 mediator 接管全部工具激活后，认知操作逻辑从 `operation_controller.ts` 提取为 `ToolHandler`。

## 当前状态

`graph_operations.ts`（`frontend/src/graph/`，499 行）是一个 GraphData 操作翻译层，经历 1.11（工具 handler 重构）和 1.13（draft 内联）后，其全部消费者的实际调用路径如下：

| 函数 | 消费者 | 现状 |
|------|--------|------|
| `confirmExistingNodeEdit` | `GraphNodeWindow.vue` → `controller` 透传 | 薄包装：`graphStore.applyBatchToGraph([update_node])` |
| `confirmExistingEdgeEdit` | `GraphNodeWindow.vue` → `controller` 透传 | 薄包装：`graphStore.applyBatchToGraph([update_edge])` |
| `closeFloatingWindow` | `GraphNodeWindow.vue`、`GraphNavigationCard.vue`、`Graph.vue`、`delete.ts` | 薄包装：`uiStore.closeFloatingWindow()` |
| `deconstruct` | `operation_controller.ts` → `ops` 透传 | 引擎 compose → applyBatchToGraph |
| `induce` | `operation_controller.ts` → `ops` 透传 | 引擎 compose → applyBatchToGraphs |
| `internalize` | `operation_controller.ts` → `ops` 透传 | 引擎 compose → applyBatchToGraphs |
| `diverge` | 无 UI 入口（`operation_controller` 暴露但无调用） | 待后续步骤激活 |
| `moveNode` | 无 UI 入口（`operation_controller` 暴露但无调用） | 待后续步骤激活 |
| `explore` / `unearth` | `operation_controller` 暴露但均为空 TODO stub | Phase 4 AI Runtime |
| `computeNodeRadiusOverrides` | 仅 `induce`、`internalize`、`moveNode` 调用 | 辅助纯函数 |
| `findCommonLayer` | 仅 `internalize` 调用 | 辅助纯函数 |

工具栏工具（add-node / add-edge / delete / fold）已全部绕过 `graph_operations.ts`，直接调 `graphStore.applyBatchToGraph()`。`feature-tools/mediator.ts` 不 import `graph_operations.ts`。

## 架构变更

```
旧：graph_operations.ts 作为中间透传层

GraphNodeWindow.vue → controller → ops → graphStore.applyBatchToGraph
operation_controller  → ops.deconstruct → engine compose → graphStore.applyBatch

新：删除中间层，调用方直接对接目标

GraphNodeWindow.vue → graphStore.applyBatchToGraph（浮空窗确认编辑，3.0 后改为通过 mediator 获取 update handler）
operation_controller  → engine compose → graphStore.applyBatch（认知操作）
operation_controller  → controller.closeFloatingWindow（保留在 controller，多消费者复用）

3.0 展望：新建 feature-tools/toolbar/update.ts 作为 update_node / update_edge 的统一 handler（引擎 discriminated union 按 type 自动分派），GraphNodeWindow.vue 移除 graphStore 直调，改为通过 mediator 获取 handler 执行更新。GraphNodeWindow.vue 恢复零 store import。
```

## 核心任务

### 任务 1：浮空窗编辑迁入 GraphNodeWindow.vue

将 `graph_operations.ts` 中 `confirmExistingNodeEdit` 和 `confirmExistingEdgeEdit` 两个函数迁入 `GraphNodeWindow.vue` 的 `<script setup>` 中作为局部函数。

- 新增 import：`useGraphStore`（从 `@/graph/graph_store`），新增 `const graphStore = useGraphStore()`
- 两个函数的逻辑照搬——仅将原函数体内的 `uiStore.closeFloatingWindow()` 替换为 `controller.closeFloatingWindow()`（`controller` 已 import，`closeFloatingWindow` 保留在其公开 API 中）
- `handleFloatingConfirm()` 改为调用局部函数 `confirmExistingNodeEdit(editingData)` / `confirmExistingEdgeEdit(editingData)`，不再经 `controller.confirmExistingNodeEdit` / `controller.confirmExistingEdgeEdit`
- Cancel 按钮模板不变：`v-on:click="controller.closeFloatingWindow"` 继续有效
- 不新增 `useUIStore` import——GraphNodeWindow.vue 的 UI store 访问全部通过 `controller`

### 任务 2：认知操作迁入 operation_controller.ts

将 `graph_operations.ts` 中所有认知操作和辅助函数迁入 `operation_controller.ts`：

- `deconstruct` — 引擎 composeDeconstruct → applyBatchToGraph
- `induce` — 引擎 composeInduce → applyBatchToGraphs
- `internalize` — 引擎 composeInternalize → findCommonLayer → applyBatchToGraphs
- `diverge` — 引擎 composeDiverge → applyBatchToGraphs（保持函数体不变，暂不激活）
- `moveNode` — 引擎 composeMoveNode → applyBatchToGraph（保持函数体不变，暂不激活）
- `explore` / `unearth` — TODO stub，保持占位
- `computeNodeRadiusOverrides` — 模块级私有辅助函数
- `findCommonLayer` — 模块级私有辅助函数（从 `graph_registry` 导入 `GraphRegistry` 类型）

新增 import：各 compose 函数（`deconstruct as composeDeconstruct` 等）、`hasErrors`、`mapComposeIssues`、`DEFAULT_LAYOUT_RULES`、`NodeRadiusMap`、`GraphRegistry` 类型。

### 任务 3：移除 useGraphOperations 依赖

在 `operation_controller.ts` 中：

- 删除 `import { useGraphOperations } from '@/graph/graph_operations'`
- 删除 `const ops = useGraphOperations()`
- 公开 API 返回对象中：原 `ops.xxx` 透传条目改为引用本地同名函数
- `closeFloatingWindow` 保留为 `operation_controller.ts` 的本地函数（`uiStore.closeFloatingWindow()` 包装）

### 任务 4：删除 graph_operations.ts

删除 `frontend/src/graph/graph_operations.ts` 文件。

## 不确定事项

### 不确定项 1：GraphNodeWindow.vue 新增 useGraphStore import

**问题**：迁入 `confirmExistingNodeEdit` / `confirmExistingEdgeEdit` 后 `GraphNodeWindow.vue` 需新增 `import { useGraphStore }`。该组件当前不 import graphStore，且 `frontend/src/components/AGENTS.md` 规定子组件不应导入 graphStore 写方法。

**决定**：接受此中间态。`confirmExistingNodeEdit` / `confirmExistingEdgeEdit` 是薄包装（applyBatchToGraph + 关浮空窗），不涉及多步编排，与 toolbar handler 模式一致的临时直调。3.0 统一激活系统时，新建 `feature-tools/toolbar/update.ts`（单一 handler，通过引擎 discriminated union 按 `type` 自动分派 update_node / update_edge），GraphNodeWindow.vue 改为通过 mediator 获取 handler 执行更新，届时移除 graphStore import。

**状态**：✅ 已确认（提示词已按此方案书写）

### 不确定项 2：closeFloatingWindow 保留在 operation_controller.ts

**问题**：步骤文档原计划将 `closeFloatingWindow` 也迁入 `GraphNodeWindow.vue`，但该函数有 4 个外部消费者（`GraphNavigationCard.vue`、`Graph.vue`、`delete.ts`、`GraphNodeWindow.vue`），不是 GraphNodeWindow.vue 独享的。保留在 `operation_controller.ts` 避免多消费者重复或循环依赖。

**状态**：✅ 已确认（提示词已按此方案书写）
