# 3.0-2 operation_controller 职责收缩

> 步骤文档：[05-步骤-共依赖.md](../../../P2开发文档/phase2b/05-步骤-共依赖.md) § 3.0-2

## 设计文档依据

- **CLAUDE.md** — "工具"定义：用户主动激活的互斥状态，画布交互解释为该工具语义，最终写 GraphData。默认模式是特殊的非显式工具，跨模式共享。
- **`docs/设计/06-交互逻辑.md`** §"显式表达默认状态"——默认指针图标代表"什么都不做"的交互语义，从这种意义上来说也是一种工具。

## 当前状态

`operation_controller.ts` 在 3.0-1 后失去了模式管理角色，当前持有三类内容：

| 类别         | 内容                                                                                 | 问题                                      |
| ------------ | ------------------------------------------------------------------------------------ | ----------------------------------------- |
| 薄包装       | `closeFloatingWindow` / `requestCanvasFocus` / `clearCanvasFocus` / `ui.state`       | 对 uiStore 的零价值透传                   |
| 默认路由     | `handleNodeClicked` / `handleEdgeClicked`                                            | 非 ToolHandler 模式，与 mediator 管线割裂 |
| compose 库存 | `induce` / `internalize` / `diverge` / `moveNode` / `explore` / `unearth` + 私有辅助 | 待各自步骤迁出到独立 ToolHandler          |

消费者分布：

| 消费者                  | 用到的 controller API                                                                                                 |
| ----------------------- | --------------------------------------------------------------------------------------------------------------------- |
| Graph.vue               | `handleNodeClicked`, `handleEdgeClicked`, `closeFloatingWindow`, `requestCanvasFocus`, `clearCanvasFocus`, `ui.state` |
| GraphNodeWindow.vue     | `closeFloatingWindow`, `ui.state.floatingWindowData`                                                                  |
| GraphNavigationCard.vue | `closeFloatingWindow`, `requestCanvasFocus`                                                                           |
| GraphModeSelector.vue   | `explore`, `unearth`, `induce`, `internalize`                                                                         |

## 架构变更

### 旧：Graph.vue 事件分叉

```
mediator.activeHandler?.onNodeClick
    ↓ YES → mediator.onNodeClick(nodeId)        ← ToolHandler 路径
    ↓ NO  → controller.handleNodeClicked         ← 回退路径（有问题）
              → uiStore.openFloatingWindow
```

### 新：mediator 统一路由

```
mediator.onNodeClick
    ↓ mediator.activeHandler?.onNodeClick
        ↓ YES → handler 处理
        ↓ NO  → fallback: default 工具（始终注册）
                  → uiStore.openFloatingWindow
```

### 旧：薄包装透传

```
consumer → controller.closeFloatingWindow() → uiStore.closeFloatingWindow()
consumer → controller.ui.state              → uiStore
```

### 新：消费者直调

```
consumer → uiStore.closeFloatingWindow()
consumer → uiStore
```

## 核心任务

### 1. 新建 `feature-tools/default.ts`

实现 ToolHandler 接口。函数内声明 `const uiStore = useUIStore()` 和 `const graphStore = useGraphStore()`，然后：

- `onNodeClick(nodeId)`：在 graphView 中查找节点 → `uiStore.openFloatingWindow(node)`
- `onEdgeClick(edgeId)`：在 graphView 中查找边 → `uiStore.openFloatingWindow(edge)`
- `activate` / `deactivate`：空操作（默认工具不设显式状态切换）
- `isActive`：始终返回 true（baseline tool 始终"活跃"）
- `cursorClass`：null（默认指针）
- `notification`：null

### 2. `mediator.ts` 新增 default 工具 fallback

当前 `onNodeClick` / `onEdgeClick` / `onCanvasClick` 仅检查 `activeHandler.value?.xxx`。`activeHandler` 为 null 时（工具自取消后）事件直接丢弃，default 工具永远不会被触发。

在三个事件转发方法中新增 fallback 逻辑：

```
activeHandler 存在 + 有对应回调 → 走 handler
activeHandler 不存在               → fallback 到 registry.get('default') 的回调
```

不修改接口签名、不修改 `activate` / `deactivate` 机制。仅在事件转发层增加一段 else 分支。

### 3. `Graph.vue` 事件路由简化

- 在 `onMounted` 中注册 default 工具：`mediator.register('default', useDefaultTool())`
- 删除 `onNodeClicked` 回调中的 `if (activeHandler?.onNodeClick)` 分叉——改为统一调 `mediator.onNodeClick(nodeId)`。default 工具作为未匹配其他 handler 时的 fallback 自动生效
- 删除 `onEdgeClicked` 回调中的同理分叉
- `onNodeDoubleClicked` 中的导航拦截检查需更新：原检查 `mediator.activeHandler.value?.onNodeClick` 在 default 工具始终注册后会误拦截。改为检查 `activeToolId` 不为 null 且不为 `'default'`——即"有非默认工具激活时禁止导航"

### 4. `operation_controller.ts` 清理

删除以下公开 API：

- `handleNodeClicked` 函数 + `NodeClickedPayload` / `EdgeClickedPayload` 类型（迁入 default.ts）
- `closeFloatingWindow` 函数
- `requestCanvasFocus` 函数
- `clearCanvasFocus` 函数
- `ui` 字段
- `CanvasClickedPayload` 类型（已无消费者？确认后决定）

保留不动：

- `induce` / `internalize` / `diverge` / `moveNode` / `explore` / `unearth`
- `computeNodeRadiusOverrides` / `findCommonLayer` 私有辅助
- 文件头注释更新为反映当前职责

`CanvasClickedPayload` 如果当前无消费者则一并删除。

### 5. `GraphNodeWindow.vue` 解耦

- 删除 `const controller = useOperationController()`
- 新增 `const uiStore = useUIStore()`
- `controller.closeFloatingWindow()` → `uiStore.closeFloatingWindow()`
- `controller.ui.state.floatingWindowData` → `uiStore.floatingWindowData`
- `controller.ui.state.xxx` 形式的所有引用 → `uiStore.xxx`
- 删除 `import { useOperationController }`

### 6. `GraphNavigationCard.vue` 解耦

- 删除 `const controller = useOperationController()`
- 新增 `const uiStore = useUIStore()`
- `controller.closeFloatingWindow()` → `uiStore.closeFloatingWindow()`
- `controller.requestCanvasFocus(id)` → `uiStore.requestCanvasFocus(id)`
- 删除 `import { useOperationController }`

### 7. `Graph.vue` 解耦 controller 非路由 API

- 新增 `const uiStore = useUIStore()`
- `operationController.closeFloatingWindow()` → `uiStore.closeFloatingWindow()`
- `operationController.requestCanvasFocus(id)` → `uiStore.requestCanvasFocus(id)`
- `operationController.clearCanvasFocus()` → `uiStore.clearCanvasFocus()`
- `operationController.ui.state.pendingCanvasFocusId` → `uiStore.pendingCanvasFocusId`
- 如果 Graph.vue 不再使用 controller 除 compose 库存外的任何 API，则删除 `const operationController = useOperationController()` 和对应 import

注意：GraphModeSelector.vue 仍通过 controller 调用 compose 库存函数，所以 operation_controller 的 import 不能全局删除——只在不再需要的文件中解耦。

## Scope Guard

禁止修改以下内容：

- compose 库存函数（`induce` / `internalize` / `diverge` / `moveNode` / `explore` / `unearth`）及私有辅助
- `mediator.ts` 的接口签名和 `activate` / `deactivate` 机制（仅允许在事件转发方法内部新增 default 工具 fallback 逻辑）
- `feature-tools/types.ts`
- `GraphNodeWindow.vue` 的 Confirm / Cancel 写入逻辑
- `GraphModeSelector.vue` 中对 controller compose 函数的调用
- `graphStore` / `draft_store` / `graph_persistence`
- `feature-tools/cognition/deconstruct.ts` 及其他已有 handler
- 实现 update handler（3.0-3 的工作）
