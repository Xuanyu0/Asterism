## 当前状态

`operation_controller.ts` 中 `moveNode` 是单次调用的位置 setter（无拖拽交互，无状态机）。Cytoscape 全局 `autoungrabify: true`，节点不可原生拖拽。`ToolHandler` 接口无鼠标追踪事件。`ArrangementTool` 类型已包含 `'move'`，但无对应 handler。

引擎 `composeMoveNode` 已就绪：返回 `{ drafts, issues, operations }`，`hasCollisionAt` 自动排除 `nodeId` 自身（`collision.ts:127`）。

`mediator.ts` 的 `onRightClick` 当前无条件调用 `deactivate()`，所有工具栏工具的右键行为未区分"取消内部操作"和"退出工具"。

## 核心任务

### 1. `getCy()` getter

在 `use_cytoscape_renderer.ts` 中，cy 实例创建后存入 module 级变量，导出 getter 函数供外部读取。cy 销毁时清空变量。

### 2. `onRightClick` 可选方法

`ToolHandler` 新增 `onRightClick?(): boolean`。`mediator.ts` 的 `onRightClick` 先调 `activeHandler.value?.onRightClick?.()`——返回 `true` 则跳过 `deactivate()`；返回 `false` 或 `undefined` 则走原 deactivate 逻辑。

### 3. 常驻工具栏右键对齐

已有 4 个 toolbar handler 各自实现 `onRightClick`，返回 `true` 阻止 mediator 的默认 deactivate。各自行为：

- **add-node**：取消 `draftNode` 状态，回到待点击状态
- **add-edge**：取消内部待定状态（如有），回到待选择状态
- **delete**：清除待删除目标（`pendingTarget`），回到待选择状态
- **fold**：无内部待定状态，返回 `true` 即可保持激活

### 4. move_node handler（核心）

新建文件，实现 ToolHandler 完整接口。

**拾取放置流程**：

```
激活工具（待拾取，光标 crosshair）
  → 左键点击节点 → 拾取（已拾取，节点跟随光标，原位置节点不可见）
  → 鼠标移动 → 节点跟随（仅 Cy 视觉层，有碰撞时红色高亮）
  → 左键再点击 → 放置尝试：composeMoveNode → collision check
     ├→ 无碰撞 → applyBatch → 写入成功 → 回到待拾取
     └→ 有碰撞 → 拒绝放置，节点红色高亮，notification 提示，
                  节点保持在当前位置（不弹回），用户可微调光标后重试
  右键（已拾取状态） → 取消拾取 → 弹回原位 → 回到待拾取 → 返回 true
  Escape / 点其他按钮 → deactivate
```

**内部状态**：工具激活后在以下两种状态间切换：

- 待拾取：等待用户点击节点，光标 `cursor-crosshair`
- 已拾取：节点已拾取并跟随光标，等待放置或取消

**各方法实现点**：

- `activate()`：进入待拾取状态；注册 `mousemove` DOM 事件监听（`cy.container()` 上 `addEventListener('mousemove', ...)`）；光标设为 `cursor-crosshair`
- `deactivate()`：卸载 `mousemove` 监听；如果处于已拾取状态则弹回节点到 originalPosition、恢复节点可见（`opacity: 1` 或移除 `visibility: hidden`）
- `onNodeClick(nodeId)`：
  - 待拾取 → 进入已拾取：记录 `nodeId` + `originalPosition`；设 Cy 节点原位置不可见
  - 已拾取 → 放置尝试
- `onCanvasClick(pos)`：已拾取状态 → 放置尝试
- `onRightClick()`：已拾取状态 → 取消拾取（弹回 originalPosition，恢复原位置节点可见），回到待拾取，返回 `true`；待拾取状态 → 返回 `false`（走 mediator deactivate）
- `cursorClass`：待拾取时 `'cursor-crosshair'`，已拾取时 `null`
- `notification`：碰撞时显示 "节点在目标位置与已有节点碰撞，无法放置。"，附带 `onCancel`：取消拾取回到待拾取

**鼠标追踪**（仅在已拾取状态下生效）：

- DOM `mousemove` 事件绑定在 `cy.container()` 上
- 每帧更新：计算光标在 Cy 画布坐标系中的位置 → `cy.getElementById(nodeId).position({x, y})`
- `deactivate()` 和取消拾取时必须卸载

**放置尝试**：

- 计算当前视觉位置作为 `desiredPosition`
- 调 `composeMoveNode({ nodeId, desiredPosition, allNodes, nodeRadiusOverrides })`，其中 `nodeRadiusOverrides` 通过 `computeNodeRadiusOverrides(graphView)` 获得（该函数从 `operation_controller.ts` 复制到本文件）
- 无 collision → `graphStore.applyBatchToGraph(graphView, result.operations)` → 回到待拾取
- 有 collision → 拒绝写入，节点不弹回原位，设置被拾取节点 Cy 样式为红色高亮（如 `border-color: #ef4444`），显示 notification "节点在目标位置与已有节点碰撞，无法放置。"，保持已拾取状态。后续 `mousemove` 时清除红色高亮恢复正常样式；再次左键点击若仍有碰撞则重新弹出 notification

### 5. toolbar 按钮 + GraphOperationToolbar.vue CSS 确认

`toolbar/registry.ts` 新增 move 条目。使用 `ArrowsPointingOutIcon`（`@heroicons/vue/24/outline`），`label: '移动节点'`。与 delete / fold 同组，追加到工具栏最右侧（第 9 个按钮，工具组第 3 个）。

`GraphOperationToolbar.vue`：move 按钮作为第 9 个 `nth-child`，仍在工具组内（组间间距由 `nth-child(7)` 的 `margin-left: 8px` 覆盖），CSS 无需变更。**仅需验证**，不修改。

### 6. 清理 operation_controller

移除：

- `moveNode` 函数体
- `import { moveNode as composeMoveNode }`（来自 `@my-project/graph-engine`）
- `computeNodeRadiusOverrides` 函数（迁入 `move_node.ts`）

`findCommonLayer` 不受影响（仅被其他 compose 函数使用）。
