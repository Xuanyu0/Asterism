# 3.0-1 统一激活框架

> 步骤文档：[05-步骤-共依赖.md](../../../P2开发文档/phase2b/05-步骤-共依赖.md#30-1-统一激活框架-)

---

## 设计文档依据

- `CLAUDE.md` § 工具 UI/UX 层：mediator 负责工具生命周期管理（注册、激活/取消、互斥保证）。同一时刻最多一个工具激活。
- `05-步骤-共依赖.md` § 3.0-1：mediator 成为唯一激活管理者，ui_store 退化为展示状态，operation_controller 退化为默认路由。
- `05-步骤-共依赖.md` § 终态目标：所有工具（工具栏 + 认知 + 布局）统一通过 mediator 激活，互斥约束天然满足。

## 当前状态

两套并行的激活系统：

```
mediator（管工具栏 8 工具）             ui_store + operation_controller（管认知/布局）
  activeToolId → activeHandler              interactionMode → selectedCognitionTool
  activate('add-real-node') ✓               'deconstruct' 通过 if-else 分派 ✓
  activate('deconstruct') ✗                 同一个工具两套代码路径
```

`Graph.vue` 用 "handledByRouter" 分叉拼接两者。`ui_store.ts` 持有 `interactionMode`、`selectedCognitionAction`、`selectedArrangementAction` 三个工具选择状态。`operation_controller.ts` 通过 if-else 检查 `selectedCognitionAction` 分派认知操作。

## 架构变更

```
旧                                        新
──                                        ──
mediator — 仅管 OperationTool              mediator — 管全部 ToolId
ui_store — 持有工具选择状态                 ui_store — 纯展示（浮空窗等）
operation_controller — 模式管理 + 分派     operation_controller — 默认路由 + compose 库存
Graph.vue — if-else 分叉路由              Graph.vue — 统一走 mediator.activeHandler
GraphModeSelector.vue — 走 controller      GraphModeSelector.vue — 走 mediator
```

关键原则：**deconstruct handler 自包含 compose 逻辑**（与 toolbar handler 一致），不依赖 operation_controller 的 compose 函数。其余 compose 函数（induce/internalize/diverge/moveNode）保留在 operation_controller 作为待迁移库存。

## 核心任务

### 任务 1：类型统一——ui_types.ts 全量迁入 feature-tools/types.ts

**1a. 迁入 + 重命名**：将 `frontend/src/types/ui_types.ts` 的全部类型定义迁入 `frontend/src/feature-tools/types.ts`。迁入时：
- `CognitionAction` → 重命名为 `CognitionTool`
- `ArrangementAction` → 重命名为 `ArrangementTool`
- `OperationTool` → 保持不变
- 新增 `ToolId` 联合类型：`export type ToolId = OperationTool | CognitionTool | ArrangementTool`
- 类型成员和 JSDoc 不变——仅改名或新增
- 注意 `feature-tools/types.ts` 当前已有的 `ToolId = OperationTool`（纯 import 重导出）替换为上述联合类型

**1b. 删除 ui_types.ts**：确认所有 import 更新后，删除 `frontend/src/types/ui_types.ts`。

**1c. 全局更新引用**：所有 `import ... from '@/types/ui_types'` 改为 `import ... from '@/feature-tools/types'`。`CognitionAction` → `CognitionTool`，`ArrangementAction` → `ArrangementTool`。涉及的文件由 fixer 通过 grep 全量定位后批量替换。

### 任务 2：mediator 清理

**mediator.ts**：`onRightClick` 函数中移除清理 `uiStore.selectedCognitionAction` 和 `uiStore.selectedArrangementAction` 的代码（当前第 99-104 行）。`onRightClick` 仅保留 `deactivate()` 调用。

`activate` 函数签名和行为不变——参数类型 `ToolId | null` 因 `ToolId` 类型定义扩展而自动接受认知/布局工具 ID。`registry` 的类型自动跟随 `ToolId` 扩展。

### 任务 3：ui_store 清理

**ui_store.ts**：移除以下内容：

- 三个响应式状态：`interactionMode`、`selectedCognitionAction`、`selectedArrangementAction`
- 三个 setter 函数：`setInteractionMode`、`selectCognitionAction`、`selectArrangementAction`
- 类型 import 中的 `InteractionMode`、`CognitionAction`、`ArrangementAction`（如无其他使用则移除）
- return 对象中上述 6 个条目的暴露
- 文件头注释中相关描述

所有其他状态（`floatingWindowData`、`canvasFocusTarget` 等）保持不变。

### 任务 4：operation_controller 清理

**operation_controller.ts**：

- 移除 4 个模式管理函数：`enterCognitionMode`、`enterArrangementMode`、`selectCognitionAction`、`selectArrangementAction`
- 简化 `handleNodeClicked`：删除 `if (uiStore.selectedCognitionAction === 'deconstruct')` 分支。函数仅保留"无工具时打开浮空窗"逻辑
- 移除 `handleNodeClicked` 中不再需要的 import（如 `CognitionTool` 类型，若无其他使用）
- `deconstruct` compose 逻辑迁出至 deconstruct.ts handler——controller 中不再保留
- return 对象移除上述 4 个模式函数 + `deconstruct` 条目
- 更新类型引用：`CognitionAction` → `CognitionTool`，`ArrangementAction` → `ArrangementTool`
- 其余 compose 函数（`induce` / `internalize` / `diverge` / `moveNode` / `explore` / `unearth`）保留不变
- `closeFloatingWindow`、`handleNodeClicked`、`handleEdgeClicked`、`requestCanvasFocus`、`clearCanvasFocus`、`ui.state` 保留不变

### 任务 5：deconstruct.ts handler 新建

在 `frontend/src/feature-tools/cognition/deconstruct.ts` 新建文件，实现 ToolHandler 接口。deconstruct 是认知工具中最简单的——单节点、单图、无草稿、无预览。

handler 自包含 compose 逻辑——直接 import engine compose 函数和 graphStore，不依赖 operation_controller：

- `activate()`：设置内部 `isActive = true`，无额外操作
- `deactivate()`：设置 `isActive = false`
- `onNodeClick(nodeId)`：调 `composeDeconstruct` → 判 issues → `graphStore.applyBatchToGraph` → 写 `lastValidationResult` → 调 `mediator.deactivate()` 取消自身（单次操作完成后自动退出）
- `cursorClass`：返回 `'cursor-deconstruct'`（crosshair）
- `id`：返回 `'deconstruct'` 字符串
- `isActive`：内部 ref
- `notification`：返回 null

handler 编译逻辑与 toolbar handler（如 add-node.ts）模式一致——自包含、无外部 compose 依赖。

### 任务 6：GraphModeSelector.vue 适配

**GraphModeSelector.vue**：

- 新增 import `useToolMediator`，获取 `const mediator = useToolMediator()`
- 移除对 `uiStore.interactionMode`、`uiStore.selectedCognitionAction` 的读取——这些字段已从 ui_store 移除
- 模式切换按钮（cognition / arrangement）：改为调用 `mediator.deactivate()` 切换模式列显隐（不再设 interactionMode）
- 认知子工具按钮（deconstruct / induce / internalize 等）：`v-on:click` 改为 `mediator.activate('deconstruct')` 等
- `active` class 判断：改为检查 `mediator.activeToolId.value === 'deconstruct'` 等
- 移除不再需要的 `useOperationController` import（如已无其他使用）
- 移除不再使用的 `watch` 对 `interactionMode` 的监听

注意：induce / internalize / diverge 等按钮在 3.0-1 中只是"可点击但无 handler"——`mediator.activate('induce')` 不会找到 handler（因为 handler 尚未注册），`activate` 函数内 `registry.get(id)` 返回 undefined 后直接 return，无副作用。这些按钮的视觉状态（如灰色）由 mediator 是否有对应 handler 决定。

### 任务 7：Graph.vue 事件路由统一

**Graph.vue**：

- `onNodeClicked` 回调：删除 `handledByRouter` 判断和 if-else 分叉。改为统一走 `mediator.onNodeClick(nodeId)`，无论 handler 是否实现 `onNodeClick`。无 handler 时由 `operationController.handleNodeClicked` 打开浮空窗——保持现有回退逻辑，但不再有条件分叉
- `onEdgeClicked` 回调：同上——统一走 mediator
- `onRightClick` 回调：不变（`mediator.onRightClick()` 已清理）
- cursor computed 属性：删除对 `s.selectedCognitionAction === 'deconstruct'` 的检查。改为从 `mediator.activeHandler.value?.cursorClass` 读取——当 deconstruct handler 激活时返回 `'cursor-deconstruct'`

Graph.vue 中 `onMounted` 需确保 deconstruct handler 已注册到 mediator：

```ts
// 伪代码——注册 deconstruct handler
mediator.register('deconstruct', useDeconstructTool())
```
