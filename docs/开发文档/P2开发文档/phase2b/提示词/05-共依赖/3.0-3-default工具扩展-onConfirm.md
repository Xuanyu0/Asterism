# 3.0-3 default 工具扩展 — 浮空窗 Confirm 走 mediator

> 步骤文档：[05-步骤-共依赖.md](../../../P2开发文档/phase2b/05-步骤-共依赖.md) § 3.0-3

## 设计文档依据

- **CLAUDE.md** — "工具"定义：用户主动激活的互斥状态，画布交互解释为该工具语义，最终写 GraphData。默认模式是特殊的非显式工具，其完整语义包括"查看 → 编辑 → 保存"。
- **CLAUDE.md** — GraphData 唯一事实源：修改 GraphData 的唯一合法路径是 graphStore.applyBatch。

## 当前状态

3.0-2 的默认工具（`feature-tools/default.ts`）实现了 ToolHandler 接口的交互路由：

```
onNodeClick → uiStore.openFloatingWindow → 用户编辑属性 → ???
```

但 "浮空窗 Confirm → 写入 GraphData" 仍在 `GraphNodeWindow.vue` 中直调 `graphStore.applyBatchToGraph`：

```
// GraphNodeWindow.vue:208-259（当前）
confirmExistingNodeEdit(node):    graphStore.applyBatchToGraph(graphView, [{ type: 'update_node', node }])
confirmExistingEdgeEdit(edge):    graphStore.applyBatchToGraph(graphView, [{ type: 'update_edge', edge }])
handleFloatingConfirm():          调用上述两者之一 + uiStore.closeFloatingWindow()
```

**问题**：写入路径绕过 mediator 管线，默认工具只覆盖了一半流程。

**对照**：add-node 工具的 Confirm 走的是 ToolHandler 路径：

```
handleConfirmDraftNode() → active.onConfirm(draft.label, draft.summary)
```

## 架构变更

### 旧：GraphNodeWindow Confirm 直调 graphStore

```
handleFloatingConfirm()
  → confirmExistingNodeEdit / confirmExistingEdgeEdit
    → graphStore.applyBatchToGraph()
    → uiStore.closeFloatingWindow()
```

### 新：GraphNodeWindow Confirm 走 mediator

```
handleFloatingConfirm()
  → mediator.activeHandler?.onConfirm?.(label, summary)
    → default.onConfirm(label, summary):
        → 从 uiStore.floatingWindowData 获取原始实体
        → 构造 update_node / update_edge operation
        → graphStore.applyBatchToGraph()
        → uiStore.closeFloatingWindow()
```

**设计要点**：
- `onConfirm(label, summary)` 签名**不变**。label/summary 来自 editingData，现有签名已足够。默认工具从 `uiStore.floatingWindowData` 获取实体身份（ID、类型），将 label/summary 覆盖到克隆体上，构造 GE operation。
- add-node 的 `onConfirm(label, summary)` 不受影响——两者共享同一接口签名，语义不同：add-node 用于草稿创建，default 用于已有实体修改。

## 核心任务

### 1. `default.ts` 新增 `onConfirm` 实现

在 `useDefaultTool()` 返回值中新增 `onConfirm(label: string, summary: string)` 方法：

- 读取 `uiStore.floatingWindowData` 获取当前被编辑的实体
- 若为空（防御——浮空窗异常关闭），提前返回
- 判断实体类型（node vs edge，通过 isEdgeData 判别）：
  - 若为节点：克隆原节点 → 覆盖 `label` → 若为 KnowledgeNode 则覆盖 `summary` → 构造 `[{ type: 'update_node', node }]` 操作
  - 若为边：克隆原边 → 覆盖 `label` → 构造 `[{ type: 'update_edge', edge }]` 操作
- 调用 `graphStore.applyBatchToGraph(graphView, operations)`
- 设置 `graphStore.lastValidationResult`
- 若校验通过，调用 `uiStore.closeFloatingWindow()`

### 2. `GraphNodeWindow.vue` Confirm 走 mediator

- **删除** `confirmExistingNodeEdit`（L208-223）和 `confirmExistingEdgeEdit`（L235-250）
- **重写** `handleFloatingConfirm()`（L252-262）：
  - 检查 `editingData` 非空（保持）
  - 调用 `mediator.activeHandler.value?.onConfirm?.()`
  - 参数：`editingData.label ?? ''` 作为 label，若为 KnowledgeNode 则传 `(editingData as KnowledgeNodeData).summary ?? ''` 作为 summary，否则传空串
  - 清除 `editingData = null`（保持）

**注意**：`handleConfirmDraftNode`（L155-163）已走 mediator 管线，不需要改动。
