## 核心任务

### 1. `useDragPosition` — 拖拽通用能力

从 `GraphNavigationCard.vue` 的拖拽逻辑中提取。

对外接口：

```ts
function useDragPosition(options: {
  storageKey?: string
  defaultPosition: { x: number; y: number }
  margin?: number
  snap?: { threshold: number; margin: number }
  onDragEnd?: (pos: { x: number; y: number }) => void
}): {
  position: Ref<{ x: number; y: number }>
  isDragging: Ref<boolean>
  elementRef: Ref<HTMLElement | null>
  handlers: {
    onPointerdown: (e: PointerEvent) => void
    onPointermove: (e: PointerEvent) => void
    onPointerup: (e: PointerEvent) => void
  }
  clampToViewport: () => void
}
```

行为：

- pointer capture 锁定到手柄元素
- pointermove 拖拽期间实时 clamp 到视口（距离视口边缘 ≥ margin）
- pointerup 时执行 snap（若提供 snap 参数）→ 触发 onDragEnd 回调 → 若提供 storageKey 则持久化到 localStorage
- clampToViewport 供外部在 resize / mount 后调用
- 接口不出现 `nav-card` 字样

### 2. `useAutoFade` — 淡化通用能力

从 `GraphNavigationCard.vue` 的淡化逻辑中提取。

对外接口：

```ts
function useAutoFade(options: {
  delay?: number
  opacity?: number
  preventFade: Ref<boolean>
}): {
  isFaded: Ref<boolean>
  onPointerEnter: () => void
  onPointerLeave: () => void
}
```

行为：

- pointer 离开后 delay ms 后 isFaded → true
- pointer 进入 → 立即清除 timer，isFaded → false
- preventFade 为 true 时不启动 timer
- opacity 控制淡化目标值（而非硬编码 0.35）

### 3. `useOverflowDetection` — DOM 溢出检测

从 `GraphNavigationCard.vue` 的路径截断逻辑中提取。接口不绑定路径语义，diverge 搜索浮窗等水平溢出场景可复用。

对外接口：

```ts
function useOverflowDetection(element: Ref<HTMLElement | null>): {
  isOverflowing: Ref<boolean>
  measure: () => Promise<void>
}
```

规则：

- composable 不主动 watch 任何东西——何时测量由调用方决定
- `measure()` 内部 `await nextTick()` 后判断 `element.scrollWidth > element.clientWidth + 1`（1px 容差吸收亚像素舍入）
- 调用方在 onMounted、watch(pathSegments)、onWindowResize 中自行调 `measure()`

### 4. `NavigationCardDock.vue` — Dock 行

- props：`pathSegments: PathSegment[]`、`parentGraphId: GraphId | null`、`isAtRoot: boolean`、`activePanel: PanelKind`、`dragHandlers: { onPointerdown, onPointermove, onPointerup }`
- emits：`go-parent-graph` / `go-root-graph` / `go-segment-graph(graphId: GraphId)` / `toggle-search` / `toggle-navigation`
- 四个导航 emit 在编排器统一走 `(graphId) => switchGraphTo(graphId)`，Dock 内部自己算出 graphId
- 内部使用 `useOverflowDetection(pathStripElement)` 管理路径截断检测，watch `pathSegments` 触发重测
- 不向编排器暴露 `isOverflowing` 或 `pathStripElement`——编排器无需关心截断状态
- 模板：grip handle（六点握把）+ 返回按钮 + logo 按钮 + 面包屑路径条 + 搜索按钮 + 分隔线 + 导航面板按钮
- 样式跟随当前 Dock 行样式，不做重新设计

### 5. `NavigationPanel.vue` — 根图谱 CRUD 面板

- props：`currentRootId: GraphId | null`
- emits：`switch-root-graph(graphId: GraphId)`、`close`
- 内部 import graphStore，自管理 `rootSummaries` / `newRootTitle` / `armedDeleteId` 状态
- 根图谱列表点击 → emit switch-graph
- 删除二次确认（与删除工具交互一致）
- 创建表单：输入标题 → 创建 → emit switch-graph → emit close
- 占位按钮：笔记库 / 常识层 / 设置（disabled，与当前模板一致）
- 样式跟随当前导航面板样式，不做重新设计

### 6. `SearchPanel.vue` — 搜索面板

- props：无
- emits：`focus-element(elementId: string)`、`close`
- 内部 import graphStore，自管理 `searchQuery` / `searchResults` computed
- 输入即时匹配节点/边标签（大小写不敏感），最多 8 条
- Enter 选中第一条 → emit select；Escape → emit close
- 空查询显示提示文字，无结果显示"无匹配结果"
- 结果项左侧类型标识（节点圆点 + 边短线）与当前模板一致
- 每次 v-if 重建时搜索状态自动重置（由编排器的 :key 控制）

### 7. 编排器 `GraphNavigationCard.vue` 重写

setup 只做：

- 调 `useDragPosition({ storageKey: 'nav-card-position', defaultPosition: {x:52,y:12}, margin:8, snap:{threshold:32,margin:12} })`
- 调 `useAutoFade({ preventFade: computed(() => hasOpenPanel.value || isDragging.value) })`
- 持有 `activePanel` + `hasOpenPanel`（computed）+ `panelOpensUpward`（computed）+ `panelTransitionName`
- 持有 `pathSegments` / `parentGraphId` / `currentRootId` / `isAtRoot`（computed from graphStore）
- 持有 `switchGraphTo`（调用 controller.closeFloatingWindow + mediator.deactivate + graphStore.loadGraphToView）
- 持有 `toggleNavigationPanel` / `toggleSearchPanel` / `closePanels`
- 持有全局事件：`onDocumentPointerdown`（outside click 关闭面板）、`onDocumentKeydown`（Ctrl+K / Escape）
- 生命周期：onMounted（绑定全局事件 + window resize）+ onBeforeUnmount（解绑 + 清理 timer）

template 只做：

- nav-card 容器（position + fade class + pointer 事件）
- NavigationCardDock（props 下行 + emits 上行）
- Transition 内 v-if 切换 NavigationPanel / SearchPanel

编排器不持有 `useOverflowDetection`——溢出检测由 `NavigationCardDock` 内部自管理。
