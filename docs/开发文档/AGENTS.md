# 开发文档写作约定

本文件描述 `docs/开发文档/` 下所有开发文档的格式约束。当在本目录下工作时自动加载。

## 格式依赖来源

以下格式是 `scripts/dev-status.sh` 脚本的解析契约。改变格式前必须同步更新脚本。

---

## 目录结构

```
docs/开发文档/{阶段名}/
├── AGENTS.md
├── {阶段名}/
│   ├── 00-总纲.md              ← 步骤总览表
│   ├── 步骤/                    ← 步骤文档（不含 "步骤-" 前缀）
│   │   ├── 01-设计文档补完.md
│   │   └── ...
│   ├── 发现/                    ← 发现文档（文件名与步骤文档相同）
│   │   ├── 03-规则系统.md
│   │   └── ...
│   └── 提示词/                  ← 执行契约（目录名以步骤编号开头）
│       ├── 04-多根图谱切换/
│       └── 05-共依赖/
```

**命名规则**：步骤文档放在 `步骤/` 目录下，发现文档放在 `发现/` 目录下，两者使用相同的文件名（不含类型前缀）。例如步骤文件 `步骤/01-设计文档补完.md`，对应的发现文件为 `发现/01-设计文档补完.md`。

---

## 总纲文件 (`00-总纲.md`)

### `## 开发步骤` 表格

总纲文件中必须包含一个 `## 开发步骤` 小节，其下第一个 Markdown 表格有固定的 4 列：

```
| # | 文件 | 内容 | 状态 |
|---|------|------|------|
| NN | [显示文字](文件名.md) | 一句话描述 | ✅/🔨/空 |
```

**列约束**：

| 列 | 要求 |
|------|------|
| `#` | 步骤编号。纯数字前缀（如 `01`、`050`） |
| `文件` | Markdown 链接 `[显示文字](文件名.md)`。括号内的文件名必须与 `步骤/` 目录下的实际文件名精确一致。显示文字可包含 "步骤-" 前缀供人阅读 |
| `内容` | 步骤的一句话描述。脚本不读此列 |
| `状态` | `✅`：已完成 / `🔨`：进行中 / 空：未开始 |

**规则**：

1. 表格放在 `## 开发步骤` 二级标题的正下方
2. 表格不含难度列——难度在各自步骤文件中
3. 新增步骤必须追加一行；删除步骤同步删行
4. 步骤完成后状态必须更新为 `✅`，不得留空或保持 `🔨`
5. 链接文件名 `.md` 后缀不可省略，不含目录前缀（`步骤/` 由脚本自动拼接）

**示例**：

```markdown
| 05 | [05-步骤-共依赖](05-共依赖.md) | 多选机制 + 拾取放置基础设施 | ✅ |
```

---

## 步骤文档 (`步骤/NN-xxx.md`)

- 文件放在 `步骤/` 子目录下
- 文件名不含 `步骤-` 前缀（目录已表达类型）
- 步骤标题用 `## Step N：...` 格式
- 子步骤用 `### N.N ...` 格式
- 状态标记 `✅` / `⏳` 放在标题行末尾

## 发现文档 (`发现/NN-xxx.md`)

- 文件放在 `发现/` 子目录下
- 文件名与对应步骤文档完全相同
- 待确认事项标记格式：`状态：⏳ 待确认`
- 已确认事项标记格式：`状态：✅ 已确认`

## 提示词文件 (`提示词/`)

- 位于阶段目录下的 `提示词/` 子目录
- 子目录名以步骤编号开头（如 `05-共依赖`）
- 目录内的 `.md` 文件数为该步骤的执行契约数量

---

## 脚本如何使用这些格式

| 脚本读取 | 来自 | 用于 |
|------|------|------|
| `grep '^## 开发步骤'` | 总纲 | 定位表格起始行号 |
| `cut -d'\|' -f2` | 总纲表格 | 提取步骤编号 |
| `cut -d'\|' -f3` + `sed 's/.*(//;s/).*//'` | 总纲表格 | 提取文件名 |
| `cut -d'\|' -f5` | 总纲表格 | 提取状态（✅/🔨/空） |
| `stat -c %Y "$D/步骤/$file"` | 文件系统 | 步骤文档最后修改时间 |
| `grep '状态：⏳' "$D/发现/$file"` | 发现文档 | 统计待确认事项数 |
| `find "$D/提示词/" -type d -name "NN-*"` | 文件系统 | 检查是否有执行契约 |
