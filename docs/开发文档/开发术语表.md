# 开发术语表

> 本表服务对象：代码库（`frontend/` + `packages/graph-engine/`）的阅读与检索。
>
> 服务对象与入口见 `CLAUDE.md` 的「文档地图与任务落点」。
>
> 说明：来源含 `设计/` 的条目仅收录代码标识符部分（中文翻译 + 代码标识符 + 含义），其概念定义见 `docs/设计/设计术语表.md`。

## 编写规则

1. **字段格式**：每行统一为 `中文翻译 | 代码标识符 | 含义` 三列。
2. **代码标识符**：代码中的实际名称（类型、函数、文件、字段等），**不是英文翻译**。英文翻译一律不进本表，请查 `docs/设计/设计术语表.md`。
3. **术语来源**：默认术语直接来源于已有代码。开发文档中的描述不作为术语来源。
4. **用途**：连接中文术语与代码标识符，用于 grep 检索、跨文件定位。
5. **列缺失**：某一列确无内容时用 `-` 标记缺失，并用 `()` 注明理由（如 `-（无对应单一标识符）`）。
6. **标识符解析**：每个标识符用独立反引号包裹，脚本按反引号提取标识符；多个标识符用 `, `（逗号+空格）分隔；不使用括号（括号仅用于规则 5 的缺失理由）。
7. **标识符可解析性**：反引号内必须是代码中独立可完整 grep 的代码片段。尽量不要在同一行内罗列一个概念的子概念标识符或名称——子概念靠含义列表达。
8. **标识符存活校验**：本表反引号内标识符由 `scripts/check_dev_terms.py` 在 pre-commit 校验存在性；新增/更名公开标识符必须同步本表。
9. **结构性约束**：不得改动 `## 术语表` 标题与三列列序，否则 pre-commit 校验会静默失效。
10. **不定义文件 / 目录 / 层**：本表只做「中文 ↔ 标识符」检索；文件、目录、分层的结构定义见 `CLAUDE.md` §项目架构，本表不复述。

### 二、GraphEngine 术语

#### 核心概念

| 中文翻译 | 代码标识符 | 含义 |
| --- | --- | --- |
| 图数据 | `GraphData` | 系统的唯一事实源，包含节点列表 + 边列表 + 图元信息 |
| 节点 | `NodeData` | 图中的知识单元，按 `NodeRole` 分型 |
| 边 | `EdgeData` | 知识间关系的表示，由 kind × direction 确定 |
| 节点角色 | `NodeRole` | 节点第一层判别（取值 `'knowledge'` 知识节点 / `'reference'` 引用节点） |
| 掌握阶段 | `KnowledgeNodeKind` | 知识节点第一层判别（取值 `'real'` 实节点 / `'virtual'` 虚节点） |
| 实节点 | `'real'`, `RealNodeForm` | 已掌握的知识节点（kind 为 `'real'`）；`RealNodeForm` 为其派生形式（取值 `'atomic'` 原子 / `'abstract'` 抽象） |
| 虚节点 | `'virtual'` | 未掌握的知识节点（kind 为 `'virtual'`），圆形，固定半径 r₀ |
| 知识节点 | `KnowledgeNodeData` | 表达知识的本体 |
| 原子节点 | `'atomic'` | 基础实节点，圆形，不可再分 |
| 抽象节点 | `'abstract'` | 拥有子图的实节点，正多边形，边数 = 抽象等级 + 2 |
| 引用节点 | `ReferenceNodeKind` | 原节点在其他图中的代理/投影（取值 `'communication'` 沟通 / `'heuristic'` 启发） |
| 沟通节点 | `'communication'` | 子图中联系父图的引用节点 |
| 启发节点 | `'heuristic'` | 通过发散操作创建的跨图引用节点 |
| 度数 | `degree` | 节点连接的边数。决定节点质量进而决定节点大小 |
| 认知抽象等级 | `abstractionLevel` | 内部最大子图层数，系统决定，用户不可改 |
| 图类型 | `GraphKind` | 图的四种类型 |
| 根图谱 | `root` | 无父图，整个知识系统的根 |
| 子图 | `'subgraph'` | 抽象节点内部的展开 |
| 知识块 | `'learningBlock'` | 单轮学习的临时游离产物 |
| 常识层 | `'commonLayer'` | 已内化的知识集合，仅含节点，无边 |
| 认知状态 | `cognitiveState` | 折叠/展开标记，GraphData 必选属性（fold 是标准原子操作） |

#### 边

| 中文翻译 | 代码标识符 | 含义 |
| --- | --- | --- |
| 有向实边 | `kind: 'real'`, `direction: 'directed'` | A → B，B 依赖于 A 作为前置知识。禁止成环 |
| 有向虚边 | `kind: 'virtual'`, `direction: 'directed'` | A -·→ B，启发联想。不参与环检测 |
| 无向实边 | `kind: 'real'`, `direction: 'undirected'` | A — B，明确相关，无方向 |
| 无向虚边 | `kind: 'virtual'`, `direction: 'undirected'` | A -·- B，待发掘的关联。唯一非终态边类型 |

#### 操作日志与回溯（types/operation_log.ts）

| 中文翻译 | 代码标识符 | 含义 |
| --- | --- | --- |
| 原子操作 | `AtomicOperation` | 最小图数据修改单位，定义为"正向操作 + 其代数逆元"的配对（op ↔ op⁻¹，逆元由 `reversal` 构造器从操作前状态捕获）——由执行函数（`executeOperation` / `executeGraphOperation`）纯函数式处理，不产生用户语义（业务语义属复合操作），不执行合法校验（合法性由批层前置条件校验 + 图不变量兜底）；范围涵盖图内（`AtomicOperationInGraph`）与图级（`AtomicGraphOperation`） |
| 图内原子操作 | `AtomicOperationInGraph` | 单图变换的原子操作（节点/边增删改移 + 折叠展开，共 9 种），由 `executeOperation` 执行 |
| 图级原子操作 | `AtomicGraphOperation` | 作用于多图注册表的原子操作（add_graph / delete_graph），由 `applyBatches` 兑现；`DeleteGraphOperation` 携带图数据（签名统一 `{ type, graph }`） |
| 复合操作 | `compose` | 由编排器将一系列原子操作（图内 + 图级）组织为**有序批次序列**（`OperationBatch[]`，单批或多批，输出扁平不嵌套），作为一个整体提交执行，构成用户可感知的一次完整语义操作；相当于一次日志条目（回溯/撤销单元）。 |
| 批次判别联合 | `OperationBatch` | 图内批 `{ kind: 'inGraph', graph, operations: AtomicOperationInGraph[] }` / 图级批 `{ kind: 'graphLevel', operations: AtomicGraphOperation[] }`——由类型判别，applyBatches 按 kind 分派 |
| 多批次 | `OperationBatch[]` | 一次语义操作的全部批 = 一条日志 = 一次回溯单元 |
| 提交日志 | `CommitLog` | 一批的完整记录：batches（正向，按图分组）+ reversalBatches（逆元全量，图内+图级）+ parentIndex + timestamp |
| 按图分组批 | `BatchesLog` | CommitLog 内按图分组的一批操作（graphId 替代运行时 graph 对象） |
| 游标 | `cursor` | 当前操作日志位置，undo/redo 沿树移动 |
