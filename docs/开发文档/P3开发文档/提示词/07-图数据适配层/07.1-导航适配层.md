# 07.1 导航适配层 — 提示词

## 当前状态

`components/GraphNavigationCard.vue` 与 `components/navigation-card/NavigationPanel.vue` 直接消费 `graph_store` 的查询/管理 API：

- `GraphNavigationCard.vue`：`pathSegments` computed（graphPath → 面包屑段，经 `getGraphById` 补标题）、`parentGraphId`、`currentRootId`、`isAtRoot` 四个派生；`switchGraphTo` 内调 `loadGraphToView` 切图
- `NavigationPanel.vue`：`refreshRootList`（`listRootGraphInfos`）、`createAndSwitch`（`createRootGraph`）、`requestDeleteRoot`（`deleteRootGraphTree`）——子组件直调 store 写方法，是 AGENTS.md 记录的已知技术债务
- `SearchPanel.vue`：只读 `graphView`（搜索匹配源）

目标：导航相关图数据业务收敛到 `graph/adapters/useNavigationAdapter.ts`（模块级单例），两个组件改经适配层消费；`graph_store` 侧将仅内部使用的 `deleteAndUnregisterGraph` 私有化（从 return 移除）。

## 架构变更

```
旧：                                    新：
components/navigation-card/             graph/adapters/
  GraphNavigationCard → graph_store       useNavigationAdapter.ts（模块级单例）
    graphPath 派生 + getGraphById           breadcrumb / currentRootId / isAtRoot
    loadGraphToView                         parentGraphId / hasCurrentGraph
  NavigationPanel → graph_store             goToGraph / listRootInfos / createRoot / deleteRootTree
    listRootGraphInfos / createRootGraph
    deleteRootGraphTree                  消费路径：
                                        GraphNavigationCard → useNavigationAdapter()
                                        NavigationPanel → useNavigationAdapter()
                                        SearchPanel → graph_store（只读，保持直读）
```

## 具体子任务

### 1.1 新建 useNavigationAdapter 组合式函数

新建 `frontend/src/graph/adapters/useNavigationAdapter.ts`：

- 模块级单例：`let singleton` + 工厂函数 + `useNavigationAdapter()` 返回单例（同 `useFloatingWindow` / `useCanvasFocus` 手法）
- 内部 `useGraphStore()` 获取核心 store
- **导航派生**（computed 保持响应式，全部经 store 状态推导）：
  - 面包屑路径段：由 `graphPath` + `getGraphById` 推导，段结构含 graphId / title（无标题兜底"未命名"）/ isCurrent——**类型在适配层内定义**，禁止 import `components/navigation-card/types.ts` 的 `PathSegment`（graph 域不反向依赖组件域）
  - `currentRootId`：路径首段（无则 null）
  - `isAtRoot`：路径长度 ≤ 1
  - `parentGraphId`：当前图父图 id（无则 null）
  - `hasCurrentGraph`：当前图是否存在
- **切图**：`goToGraph(graphId): boolean`（透传 `loadGraphToView`）
- **图谱树管理**（透传 store 方法）：
  - `listRootInfos(): RootGraphInfo[]`
  - `createRoot(title: string): GraphId`
  - `deleteRootTree(rootId: GraphId): void`
- JSDoc 按项目规范（公开 API 有 JSDoc，内部工厂函数无）

### 1.2 消费方切换

`components/GraphNavigationCard.vue`：

- `pathSegments`、`parentGraphId`、`currentRootId`、`isAtRoot` 四个 computed 的数据源改为适配层（保持组件侧最终视图模型类型不变——若适配层返回结构与 `PathSegment` 结构一致，组件侧做类型映射或直接消费适配层类型）
- `switchGraphTo` 内切图改经 `goToGraph`
- 模板中 `graphStore.graphView` 的展示判断改经 `hasCurrentGraph`
- 确认无其他 `graphStore` 消费后移除 `useGraphStore` import 与实例

`components/navigation-card/NavigationPanel.vue`：

- `refreshRootList` / `createAndSwitch` / `requestDeleteRoot` 三个方法改经适配层（`listRootInfos` / `createRoot` / `deleteRootTree`）
- 确认无其他 `graphStore` 消费后移除 `useGraphStore` import 与实例

`components/navigation-card/SearchPanel.vue`：**不动**（只读 `graphView`，保持直读）。

### 1.3 store 收窄

`graph/graph_store.ts`：

- `deleteAndUnregisterGraph` 从 return 对象移除（仅被内部 `deleteRootGraphTree` 调用，外部无消费）
- 其余 API 与逻辑一概不动
