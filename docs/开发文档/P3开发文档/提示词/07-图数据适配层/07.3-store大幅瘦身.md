# 07.3 store 大幅瘦身（语义层级收敛）— 提示词

## 当前状态

`frontend/src/graph/graph_store.ts`（615 行）混合了多个抽象层级：共享运行时状态 + 底层能力（Graph.vue 调用）+ 唯一修改/回溯入口 + 查询加工 + 业务编排 + 查询包装。目标是把后三类迁入两个适配层，store 瘦身为"状态 + 底层能力 + 唯一入口"。

判定标准（已确定）：**留在 store = Graph.vue 调用 ∨ 唯一图数据修改入口（commitBatchToGraphs）∨ 唯一图数据回溯入口（undo）**。

## 目标

graph_store 保留：共享状态 ×6（graphView / graphPath / graphRegistry / undoStack / lastSaveTime / lastValidationResult）+ `loadGraphToView` / `initRegistry` / `createRootGraph` / `clearValidationResult`（Graph.vue 调用）+ `commitBatchToGraphs` / `undo`（唯一入口）+ `buildGraphPath`（私有辅助）。其余迁入适配层，函数名保留原 store 完整名。

## 具体子任务

### 4.1 store 底层化

`graph/graph_store.ts` 移除以下函数（含其 JSDoc 与 return 对象条目）：

- `commitBatchToGraph`（单图便捷包装 + 冗余校验同步——适配身份由 useGraphOperationAdapter.applyToCurrentGraph 接管）
- `listRootGraphInfos`（查询加工）
- `deleteRootGraphTree`（级联删除编排）
- `getGraphById`（查询包装）
- `makeLookup`（查询包装）
- `isInRootTree` / `deleteAndUnregisterGraph`（私有辅助，随 deleteRootGraphTree 迁出）

保留全部共享状态 ref、`loadGraphToView` / `initRegistry` / `createRootGraph` / `clearValidationResult` / `commitBatchToGraphs` / `undo` / `buildGraphPath`，行为与签名不变。

**文件头注释更新**：在 `graph_store.ts` 文件头"说明"区补充职责边界——**"留在 store 的判定标准：Graph.vue 调用 ∨ 唯一图数据修改入口（commitBatchToGraphs）∨ 唯一图数据回溯入口（undo）"**，说明查询加工 / 业务编排 / 查询包装已迁入 `graph/adapters/` 两个适配层。

**注意**：`commitBatchToGraphs` 内部逻辑与 `lastValidationResult` 同步等行为保持原样——它是唯一修改入口，不可动其事务语义。

### 4.2 查询与编排迁入 useNavigationAdapter

`graph/adapters/useNavigationAdapter.ts` 内实现（函数名保留原 store 完整名）：

- `listRootGraphInfos(): RootGraphInfo[]`——listRootGraphIds 扫描 → loadGraph → 摘要（id/title/updatedAt）→ title 排序（zh-Hans-CN localeCompare），逻辑与 store 原实现一致
- `deleteRootGraphTree(rootId): void`——防御当前根图（graphPath[0] 判定）→ listSavedGraphIds 收集树成员（isInRootTree 判定）→ 逐图 delete + unregister → 清 lastActiveRootId；`isInRootTree` / `deleteAndUnregisterGraph` 作为适配层私有辅助迁入
- `getGraphById(graphId): GraphData | undefined`——lookupGraph + graphStore.graphRegistry 的语义包装，供 breadcrumb 标题查询
- **适配层现有含混短名一并改回完整名**：`listRootInfos` → `listRootGraphInfos`、`deleteRootTree` → `deleteRootGraphTree`、`createRoot` → `createRootGraph`（createRootGraph 逻辑留在 store，适配层仅转发调用）；消费方（NavigationPanel / GraphNavigationCard / 测试）同步更新
- `goToGraph` 保留（导航域访问 loadGraphToView 的入口，行为不变）
- 适配层 store 解析保持 lazy（computed 求值 / 方法调用时 useGraphStore）

### 4.3 工具能力迁入 useGraphOperationAdapter

`graph/adapters/useGraphOperationAdapter.ts` 内实现：

- `applyToCurrentGraph(operations)` 改为**直调 `commitBatchToGraphs`**（单图包装 `[{ graph: graphView, operations }]` + 校验结果返回），不再调 `commitBatchToGraph`；校验同步行为保持（commitBatchToGraphs 内部已同步 lastValidationResult）
- `makeLookup(): GraphLookup`——lookupGraph + graphStore.graphRegistry 的语义包装（`(id) => lookupGraph(graphRegistry, id)`），供认知操作 compose 层跨图查询；函数名保留
- 适配层 store 解析保持 lazy

`ui/operation_controller.ts` 的临时过渡修改（**注释说明"待 operation_controller 迁移后移除"**）：
- `makeLookup` 调用（3 处）改经 useGraphOperationAdapter
- `getGraphById` 调用（1 处）改经 useNavigationAdapter
- 其余逻辑（commitBatchToGraphs 直调、lastValidationResult 直写）**保持不动**

### 4.4 调用方切换

- `views/Graph.vue`：确认仍直调 store 底层能力（loadGraphToView / initRegistry / createRootGraph / clearValidationResult）——装配层保留对底层能力的访问，**不引入适配层**
- `components/navigation-card/NavigationPanel.vue`：listRootGraphInfos / createRootGraph / deleteRootGraphTree 经 useNavigationAdapter（注意改名后的调用点）
- `components/GraphNavigationCard.vue`：经 useNavigationAdapter（goToGraph / getGraphById 相关），确认改名后无残留
- `feature-tools/` 各工具：经 useGraphOperationAdapter.applyToCurrentGraph（07.2 已完成，确认无 commitBatchToGraph 直调）
- `dev/bootstrap.ts`：`commitBatchToGraph` 调用（6 处）改经 useGraphOperationAdapter.applyToCurrentGraph（种子数据走用户路径）

### 4.5 测试与回归
