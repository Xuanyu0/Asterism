# 07.2 工具层适配 — 提示词

## 当前状态

feature-tools 各工具对 `graph_store` 的写操作存在高度重复模式：每个工具"提交批量操作 + 同步校验结果"两步散写，另有 2 处预校验失败分支直写 `lastValidationResult`：

- 提交 + 校验同步（6 处）：`toolbar/add_node.ts`（onConfirm 提交 + 校验写入）、`toolbar/add_edge.ts`（提交 + 校验写入）、`toolbar/delete.ts`（executeDeleteNode / executeDeleteEdge 各一组）、`toolbar/fold.ts`（提交 + 校验写入）、`cognition/deconstruct.ts`（提交 + 校验写入）、`feature-tools/default_tool.ts`（编辑节点/边各一组提交）
- 预校验失败直写（2 处）：`toolbar/add_node.ts`（label 校验失败分支）、`cognition/deconstruct.ts`（前置校验失败分支）——绕过 store 方法直接给 `lastValidationResult` 赋值

目标：新建 `graph/adapters/useGraphOperationAdapter.ts`（模块级单例），提供 `applyToCurrentGraph` 收敛"提交 + 校验同步"为一步，预校验失败收口为显式方法；堵住绕过 store 的状态直写路径；为步骤 05 错误反馈链路预留唯一翻译落点（本步骤只收敛写入，不实现错误翻译）。

## 架构变更

```
旧：                                    新：
feature-tools/ 8 处散调                 graph/adapters/
  commitBatchToGraph(graphView, ops)     useGraphOperationAdapter.ts（模块级单例）
  lastValidationResult = result.validation  applyToCurrentGraph(ops)
  （add_node/deconstruct 预校验直写）         （提交 + 校验同步 + 预校验失败收口）
  graphStore.lastValidationResult = {...}
                                       消费路径：
                                       feature-tools → useGraphOperationAdapter()
```

## 具体子任务

### 2.1 新建 useGraphOperationAdapter 组合式函数

新建 `frontend/src/graph/adapters/useGraphOperationAdapter.ts`：

- 模块级单例：`let singleton` + 工厂函数 + `useGraphOperationAdapter()` 返回单例（同 `useFloatingWindow` 手法）
- 内部 `useGraphStore()` 获取核心 store
- **`applyToCurrentGraph(ops): ValidationResult`**——对当前图执行批量操作：
  - 内部完成 `commitBatchToGraph(graphView, ops)` + `lastValidationResult = result.validation` 两步
  - 返回 `result.validation`（**原样透传 `ValidationResult`**，不做错误翻译/结构化，留给步骤 05）
  - 当前图不存在时行为与重构前一致（各工具原有空图守卫保留在调用方，适配层不做额外兜底）
- **预校验失败收口**：适配层暴露显式方法供调用方在提交前写入校验失败结果（替换 2 处直写），签名以能承载"失败校验结果"为准（如透传一个 `ValidationResult`）
- JSDoc 按项目规范（公开 API 有 JSDoc，内部工厂函数无）

### 2.2 调用方切换

以下各文件的"提交 + 校验同步"改为经 `applyToCurrentGraph`；"预校验失败直写"改为经适配层收口方法：

- `feature-tools/toolbar/add_node.ts`：onConfirm 提交 + 校验写入；label 预校验失败分支直写
- `feature-tools/toolbar/add_edge.ts`：提交 + 校验写入
- `feature-tools/toolbar/delete.ts`：executeDeleteNode / executeDeleteEdge 两组提交 + 校验写入
- `feature-tools/toolbar/fold.ts`：提交 + 校验写入
- `feature-tools/toolbar/move_node.ts`：提交（该工具无校验同步则仅换提交入口）
- `feature-tools/cognition/deconstruct.ts`：提交 + 校验写入；前置预校验失败分支直写
- `feature-tools/default_tool.ts`：编辑节点 / 编辑边两组提交 + 校验写入

替换后确认各文件对 `lastValidationResult` 不再直接赋值；`useGraphStore` import 若不再需要则移除（**注意**：多数工具仍读 `graphStore.graphView` 作为查询/守卫，此时保留 import——仅移除"为直写 lastValidationResult 而存在"的使用，勿误删查询用途）。
