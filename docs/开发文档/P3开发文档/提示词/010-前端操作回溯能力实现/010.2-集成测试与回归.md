## 具体子任务

### 3.1.1 双存接线测试

- 一次 `commitBatchToGraphs` 提交（单图多操作）→ 断言 `operationLog.entries` 新增 1 条 entry：
    - `operation` 按图分组、含图级操作、正向顺序
    - `reversalOperations` item 内逆序（后执行先撤销）
    - `graphSignals` 提取正确（构造含 add_graph 或 delete_graph 的批验证 added/deleted）
    - `parentIndex` 正确（首条 -1，第二条 0）
- 混合多图批（两个 graph 的 item）→ `reversalOperations` item 间逆序（后提交的图先撤销）。
- `recordLog: false` 提交 → 不追加 entry、cursor 不变。

### 3.1.2 undo 链测试

- 构造 add_node → update_node(+summary) → delete_node 链（每条一次提交），逐级 undo：
    - 节点/边/属性精确恢复（删除的节点带回 summary；更新回退旧值；新增消失）
    - 每级 undo 后 cursor 回退、redoStack 增 1
- 折叠链：collapse_dependency → expand_dependency 后 undo，折叠状态恢复（含 foldedNodeIds 成员）。
- undo 后执行新操作 → 旧 entry 保留（分支）+ redoStack 清空。

### 3.1.3 redo 链测试

- undo 后 redo 重走原路径（图数据回到 redo 前状态，cursor 前进到原 entry）。
- redoStack 空时 `redo()` → false 且不写任何状态。
- undo → 新操作 → redo 失效（redoStack 已清）。

### 3.1.4 图级测试

- 含 add_graph 的批（模拟 induce：add_graph + 子图内 add_node）：
    - undo → 子图从 registry 注销、持久化数据保留（`loadGraph` 仍可读）
    - redo → 子图重新注册且节点完整（add_graph.graph 空壳 + add_node 重新填充）
- 含 delete_graph 的批：undo → 图从持久化 loadGraph 恢复注册；redo → 再次注销。
- 视图一致性：graphView 指向子图时 undo（撤销含 add_graph 的批）→ graphView 上溯到父图（registry 中活跃祖先或根图）+ graphPath 重算；graphView 为 null 时 undo 不崩溃。

### 3.1.5 边界与回归

- 空日志（cursor = -1）`undo()` → false 不写状态；`redo()` 空栈 → false 不写状态。
- 已存在回归套件全量通过（graph_store / graph_persistence / useGraphOperationAdapter / fold 等）——010.1 改动不得破坏既有断言（如适配层 commitToCurrentGraph 经 commitBatchToGraphs 提交的 spy 断言）。
- 测试脚手架沿用既有风格：`setActivePinia(createPinia())` + `localStorage.clear()` + `vi.restoreAllMocks()`；`test()` 命名；禁止 `import { ... } from 'vitest'`。
