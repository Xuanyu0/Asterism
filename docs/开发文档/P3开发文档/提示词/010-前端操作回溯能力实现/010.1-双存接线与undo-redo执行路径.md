# 010.1.双存接线与 undo/redo 执行路径 — 提示词

## 当前状态

- `frontend/src/graph/graph_store.ts`：`commitBatchToGraphs` 为四阶段（逐项 applyBatch → 快照 undoStack → 更新 state → 兑现图级信号 → 持久化）；`undo()` 为快照式 pop；无日志、无 redoStack、无 applyEntry。
- `undoStack`（GraphData 快照栈）+ `MAX_UNDO_STACK_SIZE = 20` 为快照式占位，需整体移除。
- `commitBatchToGraphs` 第三阶段：add_graph 用 `operation.graph` 注册（induce 场景为空壳，会覆盖 applyBatch 捏完的图）；delete_graph 走 `unregisterGraph + deleteGraph`（硬删，undo 无法恢复）。
- 引擎侧已就绪（**禁止修改**）：`createReversal(graph, op)`（目标缺失抛异常，图级操作返回 []）；`applyBatch(graph, ops, { onBeforeEachOperation })`（回调在逐操作 execute 前触发，dryRun 同样触发）；`OperationLogEntry` / `ItemOperations` 类型已带 `graphSignals: { added, deleted }`。
- 本任务为 010 步骤 §1 + §2 + §3.2（临时快捷键），全部前端改动，引擎零改动。

## 目标

- `commitBatchToGraphs` 升级为双存日志写入：执行同生命周期内经回调构造逆元，整批成功后组装 entry 写 OperationLog，undo/redo 复用同一执行引擎。
- store 新增 operationLog / redoStack 状态，`undo()` / `redo()` 重写为日志驱动；抽出 `applyEntry` 原语（011 timeLeap 前置依赖）。
- 图级兑现收口到单一模块 graph_signals；delete_graph 改软删。
- 临时快捷键接线（Ctrl+Z / Ctrl+Y）供手动冒烟验证，非契约。

## 架构变更

```
旧：commitBatchToGraphs(operationBatch) → 快照 undoStack → 兑现信号(硬删/空壳注册)
    undo() = pop 快照恢复

新：commitBatchToGraphs(operationBatch, { recordLog })
    → 逐项 applyBatch(onBeforeEachOperation 收集逆元)
    → 整批成功后组装 entry 写 operationLog + cursor 移动 + 清 redoStack（recordLog !== false 时）
    → 兑现信号（graph_signals：软删 / 注册 latestGraphs 结果）
    undo/redo → applyEntry(index, direction) → 组装 batch → commitBatchToGraphs(recordLog:false)
    → 游标移动 → 视图一致性
```

## 具体子任务

### 1.1 commitBatchToGraphs 双存接线

- 签名改为 `commitBatchToGraphs(operationBatch, options?: { recordLog?: boolean })`；`recordLog` 默认 `true`。
- 第一阶段循环内，`applyBatch(inputGraph, item.operations, { onBeforeEachOperation })` 传回调：图级操作（add_graph / delete_graph）跳过；图内操作在回调内 `createReversal(graphBeforeOp, op)` 将逆元 push 到该 item 的收集数组（按正向执行顺序收集）。
- 回调内 createReversal 抛异常（正常流程不可达，validate 已保证目标存在）：**不捕获，自然传播**——applyBatch Phase 2 中断 → commitBatchToGraphs 中断 → 整批不执行不记录不持久化（latestGraphs 为局部变量，无部分状态泄漏）。
- 删除快照段：`hasGraphViewTarget` 之外的 needsUndoSnapshot 判定、`undoStack.value = [...]` 入栈逻辑整段移除。
- 空批守卫保持现状（调用方保证非空）；但组装段对 `operationBatch.length === 0` 跳过记录（防御，不产生空 entry）。

### 1.2 entry 组装与写入 + recordLog 开关

- 整批成功后（第四阶段持久化之后、return 之前）组装 entry，仅当 `options?.recordLog !== false` 且批非空：
    - `operation`：`operationBatch.map(item => ({ graphId: item.graph.id, operations: item.operations }))`（含图级操作，正向顺序）。
    - `reversalOperations`：`item 间逆序 + item 内逆序`——每个 item 收集的逆元数组 reverse 后作为一项 `{ graphId, operations }`，整体数组再 reverse。
    - `graphSignals`：扫描 operationBatch 全部 operations，`add_graph` → added 推入其 graph.id，`delete_graph` → deleted 推入其 graphId。
    - `parentIndex = operationLog.cursor`（首条为 -1）、`timestamp = new Date().toISOString()`。
- 追加 entry 后：`operationLog.cursor = 新 entry 索引`；**清空 redoStack**（新操作使 redo 失效，2.5）。
- `recordLog: false`：跳过组装、不动 cursor、不清 redoStack（undo/redo 用）。

### 1.3 图级操作软删兑现 + graph_signals 收口

- 新增 `frontend/src/graph/graph_signals.ts`，导出三个函数（图级正/逆向执行唯一落点）：
    - `applyAddGraph(registry, graph)` — 注册新图（正向 add_graph / redo 场景）。
    - `applyDeleteGraph(registry, graphId)` — 注销图（正向 delete_graph 软删 / undo 注销 added）。**不触碰持久化**（软删：数据保留）。
    - `restoreGraphFromPersistence(registry, graphId)` — `loadGraph(graphId)` 成功后注册；missing / corrupted 走开发者通道（console.warn，沿用 `[data-integrity]` 前缀与既有 report 风格）并返回失败信号。
- commitBatchToGraphs 第三阶段改造：
    - add_graph 兑现：`applyAddGraph(graphRegistry.value, latestGraphs.get(op.graph.id))` —— 注册 **applyBatch 捏完的结果图**（非 operation.graph 空壳）。
    - delete_graph 兑现：`applyDeleteGraph(graphRegistry.value, op.graphId)` —— 软删，**删除 `deleteGraph` 持久化调用**。

### 2.1 store 日志状态

- 新增 `operationLog = ref<OperationLog>({ entries: [], cursor: -1 })`（cursor = 当前 entry 索引，-1 = 空日志）、`redoStack = ref<number[]>([])`。
- 移除 `undoStack`、`MAX_UNDO_STACK_SIZE` 及所有引用；`undo()` 重写。
- **日志生命周期 = 工作根图谱**（决策定案）：子图与根图共享一份日志；仅当切换视图跨越到**不同根图谱**时重置 `operationLog` + `redoStack`。同根图树内导航（子图↔根图、子图↔子图）不清日志。
    - 实现：`loadGraphToView` 加载成功后，取新旧 graphPath 首元素（根图 ID，graphPath 为根→叶，`graphPath[0]` 即根）比较；graphPath 非空且根图 ID 变化 → 重置两状态；graphPath 为空（链断裂防御）→ 不重置。
    - **TODO（011 范畴）**：操作日志最终需持久化且按根图谱隔离存储（IndexedDB 基建），010 为内存版（刷新即丢）；当前仅单份内存日志随根图谱切换重置。

### 2.2 applyEntry 原语

- 新增内部原语 `applyEntry(entryIndex: number, direction: 'forward' | 'reverse'): boolean`：
    - 读 `entries[entryIndex]`，不存在 → false。
    - **reverse（undo 三段式）**：
        1. 图级恢复：`graphSignals.deleted` 逆序遍历 → `restoreGraphFromPersistence`（恢复失败仅开发者通道，不中断）。
        2. 图内逆元：`reversalOperations` 顺序遍历，组装 `{ graph: lookupGraph(registry, graphId), operations }`；operations 为空或 registry 解析失败（开发者通道记录）的 item 跳过；组装出的 batch 非空则 `commitBatchToGraphs(batch, { recordLog: false })`。
        3. 图级消失：`graphSignals.added` 逆序遍历 → `applyDeleteGraph`。
    - **forward（redo）**：`operation` 顺序遍历组装 batch——graph 优先 `lookupGraph(registry, graphId)`，registry 缺失（被 undo 注销的 added 图）时从该 item 的 `add_graph` 操作提取 `graph` 字段作 applyBatch 入参；组装后 `commitBatchToGraphs(batch, { recordLog: false })`。图级信号由 commitBatchToGraphs 第三阶段兑现，applyEntry 不自行处理。
    - 步骤 ② 中 `commitBatchToGraphs` 返回 `validation.valid === false`（防御，正常不可达）→ 开发者通道记录 + return false。
    - 游标移动：reverse 成功 → `cursor = entries[entryIndex].parentIndex`；forward 成功 → `cursor = entryIndex`。失败不移动。

### 2.3 undo 执行路径

- `undo(): boolean`：`cursor < 0` → false；`idx = cursor`；`applyEntry(idx, 'reverse')` 成功 → `redoStack.push(idx)` 并 return true，失败 return false（游标已由 applyEntry 保证不动）。
- 视图一致性：undo/redo 后检查 `graphView` 是否仍在 registry；不在（撤销含 add_graph 的批且正在查看该子图）→ 沿 parentGraphId 上溯找第一个在 registry 的图，找不到则取任一 root（graphRegistry 中 kind === 'root'）或 null；随后用 `buildGraphPath` 重算 graphPath，必要时更新 lastActiveRootId。

### 2.4 redo 执行路径

- `redo(): boolean`：`redoStack.pop()` 为 undefined → false；否则 `applyEntry(idx, 'forward')`（游标移动在 applyEntry 内完成）。

### 2.5 树形分支

- 分支语义由 entry.parentIndex 链承载：新操作 `parentIndex = cursor`、`cursor = 新索引`（1.2 已含）；undo 游标回退用 parentIndex（2.2 已含）。
- 开分支判断（`entries.some(e => e.parentIndex === cursor)`）仅服务未来 UI 分支导航，010 不实现 UI，无需额外代码；日志 entry 永不删除。

### 3.2 临时快捷键接线（非契约）

- `frontend/src/views/Graph.vue`：onMounted 注册 / onBeforeUnmount 移除 window keydown 监听：
    - Ctrl+Z → `graphStore.undo()`；Ctrl+Shift+Z 或 Ctrl+Y → `graphStore.redo()`。
    - 命中组合时 `preventDefault`（拦截浏览器原生回退）。
    - 不做焦点判断（试玩阶段全页面拦截）、不做灰显/按钮/分支导航（04 承接）。

### 适配层暴露（辅助）

- `useGraphOperationAdapter` 新增 `undo(): boolean`、`redo(): boolean`（薄封装调 store，返回 store 结果），供后续 04 UI 与测试使用。

## 缺陷修复（010.2 回流，用户已批准方案）

### D1. 撤销「删除带关联边的节点」失败（用户可见 BUG）

- **根因**：① 逆元组装 `collectedReversals.reverse()` 将打平数组整体逆序——`createReversalForDeleteNode` 返回的 `[add_node, add_edge]`（先节点后边）被翻成 `[add_edge, add_node]`；② 更根本——`applyBatch` validate-all-first 基于输入图校验，恢复型逆元批（add_edge 端点依赖批内 add_node 恢复的节点）必然 `EDGE_SOURCE/TARGET_NOT_FOUND`。
- **修复（引擎 + 前端）**：
    1. **引擎 `pipeline.ts`**（用户批准破例）：`BatchOptions` 新增 `skipValidate?: boolean`（默认 false）；Phase 1 在 skipValidate 时跳过 `validateOperation` 循环（全部视为通过，直接 Phase 2）。`index.ts` 的 `BatchOptions` 类型导出自动携带。
    2. **前端逆元组装修正为「操作级逆序」**：每个 op 的逆元数组保持内部执行序（`[add_node, add_edge]` 不动），op 间逆序（后执行先撤销）——收集阶段按 `perOpReversals: GraphOperation[][]` 存储，组装时 `perOpReversals.reverse().flat()`，不再整体 reverse 打平数组。
    3. **skipValidate 透传**：`commitBatchToGraphs` options 扩展 `skipValidate?: boolean`，透传给内部 `applyBatch`；`applyEntry` 的 reverse（图内逆元）与 forward（redo）均传 `skipValidate: true`——undo 恢复已知合法状态、redo 重走已验证过的正向操作，校验冗余（正向用户操作保持默认校验）。
- **验证**：`undo_redo.test.ts` 缺陷 #1 测试（`undo_redo.test.ts:559`）转绿；add/update/delete 逐级 undo 全链恢复节点+关联边。

### D2. 多级 undo 抛 DataCloneError（必然崩溃）

- **根因**：`operationLog` 为 reactive ref，读出操作对象被 Vue 深层 proxy 包装；引擎 execute `{...op.node}` 浅展开将嵌套 position proxy 烘焙进图数据；后续逆元 `structuredClone` 命中 proxy 崩溃。
- **修复（前端）**：组装 entry 时对 entry 整体 `markRaw` 后再 push 进 `entries`（Vue 尊重 markRaw，读出时不包装）——operation / reversalOperations 内的操作保持普通对象，彻底消除 proxy 泄漏；`commitBatchToGraphs` 已有的 `toRaw(inputGraph)` 保留。forward 路径同源风险一并消除。
- **验证**：`undo_redo.test.ts` 缺陷 #2 测试（`undo_redo.test.ts:189`）转绿；带 position 节点的多级 undo 链不崩溃。
