# 06-UI层重构：浮空窗生命周期归属重构 — 提示词

## 当前状态

浮空窗状态当前存放于 `frontend/src/ui/ui_store.ts` 的 `floatingWindowData`（Pinia store），被 9 处调用点手动关闭（mediator 切换工具、delete 工具删除实体、导航卡片切图、Graph.vue 双击导航、default_tool 双击、GraphNodeWindow 叉号、default_tool confirm、default_tool 双击内）。状态归属与关闭义务扩散到多个模块。

本次重构：浮空窗状态迁出 ui_store，归入 default 工具的交互会话——新建 `feature-tools/composables/useFloatingWindow.ts`（模块级单例），关闭机制收敛为"外部点击规则 + 明确关闭点"。

## 具体子任务

### 1. 新建 useFloatingWindow 组合式函数

新建 `frontend/src/feature-tools/composables/useFloatingWindow.ts`：

- 模块级单例：`let singleton` + 工厂函数 + `useFloatingWindow()` 返回单例（参照 `feature-tools/mediator.ts` 的 `useToolMediator` 手法）
- 状态：`floatingData: Ref<NodeData | EdgeData | null>`
- API：
  - `open(data)` — 写入展示数据
  - `close()` — 置空 floatingData，并调用 `useGraphStore().clearValidationResult()`（迁移自 ui_store 的联动行为）
  - `registerContainer(el: HTMLElement | null)` — 组件挂载/销毁时注册/注销浮空窗根元素
  - 暴露 `floatingData` 供门面转发（内部用 shallowRef 或 ref 均可，保持响应式）
- 外部点击关闭规则：单例创建时绑定 `window` 级 `pointerdown` 监听（常驻）：
  - 容器已注册且 `container.contains(event.target)` → 内部点击，不动
  - 容器未注册或点击在容器外 → `close()`（幂等，无副作用）
- 监听回调不常驻多余状态，全部状态存于单例

### 2. ToolHandler 接口扩展 + default_tool 接入

`feature-tools/types.ts`：

- `ToolHandler` 新增可选字段 `readonly floatingWindowData?: NodeData | EdgeData | null`（需要从 `@my-project/graph-engine` import 对应类型）

`feature-tools/default_tool.ts`：

- 内部 `useFloatingWindow()`，替换全部 `uiStore.openFloatingWindow` / `uiStore.closeFloatingWindow` / `uiStore.floatingWindowData` 调用：
  - `onNodeClick` / `onEdgeClick` → `open(node/edge)`
  - `onConfirm` → 读 `floatingData`（原读 `uiStore.floatingWindowData`）；**写入逻辑不变**（构造 update 操作 → commitBatchToGraph → 校验通过后关窗，校验失败保留）；成功后调 `close()`
  - `onNodeDoubleClick` 内保留关窗调用，改调 `close()`
- 返回对象新增 `get floatingWindowData()` 转发单例状态
- 迁移完成后若 `useUIStore` 不再被使用，移除对应 import 与变量

### 3. GraphNodeWindow.vue 消费路径切换

- 数据源：经 `useToolMediator()` 取 `registry.get('default')`，用 `computed` 包装其 `floatingWindowData` 供模板消费（保持响应式——getter 需在 computed 回调内访问以建立依赖）；现有 `watch(floatingData)` 的 watch 源同步切换
- 容器注册：浮空窗区块（Edit Node/Edge 根元素）绑定 ref 回调转发给 `useFloatingWindow().registerContainer`（Vue 挂载/卸载时自动注册/注销，v-if 切换时 ref 随之更新，registerContainer 幂等）
- **Cancel 按钮 → 右上角叉号**：浮空窗区块（Edit Node/Edge）底部 Cancel 按钮移除，改为窗口右上角 × 图标按钮（`@heroicons/vue/24/outline` 的 XMarkIcon 或等价图标，与 h3 标题同行右上角），点击调 `useFloatingWindow().close()`（替换 `uiStore.closeFloatingWindow`）；Confirm 按钮保留在底部按钮行
- **DraftNode 区块不动**：其 Cancel 按钮与 `onCancel` 草稿流程属于 add_node 工具，禁止修改
- 其余展示与编辑逻辑不变

### 4. 清理旧关闭点 + ui_store 瘦身

- `feature-tools/toolbar/delete.ts`：删除 `executeDeleteNode` / `executeDeleteEdge` 中的浮空窗检查与关闭块（两处），若 `useUIStore` 不再被使用则移除 import
- `components/GraphNavigationCard.vue`：`switchGraphTo` 中删除 `closeFloatingWindow()` 调用，若 `useUIStore` 不再被使用则移除 import
- `views/Graph.vue`：双击导航处理中删除 `closeFloatingWindow()` 调用（保留 activeToolId 检查、deactivate、转发）
- `ui/ui_store.ts`：删除 `floatingWindowData` 状态、`openFloatingWindow`、`closeFloatingWindow`（联动行为已迁入组合式函数 close）；**保留** `pendingCanvasFocusId` / `requestCanvasFocus` / `clearCanvasFocus` 及导出
- 全局 grep 确认无残留引用

### 5. 测试与回归

- 新增 `frontend/src/feature-tools/composables/useFloatingWindow.test.ts`：
  - 单例性：多次调用返回同一实例
  - open/close 状态流转
  - close 触发 `clearValidationResult` 联动（mock graphStore）
  - 容器内 pointerdown 不关闭；容器外 pointerdown 关闭；容器未注册时任意 pointerdown 关闭
- 检查并修正现有测试对 `ui_store` 浮空窗字段的引用（如 mediator.test.ts 等）
- 运行 `pnpm --filter frontend test` 全绿

### 6. mediator 类型收紧（移除 null 状态）

`feature-tools/mediator.ts`：

- `activeToolId` 类型收紧为 `Ref<ToolId>`，初始值 `'default'`（创建时即激活 default）
- `activeHandler` 类型收紧为 `ShallowRef<ToolHandler>`，初始为 default handler 实例
- `activate(id: ToolId | null)` 的 null 分支删除；接口签名收紧为 `activate(id: ToolId)`——取消工具一律走 `deactivate()`
- `deactivate()` 行为不变（恢复 default）
- `Graph.vue`：双击工具检查简化为单分支 `if (activeToolId !== 'default') return`；若 default 已由 createMediator 初始激活，删除挂载时的 `activate('default')` 冗余调用
- `mediator.test.ts`：`activate(null) 取消所有` 测试改为验证 `deactivate()` 恢复 default；补充"初始化即 default"断言；全部断言移除 null 期望
