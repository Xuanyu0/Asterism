# 06.2 画布焦点请求迁出 ui_store — 提示词

## 当前状态

画布视口定位请求（`pendingCanvasFocusId` / `requestCanvasFocus` / `clearCanvasFocus`）是 `frontend/src/ui/ui_store.ts`（Pinia store）仅剩的状态——浮空窗已在前次重构迁出，ui_store 已成空壳。

调用面（已确认）：

- `views/Graph.vue`：import + 实例化 `useUIStore`；watch `pendingCanvasFocusId` → `renderer.centerOnElement` → `clearCanvasFocus`（消费方）
- `feature-tools/default_tool.ts`：`onNodeDoubleClick` 跨图导航成功后调 `requestCanvasFocus(focusNodeId)`（写入方）
- `components/GraphNavigationCard.vue`：模板 `focus-element` 事件调 `requestCanvasFocus(id)`（写入方）
- `ui/operation_controller.ts`：import + 实例化 `useUIStore` 但**从未使用**（历史遗留）

注释层面存在 ui_store 提法：`cytoscape/useRenderer.ts`（"graph_store / ui_store"）、`cytoscape/cy_interaction.ts`（"禁止读取 ui_store / graph_store"）、`feature-tools/composables/useFloatingWindow.ts`（"迁移自 ui_store 的联动行为"，历史陈述）。

## 目标

画布焦点请求迁出 Pinia，成为 `frontend/src/composables/useCanvasFocus.ts` 模块级单例；`ui_store.ts` 整体删除；`CLAUDE.md` 分层表述同步更新。行为零变更：一次性画布视口定位意图，写入 → Graph.vue watch 消费 → 清除回 null。

## 架构变更

```
旧：                                    新：
ui/                                     composables/
  ui_store.ts（Pinia store）              useCanvasFocus.ts（模块级单例）
    pendingCanvasFocusId                   pendingCanvasFocusId / requestCanvasFocus / clearCanvasFocus
    requestCanvasFocus / clearCanvasFocus
                                        ui/ ✗（ui_store.ts 删除）

消费路径：                              消费路径：
  default_tool → uiStore                default_tool → useCanvasFocus()
  GraphNavigationCard → uiStore          GraphNavigationCard → useCanvasFocus()
  Graph.vue watch → uiStore              Graph.vue watch → useCanvasFocus()
```

## 具体子任务

### 2.1 新建 useCanvasFocus 组合式函数

新建 `frontend/src/composables/useCanvasFocus.ts`：

- 模块级单例：`let singleton` + 工厂函数 + `useCanvasFocus()` 返回单例（同 `useFloatingWindow` / `useToolMediator` 手法）
- 状态：`pendingCanvasFocusId: Ref<string | null>`，初始 `null`
- API：
  - `requestCanvasFocus(targetId: string)` — 写入定位目标 ID
  - `clearCanvasFocus()` — 清除回 null
  - 导出 `pendingCanvasFocusId` 供消费方 watch
- JSDoc 沿用 ui_store 原语义：一次性画布视口定位请求；消费后必须清除（保证同一元素可重复定位）；本状态只描述 UI 意图，不保存 GraphData

### 2.2 调用方切换

- `views/Graph.vue`：改用 `useCanvasFocus()`；watch 源切换为 `pendingCanvasFocusId`，消费逻辑（`renderer.centerOnElement` + `clearCanvasFocus`）不变；移除 `useUIStore` import 与实例
- `feature-tools/default_tool.ts`：`onNodeDoubleClick` 内的 `requestCanvasFocus` 调用改经 `useCanvasFocus()`；移除 `useUIStore` import 与实例（确认无其他使用后）
- `components/GraphNavigationCard.vue`：模板 `focus-element` 事件处理改经 `useCanvasFocus()`；移除 `useUIStore` import 与实例（确认无其他使用后）
- `ui/operation_controller.ts`：移除未使用的 `useUIStore` import 与实例化语句，其余代码不动

### 2.3 删除 ui_store.ts 并同步架构表述

- 删除 `frontend/src/ui/ui_store.ts`
- 更新 `CLAUDE.md`：
  - "两个 Pinia Store" 小节改为单个 graph_store（ui_store 条目移除）
  - 架构分层图中 ui_store 条目移除，注明画布焦点请求归 `composables/useCanvasFocus`（与既有 composables 提法风格一致）
  - 其余内容与风格保持不动；基于当前工作区未提交版本增量修改，不冲突
- 注释清理（仅更新表述，不动逻辑）：
  - `cytoscape/cy_interaction.ts`：约束注释中 ui_store 提法移除（语义收敛为仅指 graph_store）
  - `cytoscape/useRenderer.ts`：注释中 ui_store 提法更新为 useCanvasFocus（若提法属"不得引用"类约束，按同一处理）
  - `feature-tools/composables/useFloatingWindow.ts` 的"迁移自 ui_store"为历史事实陈述，允许保留；如有"迁移来源"类其他提法一并按历史陈述保留，不做改写

### 2.4 测试与回归

新建 `frontend/src/composables/useCanvasFocus.test.ts`（对齐 useFloatingWindow.test.ts 写法）：

- 单例性：多次调用返回同一实例
- 写入 → 读取闭环：`requestCanvasFocus` 写入后 `pendingCanvasFocusId` 等于目标 ID
- 清除：`clearCanvasFocus` 后回 null
- 可重复触发：清除后可再次写入

运行 `pnpm --filter frontend test` 全绿。
