# 08.3 测试与验证 — 提示词

## 当前状态

08.1（loadGraph 判别联合）与 08.2（loadGraphToView 与静默路径治理）已完成：`loadGraph` 返回判别联合、`loadGraphToView` 拆分 missing/corrupted 并退出对 validation 通道的借用、开发者通道（console.warn）落地。本子任务补齐行为变更的断言覆盖并做全量验证。

## 目标

判别联合各分支、loadGraphToView 拆分语义、警告迁移均有测试覆盖；frontend 与 graph-engine 全量测试通过。

## 具体子任务

### 4.1 判别联合分支测试

`graph_persistence` 相关测试新增/补全：

- missing 分支：key 不存在 → `{ ok: false, reason: 'missing' }`
- corrupted 分支：key 存在但 JSON 非法 → `{ ok: false, reason: 'corrupted' }`
- ok 分支：合法数据 → `{ ok: true, graph }`

### 4.2 行为变更断言

- `graph_store` 测试：`loadGraphToView` 对 missing（静默返回 false、无状态写入）与 corrupted（console.warn + 返回 false、不写 lastValidationResult）的行为断言
- `ANCESTOR_CHAIN_BROKEN` 不再写 `lastValidationResult` 的断言（如适用，改用对报告辅助 / console.warn 的 spy 断言）
- 规则校验路径（`commitBatchToGraphs` / 工具层 / useGraphOperationAdapter）的 `lastValidationResult` 行为**不回归**确认（既有断言保持全绿）

### 4.3 全量验证

- `pnpm --filter frontend test` 全绿
- `pnpm --filter @my-project/graph-engine test` 全绿（引擎未动，回归确认）
- `vue-tsc --build` 干净（如项目使用，未配置则跳过）
