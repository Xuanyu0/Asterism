# 08.5.2 前端构造方收口 — 提示词

## 当前状态

`lastValidationResult` 仍存在前端直写（越界）：`add_node` 预校验（setValidationFailure + EMPTY_LABEL 构造）、`deconstruct` 前置校验（setValidationFailure + mapComposeIssues）、`operation_controller` 7 处直写（3 处 `batchResult.validation` 冗余——`commitBatchToGraphs` 内部已同步；3 处 mapComposeIssues 构造越界；1 处 COMMON_LAYER_NOT_FOUND 前端纯构造且不可达）、`commitToCurrentGraph` 防御分支返回假 validation、适配层 `setValidationFailure` 接口（前端构造 validation 的入口）。

前置：08.5.1 已把 EMPTY_LABEL 迁入引擎 `validateAddNode`（本任务依赖此产物——add_node 删预校验后由引擎兜底）。

## 目标

前端对 `lastValidationResult` **零直写**：写入收敛为 `commitBatchToGraphs`（引擎 applyBatch 返回）+ 适配层统一方法（compose issues 适配转发）两处。前端业务层不构造任何规则，只做适配 + 转发。

## 架构变更

```
旧：                                       新：
前端业务层直写 lastValidationResult       lastValidationResult 仅两处写入：
  add_node 预校验（构造 EMPTY_LABEL）       ├─ commitBatchToGraphs（applyBatch 返回，已有）
  deconstruct 前置校验（mapComposeIssues）  └─ useGraphOperationAdapter 统一方法
  operation_controller ×7                   （ComposeIssue[] → hasErrors → map → 写状态）
    ├─ batchResult.validation ×3（冗余）
    ├─ mapComposeIssues ×3（越界）         前端业务层（add_node / deconstruct / operation_controller）
    └─ COMMON_LAYER_NOT_FOUND（不可达）      → 仅调适配层方法，零构造零直写
  commitToCurrentGraph 防御分支假 validation
  setValidationFailure 接口（废弃）
```

## 具体子任务

### 5.2 适配层统一方法

`graph/adapters/useGraphOperationAdapter.ts` 新增统一方法（语义约定）：

- 入参：`ComposeIssue[]` + targetType + targetId（可选）
- 行为：内部判断 hasErrors → mapComposeIssues 转换（`issue_mapper.ts` 逻辑收进适配层，成为适配层内部实现）→ 写 `lastValidationResult` → 返回是否失败（供调用方决定是否阻断）
- `mapComposeIssues` / `hasErrors` 不再被业务层直接 import（`issue_mapper.ts` 保留文件但仅适配层消费；若适配层内联逻辑后无其他引用，可整体移入适配层）
- 方法命名与签名以语义清晰为准（如 `reportComposeValidation(...)` 形态），JSDoc 说明"判定来自引擎 compose，适配层仅转换 + 转发"

### 5.3 调用方切换与越界入口清理

- `feature-tools/toolbar/add_node.ts`：删除预校验直写（setValidationFailure + EMPTY_LABEL 构造块）——空 label 提交由引擎拒绝（08.5.1 产物），`draftNode` 保留行为与现状等价（提交后 `validation.valid` false 不清空）
- `feature-tools/cognition/deconstruct.ts`：前置校验改经适配层统一方法（返回是否失败决定 return）；删除 `mapComposeIssues` / `hasErrors` import
- `ui/operation_controller.ts` 7 处直写分类处理：
  - `batchResult.validation` 冗余直写 3 处（induce / internalize / diverge 各 1）——**直接删除**（commitBatchToGraphs 内部已同步）
  - `mapComposeIssues` 构造直写 3 处（induce / internalize / diverge 各 1）——改经适配层统一方法
  - `COMMON_LAYER_NOT_FOUND` 直写 1 处（internalize 前置检查，当前不可达）——改为 `throw`（编程错误：internalize 前置条件违约）
  - 同步清理 operation_controller 对 `mapComposeIssues` / `hasErrors` / `issue_mapper` 的 import（如无残留）
- `setValidationFailure` 废弃：add_node / deconstruct 切换后无调用方，从 `useGraphOperationAdapter` 接口与实现移除
- `commitToCurrentGraph` 防御分支（graphView 缺失返回假 validation）：改为 `throw`（编程错误通道）

### 5.4 测试与验证

- `add_node` 测试：预校验直写断言更新为"提交后引擎拒绝 EMPTY_LABEL"（依赖 08.5.1 引擎规则）
- 适配层：统一方法测试（compose 失败 → 写状态 + 返回 true；无 error → 不写 + 返回 false）
- `deconstruct` / `operation_controller` 相关测试：随直写删除清理断言
- `setValidationFailure` 相关测试删除
- 全量：`pnpm --filter frontend test` + `pnpm --filter @my-project/graph-engine test` 全绿（GE 回归确认 08.5.1 无副作用）
