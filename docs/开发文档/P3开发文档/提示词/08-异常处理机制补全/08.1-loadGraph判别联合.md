# 08.1 loadGraph 判别联合（方案 A）— 提示词

## 当前状态

`frontend/src/graph/graph_persistence.ts` 的 `loadGraph(graphId): GraphData | null` 把两种失败折叠为 `null`：key 不存在（missing）与 JSON.parse 失败（corrupted，当前 try-catch 吞掉）。调用方无法区分"图不存在"（正常状态）与"图损坏"（系统异常），导致 `initRegistry` 把损坏当作首次使用掩盖。

## 目标

`loadGraph` 返回判别联合，使 missing / corrupted / ok 在信号层面可区分。本子任务只做**签名变更 + 调用方编译适配**，各调用方行为保持现状不变（LOAD_FAILED 等语义重构在 08.2 进行）。

## 具体子任务

### 2.1 判别联合类型与 loadGraph 改造

`graph_persistence.ts`：

- 定义判别联合类型（导出）：`LoadGraphResult = { ok: true; graph: GraphData } | { ok: false; reason: 'missing' | 'corrupted' }`
- `loadGraph(graphId): LoadGraphResult`：key 不存在 → `{ ok: false, reason: 'missing' }`；`JSON.parse` 抛异常（try-catch 捕获）→ `{ ok: false, reason: 'corrupted' }`；成功 → `{ ok: true, graph }`
- 文件内其余函数（saveGraph / deleteGraph / listSavedGraphIds / listRootGraphIds / loadLastActiveRootId 等）行为不变；`listRootGraphIds` 内部对 `loadGraph` 的消费改为判别联合 ok 判定，语义不变
- 更新 `loadGraph` 的 JSDoc：规则区写明 missing / corrupted 的区分语义

### 2.2 调用方编译适配（行为保持）

以下调用方从 `GraphData | null` 消费改为判别联合消费，**判定语义与现状等价、不改变任何写状态/返回值行为**：

- `graph_store.ts`：
  - `loadGraphToView`：`!graph` 判定改为 `!result.ok`；现状的 `LOAD_FAILED` 写入分支**保留原样**（missing 与 corrupted 暂不区分，08.2 再拆分）
  - `initRegistry`：`!rootGraph || kind !== 'root'` 改为判别联合 ok + kind 判定；循环内 `!graph` 跳过改为 `!result.ok` 跳过，静默行为保持
  - `buildGraphPath`：惰性加载父图处消费判别联合（registry 未命中时从 `loadGraph` 取 ok 分支），链断裂行为不变
- `useNavigationAdapter.ts`：`listRootGraphInfos` 内 `loadGraph` 消费改为判别联合 ok 判定（`continue` 跳过逻辑不变）
- `localStorageAdapter.list()`（graph_persistence.ts 内）：`map(loadGraph)` 后过滤改为取 ok 分支，返回 `GraphData[]` 不变

### 2.3 既有测试同步（编译通过 + 行为保持）

- 直接消费 `loadGraph` 返回值的既有测试（graph_persistence / graph_store / useNavigationAdapter 相关）改为消费判别联合，断言行为与现状等价
- 本子任务**不新增**判别联合分支测试（08.3 覆盖）
