## 1.导航适配层（useNavigationAdapter）✅

### 目标

GraphNavigationCard 与 NavigationPanel 不再直接消费 graph_store 的查询/管理 API，改经 `graph/adapters/useNavigationAdapter.ts` 模块级单例。路径导航派生、切图、图谱树管理收敛为单一适配层；NavigationPanel 借此不再直接 import store（合规 AGENTS.md"子组件不做决策层操作"）。

### 1.1.新建 useNavigationAdapter ✅

**子目标**：

- `graph/adapters/useNavigationAdapter.ts`——模块级单例（`let singleton` + 工厂，同 useFloatingWindow / useCanvasFocus 手法），内部 `useGraphStore()`
- 路径导航派生（GraphNavigationCard 消费，computed 保持响应式）：breadcrumb 路径段（id/title/isCurrent）、currentRootId、isAtRoot、parentGraphId、hasCurrentGraph
- 图谱树管理（NavigationPanel 消费）：`listRootInfos()`、`createRoot(title): GraphId`、`deleteRootTree(rootId)`
- 切图：`goToGraph(graphId): boolean`（透传 `loadGraphToView`）

- 不确定度：低（模式成熟，参照 useFloatingWindow 单例）
- 算法复杂度：低（computed 派生 + 方法透传）
- 工作量：中（新文件 + 派生逻辑搬移）

### 1.2.消费方切换 ✅

**子目标**：

- `GraphNavigationCard.vue`：pathSegments 派生（L97-100）、parentGraphId（L104）、currentRootId（L105）、isAtRoot（L106）、hasCurrentGraph（L183）、goToGraph（L110）全部改用适配层；确认无其他 store 消费后移除 `useGraphStore` import
- `NavigationPanel.vue`：`refreshRootList`（listRootGraphInfos）、`createAndSwitch`（createRootGraph）、`requestDeleteRoot`（deleteRootGraphTree）改用适配层；移除 `useGraphStore` import（合规 AGENTS.md 记录的技术债务）
- `SearchPanel.vue`：**保持直接读 `graphView`**（纯只读搜索源，不迁移）

- 不确定度：中（组件模板与 computed 引用面需逐一核对，行为零变更）
- 算法复杂度：低
- 工作量：中

### 决策项

**待确定决策**

> **Q1**：适配层目录名——`graph/adapters/` 是否可接受？（备选 `graph/business/`）

> **建议**：`graph/adapters/`。理由：语义聚焦"适配层"，与 store / registry / persistence 平行，不引入"业务"这一易混词。

## 2.工具层适配（applyToCurrentGraph）✅

### 目标

feature-tools 各工具的"提交 → 同步校验结果"重复模式（6 处）与预校验失败直写（2 处）收敛为适配层方法，堵住绕过 store 的状态直写路径；为步骤 05 错误反馈链路预留唯一翻译落点（本步骤只收敛写入，不实现错误翻译）。

### 2.1.新建工具层适配 ✅

**子目标**：

- `graph/adapters/` 下新建工具层适配（模块级单例，内部 `useGraphStore()`）
- `applyToCurrentGraph(ops): ValidationResult`——`commitBatchToGraph(graphView, ops)` + `lastValidationResult = result.validation` 一步完成，返回校验结果
- 预校验失败收口：适配层暴露显式失败写入方法，替换 add_node / deconstruct 两处直写（L90 / L69）
- 返回类型**原样透传 `ValidationResult`**，不预做错误翻译/结构化（留给步骤 05）

- 不确定度：中（6+2 处调用点替换，行为必须零变更）
- 算法复杂度：低（组合两个 store 调用）
- 工作量：中

### 2.2.调用方切换 ✅

**子目标**：

- `toolbar/add_node.ts`（L118+L123、预校验 L90）、`toolbar/add_edge.ts`（L183+L188）、`toolbar/delete.ts`（L112+L117、L123+L128）、`toolbar/fold.ts`（L63+L68）、`toolbar/move_node.ts`（L283，无校验同步则仅换提交入口）、`cognition/deconstruct.ts`（L77+L82、预校验 L69）、`default_tool.ts`（L147、L163）——提交 + 校验同步改为适配层调用

## 4.store 大幅瘦身（语义层级收敛）⏳

### 目标

graph_store 按**语义层级**收敛为"状态容器 + 底层能力"：只保留共享运行时状态与 Graph.vue 直接调用的底层能力，以及唯一图数据修改/回溯入口；查询加工、业务编排、查询包装全部迁入两个适配层。判定标准（充要条件）：**留在 store = Graph.vue 调用 ∨ 唯一图数据修改入口 ∨ 唯一图数据回溯入口**。

### 4.1.store 底层化 ⏳

**子目标**：

- store 保留共享运行时状态 ×6：graphView / graphPath / graphRegistry / undoStack / lastSaveTime / lastValidationResult——graphPath 因未来发散工具消费，不并入单一适配层
- store 保留底层能力（Graph.vue 直接调用）：`loadGraphToView` / `initRegistry` / `createRootGraph` / `clearValidationResult`
- store 保留唯一入口：`commitBatchToGraphs`（唯一修改入口）+ `undo`（唯一回溯入口）
- `buildGraphPath` 保留为私有辅助（loadGraphToView 内部使用）
- store 移除：`commitBatchToGraph` / `listRootGraphInfos` / `deleteRootGraphTree` / `getGraphById` / `makeLookup` / `isInRootTree` / `deleteAndUnregisterGraph`

- 不确定度：中（拆分后需确认 store 对外接口面与既有调用方兼容）
- 算法复杂度：低（搬移为主）
- 工作量：中

### 4.2.查询与编排迁入 useNavigationAdapter ⏳

**子目标**：

- `listRootGraphInfos` 迁入（承载原 store 完整逻辑：listRootGraphIds 扫描 → loadGraph → 摘要 → 排序）
- `deleteRootGraphTree` 迁入（承载原 store 完整逻辑：防御当前根图 → 收集树成员 → 级联删除 → 清活跃标记）；`isInRootTree` / `deleteAndUnregisterGraph` 随迁为适配层私有辅助
- `getGraphById` 语义包装迁入：导航层按 id 查图（lookupGraph + graphRegistry），供 breadcrumb 标题查询——包装从 store 迁入适配层，不删除、不留在 store
- **函数名一并迁移**：适配层现有含混短名（`listRootInfos` / `deleteRootTree` / `createRoot`）全部改回原 store 完整名（`listRootGraphInfos` / `deleteRootGraphTree` / `createRootGraph`），消费方同步更新
- `goToGraph` 保留：导航域访问 store 底层能力 `loadGraphToView` 的入口（导航卡片不直接碰 store）

- 不确定度：高（级联删除含树遍历、面包屑依赖 getGraphById，需逐行保真）
- 算法复杂度：低（逻辑原样迁移，不新增）
- 工作量：中

### 4.3.工具能力迁入 useGraphOperationAdapter ⏳

**子目标**：

- `applyToCurrentGraph` 改为直调 `commitBatchToGraphs`（单图包装 + 校验同步在适配层完成）——`commitBatchToGraph` 从 store 消失，其适配身份由适配层接管
- `makeLookup` 语义包装迁入：工具层为 compose 提供跨图查询函数（lookupGraph 包装），供认知操作（induce / internalize / diverge）使用——函数名保留
- `operation_controller` 的 `makeLookup` / `getGraphById` 调用改经适配层；**为临时过渡修改**，注释说明"待 operation_controller 迁移后移除"，不构成架构变更

- 不确定度：中（operation_controller 为历史遗留，改动需保守并注释）
- 算法复杂度：低
- 工作量：中

### 4.4.调用方切换 ⏳

### 决策项

**已确定决策**

- 判定标准（充要条件）：**留在 store = Graph.vue 调用 ∨ 唯一图数据修改入口（commitBatchToGraphs）∨ 唯一图数据回溯入口（undo）**
- graphPath 等共享运行时状态留在 store（跨业务消费，不并入单一适配层）
- 查询包装（getGraphById / makeLookup）**不删除、不留在 store**——迁入各适配层按语义重新包装（导航层查标题、工具层供 compose 跨图查询）
- `commitBatchToGraph`（不带 s）为工具层适配身份，并入 `applyToCurrentGraph`（直调 commitBatchToGraphs，最简单签名：针对当前图）
- **函数名随迁移保留原 store 完整名**（listRootGraphInfos / deleteRootGraphTree / getGraphById / makeLookup / createRootGraph）；适配层既有含混短名（listRootInfos / deleteRootTree / createRoot）一并改回，禁止缩写
- `operation_controller` 的修改为**临时过渡**（改经适配层调用），注释说明，不构成架构变更
- 适配层经 store 公开状态访问共享运行时数据，不反向依赖组件域
- 适配层 store 解析统一 lazy（computed 求值 / 方法调用时解析）
