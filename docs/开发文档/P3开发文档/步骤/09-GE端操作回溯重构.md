# 09-GE 端操作回溯重构

---

## 1. 逆元构造重构 ⏳

### 目标

引擎侧逆元从"单图窄语义、捕获面不完整"重构为"与 execute 实际副作用面镜像、图级操作 O(1)"，对齐双存模型（`{ operation, reversalOperations }` 互补无冗余）。重构依据为 `docs/临时文档/GE端逆元问题报告.md` §2/§8/§9 + 图级软删除定案。

### 1.1. delete_node 捕获面扩展

**子目标**：

* 现状：`createReversalForDeleteNode` 只捕获被删节点 + 直接关联边（reversal.ts L113-144），但 `executeDeleteNode` 实际还**级联删除同图引用节点**（`sourceNodeId === 被删节点`）及其关联边。
* 重构：逆元捕获面 = execute 删除面（镜像）——被删节点 + 直接关联边 + **级联引用节点 + 其关联边**；恢复顺序先节点后边（边依赖端点存在）。
* 折叠状态：**不恢复（决策 B）**——executeDeleteNode 顺带清理折叠条目（execute.ts L183-201），逆元不反向恢复；折叠近似性作为已知限制（见 §8 记录）。
* 静默失败（`if (!deletedNode) return []`）不再允许——回调方案下逆元在操作执行前构造，目标必然存在；异常情况改为显式错误（见 1.4）。

* 不确定度：低（execute 删除面已明确，仅镜像扩展）
* 算法复杂度：低
* 工作量：低

### 1.2. expand 逆元携带原折叠条目 + 类型扩展

**子目标**：

* 现状：`createReversalForExpandDependency` 查到了原条目却丢弃 `foldedNodeIds`，只返回 `collapse_dependency(targetNodeId)`——executeCollapseDependency 只能重算，undo 链中间时刻会数错。
* 重构：逆元携带**原折叠条目**（`foldedNodeIds` 快照）。
* 类型扩展：`CollapseDependencyOperation` 增加可选字段 `foldedNodeIds?: NodeId[]`——存在时 executeCollapseDependency **用字段值**（照名单恢复），缺省时重算（兼容正常折叠路径）。
* 对齐设计语义 01 L294"展开：折叠的逆操作"。

* 不确定度：低
* 算法复杂度：低
* 工作量：低

### 1.3. 删除图级逆元构造 + entry 图级元数据（graphSignals）

**子目标**：

* 现状：`createReversalForAddGraph` / `createReversalForDeleteGraph` 存在（后者返回整图快照，reversal.ts L161-172）。
* 重构：**删除这两个图级逆元构造函数**——图级操作的逆元信息（graphId）完全包含在正向操作中（`add_graph.graph.id` / `delete_graph.graphId`），无需捕获操作前状态；图级操作的正向/逆向执行都归前端（与"图级兑现在前端"原则一致）。
* entry 增加**图级元数据** `graphSignals: { added: GraphId[]; deleted: GraphId[] }`——组装 entry 时从批操作提取（add_graph → added、delete_graph → deleted）。undo 时照摘要反向执行：注销 added（撤销 add_graph）、从持久化加载注册 deleted（撤销 delete_graph）——替代图级逆元的角色。
* 前端回调对 `add_graph` / `delete_graph` **跳过 createReversal**（图内操作才构造逆元）。
* 对齐：`add_graph ↔ delete_graph` 互为 O(1) 逆元（语义上）；根图谱删除不支持逆元（用户级操作，不进日志）。

* 不确定度：低
* 算法复杂度：低
* 工作量：低

### 1.4. 静默失败统一处理（GE 待处理 #4）

**子目标**：

* 现状：`createReversal` 各函数对"找不到目标"静默返回 `[]`——undo 变静默 no-op，用户无感知。
* 重构：逆元构造失败改为**显式错误**（返回错误信号或抛异常）——回调方案下，前端在回调中感知失败并阻断整批提交（逆元不完整 ⇒ 该批不可记录）。
* 影响函数：delete_node / delete_edge / update_node / update_edge / move_node（`!current` 与 `!current.position` 双条件）/ expand。

* 不确定度：低
* 算法复杂度：低
* 工作量：低

### 影响范围（引擎侧文件）

```
旧：                                       新：
reversal.ts                                 reversal.ts
  ├─ createReversalForDeleteNode            ├─ createReversalForDeleteNode  捕获面 = execute 删除面
  │    └─ 节点 + 直接边                     │    └─ 节点 + 直接边 + 级联引用节点/边
  ├─ createReversalForExpandDependency      ├─ createReversalForExpandDependency  携带原 foldedNodeIds
  │    └─ collapse(id)（重算）              │    └─ collapse(id, foldedNodeIds)
  ├─ createReversalForAddGraph  ────────────┼─ 删除：图级操作不构造逆元
  ├─ createReversalForDeleteGraph           ├─ 各函数静默失败 → 显式错误
  │    └─ add_graph(整图快照)                │
  └─ 静默 return []                        atomic_operations.ts
                                            ├─ CollapseDependencyOperation.foldedNodeIds?: NodeId[]
                                            execute.ts
                                            └─ executeCollapseDependency：有字段用字段，无字段重算
                                            operation_log.ts（类型）
                                            └─ OperationLogEntry.graphSignals（图级元数据，1.3）
```

涉及文件：`packages/graph-engine/src/core/reversal.ts`、`packages/graph-engine/src/types/atomic_operations.ts`、`packages/graph-engine/src/core/execute.ts`、`packages/graph-engine/src/core/validate.ts`（若 CollapseDependencyOperation 新字段需校验配套）。

### 决策项

**已确定决策**：

* delete_node 逆元捕获面 = execute 删除面镜像（级联引用节点 + 边）；折叠状态不恢复（决策 B，已知限制）
* expand 逆元携带原折叠条目（对齐 01 L294"展开：折叠的逆操作"）
* **删除图级逆元构造**（createReversalForAddGraph / createReversalForDeleteGraph）——图级操作的正/逆向执行都归前端；entry 以 graphSignals 元数据记录图级副作用（替代图级逆元角色）
* 静默失败改为显式错误（GE 待处理 #4 关闭）

## 2. applyBatch 逐操作回调 ⏳

### 目标

`applyBatch` 从"整批事务、内部中间态不可观测"增加逐操作挂点，使前端能在每个原子操作执行前构造逆元（引擎保持无感知，不内部调用 createReversal）。

### 2.1. onBeforeEachOperation 可选回调

**子目标**：

* `applyBatch(graph, ops, options)` 的 `options` 新增可选 `onBeforeEachOperation?(op, graphBeforeOp)`——在 dry-run 循环（pipeline.ts L163-165）**每个原子操作执行前**调用，`graphBeforeOp` = 该操作执行前的图状态（中间态）。
* 引擎语义不变：回调不改变执行结果，仅暴露中间态；默认不调用（零开销）。
* 既有注释决策（pipeline.ts L24-28"applyBatch 不内部调用 createReversal"）**保持不变**——逆元构造在回调内由前端执行。

* 不确定度：低
* 算法复杂度：低（每操作一次回调调用）
* 工作量：低

### 影响范围

```
pipeline.ts（dry-run 循环）：
  for (const op of ops) {
      options?.onBeforeEachOperation?.(op, resultGraph)   // 新增一行挂点
      resultGraph = executeOperation(resultGraph, op)
  }
```

涉及文件：`packages/graph-engine/src/compose/pipeline.ts`、`packages/graph-engine/src/types/operation_log.ts`（BatchOptions 类型）。

### 决策项

**已确定决策**：

* 回调方案（而非 pipeline 内部构造逆元返回）——引擎保持无感知，前端在回调中构造（报告模型基准"接线重构"定案）
* 中间态 = dry-run 循环的 resultGraph（该 op 执行前状态）

## 3. operation_log.ts 批语义类型升级 ⏳

### 目标

操作日志类型从"原子粒度（`operation: GraphOperation` 单操作）"升级为"批粒度 + 按图分组"，支撑"一次 `commitBatchToGraphs` = 一条 entry = 一次回溯单元"。

### 3.1. ItemOperations 结构与 entry 升级

**子目标**：

* 新增 `ItemOperations { graphId: GraphId; operations: GraphOperation[] }`——按图分组的一批操作（item 的日志形态，graphId 替代运行时 graph 对象）。
* `OperationLogEntry` 升级：`operation: ItemOperations[]` + `reversalOperations: ItemOperations[]`（item 间逆序 + item 内逆序为 undo 执行顺序）+ `graphSignals: { added: GraphId[]; deleted: GraphId[] }`（图级元数据，见 1.3）；`parentIndex` / `timestamp` 不变。
* 依据：扁平原子操作无法反推图归属（delete_node / move_node / collapse 仅含 nodeId，无 graphId），undo 需按图应用逆元。
* `State`（粗粒度历史标记）保留定义，MVP 后置不实现。

* 不确定度：低
* 算法复杂度：低
* 工作量：低

### 影响范围

```
operation_log.ts：
  interface ItemOperations { graphId: GraphId; operations: GraphOperation[] }
  interface OperationLogEntry {
      operation: ItemOperations[]            // 一批正向操作（按图分组）
      reversalOperations: ItemOperations[]    // 一批逆元（undo 执行顺序，仅图内操作）
      graphSignals: { added: GraphId[]; deleted: GraphId[] }   // 图级元数据
      parentIndex: number; timestamp: string
  }
```

涉及文件：`packages/graph-engine/src/types/operation_log.ts`（index.ts 导出相应更新）。

### 决策项

**已确定决策**：

* 批粒度：一次 commitBatchToGraphs = 一条 entry = 一次回溯单元（报告模型基准定案）
* 按图分组存储（图归属不可从扁平原子操作反推）
* 类型命名 `ItemOperations`（原 BatchOperations 改名——避免与"批"层级混淆）

## 4. 引擎单测配套 ⏳

### 目标

逆元重构后的正确性由引擎单测保障（不重复前端集成测试——前端只测 Runtime 链路，引擎只测逆元构造）。

### 4.1. 测试更新与新增

**子目标**：

* `tests/core/reversal.test.ts` 更新：
  * **删除** `createReversal add_graph` 测试块（图级逆元函数已删除，见 1.3）
  * **更新** delete_node 测试：级联引用节点 + 其关联边纳入逆元（恢复后引用节点不缺失）
  * **更新** expand 测试：逆元携带原折叠条目（foldedNodeIds），executeCollapseDependency 用字段恢复
  * **新增** collapse 显式折叠成员测试（CollapseDependencyOperation.foldedNodeIds 生效路径）
  * **新增** 静默失败显式化测试（目标缺失 → 显式错误而非空数组）
* 引擎其他测试（execute / pipeline）不受影响——executeCollapseDependency 无字段时保持重算（兼容旧调用）。

* 不确定度：低
* 算法复杂度：低
* 工作量：中
