## 1.浮空窗生命周期归属重构 ✅

### 目标

浮空窗状态从全局 Pinia store（`ui_store`）迁出，归属 default 工具的交互会话；关闭机制从"9 处手动调用"收敛为"1 条外部点击规则 + 少量明确关闭点"；为未来其他工具复用浮空窗/确认弹窗能力提供共享组合式函数基础设施（`feature-tools/composables/`）。

### 1.1.新建 useFloatingWindow 组合式函数 ✅

**子目标**：
  * `feature-tools/composables/useFloatingWindow.ts`——模块级单例（与 mediator / renderer 同款手法），承载浮空窗状态（展示数据 / 打开 / 关闭）
  * 内置外部点击关闭规则（全局 `pointerdown` 监听 + 容器外判定，按下即判定防拖拽误触）
  * 暴露容器注册 API（`registerContainer(el)`）；关闭时保留"清空校验结果"联动

* 不确定度：低（模式成熟，参照 mediator 单例手法）
* 算法复杂度：低（事件监听 + 容器包含判定）
* 工作量：中（新文件 + 监听生命周期管理）

### 1.2.ToolHandler 接口扩展 + default_tool 接入 ✅

**子目标**：
  * `ToolHandler` 新增可选字段暴露浮空窗数据（响应式门面，转发单例状态）
  * `default_tool` 打开浮空窗时写入状态；confirm 写入逻辑（构造 update 操作 + commitBatchToGraph）保留在 `default_tool.onConfirm`，`ToolHandler.onConfirm` 契约不变

* 不确定度：低
* 算法复杂度：低
* 工作量：低

### 1.3.GraphNodeWindow.vue 消费路径切换 ✅

**子目标**：
  * 组件改经 default handler 门面读取浮空窗数据（不再直接读 ui_store）
  * 挂载时注册自身根元素为容器；保留叉号按钮

* 不确定度：低
* 算法复杂度：低
* 工作量：低

### 1.4.清理旧关闭点 + ui_store 瘦身 ✅

**子目标**：

  * `ui_store` 移除 `floatingWindowData`，仅剩 `pendingCanvasFocusId`

* 不确定度：中（删点后需确认无遗漏场景，外部点击规则对 Cytoscape 画布与 DOM 点击的覆盖）

### 决策项

**待确定决策**

> **Q1**：外部点击规则是否同时覆盖"工具栏按钮点击"（DOM 点击在容器外，天然覆盖）与"快捷键切换工具"（无点击事件，不覆盖）？
>
> **建议**：覆盖前者（外部规则天然生效），后者因项目尚无键盘监听体系而搁置。理由：确认的决策范围只处理点击路径，快捷键留待未来统一设计。

**已确定决策**

- 浮空窗状态归属 default 工具的交互会话，不留在全局 store
- 非编辑点击（外部点击）自动关闭浮空窗，替代大部分手动关闭点
- `ToolHandler` 接口扩展暴露浮空窗数据，组件消费路径走接口门面（浮空窗数据修改是工具使用流程的一部分，不可割裂）
- confirm 写入逻辑保留在 `default_tool.onConfirm`（构造 update 操作 + commitBatchToGraph），`ToolHandler.onConfirm` 契约不变
- 保留叉号按钮（主动关闭路径，与外部点击规则共存）
- 键盘快捷键触发关闭——搁置（项目暂无键盘监听体系）
- 组合式函数位置：`feature-tools/composables/`（工具层共享组合式函数目录；与 `frontend/src/composables/` 的"通用无业务语义 UI 辅助"定位区分）
- 组合式函数采用模块级单例形态（浮空窗是全局唯一 UI 单元；与 mediator / renderer 同款手法）
- 外部点击判定使用 `pointerdown` 而非 `click`（按下即判定，防拖拽画布后的 click 误触发）
- 关闭时保留"清空校验结果"联动（原 `ui_store.closeFloatingWindow` 行为迁移至新组合式函数）
- 保留 `mediator.activate` 内的关闭（程序化切工具的语义守护，不依赖点击事件）
- 双击导航的关闭收进 `default_tool.onNodeDoubleClick` 内部（click 先于 dblclick 触发，双击时浮空窗已被 onNodeClick 打开，时序特殊）；`Graph.vue` 装配层不直接操作浮空窗状态，仅做激活工具检查与转发——双击逻辑由 default 工具经 `ToolHandler.onNodeDoubleClick` 接口接入

`pendingCanvasFocusId`（画布视口定位请求）从 Pinia store 迁出为通用组合式函数单例，`ui_store.ts` 整体删除；至此前端不再有专门承载"纯 UI 意图"的 Pinia store——画布定位请求走 `composables/` 模块级单例，与项目"UI 状态尽量归属局部/组合式函数"的既定惯例（AGENTS.md 拆分标准、useFloatingWindow 先例）完全对齐。

### 决策项

**待确定决策**

> **Q1**：`useCanvasFocus` 是否补单元测试？
>
> **建议**：补——对齐 useFloatingWindow 测试先例，覆盖"写入 → 消费 → 清除"闭环。

**已确定决策**

- 位置：`frontend/src/composables/`（通用组合式函数目录，非工具层共享——画布定位请求不属于任何工具特有，跨工具/组件共享）
- 形态：模块级单例（同 useFloatingWindow）
- 一次性意图语义与"消费后清除"规则原样保留，行为零变更
- 删除 `ui/ui_store.ts`，前端不再保留"纯 UI 意图"专用 Pinia store
- `operation_controller.ts` 未使用 import 一并清理（删除 store 后编译必需）
- `CLAUDE.md` 分层表述同步更新（本次迁移的文档改动，用户已许可）
