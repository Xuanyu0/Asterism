# 01-前置依赖：多选机制

> 占位步骤文档。多选机制从 P2 `phase2b/步骤/05-共依赖.md` 迁移至此，作为 P3 认知操作（induce / internalize）的前置依赖。未经详细规划，仅记录想法，后续可再完善。

## 目标

为认知操作提供"一次选中多个节点"的交互能力。设计文档依据：`docs/设计/02-核心功能.md` 中归纳和内化操作的作用对象均为"多个节点"。

## 多选机制

- `graph_store.ts` 新增 `selectedNodeIds: Set<NodeId>`（当前仅有单选 `selectedNodeId: NodeId | null`）
- 新增 `toggleNodeSelection(nodeId)` / `clearNodeSelection()` 动作
- 交互层：普通点击 = 单选并清空其他；配合修饰键或框选实现多选

## 交互方式（待定）

> **Q1**：多选交互方式：拖拽框选 vs Ctrl/Shift+点击 vs toggle 逐个点击。
>
> **建议**：拖拽框选为主 + toggle 点击为辅（直接点击已选中节点取消选中，不需要修饰键）。理由：框选是画布应用最直觉的多选方式（Cy 原生支持 `boxselect`），toggle 点击无需修饰键，符合低认知负担原则。

> **Q2**：框选拖拽过程中的选中区域视觉呈现。
>
> **建议**：Cytoscape 原生半透明蓝色选框即可，不自定义渲染。

## 多选 UI 反馈

| 状态 | 视觉反馈 |
|------|---------|
| 未选中 | 正常渲染 |
| 单个选中 | 高亮边框（现有单选逻辑） |
| 多个选中 | 所有选中节点统一高亮样式 |

## 选中状态归属（待定）

选中状态本质是 UI Runtime 状态，不是 GraphData。

| 方案 | 位置 | 优点 | 缺点 |
|------|------|------|------|
| A（当前） | `graph_store.ts` | 与图数据邻近，组件读取方便 | 污染 GraphData Store 的纯度 |
| B | `ui_store.ts` | UI 状态归位 | 部分读取路径需改到 ui_store |

> **建议**：P3 暂沿用方案 A。若未来 UI 需要根据选中状态做复杂反馈（右键菜单、批量操作面板），再迁移到 `ui_store.ts`。
