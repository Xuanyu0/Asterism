## 1. 浮空窗锚定到目标节点/边 ⏳

### 目标

浮空窗（GraphNodeWindow）从"固定画布右上角"改为"**跟随目标渲染在目标右侧**"：

- **添加节点工具**：浮空窗锚定到"将要添加的新节点"（光标跟随的预览节点，点击后定格）右侧
- **编辑已有节点/边**：浮空窗锚定到被点击节点/边右侧

锚定跟随目标移动/画布平移缩放实时更新；样式定义权完全保留在项目（popper 只负责定位 left/top）。

### 1.1. 依赖安装与扩展注册

**子目标**：

- 安装 `cytoscape-popper`（v4，官方 0 依赖壳）+ `@floating-ui/dom`（定位引擎）。
- 实现 `popperFactory`：`computePosition(ref, content, options)` → 写 `left/top` → 返回 `{ update }`；middleware 必带 `flip()` + `shift({ limiter: limitShift() })`（官方推荐防溢出组合——视口边缘自动翻转/平移，不截断）。
- 注册扩展：`cytoscape.use(cytoscapePopper(popperFactory))`（v4 必须传 factory）。

- 不确定度：低（官方示例明确）
- 算法复杂度：低
- 工作量：低

### 1.2. 渲染层/交互层锚定能力

**子目标**：

- 渲染层（cytoscape/ 严格隔离边界内）提供**通用锚定 API**：给定 cy 元素 ID + 浮窗 DOM 元素 → 创建 popper 实例 → 返回 `{ update, destroy }` 句柄。
- **抽象为通用能力而非 GraphNodeWindow 专用**——设计文档 07-操作回溯.md「UX 设计」的"单击日志节点 → 详情浮卡在节点右侧并跟随"将复用同一 API（011 是它的前置地基）。
- **跟随更新**：`node.on('position')`（节点被拖动/布局移动）+ `cy.on('pan zoom resize')`（画布平移/缩放/尺寸变化——含未来操作日志侧边栏挤压画布触发的 `cy.resize()`）→ 调 `popper.update()`。
- 生命周期：浮窗打开时创建、关闭时 `destroy`（含解除事件监听）——**单实例**，无多实例性能问题。
- 锚定目标解析：按 ID `cy.getElementById(id)` 找元素；**边锚定到边中点**（floating-ui 的 ref 用元素包围盒，边包围盒中心即其中点）。
- **扩展口**：锚定 API 支持传入 floating-ui 边界选项（boundary / padding）——供未来操作日志侧边栏把"画布右边缘 = 侧边栏左边缘"纳入不可溢出区域；**当前 011 不实现边界感知**（侧边栏未落地）。

- 不确定度：中（边中点锚定的 ref 构造需确认）
- 算法复杂度：低
- 工作量：中

### 1.3. 浮空窗 DOM 传送与样式保持

**子目标**：

- GraphNodeWindow 根元素经 `<Teleport to="body">` 传送到画布外——**popper content 必须挂画布外，否则被 canvas 遮挡**。
- 浮空窗**外观样式（.floating-window 及子元素）完全不变**——popper 只写 `left/top`，视觉样式（背景/边框/圆角/阴影/尺寸/字体）仍由项目 CSS 全权定义。
- 移除 `position: absolute; top: 20px; right: 20px` 定位（改为 popper 计算注入）。

- 不确定度：低
- 算法复杂度：低
- 工作量：中

### 1.4. 锚定目标接线（数据流）

**子目标**：

- **default 工具（编辑已有节点/边）**：`floatingWindow.open(node/edge)` 时已有实体 ID——渲染层按 ID 解析目标锚定。
- **add-node 工具（预览节点）**：`previewAddNode` 生成的 `nodeId` 即为锚定目标；浮空窗打开时该预览节点仍定格在画布上（011 前置改动已保证），按 `nodeId` 锚定即可。
- 浮空窗关闭时机（confirm 成功 / cancel / 外部点击）→ 同步 `destroy` popper 实例。

- 不确定度：中（预览节点在浮窗编辑期间的生命周期与锚定目标一致性）
- 算法复杂度：低
- 工作量：中

### 影响范围

```
新功能所属架构地位：

cytoscape/（渲染/交互层，严格隔离 Cytoscape 外部库）
  └── popper 注册 + popperFactory + 锚定 API（新增模块或 useRenderer 扩展）
        ↓ 返回 { update, destroy } 句柄
components/GraphNodeWindow.vue（UI 层）
  └── Teleport to body + 根元素 ref 暴露给锚定层
        ↓ 样式 .floating-window 全部保留（popper 只定位）
feature-tools/（交互逻辑层）
  └── default_tool / add_node 打开浮窗时携带锚定目标 ID
```

涉及文件（预计）：

- `frontend/package.json`（+2 依赖）
- `frontend/src/cytoscape/`（新增 popper 注册/锚定模块，或扩展 useRenderer）
- `frontend/src/components/GraphNodeWindow.vue`（Teleport + 锚定接线）
- `frontend/src/feature-tools/default_tool.ts` / `add_node.ts`（锚定目标传递）
- 相关测试

### 决策项

**已确定决策**：

- 技术路线：**cytoscape-popper v4 + @floating-ui/dom**（用户已确认）
- 锚定范围：**节点和边都锚定**（用户已确认）；边锚定到边中点右侧
- 锚定位置：目标**右侧**（floating-ui `placement: 'right'`，视口边缘由 flip/shift 自动翻转）
- 样式定义权：**100% 留在项目**——popper 只负责定位（left/top），浮窗视觉样式完全由项目 CSS 控制
- middleware 必带 `flip()` + `shift({ limiter: limitShift() })`——视口边缘自动翻转/平移，不截断

**待确定决策**：

> **Q1**：锚定 API 放哪里？
> **建议**：cytoscape/ 目录新增独立模块（如 `cy_popper.ts`）承载 popper 注册 + 锚定函数，useRenderer 不膨胀。
> **理由**：遵循"渲染层严格隔离 Cytoscape 外部库"原则，popper 是 Cytoscape 扩展，应收在渲染层内且独立成模块，便于测试与替换。

> **Q2**：浮空窗组件如何拿到锚定 API？
> **建议**：GraphNodeWindow 通过 useRenderer 已存在的单例间接获取（渲染层锚定 API 经 useRenderer 暴露），组件不直接 import cytoscape。
> **理由**：保持"组件层不碰 Cytoscape"的既有边界（当前组件经 mediator/renderer 间接访问）。

> **Q3**：锚定目标 ID 从哪来？
> **建议**：浮窗打开时（open 调用）渲染层读取当前 floatingData 的实体 ID（node.id / edge.id）解析锚定；add-node 场景读取预览节点 nodeId。
> **理由**：数据驱动，与"GraphData 是唯一事实源"一致；不新增状态。

## 2. 测试与验证 ⏳

### 目标

锚定功能通过单元测试 + 手动冒烟验证覆盖：打开锚定、跟随更新、关闭销毁、样式保持。

### 2.1. 单元测试

**子目标**：

- popperFactory：注册成功、middleware 含 flip/shift、update 写 left/top。
- 锚定生命周期：open → 创建实例并绑定监听；close → destroy 并解绑；重复 open 不泄漏（单实例）。
- 目标解析：nodeId / edgeId → 正确 cy 元素或边中点 ref。
- 回归：GraphNodeWindow 现有渲染/交互测试不破坏（Teleport 改造后）。

- 不确定度：中（jsdom 无真实 popper 环境，需 mock 边界）
- 算法复杂度：低
- 工作量：中

### 2.2. 手动冒烟验证（非契约）

**子目标**：

- 添加节点工具：光标跟随预览 → 点击 → 浮空窗出现在预览节点**右侧**；拖动/缩放画布 → 浮窗跟随。
- default 工具：点击已有节点/边 → 浮空窗锚定到该节点/边右侧；拖动节点 → 浮窗跟随。
- 视口边界：把节点拖到画布角落 → 浮窗自动翻转/平移，不溢出视口。
- 样式：浮窗外观与改动前一致（半透明白底、圆角、阴影等均不变）。

- 不确定度：低
- 算法复杂度：低
- 工作量：低

### 决策项

**已确定决策**：

- 前端只测 Runtime/渲染层集成链路（沿用既有测试原则），popper 底层行为不重复测（floating-ui 自带）。
