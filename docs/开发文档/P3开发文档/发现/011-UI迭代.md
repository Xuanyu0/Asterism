### BUG

#### B-2：编辑模式无编辑点确认无反应（已修复）

- 状态：✅ 已确认（用户发现，已修复）
- 位置：`frontend/src/components/GraphNodeWindow.vue`（`handleFloatingConfirm`）
- 现象：编辑浮空窗打开后**不做任何输入**直接点 ✓——`editingData` 为 null，`if (!editingData.value) return` 直接短路，窗口无任何反馈（用户感知"按钮点了没反应"）。草稿模式无此问题（空 label 提交走引擎校验拒绝，有错误提示）。
- 处理：无编辑时点确认改为 `floatingWindow.close()`（视为"完成"，关闭窗口；不产生无变更的操作记录）。186 测试全绿。

#### B-3：编辑确认提交崩溃——structuredClone 无法克隆 Vue Proxy（已修复）

- 状态：✅ 已修复（待用户浏览器复测）
- 位置：`frontend/src/feature-tools/default_tool.ts`（`onConfirm`）；根因在数据流：`useFloatingWindow` 单例经 `ref` 深度响应式包装
- 现象：编辑浮空窗修改内容后点 ✓——`handleFloatingConfirm` 正常触发（log 确认 `editingData` 非 null），但提交中断：`Uncaught DataCloneError: Failed to execute 'structuredClone' ... at createReversalForUpdateNode (reversal.ts:199) at applyBatch.onBeforeEachOperation (graph_store.ts:339)`。浮空窗不关闭，用户感知"点了没反应"。
- 根因：`floatingWindow.floatingData.value` 是 **Vue reactive Proxy**；`default.onConfirm` 里 `{ ...original, label }` 仅浅拷贝顶层，**嵌套字段（如 `position`）仍是 Proxy**。引擎操作回溯（P3 010）在 `applyBatch.onBeforeEachOperation` 用 `structuredClone` 深拷贝原对象生成逆操作——**structuredClone 无法克隆 Proxy** → 抛 `DataCloneError` → 整批提交中断。
- 处理：`default.onConfirm` 提交前 `toRaw(original)` 剥离 Proxy（嵌套字段随之还原为原始对象）。186 测试全绿 + type-check 通过。
- 连带观察：add_node 工具构造的新对象非 Proxy，不受影响；undo/redo 其他路径（P3 010 已验证）提交的是纯数据对象，同样不受影响。仅浮空窗编辑路径泄漏 Proxy。前端 toRaw 修复已覆盖。
- ⚠️ 架构提示：引擎 reversal 依赖 structuredClone 的兼容性是隐式约束——未来凡从 Vue 响应式对象构造提交数据的路径，都必须先剥离 Proxy（toRaw / JSON 序列化）。
