## 第零梯队：前端编程范式 

从 C/C++/Java 过渡到前端需要理解的根本范式差异，与具体语法无关。

### 思维转变关键点

| 后端/算法背景 | 前端范式 | 本质区别 |
|-------------|---------|---------|
| 命令式（"怎么做"） | 声明式（"是什么"） | 前者手动控制执行流程；后者描述目标，框架自动调度 |
| main() 入口 + 函数调用 | 组件树 + 事件驱动 | 前端没有"主函数"，UI 是组件嵌套的组合结果 |
| 数据在变量里，输出靠 printf/return | 数据在 ref 里，显示靠 template 绑定 | 前端输出不是主动打印，是声明数据与 UI 的关系 |
| 调用函数 → 得到结果 | 用户操作 → 改数据 → UI 自动更新 | 数据流是环形的，不是线性的 |
| 你的代码控制所有行为 | 框架接管了"数据→UI"的同步 | Vue 替你做了 document.getElementById/innerText 等手动操作 |

### 核心认知：声明式响应式

```
"我不说怎么更新 UI，我只说数据和 UI 的关系是什么。"
    ↓
Vue 响应式系统：ref 变了 → 自动同步到所有消费它的地方
    ↓
你只需维护数据（ref / Pinia state），框架管显示
```

### 建议：带着这个思维模型看后面所有语法

不需要一上来就完全接受，但每学一个语法（ref / computed / template / import），都问一次：
**"这个语法是在描述'是什么'，还是在说'怎么做'？"**

### ECMAScript vs JavaScript + 语言家族

1. **ECMAScript 是规范，JavaScript 是实现**。ECMA-262 标准规定了语言核心语法和类型，浏览器厂商（V8、SpiderMonkey 等）各自实现它。红宝书前 10 章学的实际是 ECMAScript 核心。
2. **C → C++ → Java → JS 语法一脉相承**：`if`、`for`、`while`、`switch`、`{ }`、`//` 注释等基础控制流结构一致。读 JS 代码不需要重新学怎么写循环和分支。
3. **JS 不同于前三者的根本点在运行时模型**：
   - 动态类型（运行时才知道是什么类型）
   - 对象是开放的（`{}` 随便增删属性）
   - 函数是一等公民（可以当值传来传去）
   - 原型继承而非类继承

### TS 编程范式的核心认知（通过项目代码现学的）

1. **类型擦除**：TS 的类型系统是纯编译时的，编译后完全不剩。不能在运行时依赖任何类型信息。项目里区分虚实节点靠数据字段（`role: 'knowledge'` 字符串），不靠 TS 类型。这和 C++/Java 的"类型保留到运行时"是根本区别。
2. **类型可以是值**：`'knowledge' | 'reference'` 中的字符串同时是 TS 类型约束（编译时）和 JS 对象中的字段值（运行时）。同一个代码同时服务两个层面，不冲突。
3. **收窄逻辑 = 运行时逻辑**：`if (node.role === 'knowledge')` 既是 TS 类型收窄的依据（编译时推导出此分支下 node 为 KnowledgeNodeData），也是 JS 真实的字符串比较（运行时执行）。不需要额外写任何"类型专用代码"。
4. **结构即类型**：TS 只关心对象的形状（有什么属性、什么类型），不关心对象叫什么名字。JSON.parse 回来的、`{}` 手写的、`{...spread}` 拼出来的——结构对上就是合法 GraphData。

### 1. TypeScript 类型标注 ✅ 已学

- 变量/参数/返回值类型标注：`x: string` / `: void` / `: GraphData`
- 类型断言 `as`（≈ Java 强制转型）
- interface / type 定义
- 可选字段 `?:`、只读字段 `readonly`
- **参考资料**：TS Handbook（Everyday Types / Interfaces）

**笔记：TS 类型标注核心认知**

1. **类型注解在右边**：`x: string` 而非 `string x`。这是为了兼容 JS 语法——任何合法 JS 文件可以直接改名 .ts 用。变量名永远在最左，一眼看到"什么变量"再看"什么类型"。
2. **readonly**：编译时约束——尝试给 readonly 字段赋值会编译报错。不产生运行时影响。适合放在 id、createdAt 这种创建后不该再变的字段上。
3. **类型注解并不总是需要**：项目遵循"能推断就不写"的原则。变量初始值来自字面量（`"abc"`、`42`）时不写类型注解；空数组（`[]: Type[]`）和对象字面量（`{}: Type`）因为 TS 无法推断足够精确才写。
4. **`as` 类型断言**：`x as Type`，运行时零开销（编译后消失），不检查不抛错。只在"你比 TS 更清楚实际类型"时用（如 `event.target as HTMLInputElement`）。≈ Java 强制转型但不抛 ClassCastException。
5. **interface vs type 选择**：项目严格遵循"优先 interface，需要联合/别名时换 type"：
   - `interface`：定义对象形状（`GraphData`、`NodeData`、`EdgeData`）——有属性列表的数据结构
   - `type`：联合类型（`NodeData = A | B`）、原始类型别名（`GraphId = string`）、枚举（`GraphKind = 'main' | 'subgraph'`）
6. **结构类型系统（Structural Typing）**：TS 只检查值**有没有预期的属性**（结构是否匹配），不检查值的声明类型叫什么名字。和 C++/Java 的"名称类型系统"（类型由名字决定）是根本区别。项目里从 JSON.parse 回来的、手动 `{}` 构建的、展开运算符拼出来的——结构对上就是合法 GraphData。

### 2. TypeScript 类型系统（项目核心模式）✅ 已学

- Union type `A | B`、Discriminated union（通过 `role` 字段判别）
- Generics 基础 `Ref<T>`、`Array<T>`（≈ Java 泛型）
- **参考资料**：TS Handbook（Union Types / Discriminated Union）

**笔记：Union Types 与类型收窄**

1. **联合三种形式**：`A | B` 语法统一，分支可以是任意类型：
   - 字符串字面量联合 `'main' | 'subgraph'` — 相当于 C 的 enum
   - 原始类型名联合 `number | string` — 属性可接受多种基础类型
   - 对象类型联合 `KnowledgeNodeData | ReferenceNodeData` — 可辨识联合

2. **可辨识联合（Discriminated Union）**：对象类型联合通过一个共同的"标签"字段区分分支。项目中的 `NodeData` 用 `role` 做标签（`'knowledge' | 'reference'`），`GraphOperation` 用 `type` 做标签。

3. **类型收窄（Narrowing）**：TS 编译器根据运行时条件自动推导当前分支的具体类型。不会产生额外的运行时开销。
   - `if (node.role === 'knowledge')` — TS 在 if 分支自动推导 `node` 为 `KnowledgeNodeData`，else 分支为 `ReferenceNodeData`
   - `switch (operation.type)` — 每个 case 里 TS 知道具体是哪个子类型
   - `'source' in data` — 没有共同标签时用独有属性存在性检查收窄

4. **关键认知**：类型收窄是编译时效果（TS 推导类型），但 `if`/`switch` 语句本身就是真实的运行时代码。同一个 if，同时在两个层面工作——编译时帮你检查属性访问是否正确，运行时做真实的字符串比较。

### 3. 展开运算符 `...` 与解构赋值
- 展开 `{ ...obj }`、合并 `{ ...a, ...b }`、覆盖 `{ ...obj, key: newVal }`
- 解构赋值 `const { cy } = obj`、`const [a, b] = arr`
- **参考资料**：红宝书第 4 章 §4.1.5（解构）、第 6 章 §6.2（展开运算符）

### 4. 可选链 `?.` 与空值合并 `??`
- `obj?.prop`（安全读取） vs `obj.prop`（可能抛错）
- `a ?? b`（null/undefined 时取默认值） vs `a || b`（所有假值都取默认）
- **参考资料**：红宝书第 4 章 §4.4

### 5. ES Module（import / export）
- 具名导出 `export const/interface`、默认导出 `export default`
- 类型导入 `import type`
- **参考资料**：红宝书第 26 章（模块）

### 6. 变量声明与箭头函数 ⚡ 快速通过
- `const / let`、块级作用域（`{ }`）、暂时性死区（TDZ）
- 箭头函数语法 `() => expr`
- **参考资料**：红宝书第 3 章 §3.3、第 10 章 §10.2

**笔记：const vs let 实践**

| | const | let |
|---|---|---|
| 重新赋值 | ❌ | ✅ |
| 块级作用域 | ✅ | ✅ |
| TDZ | ✅ | ✅ |

- **默认用 `const`**，遇到编译报错"不能给常量赋值"再换 `let`。不用反过来想。
- **`const` 不保护对象属性**：`const obj = { a: 1 }; obj.a = 2` ✅ 可以。`const` 只保护变量名到对象的绑定关系，不保护对象内部。
- **`let` 只在需要时用**：循环计数器（`for (let i...)`）、先 null 后赋值（`let cy: Core \| null = null`）、累加器。
- 项目 99% 是 `const`，仅 8 处 `let`，零 `var`。
- **严格模式**：项目已是 ES Module（有 import/export），ES Module 自动强制严格模式，不需要写 `"use strict"`，写了也没意义。

### 7. 对象类型与属性 ✅ 已学

- 对象字面量构造、简写属性 `{ x, y }`
- 属性的三要素：属性名 + 类型标注 `: type` + 运行时值
- 必需属性、可选属性 `?:`、只读属性 `readonly`
- **参考资料**：红宝书第 8 章 §8.1

**笔记：JS 对象的核心特性**

1. **函数也是对象**：JS 的函数天生就是对象，可以赋值给变量、作为参数传递、作为返回值、动态添加属性。
2. **null vs undefined**：
   - `undefined`：JS 引擎自动产生的"空"。
   - `null`：开发者主动写的"空"，语义是"我知道现在是空的，以后会填上"
   - 原则：不主动写 `undefined`，那是引擎的事；主动置空就用 `null`
3. **`typeof null === "object"`**：这是 JS 初版设计的 bug，为了兼容无法修复

## 第 1.5 梯队：函数式数组操作（理解 execute.ts 的关键前置）

`execute.ts` 每行代码都在操作数组。这些方法是该文件的"高频词汇"。

### `array.map(fn)` → 新数组

输入一个函数，对每个元素应用该函数，返回**新数组**（不修改原数组）。

```
C++ 等价：std::transform
```

```ts
// execute.ts 典型用法：
graph.nodes.map(node =>
    node.id === targetId ? { ...node, degree: node.degree + 1 } : node
)
// "每个节点：命中就改 degree 后返回，没命中就原样返回。结果是一个新数组。"
```

### `array.filter(fn)` → 新数组

输入一个谓词，返回**所有**满足条件的元素组成的新数组。

```
C++ 等价：std::copy_if
```

```ts
// execute.ts 典型用法：
graph.edges.filter(edge => edge.source !== deletedNodeId && edge.target !== deletedNodeId)
// "去掉两端之一是被删节点的边，保留其余。"
```

### `array.find(fn)` → 单个元素 | undefined

返回**第一个**满足条件的元素，找不到返回 `undefined`。

```
C++ 等价：std::find
```

```ts
const deletedEdge = graph.edges.find(edge => edge.id === operation.edgeId)
```

### `array.findIndex(fn)` → 索引 | -1

同上但返回索引。

### `array.some(fn)` → boolean

**是否存在**满足条件的元素。

```
C++ 等价：std::any_of
```

**参考资料**：红宝书第 6 章 §6.2 Array（搜索方法：find / findIndex；迭代方法：map / filter / some）

### 链式调用：`array.filter().map().filter()`

每个方法返回新数组，可以直接接着调。从左读到右。

```ts
// execute.ts:132-137
currentCognitiveState.foldedDependencies
    .filter(item => item.targetNodeId !== deletedNodeId)  // 去掉被删目标
    .map(item => ({                                        // 每个: 去掉被删 node 引用
        ...item,
        foldedNodeIds: item.foldedNodeIds.filter(nodeId => nodeId !== deletedNodeId),
    }))
    .filter(item => item.foldedNodeIds.length > 0)        // 空的去掉了
```

阅读习惯：把 `.` 换行当作管道 `|` 看。`数据 → filter → map → filter → 结果`。

**参考资料**：红宝书第 6 章 §6.2（数组）、第 7 章 §7.2（迭代器）

### `Map<K, V>` — 键值对集合

```
C++ 等价：std::unordered_map
```

```ts
// execute.ts:206
const degreeLoss = new Map<string, number>()
degreeLoss.set(edge.source, (degreeLoss.get(edge.source) ?? 0) + 1)
//          ↑ put    ↑ get (返回 undefined 如果 key 不存在)
//                                    ↑ ??. key 不存在时用 0 作为初始值
```

### `Set<T>` — 值集合

```
C++ 等价：std::unordered_set
```

```ts
const visitedNodeIds = new Set<NodeId>()
visitedNodeIds.add(edge.source)       // 添加
visitedNodeIds.has(edge.source)       // 是否存在
visitedNodeIds.delete(targetNodeId)   // 删除
```

**参考资料**：红宝书第 6 章 §6.4（Map）、§6.5（Set）

### 箭头函数：`(参数) => 表达式`

execute.ts 中作为回调出现了 ~50 次。识别它 = 看清代码骨架。

```ts
// 单行箭头函数 = 表达式直接是返回值
node => ({ ...node, degree: node.degree + 1 })
edge => edge.target === currentNodeId

// 多行箭头函数 = { } 包体，显式 return
node => {
    const loss = degreeLoss.get(node.id) ?? 0
    return { ...node, degree: Math.max(0, node.degree - loss) }
}
```

**注意括号**：返回对象字面量时需要用 `()` 包裹——`node => ({ ...node, degree: ... })`。不包裹时 `{` 被解析为函数体起始块，`...` 展开运算符在块内是非法的。

**参考资料**：红宝书第 10 章 §10.2

### 展开运算符作为不可变更新模式（execute.ts 核心模式）

```ts
// "不修改原对象。创建一个新对象，复制所有旧字段，只改我指定的字段。"
return {
    ...graph,                    // 复制 graph 的所有字段
    nodes: graph.nodes.map(...), // 替换 nodes
    updatedAt: now,              // 替换 updatedAt
}
```

这是 execute.ts 每个函数的返回模板。C++ 程序员可能会问"为什么不 `graph.nodes[i].degree += 1`？"——因为 `executeOperation` 的契约是纯函数，不修改入参。展开运算符是 JS 实现不可变更新的最简语法。

### 6. Vue 3 响应式系统 ✅ 已学

- `ref()` 包装原始值、`.value` 访问、`ref<DOM>(null)` 模板引用
- `computed()` 自动追踪依赖的缓存计算属性
- `watch(source, callback, { deep: true })` 响应式观察者
- 底层依赖 Proxy → **参考资料**：红宝书第 9 章（代理与反射）
- **参考资料**：Vue 3 官方文档（Reactivity Fundamentals / Computed / Watchers）

**笔记：Vue 响应式核心模型**

```
ref() / Pinia state = 响应式数据盒子（改了能通知观察者）
    ↓  getter 函数（读取值的函数）
computed = 从已有 ref 派生新数据，自动追踪 getter 里访问的 ref，自动缓存
watch    = ref 变了执行副作用，同样自动追踪 getter 里的依赖
template = ref 变了重新渲染 UI，会递归追踪到链上所有原始 ref
```

**三个核心认知：**
1. **ref 本质**：`ref(x)` = 创建一个 `{ value: x }` 盒子，Vue 通过 Proxy 拦截 .value 的读写实现追踪
2. **依赖自动追踪**：computed / watch / template 都通过"执行 getter 函数 → 沿途记录访问了哪些 ref"来建立依赖列表，无需手动声明
3. **computed 与 watch 的区别**：computed 的 getter 返回值被缓存为 .value，watch 的 getter 返回值只用于新旧对比（触发回调）；两者追踪依赖的机制完全相同
4. **template 特殊性**：template 比 computed/watch 的依赖追踪更深一层，会递归追踪到链上所有原始 ref
