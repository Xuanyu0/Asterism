# 原创性验证：Asterism 认知/布局操作

> 验证方法：逐操作搜索所有已知同类产品（开源 20+ 项目 + 闭源 11 个产品 + 学术领域），确认是否有功能相同的实现。
> 调研时间：2026 年 7 月。

---

## 一、什么是"认知操作"

Asterism 的认知操作定义在 `packages/graph-engine/src/compose/cognitive/`，是**形式化图转换**——不是简单的增/删/改，而是带类型验证、碰撞检测、批量操作生成、可撤销的图结构变换。

每个操作具备：
1. **类型预检** — 验证节点 role/kind/form、边 direction/referenceKind 等字段
2. **批量操作生成** — 产生 `GraphOperation[]` 供给 `applyBatch`
3. **碰撞感知布局** — 使用 `hasCollisionAt` / `hasCollisionInDrafts`
4. **纯函数** — 不持有状态，不写 store
5. **结构化产物** — `ComposeResult<DraftPosition>` 带 drafts + issues + operations

---

## 二、逐操作验证

### deconstruct（解构）

**行为**：一个 atomic 节点 → 抽象节点 + 若干子节点 + 沟通节点（透明投影）+ 边重构。

| 搜索范围 | 结果 |
|---------|------|
| 所有 20+ 开源项目 | ❌ 无 |
| 所有闭源产品（Heptabase/Obsidian/Roam 等） | ❌ 无 |
| 学术概念图领域（Chein & Mugnier 概念图理论） | ❌ 产品级无。理论上有"专门化操作"（graph homomorphism），但非产品功能 |

**最接近的误判**：Heptabase 的白板上手动分卡片。但这是**视觉行为**，不是**类型化图转换**——没有验证、没有类型约束、不可撤销。

**结论：产品级别的 deconstruct 是原创的。**

---

### induce（归纳）

**行为**：选择多个子节点 → 创建抽象父节点 + 沟通节点 + 边投影 + 碰撞检测放置。

| 搜索范围 | 结果 |
|---------|------|
| 所有 20+ 开源项目 | ❌ 无 |
| 所有闭源产品 | ❌ 无 |
| NLP 研究（taxonomy induction / ontology learning） | ❌ 研究论文从文本自动构建分类法，非用户触发的交互式图操作 |
| OWL 本体工具（Protégé） | ❌ 基于 DL 推理器推断层次结构，非用户触发的图转换 |

**结论：产品级别的 induce 是原创的。**

---

### internalize（内化）

**行为**：从工作区取节点 → 删除其边 → 递归清理子图沟通节点 → 散布到独立的"常识层"。

| 搜索范围 | 结果 |
|---------|------|
| 所有 20+ 开源项目 | ❌ 无 |
| 所有闭源产品 | ❌ 无 |

**最接近的概念**：LLM 领域 Karpathy 提到的"Wiki 模式"（原始源 → 精炼知识），但那是 AI 写入、用户阅读，不是用户驱动的图操作。

**关键区分**："常识层 vs 工作区" 的架构区分在其他任何产品中都不存在。

**结论：产品级别的 internalize 是原创的。**

---

### diverge（发散）

**行为**：跨图创建有向虚边 → 自动创建启发式节点 + 镜像节点（两侧一致性维护）。

| 搜索范围 | 结果 |
|---------|------|
| 所有 20+ 开源项目 | ❌ 无 |
| 所有闭源产品 | ❌ 无 |

**最接近的误判**：
- Roam Research 的块引用（可引用其他页面的块）— 但无边类型、无镜像机制、无跨图架构
- Obsidian 的 `[[wikilinks]]` — 未类型化的双向引用，无镜像语义

**结论：产品级别的 diverge 是原创的。** 自动跨图镜像 + 类型化虚边 + 启发式节点在其他产品中不存在。

---

### orbit / pathLayout / moveNode with collision（布局操作）

| 操作 | 可视化布局有先例？ | Asterism 的区别 |
|------|------------------|---------------|
| **orbit** | ✅ 有。d3.js 的 `d3.layout.orbit`、Obsidian Orbit 插件、VTK 的 `vtkTreeOrbitLayoutStrategy` | 这些是**可视化布局**（屏幕元素重排）。Asterism 的是**图状态转换**——验证边类型（必须是实边、非虚边）、执行碰撞检测、产生可撤销的 `GraphOperation[]`。不是装饰，是数据修改。 |
| **pathLayout** | ✅ 有。Cytoscape.js 层次化布局、D3 线性排列 | 同上。Asterism 验证边必须是有向实边。 |
| **moveNode with collision** | ✅ 有。游戏引擎、图形编辑器（3ds Max）、Cytoscape.js 约束放置 | Asterism 的区分在于**预览/提交分离**——前端每帧渲染草稿（带碰撞状态），只有无错误时才提交 `move_node` 操作。这在任何 PKM/笔记工具中不存在。 |

**结论：作为可视化布局的 orbit/pathLayout/碰撞检测不原创，但 Asterism 的编排层将它们集成为带验证和撤销的正式图状态转换——这是原创的。**

## 三、让 Asterism 从根本上独特的四个因素

不是某个单个操作，而是这四个东西的组合不存在于任何产品中：

### 1. 类型化图先决条件

每个操作在类型化节点（role/kind/form）和类型化边（direction/referenceKind）上验证前提条件。

```
// induce 内部的类型预检示例
subNodes.forEach(node => {
    if (node.role !== 'normal') issues.push(...)
    // ...
})
// orbit 预检边的类型
edges.forEach(edge => {
    if (edge.direction !== 'directed' || edge.referenceKind !== 'solid')
        issues.push(...)
})
```

没有其他产品对图操作有如此严格的类型系统。Obsidian 没有类型化节点。Heptabase 没有类型化卡片。Capacities 的对象是类型化的，但无图转换操作。

### 2. 操作 = 图重写，不是 CRUD

Asterism 的操作是**形式化图重写**：

- **deconstruct**：`atomic` 节点 → `abstract` 节点 + 子图 + 沟通节点（结构变换）
- **induce**：`normal` 节点集合 → 新 `abstract` 父节点 + 子图 + 投影边（结构生成）
- **internalize**：工作区节点 → 常识层散布 + 清理（结构迁移）
- **diverge**：本图节点 → 跨图虚边 + 镜像（结构跨越）

这不是"添加/编辑/删除"，这是**图状态的形式化转换**。

### 3. Engine + Compose 分离

- **`core/`**：原子操作（11 种 CRUD），validate → execute → createReversal
- **`compose/`**：编排操作（认知 + 布局），将多个原子操作组合为有语义的图转换

没有其他产品有这种分离。最接近的是 Tana 的"提案"系统（验证 → 应用流程），但那是 AI 内容生成的审批工作流，不是图转换。

### 4. 学习状态模型

Asterism 区分"工作区"图、"常识层"和"子图"，并有跨层移动知识的操作（internalize）。这种架构反映的是**学习状态模型**，不是内容管理模型。没有其他产品以这种架构方式概念化学习/认知状态。

## 四、最终结论

| Asterism 操作 | 有现有产品类似？ | 原创性判断 |
|---------------|----------------|-----------|
| **deconstruct** | ❌ 否 | **100% 原创** |
| **induce** | ❌ 否 | **100% 原创** |
| **internalize** | ❌ 否 | **100% 原创** |
| **diverge** | ❌ 否 | **100% 原创** |
| **orbit** | ⚠️ 可视化布局存在 | **半原创** — 作为图转换集成是独特的 |
| **pathLayout** | ⚠️ 可视化布局存在 | **半原创** — 同上 |
| **moveNode with collision** | ⚠️ 碰撞检测存在 | **半原创** — 预览/提交工作流是独特的 |

**四种认知操作（deconstruct / induce / internalize / diverge）在产品领域（开源 + 闭源）是 100% 原创的。** 没有任何已知产品具有带类型验证、碰撞检测和可撤销图转换的形式化命名操作。

**布局操作（orbit / pathLayout / moveNode with collision）作为编排集成是半原创的。** 单点可视化算法有先例，但边类型验证 + 碰撞检测 + 预览/提交流程的编排集成在其他产品中不存在。
