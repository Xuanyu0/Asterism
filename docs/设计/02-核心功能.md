# 三种交互模式

## UI 交互逻辑

### 交互模式

- 只有三种主交互模式
  - 默认模式
    - 触发时机：没有任何操作被选取（不管是在Cognition还是Arangement）
    - 可拖拽相机镜头
    - 可点击节点/边，然后弹出其浮空窗，进行编辑
  - Cognition
    - 可选择对应子列表中的操作进行操作
  - Arangment
    - 可选择对应子列表中的操作进行操作

### 模式切换

- 模式按钮（正左上角）
  - 定义：用来点击切换当前模式，或者用于提示当前处于什么模式
  - 图标样式：只有 “放大镜” / “星系两种” （MVP阶段暂时用C和A代替）
  - 点击行为：展开模式选择子列表
    - 子列表下：可选择Congnition或者Arangement

### 右键行为

- 右键功能：
  - 仅取消当前所选操作
  - 放弃当前所有的草稿的编辑

### 常驻操作

#### 视觉分组的说明

- 属于不同组别两个操作中间的间隔更宽。

#### 包含的操作：

- 节点的组别
  - 说明：必须补全标签后才可创建，点击其他位置则创建自动取消
  - 具体操作：
    - 添加实节点
    - 添加虚节点
- 边的组别
  - 添加有向实边
  - 添加无向实边
  - 添加有向虚边
  - 添加无向虚边
- 工具
  - 依赖折叠/展开
  - 删除
    - 用户在此模式下点击边或者节点弹出提示框。
    - 若操作对象是抽象节点，则以当前抽象节点为根，递归删除其下所有子图子树。操作前征求用户确认。

## 一. Cognition

- 定义：认知演化
- 图标设计：放大镜

### 包含的操作：

（格式说明：操作 +（图标设计））

- 探索（四角星）
  - 功能：开始新一轮学习，结束后产出知识块（详见 §图 > 四种类型 > 知识块）
- 发掘（铲子）
  - 作用对象：虚节点、无向虚边
  - 功能：开启新一轮学习，结束后更新被发掘对象
- 解构（分裂立方体）
  - 作用对象：实节点
  - 功能：不开始新一轮学习，将节点抽象等级加一，建立新子图。详见 §节点数量控制 > 控制策略 > 抽象。
- 归纳（聚合节点）
  - 作用对象：多个节点
  - 语义：对多个具有统一原理或理论的节点进行归纳抽象
    - 抽象后，抽象节点作为语义载体，用户能够“管中窥豹，可见一斑”
  - 功能：创建新抽象节点，将所选节点转移至抽象节点子图。基于原先已合法的图进行，不新增节点或边，结果天然合法。系统自动创建沟通节点及连接边。详见 §节点数量控制 > 控制策略 > 抽象。
- 内化（“1+1”图案）
  - 别名：常识化
  - 作用对象：任意实节点（包括抽象节点）
  - 若操作对象是抽象节点，则以当前抽象节点为根，递归将其下所有子图子树一并转移至常识层。操作前征求用户确认。
  - 功能：确认后转移节点至常识层。详见 §图 > 四种类型 > 常识层。
- 发散（无向虚边）
  - 作用对象：任意实节点
  - 设计意图：在不同子图间（在同一个图也可以）揭示各自节点间的关联
  - 衍生节点：**启发节点**（详见 §节点 > 引用节点 > 启发节点）
  - 具体过程（分三种情况）：
    - 第一种情况：
      - 用户首先点击图上空白处，之后自动弹出搜索浮空窗（搜索内容排除当前已有节点）
      - 用户通过搜索找到对应节点确认后，系统自动在空白处创建对应启发节点
      - 之后用户再点击该图内另一个节点进行连线
      - 然后系统就自动建立了从一个启发节点到图上节点的一条有向虚边
      - 同时系统自动对启发节点的源节点周围完成镜像操作
    - 第二种情况：
      - 用户首先点击图上节点，之后光标延伸出一条有向虚边
      - 再点击图上空白处，自动弹出搜索浮空窗（搜索内容排除当前已有节点）
      - 搜素到对应节点后，自动创建对应引用节点，并建立连接
      - 同时系统自动对启发节点的源节点周围完成镜像操作
    - 第三种情况：
      - 用户直接点击图上节点，后再点击另一个节点
      - 系统直接建立有向虚边，不创建任何启发节点

## 二. Arangement

- 定义：布局/知识组织
- 影响GraphData的postion属性
- 图标设计：星系
- 统一操作流程：选择操作对象 -> 确认选择完毕 -> 预览布局 -> 用户确认后写入Data

### 认知距离

- 边的距离表示的“软属性”（不是GraphData的内容，是通过边长推断出来的信息）
- 定义：视觉上代表用户在知识认知间的“关联强弱”
  - 越远，表示用户越不需要放在一起看（除非是有向虚边，启发边较为特殊）
  - 越近，表示用户越倾向于把那些知识放在一起看

### 包含的操作

- Adjust：
  - Adjust Distence（双向箭头）
    - 操作对象：任何节点
    - 定义：不改变边方向地改变两节点间边长
    - 操作：
      - 用户先选择一个“动节点”，再选择一个“不动节点”后
      - 光标在画布上移动（点击拾取节点后，节点吸附在光标上，再点击目标位置放置）
      - 系统根据光标在屏幕上的移动距离，实时连续地修改边长
      - 确认后，写入GraphData
  - Adjust orbit
    - 操作对象：任何节点
    - 定义：调整角度，并离散性地调整边长
    - 操作：
      - 用户先选择一个“不动动节点”，再选择一个“动节点”后
      - 鼠标在画布上移动（点击拾取节点后，草稿节点跟随光标自动吸附在最近轨道，再点击放置确认）
      - 系统实时生成草稿节点
      - 草稿节点自动吸附在最近的轨道，并保持鼠标和中心节点一样的夹角
      - 确认后，更新节点位置（如果产生碰撞则不能点击确认）
- Layout：
  - Orbit 环绕布局（地月系统）
    - 操作对象：实节点（中心节点）与该节点用实边（有向或无向，禁止任何虚边）相连的实节点
    - 功能：让一些节点绕一个中心节点分布
    - 操作：
      - 用户先选择一个“中心节点”
      - 再选择一些“环绕节点”
      - 选择完毕，系统计算出草稿布局
      - 用户手动微调草稿，直到满意且不产生任何碰撞
      - 注意：对单个节点的微调采取Adjust orbit的核心交互逻辑
      - 确认后，改变所有操作节点
    - 规则：
      - 只有用户明确选择的环绕节点才会参与 Orbit。
      - 未被选择的节点若没其他规则施加，则保持原位，即便它与中心节点有边。
      - 支持有向和无向实边，但禁止虚边。
      - 如果环绕节点本身是其他 Orbit 的中心节点，只要本次操作没有选择它，它的位置保持不变。
  - Path 路径布局（三点一线）
    - 操作对象：实节点（轴心节点）与该节点用有向实边相连的实节点
    - 功能：让认知路径更加规整
    - 操作：
      - 用户先选择一个“轴心节点”
      - 再选择一些“路径节点”
      - 选择完毕后，通过拾取放置确定旋转角（点击设置方向参考点→路径自动对齐）
      - 之后，系统实时计算出多个路径节点形成一条线的预览布局，但不改变边结构。
  - Cloud Layout（电子云）
    - 定义：
      - 表达知识间的认知联想（Association）。
      - 用户认为这些知识应该放在一起看，但不表达中心、顺序或层级关系。
    - 认知语义：
      - 表达：Association（联想）、Similarity（相似）、Co-occurrence（共现）
    - 操作对象：任意节点，任意边。
    - 功能：
      - 将一组知识组织为认知云团。
    - 操作流程：
      - 选择若干节点，
      - 系统实时计算出“云”的“中心点”。
      - 选择完毕后用户通过拾取放置调整云团半径（点击设定圆心→再点击设定半径边界，确定云团范围）
      - 用户可选：编辑任意两个节点在布局后最大距离和最小距离
      - 确认操作后，系统会在范围内随机分布所选节点（保证任意两个节点的距离满足要求）
      - 预览布局
      - 用户确认后写入 Data
    - 规则：
      - 不改变边。
      - 被选节点形成聚集，未被选节点保持原位。
      - 允许多种合法布局结果，系统仅保证：节点聚集、节点不重叠、保持云团特征。
- Knowledge Group：
  - （详细的内容，见下“嵌套布局操作”）
- Move：
  - 单点移动：
    - 操作对象：单个节点
    - 功能：单独移动一个节点在图谱中的绝对位置，不改变其所属的知识群
  - 知识群移动：
    - 操作对象：知识群
    - 功能：单独移动一个知识群及其下级知识群在图谱中的绝对位置

### 嵌套布局操作（非MVP阶段实现）

用户可能对已布局对象继续进行布局操作，如：

- Path + Path
- Orbit + Orbit
- Orbit + Path
- Path + Orbit

由此引入 Knowledge Group 的概念，来界定布局操作的对象范围

#### Knowledge Group

- 定义：
  - 用户定义的一类具有共同特征的组织单元
- 语义：可以是关系松散的一些知识
  - 区别与“抽象”，知识群不要求群内节点具有统一的原理或者理论，可以是知识的平凡集合
  - 但是判断决策，交由用户
- 属性：标签
- 作用：
  - 不直接改变位置属性
  - 不改变知识结构
  - 不改变边
  - 只是表达知识的在空间中组织关系
  - 严格区分于“抽象节点”，Knowledge Group 不表达知识间的从属关系
  - 是节点的一种属性
- 规则：
  - 同一个节点不能同时属于多个知识群
- 派生概念：SubGroup
  - 定义：从属于更高级的Knowledge Group
  - 作用：
    - 对更高级的Knowledge Group的整体操作，会同时以递归的方式影响从属于其Subgroup
    - 而对Subgroup的操作，不会改变更高级的Knowledge Group。
  - 规则：
    - 无硬性要求
    - 交由用户决定知识群间的从属关系
    - 从属关系的传递具有方向性
      - 对于被操作的知识群来说：“我的附庸的附庸是我的附庸”

#### 操作

- 创建知识群
  - 操作对象：任意节点
- 链接知识群
  - 操作对象：两个知识群
  - 操作过程：
    - 先选择一个知识群A，再选择一个知识群B
    - 两次选择结束后，A自动成为B的Subgroup
- 解除知识群链接
  - 操作对象：两个知识群
  - 操作过程：
    - 先选择一个知识群A，再选择一个知识群B
    - 两次选择结束后，A与B解除原来的从属链接
  - 规则：
    - 两个知识群原来必须是链接的
- 删除知识群：
  - 操作对象：任意一个知识群
  - 操作过程：
    - 选择一个知识群
    - 然后系统弹出提示
    - 确认后删除这个知识群
  - 规则：
    - 一次操作只删除指定的一个知识群，以及其对应的所有从属关系
    - 不连带删除其他从属于其的知识群
- 成员操作：
  - 移出知识群
    - 操作对象：单个属于某个知识群的节点
  - 加入知识群
    - 操作对象：一个节点和一个知识群
