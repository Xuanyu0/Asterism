# 交互逻辑设计

## 核心定义

- 交互方式：用户进行的一次特定行为（键盘/鼠标输入）
- 交互结果：交互后给予用户的反馈
- 交互路径/流程：一种或者多种交互方式的组合
- 交互上下文：不同的上下文，同样的交互方式的交互结果不同

## 指导思想

- 交互方式应达到最低交互摩擦
- 交互方式尽量选择用户面对某种想法时最可能的行为
- 对于同一个交互结果，尽可能设计多种交互路径（因为不同的用户理解不同）
- 交互模式全局统一
- 快捷键以简洁为主，降低组合键的设计占比
- 某种操作结果必须可以通过鼠标点击或者移动达到（以适配未来可能的移动端需求）
- 显示表达用户当前处在的状态

## 全局交互逻辑

- 鼠标左键：执行/选择/切换（工具）
- 鼠标右键：取消/关闭
- Escape：与鼠标右键相同
- Tab：切换

## 新设计

### 显式表达默认状态

- 用默认指针图标（图标也是Button，点击后就回到默认模式）表达用户出于“默认”交互状态
- 所以“默认交互模式”从这种意义上来说也算是一种“工具”。
- 图标在不同地方，表示交互上下文不同
  - 在顶层工具栏旁，数字键和滚动键只在工具栏内跳转
  - 在交互模式（认知/布局）下工具栏，数字键和滚动键其内跳转

## 交互设计的借鉴

### 工具的选择

- 交互方式 1：按下键盘数字键， O(1) 跳转
- 交互方式 2：鼠标滚轮，循环数组式 O(n) 遍历

> 借鉴 Minecraft 物品栏的选择

### 模式的切换

- 交互方式：Tab，循环数组式 O(n) 遍历
- 例子：
  - 按下Tab后从认知模式切换到布局模式

> 借鉴 Opencode 的 Agent 的切换

### 意图聚焦

- 交互方式：Ctrl + ` 后切换默认指针图标位置（再按一次切换回来）
- 例子：
  - 默认光标聚焦在常驻工具栏（数字键/滚轮控制常驻工具）
  - 按 Ctrl + ` 后光标跳到交互模式工具栏，数字键/滚轮随后控制认知/布局子操作
  - 再按一次 Ctrl + ` 光标跳回常驻工具栏

> 借鉴 VS Code 终端的聚焦

### 视图切换

- 交互方式：功能键(F1 ~ F...)
- 视图定义见 §04-UI与笔记库.md > Button设计 > Overlay 视图

> 借鉴缺氧的视图切换设计

### Q键提取匹配操作

- 交互方式：对节点/边按 Q 键以类型匹配对应常驻工具栏工具
- 例子：
  - 光标悬停在实节点上，按 Q 键，此时选取添加实节点工具

> 借鉴 Factorio 的 Q 键设计

### 预览 -> 执行

- 仅限认知/布局交互模式下的工具

#### 统一交互流程

```
选择操作 → 进入预览 → 确认 → 执行
                     ↘ 取消 → 回退到选择状态
```

- 步骤说明：
  - **选择操作**：用户选择认知/布局模式下的具体子操作（如 Deconstruct / Orbit）
  - **进入预览**：系统根据当前操作和对象计算临时结果，画布上以**半透明/Draft 样式**渲染
    - 预览结果仅存在于内存的临时结构中
    - 预览阶段可调整操作参数（如拾取放置调整布局位置：点击拾取节点→节点吸附在光标上→再点击放置）
  - **确认（左键/Enter）**：预览内容写入 GraphData，操作完成
  - **取消（右键/Escape）**：清除预览内容，回到操作选择状态

#### 预览的视觉表达

- 预览内容使用半透明的样式
- 若预览导致碰撞/冲突，以**淡红色**高亮冲突节点

#### 预检查与执行阻隔

- 确认前执行所有校验规则（碰撞检测、合法性检查），预览中直接显示校验结果
- 若校验不通过，确认按钮不可用，同时显示错误信息（红色提示）
- 校验通过 → 才允许确认执行

> 借鉴 Factorio 的 Ghost 建筑模式

## 交互设计的代码实现的借鉴

### 上下文 Key

> 借鉴 VS Code：同一按键在不同上下文应产生不同结果。

#### 服务对象

- **数字键** — 当前操作的是常驻工具栏还是交互模式工具栏？
- **滚轮** — 同上
- **Escape / 右键** — 当前活跃的最近一层状态是什么？该取消谁？
- **Enter** — 仅在预览阶段：确认操作，写入 GraphData。其他阶段无效果。

#### 上下文键定义

| 上下文键                   | 取值含义                                                    | 服务于       |
| -------------------------- | ----------------------------------------------------------- | ------------ |
| `focusOnMainToolbar`       | true = 光标聚焦于顶层常驻工具栏                             | 数字键、滚轮 |
| `focusOnModeToolbar`       | true = 光标聚焦于当前交互模式的工具栏                       | 数字键、滚轮 |
| `inPreview`                | true = 处于认知/布局操作的预览阶段                          | Escape、右键 |
| `toolActivated`            | true = 有工具处于激活状态（常驻工具或模式子操作，两者互斥） | Escape、右键 |
| `notificationPanelVisible` | true = 通知面板正在显示（操作错误/提示信息）                | Escape、右键 |

#### 路由规则

**数字键 / 滚轮**

```
条件                               → 行为
focusOnMainToolbar === true        → 在常驻工具栏内跳转
focusOnModeToolbar === true        → 在当前交互模式工具栏内跳转
两者均为 false                      → 数字键/滚轮无效果
```

两者互斥（见互斥约束），由 Ctrl+\` 切换。

**Escape / 右键**

优先级从高到低匹配，第一条满足的生效：

```
条件                                                      → 行为
notificationPanelVisible === true                         → 关闭通知面板
inPreview === true                                        → 取消预览，回到操作选择状态
toolActivated === true && inPreview === false             → 取消当前激活的工具
以上均不满足                                               → 无操作
```
