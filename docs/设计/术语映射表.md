# 术语映射表

> 用途：连接中文设计术语与英文代码标识符，保证 grep 检索时搜全所有变体。
>
> 使用方式：在 grep 设计文档或代码前，先查此表获取所有相关标识符，再用 `grep -E "(术语1|术语2|...)"` 一并检索。
>
> **来源标注说明**：
> - `设计/` — 概念出自 `docs/设计/`（L1），用户亲手书写
> - `开发文档/` — 概念/实现细节出自 `docs/开发文档/`（L2）
> - `代码` — 标识符/文件名来自实际代码库
> - `设计/ + 代码` — 概念出自设计文档，英文标识符来自代码

## 六、规则分类术语

> 概念体系出自 `docs/设计/05-规则分类.md`（L1）。代码实现分布在 `rule_checkers.ts`、`validate.ts`、`compose/` 等文件中。

| 中文 | 英文标识符 | 含义 | 来源 |
|------|-----------|------|------|
| 规则 | rule | 判断系统状态的约束条件，由分类 × 应用时机 × 触发时机三个维度定义 | `设计/` |
| 硬性规则 | hard rule | 由编程语言/计算机自动保证的规则。 | `设计/` |
| 自定义规则 | custom rule | 由产品设计者定义或程序员承诺的规则。 | `设计/` |
| 全局规则 | global rule | 针对 GraphData 元素的不变量，一处定义，所有操作自动遵守。 | `设计/` + `代码` |
| 局部规则 | local rule | 与特定操作或功能绑定的规则。 | `设计/` + `代码` |
| 内联规则 | inline rule | 局部规则的子类——硬编码在功能代码中，不需要灵活开关。本质是与该功能逻辑深度耦合的语义预检 | `设计/` + `代码` |
| 非内联规则 | non-inline rule | 局部规则的子类——独立定义且可复用，需要灵活开关或跨操作泛用 | `设计/` + `代码` |
