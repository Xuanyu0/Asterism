# 规则

## 分类

* 规则总体分为**硬性规则**和**自定义规则**
  * 硬性规则：由计算机或编程语言本身定义，违反后编程语言报错，抛出异常或软件崩溃。
  * 自定义规则：由产品设计者定义或者由程序员承诺的“编程语言未定义的情形”。违反后软件不会崩溃，但是会带来用户使用体验上的差异或者意料之外运行情况。

### 自定义规则 的子类

* 全局规则：
  * 内涵：一处定义，项目所有地方都必须遵守
  * 外延：针对于GraphData中的元素定义的规则
* 局部规则：
  * 内涵：定义后不需要所有地方遵守的规则
  * 外延：与某个或某些用户操作或功能绑定的规则
  * 进一步分为**内联规则**和**非内联规则**
    * 内联规则：被硬编码在特定功能代码文件中的规则
    * 非内联规则：独立定义并且可复用的规则

## 规则的应用时机和触发时机

* 应用时机：产品设计者或开发人员需要考虑向文档或代码中写入规则的时机
* 触发时机：规则本身在程序运行时怎么被触发调用

### 应用时机

* 硬性规则：由程序员在开发时依据编程语言标准自觉遵守
* 自定义规则：针对于实际应用场景制定规则
  * 全局规则：针对于GraphData中的元素在具体应用场景下期望的行为制定规则
  * 局部规则：针对于特定的操作或功能的交互逻辑或者函数产出制定规则
    * 针对于不同情况：
      * 内联规则：**不需要**灵活开关的规则
      * 非内联规则：**需要**灵活开关或泛用的规则

### 触发时机

* 硬性规则：由编程语言在编译期自行触发，或者是计算机运行时的底层自行触发
* 自定义规则
  * 全局规则：默认所有修改GraphData的操作都执行
  * 局部规则：
    * 内联规则：在对应代码块内触发
    * 非内联规则：在对应独立文件中触发

## 规则配置表

* 内容：目前只有“全局规则”（非内联规则在项目变得更加复杂时加入）
* 作用范围：执行操作的目标图谱
* 持久化：跟随根图谱一起存储
* 一致性：一个根图谱一个表，表同时适用于所有其下子图
* 默认行为：创建一个新的图谱后，默认开启所有全局规则
  * 注：常识层按实际情况，以合理的逻辑默认直接忽略一些规则（比方说节点数）
